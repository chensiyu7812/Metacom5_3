**评分链路的实际变化。**

原 q=0…4、m=0/0.25/1、α=1、λ=0.05 保持不变。v2 将引文抄写改成选择合法来源编号，由程序恢复原文；完整复测原 55 个评分任务，49 个形成有效候选记录，6 个仍有字段或证据结构冲突，55 个均自然结束。

v2 的 6 个失败不是 6 个“不会判题”：2 个 relation/severity 冲突，2 个 findings 与错误索引不一致，1 个必需来源缺失，1 个 scored 状态混有未解决的不确定性。有效子集中，OFF 11/12、ON 10/12 都是 q=4、m=0；9 个完整自然配对全平，另 3 对缺项。10 个重复配对中 8 对完整且分数相同，另 2 对缺项。必须保留这些分母，不能只报成功子集的一致性。

这些输出也表明，模型会把一般建议、问题句或评价性鼓励当成必须有个人历史证据的断言。因此做了一次有具体依据的语义范围澄清，明确一般表达、努力与已完成结果、个人事实和时序推断的区别；没有为了拉开 OFF/ON 分差而改 q 锚点。

v3 同时让模型输出 kind 与 relation，两处实际上重复决定“是否属于事实判断”，仍可能互相矛盾。完成 14 条时有 11 条有效、3 条字段冲突，于是停止继续扩量。另 4 条当时已送入引擎，按中断 UNKNOWN 保留，不能消失在账本里，也没有自动重试或回填旧分数。

v4 只简化上述表示：用一个 relation 字段表达 non_factual / supported / contradicted / unsupported / uncertain；语法约束合法的 severity、来源与 scored/uncertain 组合；m 与错误索引按既定算式派生。它沿用 v3 的同一次语义澄清，并非第二次改评分标准。模型仍须自己判断证据关系，程序不从理由猜分或替它纠错。

全部 67 个 schema 已在 CPU 编译预检。预先固定 5 个技术检查项，通过后在同一运行身份下继续剩余 62 项；前 5 项包含在 67 中，没有再抽一次。完整请求、权重、环境、提示、parser、draw 与来源哈希均有绑定。回复按自然 EOS/EOT 结束，不设 60/256 等任务级上限；原生上下文容量、900 秒技术超时与循环保护仍保留，异常不是零奖励。

v4 的 **67 个任务全部执行，64 条形成可解析候选记录，3 条因循环保护终止，没有字段解析失败**。三个缺失分别为原卷第 12 条年龄损伤、第 6 条风格变体，以及新增“旧机会仍可接受”的损伤。原始输出和失败均保留，未自动重试或补分。

这些是开发卷的原始分布，不是独立准确率。10 对中只各重复一次，不能用 3/10 当成已校准的总体错误概率。q 仍主要集中在 4；没有据此人为打散评分或制造资源胜出。

运行中定位了循环失败的一个技术原因：grammar 约束了结构，但提示未完整列出嵌套字段，raw 显示模型在猜 q_reason 等字段，随后在 q_rationale 位置循环空白。已另存显式字段说明的 v5 **离线准备版本**及检查，未执行新的模型调用、未再次跑全卷；它不能回头修复 v4 的失败，也没有解决已证实的语义问题。

**考卷也需要接受核查。**

原卷有 24 条自然 OFF/ON 回复、9 条单点损伤、12 条轻量风格变体，另 10 次预选重复，合计 55 次。新增固定的 6 对、12 条控制回复分别覆盖：历史中的人物关系、supporter 问题与 seeker 确认、旧机会被新状态更新、意向与已完成有效结果、结束对话的边界、假设示例与用户事实。

自然 ON 条件只取一次资源，四类各 3 个前缀，完整资源块为 124–876 tokens；并未测量多次 GET 的全部计划。12 个 OFF/ON 对的回复文本均不同，但“文本不同”不等于任务效用不同。该卷可诊断奖励测量，不能由多数平分断言所有资源或多步取用都无用。

这些控制回复是助手依据公开原文构造的诊断题，未预设精确 q/m，更不是新增的真实用户效果。结束对话一题改用较早的合法切点，删除了后续 turns 与 sessions；不能借用较晚历史证明当时应该如何回复。

| 新增控制类型 | 正确/尊重边界侧 `(q,m)` | 定向改动侧 `(q,m)` |
|---|---|---|
| 历史中的家庭关系 → 无依据的经理身份 | (3,0) | (1,0.25) |
| supporter 猜测出轨 → 冒称 seeker 已确认 | (3,0) | (2,1) |
| 过去 offer 已失效 → 冒称现在仍可接受 | (3,0.25)，存在误罚 | 缺失：循环保护 |
| 正在考虑请求 → 已调整且已有效 | (4,0) | (1,1) |
| 尊重结束 → 强迫继续 | (4,0) | (1,1) |
| 听过七门课的假设例子 → 自己曾说有七门课 | (3,0) | (3,0.25) |

本轮进一步发现原风格变体中的两处构造缺陷：第 7、8 条把 “What’s been going on that’s been…” 机械展开为 “What is been going on that is been…”，这里原缩写实际对应 has。它们不是纯粹保持语言质量不变的风格对照。保留全部 12 条的原结果，同时单列这 2 条语法损伤和另 10 条轻量改写；这是事后题目质量审计，不把降分直接叫作裁判偏差，也不换题重跑。

两个新增题的证据解释也需精确：Eliza 被称为姐姐/妹妹，并不能逻辑上排除她兼任经理；错误在于回复把没有来源支持的经理身份当成已知事实。七门课程来自 supporter 的假设例子，而完整既有历史 H001:T023 还有 seeker 明说自己有六门课的证据。后一个证据在冻结 payload 中本来就存在，只是本轮审计补充定位；没有事后给模型加答案。

**格式正确之后，仍有可定位的语义问题。**

v4 第 6 条损伤将原回复改成“你已经当面与父亲和解”。模型给 q=0、m=1，方向符合损伤意图，却只援引“父亲已经去世”证明以前没有和解。这个推理不成立；真正相关的是 C:T009 中用户说他们没能尝试修复关系。该题说明“分数方向正确”“引用确实存在”和“理由充分”是三件事。

这条失败没有被助手改成另一份模型输出，也没有触发又一轮 rubric 优化。来源核查记录保存在 `outputs/pm_rl1/measurement_resolution_20260929_v1/coordinator_only/semantic_findings_first_pass.json`。这是参与开发的助手审计，不追溯性宣称为独立人评。

另一个直接影响训练的例子是第 6 条自然 ON 回复：相同回复和证据的两次预定 draw 分别得到 `(q=3,m=0.25)` 与 `(q=4,m=0)`，`q/4−m` 相差 0.5，为最大资源成本 0.05 的十倍。前者说用户只讲了问题、未确认进展，后者使用 C:T007 中用户所说的 therapy breakthrough 解释进展。这并不要求人工立刻选出唯一正确分数；仅这个实测差异，就说明冻结一次缓存抽样不能自动消除奖励测量的不确定性。

第 2 条自然 OFF 还出现语义上的内部矛盾：q 理由明说建议只是 “might be” 的探索性表达、m=0，逐项判断却把同一建议记为 unsupported、severity=0.25，同时再次承认它并非事实断言。数字组合已经合法，语义仍不一致。不能把这类结果升级为可靠的自动事实风险标签。

新增“旧机会被当前状态更新”的正确侧控制也被误罚：回复说“以前获得过海外晋升机会，但现在已不可接受”，对应 H018:T002 的 offer、H020:T004 的职位已给别人、C:T002 的 missed out 三处直接证据；模型却称以前是否有 offer 不明确，记 m=0.25。其错误侧输出发生循环，两侧不能形成完整分差。这比只看“损伤检出数”更能说明为何尚不适合自动数据准入。

**Compass 的有限诊断已经收口。**

固定 12 个盲化 pair：6 个自然 OFF/ON、6 个新增覆盖 pair，不给它 Qwen 分数或条件答案。两次运行使用相同题目：复杂结构版本 12 次中 11 次技术失败、1 次解析失败；仅做一次输出简化，复用旧两字段 verdict/rationale 协议后 12 次全部自然结束且可读，但全部未提供要求的来源编号。

简化版给出 10 个 A_better、2 个 B_better，没有 equivalent/uncertain。6 个控制题中有 5 个干净版本恰好位于 A；模型 6 个全部选 A，表面的 5/6 与“永远选 A”相同，不能写成 83.3% 语义准确率，也没有反序实验可据此估计稳定的位置偏差。

人物关系题甚至返回 A_better，理由却明确说 A 把 Eliza 错认成经理，B 才是更好回答。原标签和理由均保留，不替它修成 B。自然 pair 的理由多是轻微的具体性、共情或表达偏好，不足以把全部胜负自动转成新 q/m 差异。

Compass 是不同 checkpoint，但使用 Qwen2 架构、与 Qwen 裁判共享模型家族背景；本轮不称为独立模型家族验证。结论是保留这批诊断，不将 Compass 升级为训练教师或最终仲裁者，不继续增加模型竞争。

**E0 已发生真实的参数学习，而不只是环境算式检查。**

程序已知效用的 5 类小任务包括：完全不需要资源、单条资源有益、第一条单独无益但两条联合有益、有害干扰、预算 mask。小型 actor/critic 只读公开任务标志、已获取数量和预算，使用 3 层 128 单元网络、5 个动作。它不是生产环境的 BGE 观测编码器，也不是训练完成的真实 PM。

| 实际实验 | 每个种子的 PPO episodes | 种子 17 / 29 / 43 的终点平均回报 | 5 类中达到精确最优的数量 |
|---|---:|---|---|
| 从随机策略训练 | 4,096 | 0.6700 / 0.6725 / 0.6700 | 2 / 2 / 3 |
| 完整 toy 支持图 BC 后接 PPO | 128 | 0.6850 / 0.6850 / 0.6775 | 5 / 5 / 3 |
| BC 后用已观测回报初始化价值头，再接 PPO | 128 | 0.6850 / 0.6850 / 0.6850 | 5 / 5 / 5 |

同一小环境的精确最优平均值为 0.685，均匀合法随机策略的期望为约 0.15979，直接 STOP 为 0。第一批已学到互补资源，但停止不够准确；第二批 BC 已达到最优，一个种子在接入随机价值头后退化。第三批只用冻结 BC 策略的 5 条已完成轨迹、10 个 transition 拟合价值头，actor 与共享网络保持不变，再执行 128 个 PPO episodes，三个种子均在终点保留最优行为。中间检查仍有波动，不声称整个训练过程单调改进。

这不是三种算法的等预算排名，也不是 PPO 优于 BC 的证据：BC 在这些已知小题上已经最优。能确认的是 BC→已观测终值拟合→PPO 的集成能够工作；真实任务中未测过的计划效用不能照 toy 的完整函数补齐。

实际检验包含完整 16-episode batch、冻结采样策略的 log-prob 重算、forced STOP 不进入策略/熵项、终值无 bootstrap、旧 batch 拒绝、模型与 optimizer/RNG 保存恢复。第三批保存的 optimizer 显示各种子 8 次 batch 更新、全部 10 个参数张量均有 128 步及非零 Adam moments，独立确认 PPO 的确执行过更新。

三批共有 13,056 个 toy PPO episodes；CPU 训练主体计时合计约 54.4 秒。没有真实语义 PM 训练、LLM token-level RL 或执行器 LoRA 参数更新。

此外，公开 `Observation` 到真实冻结 BGE-M3、再到小型 actor/critic 的工程桥接已完成一次实测。24 个 train 状态只编码当前公开前缀和已 GET 正文，4 个 acquired slots 按类型/rank 规范排序，另有公开 metadata 和预算；不接收 EpisodeSpec、私有库存、评分或 owner ID。相同 acquired set 不因取得路径而改变特征，已有向量缓存不让未 GET 正文进入初始状态。全部非法动作概率为零。

该开发编码产生 5,266 维输入，网络约 70.8 万参数，只做未训练网络的前向检查；尚不是正式特征冻结或真实策略学习。固定缩放不拟合 test 统计，BGE 沿用原生 8,192 长度核查、超长拒绝而非默默截断。A4500 上加载约 11.34 秒、24 段文本编码约 0.88 秒，另列成本，不混进裁判吞吐。

**执行器训练准备也向前推进了一步。**

新增当前回复专属的 loss mask、右侧补齐 mask 和按目标 token 数聚合的 dev NLL。提示和历史不计损失；首个回答 token 由最后一个 prompt 位置预测；结束 EOT 计损失；没有目标时明确失败，不以 0 loss 通过。

真实 Llama 模板预检查发现：当前模板忽略 `add_generation_prompt=False`，仍会在完整回复后追加下一轮 assistant 标头。编码器通过同模板的空 assistant 渲染核对固定后缀，只保留本轮 EOT，排除随后标头；没有修改冻结的推理模板或剪短回答正文。这个修复在真实 tokenizer 与 24 条已有 train 回复上通过，完整序列最大 1,349 tokens，当前回复＋结束标记为 38–89 tokens。

这些 24 条仅作编码诊断，监督准入数量为 0；没有用自己的高 q 给自己制造训练集。LoRA 作者/核验者的批次绑定、数据准入、参数更新、adapter 重载和 dev checkpoint 选择仍待接通，不能写成 R05 已完成。

两张卡有并行工作，不能把设备时间相加称作实际等待时长；哈希、分析、测试与人工研究工时也不包含在上述引擎时间中。v4 共处理约 117.35 万输入 tokens、33.09 万输出 tokens，平均输出约 4,939、中位数 5,321，包含 Qwen 思考及失败已产生的部分。旧报价中的 512 输出情景不是这里的实测值，也不能直接用 Qwen token 数换算另一个 API 模型的账单。

按当前 96/18/48 分组，原默认核心调用情景是 8,244 次，另有最多 648 次 OFF 预留；它们不是当前必须全部执行的清单。若未来 3,096 次下游 J 仍采用与 v4 相近的证据长度、思考配置和并发，**仅这部分 J 就约 38.5 引擎小时**，尚未包括 G、SFT 作者/核验、OFF、加载、失败、训练和独立评价。这是有条件的量级估算；当前用途判定不支持先消耗这批算力扩大含糊奖励训练。

**后续的职责边界已经明确。**

1. 这批开发卷与单次语义澄清收口后，不再因为没有分出资源优势，就换裁判、强制排名或继续向研究者发整张人评表。
2. 若自然 q 没有可解释的资源区分，或噪声足以主导取用，就保留来源/执行错误诊断，继续执行器与确定性工程；不擅自删掉 q、改成纯风险 reward 或扩大帮助性 PPO。
3. 执行器下一步应先做小批量、来源可逐项核对的作者/核验流程：作者只看实际 G 输入，核验记录另存，修复不能泄漏未取得历史；确认准入和完整恢复后，才扩到既定 train/dev 数据额度。程序编码通过不能替代语义准入。
4. X_l 经过真实训练、dev NLL 选择与重载冻结后，再构造同动作域、同反馈的 OneShot 和有限 PM 学习；本轮 E0 成功不替代这些依赖。
5. 新的人评如要集中做一次，留给系统冻结后的既定最多 24 对独立盲审。尚未生成的 X_l/RL 回复不能现在预先评完；若某个系统未运行，相关配对如实缺失，不临时补成别的实验。

**用途已经冻结为“开发诊断，不自动生成训练标签”。** `measurement_use_decision.json` 在完整末批控制题返回前登记这一判定：已有具体的同输入波动、试探性建议误归类、证据推理不足和技术失败，后面几题通过也不能消除这些问题。保留有出处的错误分析和全部配对分布；不把当前 J 接成帮助性 PPO reward、事实错误金标或最终独立评审。剩余预定全卷照常完成，不按结果取消不利题。

这样收口后，近期工作转到执行器可核对的作者/核验小批量与训练工程。作者只能看到实际取得的材料；核验拒绝或不确定的候选保持未准入，不用 q/m 的高分替代来源依据。质量核验与当前广泛 q 标度的资格分开，不因为裁判未获全用途资格就停掉编码、来源、恢复和训练管线，也不因为管线已运行就声称语义问题解决。
