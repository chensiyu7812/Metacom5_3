版本：2026-09-30 v2。对象：研究者及接手本项目的 Codex。主方案身份：`pm_rl1_completion_20260930_v2`。

**本轮集中完成一个冻结执行器下的资源策略研究：修清资料含义，验证反馈，完成真实 PM 学习、公平对照和独立评价。执行器适配做一次有界尝试；第二套 PM、交叉迁移、全量 QA 清洗和长期心理状态建模后移。**

本文件合并网页版 continuation-v1、当前服务器证据和后续讨论。新增数额、阈值和训练额度是事前工程选择，不是已有实验结果。目标是降低返工和依赖失效的风险；不能保证正收益、PPO 胜过其他方法或论文录用。

## 1 研究问题和本轮完成标准

主问题分两层：第一，情境化资源计划是否优于不取资源和固定取量；第二，读取已取得正文后继续决定是否获取，是否比一次决定整个计划更有价值。前者成立不自动证明后者成立。

执行器问题作为重要配套：相同提示、相同资源下，监督适配是否改善使用、澄清或忽略资源的能力。LoRA 失败不阻止在 base 上研究 PM。表示修复、执行器变化和策略变化分别对照，不把三者的合并效果全算成 RL 收益。

| 必须交付 | 证据要求 | 不足以代替它的东西 |
|---|---|---|
| 真实任务的学习实验 | 实际公开前缀、合法 GET、真实生成与反馈、PM 参数更新 | toy E0、能运行的 PPO 脚本 |
| 公平的策略比较 | 同初始信息、同合法终值计划、同执行器、反馈来源及成本披露 | 弱 Fixed、只给 OneShot 五个选项 |
| 独立效果约束 | test 前冻结；独立人工子集；质量、事实风险和成本分开报告 | 训练奖励上升、同一裁判再次给高分 |
| 有限且可解释的结论 | 逐 owner／seed、缺失、暴露和失败机制 | 用回复数量冒充独立用户数量 |
| 可审查论文材料 | 主表、必要消融、方法、局限、复算入口 | 只汇总发现了多少问题 |

研究限于一次回复前的顺序信息获取。没有未来用户模拟，不证明长期心理改善。EvoEmo 的 18 个 owner 是公开构造人物；test 只有 3 个 owner，且 32/48 完整当前会话有历史评审暴露。第一篇按这一范围写；更广泛的人群结论需要新的独立来源，不能用新增同人物前缀替代。

## 3 与网页版方案相比的明确修改

1. 主攻一个执行器下的 PM；双执行器各训练 PM 和交叉迁移不再默认执行。
2. 将固定计划的回复生成提前，供覆盖诊断、校准及后续训练复用；正式反馈必须等协议冻结后产生或重评。
3. Fixed 增加混合二／三／四条资源候选；所有方法获得同一初始可行计划 mask。
4. 不把自然回复多数平局直接判为裁判失败；单列低差异、方向错误、信息不足。
5. 人评一次设计，按开发、封存验证、有限运行复核和最终评价分用途；各自有上限，不允许静默扩卷。
6. 主 PPO 优先采用 384 episodes／seed，四次均衡覆盖 96 个 train 前缀；计算不足时按预定吞吐规则统一采用 128。旧 toy 的 128 次成功不是自然任务收敛证据。
7. 反馈仍不可用时准备一条人工终值表的窄任务路线，明确新增人工量与研究范围变化；不自动伪装成四头主线完成。
8. 修正费用：$1.50724291 是历史边界，此后全部新增付费工作合计目标 $10、硬上限 $20；不是每阶段新额度，也不是把历史边界再次扣入这 $20。

## 4 保持不变的实验边界

- 只用既有允许的公开来源。禁用项目自造纵向语料及衍生物继续不读、不用。旧源会话与事实家族隔离保留。
- 保留 96／18／48 切分；当前协议的新语义设计只用 train/dev。test 仅作机械核对和冻结后评价，不读 test gold 来修方案。
- 动作为 STOP、GET_RS、GET_MP、GET_MS、GET_ME；每头排名冻结，每次取下一条，总 GET≤4。完整 MS，不跳过不合规 rank 1 去取 rank 2。
- 资源预算 2,048 Generator tokens，计入资源说明、元数据与分隔符。它不限制回答长度。自然 EOS／EOT，原生上下文边界和技术 watchdog；超时、循环和上下文耗尽不是质量零分。
- 相同最终资源集合按 RS／MP／MS／ME 和头内排名规范呈现。GET 顺序不制造不同 Generator 输入。
- actor／critic 只收 Observation；未取正文、gold、离线审查、owner ID、反馈分数和私有库存不得进入模型。新事实细节只能随合法 GET 正文交付；全量合法证据仅供评价。
- 模型、tokenizer、chat template、renderer、overlay、排序、生成及评分配置各自有身份。表示变化使生成缓存失效；只改评分则保留生成并重评。UNKNOWN、缺测不填零。
- 保留旧成果和 outcome locks。此方案不改旧 Paper-1 官方指标，不把新单轮 q/m 称作官方 ESC-Eval，不把 QA 准确率当支持效果。

## 6 P1 只修实验所需的输入含义

历史对话作为有主体标签的引用上下文，当前 AI 身份单独声明；不把历史人类支持者自传作为当前 AI 的既往发言。保留原文。RS 中依赖真实个人经历的动作适配成一般性观察或明确假设，不整类删除 Self Disclosure。

资源字段至少表达来源主体、说话者、原文位置和可用时间。另设报告时间、事件时间、最近确认时间与依据、历史／被更新／不确定状态、建议／意向／尝试／完成阶段、结果及依据。无证据保留 null／unknown；完成不自动等于有效，抽取时间不等于再次确认。去掉无条件的 Current profile 暗示。

复用已审 101 条 MP 及 overlay；核查剩余 72 条 train/dev 重复更新，28 条 test 不进入开发语义审查。完成意味着逐条有结论，不意味着全部错误或全部变成确定事实。对 ME 按源片段 hash 固定 24 个 train/dev 意向／行动／结果候选，只修有依据的漏分、误分。其余未知字段允许保留；不要求重建全部 2,236 条单元。

应用到 test 的变换规则在 train/dev 冻结；不得把人工答案写成只在测试时存在的完美事实标签。所有方法共用同版来源。错误来源与模型误读分别归因，抑制最新条目后不得自动恢复更旧的矛盾状态为 current。

固定六个 dev 前缀，含已知身份失败；其余按 owner／风险分层 hash 选。base／旧 LoRA × old／new renderer × OFF／RS-only／memory-only，最多 72 条。保持共同合法计划及原资源条目；缺少共同可行计划就记缺失。作为开发回归，不当泛化证明。若同时改包装和 RS，报告组合修复效果。

新版重新计算 token 成本、上下文和逐步可达性。将 initial_plan_mask 真正接入顺序与 OneShot 的共同初始特征。执行相关观测隔离、无未来、无跨 owner、完整 MS、规范缓存、预算测试；不重复无关全仓库测试。

## 7 P2 一次执行器适配和可复用回复池

### 7.1 覆盖示范与选择

每个 train/dev 前缀预选最多六个合法条件：OFF、单条、跨类两条、同类两条、三条、四条。按库存和固定 hash 选择，不参考生成质量。候选槽位最多 train 576、dev 108；重复计划去重，不可行槽位不换成容易条件冒充覆盖。

每槽一条弱监督候选；旧标签只有在新输入下重新核验、重建身份后才复用。每槽最多一次定向修复，**全批修复最多 96 次，其中 train 80、dev 16**，按预定 hash 次序处理有明确可修缺陷的槽位。首试加修复最多 780 条作者输出。准入逐条记录证据、接受／拒绝／不确定和资源行为；审查是 AI 辅助弱监督，不叫人类真值。

teacher 只能看该条件交付的输入；核验者可看完整合法来源，但不能将额外事实写入标签。示范需同时包含正确使用、谨慎澄清和合理忽略。剂量 0–4 及同类多取各争取至少六个 train owners、十二个独立前缀；不足如实报告，不扩容追求满表。

从原 base 重训一次 LoRA：r8、alpha16、q/v、BF16、dropout0、lr1e-4、microbatch1、accumulation16、seed17、最多三 epochs；仅回复与 EOS 损失。冻结十二个 dev 行为输入，每 epoch 生成，共 36 条。先排除有来源证实的严重身份、主体、时效或行动结果捏造的 checkpoint，再按 response NLL 选，平局取早期。错误判断需要原文及输出片段，不靠关键词或未经校准裁判直接排除。

主执行器 X*：新 LoRA 有通过者则取所选者，否则取新 renderer 下的 base。这个选择不声称 LoRA 已提升质量。三个 checkpoint 全失败就保留失败，不启动第二轮效果调参；只有可指出的实际代码／标签实现错误允许一次定向重跑，另记预算，不能用该例外无限再训。

### 7.2 共同计划和回复池

固定十五个全局数量向量：OFF；四头各一条、两条；两个跨类双条；两个混合三条；全四头各一条；另一个含同类重复的混合四条。额外组合按 `execution_contract.json` 的固定 hash 规则选择。所有数量向量先确定，再检查每个前缀的合法性；不得根据回复挑计划。

- train：十二个 owners 各 hash 取两个前缀，24×15，最多 360 条 X* 回复。
- dev：全部 18×15，最多 270 条 X* 回复，兼作 Fixed 选择和校准材料池。
- 若新 LoRA 通过，另一执行器在 dev 的 OFF／RS-only／memory-only 三个共同计划生成，最多 54 条，供执行器比较与校准。
- 输入身份相同即复用；评分未定时只生成，不以旧失败裁判制造正式标签。协议冻结后统一评分；开发版本旧分数不混入训练。

从这批池中检查：资源是否增加当前所需信息；执行器是否正确采用；人认为有差异而自动分是否遗漏；同人偏好的计划是否随前缀变化。按原抽样全体和事先定义风险层报告，不删除问候、结束对话或没有收益的场景。已测最佳只称“已测支持集内最佳”，其最大值受评分噪声与选择影响，不叫全空间 oracle。

## 8 P3 有边界的反馈建立

### 8.1 分工与外部工具

主评分默认复用已安装 Qwen3.5-9B，冻结 checkpoint、运行模式、提示、parser 和来源协议；新版身份不自动洗掉旧失败。先程序校验出处与时间，再检查回复的具体事实主张，最后评价当前支持适当性。使用统一严格 as-of 公共证据，隐藏方法、执行器、计划、成本和 seed。来源卡片按当前前缀统一构造，可查完整原文；不能只给某方法取到的资料，也不能把证据卡变成带正确答案的人工资源。

保留完整来源可追溯；裁判窗口不足时显式失败，或使用事先在 train/dev 验证并冻结的分步来源核查，不能静默截断。一般共情、建议、试探性提问不是自动的个人事实断言；对没有出处与被出处否定分别记录。旧分项实现已存在，先提交与旧版的具体差异表，避免重做同一评分器。

可选只增加一个专用核查候选 `lytang/MiniCheck-Flan-T5-Large`，固定最多 64 条开发主张：真实回复与既有控制各半，来源绑定后测试。它判断文档是否支持主张，不评价支持质量；不支持不能直接解释为事实为假。默认仅诊断；若纳入主协议，必须在封存验证前冻结并整体校准。失败即停，不接着换第二个事实模型。其加载、窗口和实际时延尚待验证。

FActScore／VISTA 的主张拆分和对话证据区分可借鉴；本项目已有部分实现，不因此重造工具。ESCA 提供规划与执行分开的研究参考；RLFF-ESC 的未来模拟奖励不接入本轮。不开通用裁判竞赛，不训练新的大型 reward model。

### 8.2 评分含义

沿用 q=0…4：严重失配、明显问题、基本回应但有重要不足、贴合适当、充分满足当前需要。最后一档不要求更多建议或更长回答。m=0／0.25／1 表示未检出可确认问题、局部失准、实质性身份／事实／主体／时态／行动结果或边界错误。每个非零 m 都要有回复片段与依据；m=0 不等于全事实认证。

q 和 m 不假定正交；额外风险权重是研究者设定。单回复评分转成 `U=q/4-m`，同前缀、同执行器的 OFF 回复及分数固定复用。训练回报为：

```text
GET:  -0.05 * (完整资源 tokens_after - tokens_before) / 2048
STOP: U(ON) - U(OFF)
总回报: U(ON) - U(OFF) - 0.05 * 最终完整资源 tokens / 2048
```

U 最小非零档差为 0.25，成本最多 0.05；这是粗档位质量优先、同档偏好低成本的目标，不是精细连续效用。分开报告 q、m、ΔU、tokens。λ=0.025／0.10 仅作预先声明的已观测结果重算，不据 test 调参，不称重新训练；单个前缀不同效用档位的优先次序不会因此改变。

### 8.3 人工一次设计并按用途封存

校准默认 40 对：开发 8 自然＋8 控制；验证 16 自然＋8 控制；另预锁最多 8 对自然备用。开发与验证按前缀及事实家族分离，尽量平衡 owner；已知旧失败放开发，不冒称新样本。自然对照包含资源计划差异及 X 差异，按条件和 hash 选，不看自动分。

控制覆盖身份、主体、时效、意向变结果；同时含等效表达和不该被事实惩罚的一般支持。相同文本由程序保障同分；不得由模型编造差异理由。诊断控制与自然样本分开统计。

两名独立人类优先，标整体偏好 A／B／相当／无法判断，以及每侧风险和关键依据。两人不一致时保留分歧；有来源可裁决的事实问题单列一次裁决，主观偏好不强行统一。单人也可做有限校准，但结论注明单人。旧联合人工 A、AI B 和旧 ESC 双人量表不改身份。

40 对可以一次填写：执行方先只读取开发标签，最多修订主协议一次；冻结后首次读取验证标签。人工问题含义不在填写后改动。备用仅因明确偏好少于八对而启用，不能因为正确率低而扩卷。验证失败不继续调 prompt 并重称独立通过。

### 8.4 准入是本轮操作边界而非准确率保证

下列规则在揭开封存标签前写入 measurement_freeze。自然主分母使用两人一致的判断；另完整报告每位评分者和分歧。单人时使用其标签并降低证据表述。计数按 pair，并披露前缀／owner 相关性。

1. 固定技术集首试结构有效率≥95%，一次固定恢复后应全部可处理；仍缺项列出，不用只报成功子集。技术合格不代替语义合格。
2. 封存中经来源确认的四类严重错误控制必须检出严重风险，并使错误侧 U 低于对应无损侧；一般支持控制不应被误罚为严重事实错误。控制题本身若不能成立，记证据不足，不事后换题补成功。
3. 固定十二条单回复独立复评分，至少十一条 U 相同，全部不得翻转“是否严重错误”；其余差异必须公开。训练用单点评分，所以检查单点评分重复，不另开一套 pairwise 裁判混入训练。
4. 在自然样本中，若明确方向至少八对，至少75%与 U 方向一致；自动平分对明确偏好计不一致。至少五对一致人工平局时，自动平局识别需≥80%。分别报全部分母；6/8 的最低通过证据很弱，不能称普遍可靠。
5. 少于八对明确方向，不直接判裁判失败。若至少五对人工平局、平局识别≥80%、其余已明确方向均一致且前述事实与稳定性通过，状态为 `CALIBRATED_LOW_CONTRAST`：只支持有限粗尺度实验，统一128 episodes，主张重点是可测差异及成本边界。否则记 `INSUFFICIENT_HUMAN_INFORMATION`。不能强迫拉开分数。
6. 自然材料中若自动偏好已由来源确认含严重错误的回复，同时漏报该风险，记 `MEASUREMENT_UNQUALIFIED`，不由其他简单题通过率抵消。

完整方向条件通过记 `CALIBRATED_FOR_BOUNDED_STUDY`。两种 calibrated 状态仅允许本范围有界研究，最终效果仍须独立评价。未通过时保留失败表，转 B0 准备；不把未合格分数投入正式 PPO。主观点分歧和人类相当不会被伪造成严重错误。

### 8.5 运行中的不确定性与反馈漂移

在评分前冻结一条追加证据核查路径，且在开发材料中实际运行：使用同一完整合法依据，定位原文及可能更新；只允许一次，不换题、不改标准、不按喜欢的结果选分。主线全程此类复核最多96条。

仍无法评分的 train 回复进入人工补核，预留最多12条单回复，最多两次集中提交；它们不占用或偷看最终人评。人工采用同一量表，记录混合反馈来源；该 batch 等全部奖励齐全再更新，原策略版本和轨迹保留。预算用尽或仍有无法判断，暂停受影响训练并转 B0，不删除难例或补零。PPO探索新增输出，因此不能承诺一次初始校准永远不需要任何核验。

技术失败同 identity 最多两次恢复，全程额外 G 请求≤96、J 请求≤192；重试同样计时、记账。技术修复不允许改实质提示后仍沿用旧实验身份。test 的缺测不反向改变评分器，报告覆盖与缺失敏感性。

## 9 P4 一个执行器下的完整学习对照

### 9.1 初始化和共同信息

冻结 BGE-M3、128维投影、两层128宽 MLP、五动作及 value 头。初始前缀、原 metadata、预算、合法动作和70位初始计划 mask 对各方法一致；取得正文规范排序，不给额外路径标识。编码长度超过原生范围显式处理，不能静默丢关键证据。

从24个 train 前缀已测计划选最高净回报作为 BC 示范；并列按较低实际 tokens、再固定向量顺序决定。展开为合法路径；路径次序不依赖未取正文，遇 token 非单调时从真实可达路径按固定顺序选。未测计划不填零、不标负，不叫最优 gold。

BC 和 OneShot 的监督默认 Adam lr3e-4、weight_decay1e-4、batch64、50 epochs、三 seeds；不做网格。训练终点固定，另记录训练拟合及 dev 误差。critic 用已测路径的真实剩余回报拟合价值头500步，actor及共享编码主体冻结；无未测价值 oracle。保存 BC-init 及实际初始优化器状态。实现参数在运行 manifest 中逐项核对。

### 9.2 PPO预算和缺失处理

seeds 为17、29、43。主 PPO 和独立训练的 PPO-NoText 各三 seeds。优先每 seed 384 episodes，四次 owner均衡且每次覆盖96个 train 前缀的预定洗牌；低差异状态或吞吐预算不足时统一128，先96个各一次，再每owner固定hash抽8个中的若干个组成额外32个，保证次数尽量均衡。抽样不看回报。

最终使用128还是384，必须在第一条正式PPO rollout前由纯吞吐和已预定请求表决定并冻结：包含生成、评分、弱标签核验和预留的总引擎时间投影≤96小时选384，否则选128；若128仍超额，先去掉可选完整RQ-X测试矩阵，再提交具体排期取舍，不静默削弱主基线。用开发任务实测均值和长上下文分层估时，不用质量结果决定预算。96小时是本轮排期边界，不是回复截断；实际到界先保存，不假称达到固定终点。

PPO沿用 lr3e-4、clip0.2、γ1、GAEλ1、value0.5、entropy0.01、grad clip0.5；16完整episodes／batch、4epochs、minibatch4。forced STOP不计policy／entropy。384配置只在128和384做dev评价；128配置只在64和128，均用18个dev前缀。主结果取固定终点，不按峰值挑选。各运行先完成共同较早检查点，再继续到最终预算，避免最后一组因排期完全没跑。

回报缓存与on-policy轨迹分开：同一冻结终点复用真实G／J；每个PPO batch仍重新采样动作、保存当时log-prob。缓存未覆盖的合法计划需要真实新反馈。不得为了省调用把未测计划mask成非法。新反馈次数、总episodes和缓存命中分别记录。

全STOP或熵下降先检查mask、反馈分布、参数更新和信用分配。有实现错误则保全后修复；无实现错误不强迫探索以制造表面收益。有限预算未改善不等于算法无效；报告曲线、拟合和小样本限制。

### 9.3 最小且足够强的基线

| 方法 | 固定规则 |
|---|---|
| OFF | 每前缀真无资源，同执行器共享一次回复及分数 |
| Fixed-Dev | 在共同十五个全局固定向量中按dev逐owner均值选一个；该向量对某前缀不可行时执行OFF并计入总体，不剔除该前缀 |
| Matched-Random | 使用主PPO终点在dev上的三seed合并计划分布；运行时合法性筛选归一，分布中无可行计划时退OFF；三个随机seed，报告实际成本差 |
| OneShot | 同初始信息，对全部最多70个合法终值预测回报；用初始特征和计划计数／交互编码，按预测选优 |
| BC-init | 实际PPO初始化，三个seed，单独身份 |
| BC-union | 最终共同train反馈重新生成示范后训练，三个seed，不能冒充实际PPO起点 |
| PPO | 读取已取得正文，继续取或STOP |
| PPO-NoText | 独立训练三seed；将已取正文编码置零，其余信息、初始化数据、预算及超参一致 |

所有train轨迹结束后，OneShot与BC-union使用同执行器的共同train反馈union，包括主PPO及NoText所获反馈。主PPO按当时反馈在线训练，不默认重跑。披露静态基线可访问最终数据、PPO在线取得数据的非对称性；其结果是有意加强的静态参照，不能说完全隔离了全部优化差异。NoText与PPO独立探索，消融也不是逐条相同数据的因果证明。

NoText从相同示范、相同初始随机seed独立进行BC和价值初始化；从初始化起直到评价都将已取正文置零。保存它自己的BC起点，不把已训练FullText网络在测试时关闭正文冒充这个消融。

OneShot、BC匹配前缀编码和相近网络规模，报告参数量及调参机会。仅参数相近不能证明容量与优化完全等价。保留全部监督目标、拒收和技术缺失，不按test选择主方法。

## 10 P5独立评价与论文收口

test前冻结全部输入、模型、协议、主执行器、预算、Fixed、Random分布、方法、seed、统计和人评抽样。正式test不进行语义修复或参数回流。发现协议错误时标受污染身份，不能靠换test重来。

主执行器下OFF1、Fixed1、Random3、OneShot3、BC-init3、BC-union3、PPO3，共17实例；加NoText3，48前缀最多960个回复槽位。相同终值、输入和生成身份复用，不把多个策略命中同一回复算独立生成。若新LoRA通过，可再做固定OFF／RS-only／memory-only×两执行器×48，最多288槽位，默认计入预算但可按事前计算取舍后移。第二套PM和交叉迁移不执行。

最终人工默认48对，三owner平衡、seed预先轮换：24对PPO／OneShot；12对PPO／强Fixed；12对同计划X_g／X_l。X_l不存在或按事前预算规则取消该执行器对照时，最后12对改为PPO／BC-union，在test前锁定。每个比较内尽量不重复前缀；实际不可行短缺保留。支持适当性、事实风险、平局／无法判断和两人分歧全部记录。小样本仅约束主张，不保证显著性；配套X对照为有限独立证据。

人工同一表单可同时标每侧q／m及整体偏好，便于检验训练效用和最终偏好是否冲突；先做开发示例确认填写含义，最终不改量表。回复来自真实冻结系统，不能先造一批未来RL答案。两名人类优先；单人注明局限；模型复评不能改称人评。

主表报告q、m、ΔU、混合回报、token、GET次数、四类剂量、主动STOP／预算阻止／库存不足、耗时及缓存／重试／缺失。prefix内配对后按owner汇总，列三seed和三个test owners；区间和显著性外推受限。质量不显著不能写为等价或非劣效。缺失结果不填零，报告按合法指标范围的上下界敏感性，不能仅给complete-case胜率。

| 最终证据 | 论文可以主张 |
|---|---|
| 学习策略胜Fixed，未胜OneShot | 情境化规划价值；顺序观察增益未建立 |
| PPO胜BC-init，未胜BC-union | 本次在线更新改善，但监督利用更多反馈可解释收益 |
| PPO胜OneShot，NoText变差，人工支持 | 本设置下顺序信息利用的条件性证据 |
| 表示／执行器改善，策略无优势 | 执行可靠性及策略收益边界；不能包装成RL有效 |
| 自动提升但人工不支持 | 代理优化与测量偏差；收缩效果主张 |
| 奖励仍不可用、真实PPO未完成 | 只能称测量／工程阶段完成，不能称第一篇自然任务RL验证完成 |

从P1起维护论文方法、来源及局限草稿；P4起填学习曲线，P5后填主表。只追加主结论所缺的证据，不因“还能加模型”扩展。官方QA和ESC-Eval若另做，保持原协议与独立用途，不成为主线前置条件。

## 11 B0与B1有限人工反馈备用路线

触发条件是一次有界修复后反馈仍不合格、自然判断信息不足，或正式训练语义缺测超过预留。B0自动可做：整理失败、计算各单头0–4条的合法剂量覆盖，准备具体人工任务与报价。**B1不能默认静默启动：它把四头联合命题缩成单头取量／停止，且人工量明显增加，需要研究者对这份具体替代任务作出选择。** 这个依赖来自研究范围与实际人力改变，不是旧文档的一般审批门槛。

备选设计：在train/dev按机械可达剂量覆盖选一个头，平局优先ME、MP、RS、MS；不看回复质量选头。24个train前缀仍为原十二owners各两个，6个dev为三个owners各两个，test保留48。分别生成每个合法k=0…4终点，最多120／30／240条，共390条。两人逐回复按冻结q/m和来源评价，上限780次单回复判断；已完成A路线的人工量另加，不从账本抹掉。必要的事实分歧裁决单独计时；仍无法判断则保持缺测。

完整train终点表冻结后，动作只有该头GET／STOP；所有可达STOP都需真实分数，不能只给预选好路径打分。PPO重新采样合法轨迹，查已测终点表，无新自动奖励；dev选择不看test标签。保留固定剂量、一次性剂量、BC、PPO、NoText，披露完整监督基线很强。完整test表仅在系统冻结后揭封，允许对已测全剂量计算确切任务内参照，但不输入策略。

此路线解决的是反馈覆盖可控，并不保证RL胜过监督学习，也不等价于完成四头主命题。若需要真实人长期支持效果，则另需新数据与研究设计，不通过换名称达成。人力未落实时继续B0、论文及无依赖工程，不伪造人工标签或声称B1已运行。

B路线应在A路线test揭封前决定。若A路线test已被检查，后续同一test上的B只能披露为后续探索，不能再称独立确认；不得重新划分现有test来掩盖这个限制。

## 12计算人工与现金预算

默认全部本地，新增API预算为0。继承边界后的新增付费总目标$10、硬上限$20；现账本$1.50724291、边界后新增0、账本未结算reservation0。付费入口仍需统一原子预算及具体授权；新模型／新namespace不产生新额度。先核验所有在途责任，再报可用现金。

主线两名人类：40对校准＋48对最终，共176次配对判断；8对备用最多再16次；运行中12条单回复最多24次，**最多192次配对＋24次单回复**。两类工作单位不同，不加总成“216道相同题”。人工事实裁决、来源阅读和填写说明的工时另记，不伪装为零。正式发卷前用四个开发样例测工作量，计入原开发额度；人评表及完整材料准备好再提交。

生成、评分上限及128／384情景由budget_estimate自动计算；它是未扣缓存的保守任务槽位，不是实耗，也不是所有任务都会独立调用。弱标签审核如由协调助手完成，记录审核条数和工时；如用本地模型，则计入其调用与设备时间。备选核查器、多步来源复核、代码错误重跑、加载下载和人工工作各列责任项。
