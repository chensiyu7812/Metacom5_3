## 2. 研究问题、根本瓶颈与完成标准

当前根本瓶颈是：**输入中的身份和时间语义、执行器应做的事、奖励所评价的事还没有充分对齐。** 在这一状态下，执行器可能把历史人类支持者当作自己、把旧状态当作现状；裁判又可能奖励流畅但不真实的支持。PPO 能优化收到的数值，却不能自行纠正这条测量链。

此外，当前监督样本覆盖明显窄于策略实际能够选择的资源组合。先扩大网络复杂度，会同时放大表示、执行和奖励三处不确定性。

| 优先级 | 要回答的问题 | 支撑该问题的主要比较 | 解决到什么程度 |
|---|---|---|---|
| 主攻 RQ-S | 在共同信息、动作与预算条件下，学习资源计划是否有用；逐步观察资源是否进一步有用？ | OFF / Fixed / Random / OneShot / BC-Seq / PPO-Seq；已取正文消融 | 能区分资源本身、情境化计划、监督初始化、PPO 更新和顺序观察的贡献；不预设 PPO 必胜 |
| 主攻 RQ-X | 相同提示、相同资源下，专门适配的执行器能否更可靠地使用或忽略资源？ | 同一固定资源计划下 X_g 与 X_l | 覆盖真实动作域，检查事实与身份错误，并取得独立支持质量证据 |
| 次攻 RQ-SX | 策略是否依赖执行器，能否迁移？ | P_g / P_l 与 X_g / X_l 的交叉组合 | 在主实验完成后利用缓存与有限额外生成回答；资源不足时移至补充或未来工作 |
| 延后 | 跨轮心理状态估计、长期关系效果、完整世界模型、第二 RL 算法大网格 | 本轮不做 | 在论文中明确边界，不用本轮单次回复结果替代长期效果 |

研究对象是**单轮回复前的顺序信息获取**：每次 GET 揭示一个资源，STOP 后生成一次回复。它可以表述为部分可观察的信息获取任务，但没有模拟后续用户，也没有识别真实心理状态的证据。

显式时间表示能解决“何时知道、说的是谁、是否再次确认、意向还是结果”等定义问题。GRU、HMM 或 Transformer 不能凭空补出缺失的行动结果，也不能替代评价标准。因此采用“修表示 → 修执行 → 校准反馈 → 实验”的方案可行；把“增加时序模型”直接当作根治方案，本轮依据不足。

本篇研究完成的标准是：协议冻结、关键对照完成或明确记录受阻、数据与成本可追溯、结论受独立证据约束、结果表和论文论证可以复现。正收益是待检验结论，不能成为继续研究的先决条件。若测量最终仍不合格，应交付可复现的局限与失败证据，不能把“代码能跑”包装成完成了自然支持策略有效性验证。

### 4.2 环境与观测

- 动作保留 `STOP / GET_RS / GET_MP / GET_MS / GET_ME`；四头冻结检索排序，每个 GET 取该头下一条。
- 总 GET 最多 4；总资源块预算 2,048 个 Generator tokens，包含说明、标签和分隔符。保留完整 MS，不靠截断原文挤入预算；rank 1 不可取时不能跳取 rank 2。
- 终值计划由四类数量表示，总和不超过 4，理论最多 70 个。最终交付按规范顺序；相同资源集合不能因 GET 顺序产生另一种生成输入。
- actor/critic 只接收 Observation。允许原始合同中的初始前缀、候选排名/相似度/长度/粗粒度年龄、可行计划 mask、预算和已获取正文；不得访问 EpisodeSpec、未取正文、私有库存、gold 或实例 ID。
- 新增的细粒度 claim 状态、主体和确认依据默认随 GET 后的资源正文交付。离线可以计算，但不能免费暴露给策略；所有方法遵循同一可见性和计费口径。
- 特别核对 `initial_plan_mask`：存在于环境对象不等于已经进入模型编码。若当前 `ObservedFeatureEncoder` 未使用，而新 OneShot 使用了，必须统一实现共同输入后再比较。
- GET 不调用 Generator 或 Judge；STOP 生成一次。无未来用户模拟、无跨轮在线记忆写回。

### 4.3 生成、版本与缓存

继续使用已建立的自然 EOS、原生上下文容量与技术 watchdog；不重新引入 60/128/256 token 的任意答案长度上限。物理上下文不足、watchdog 或异常循环是技术失败，不能记成正常短回复或低质量零分。

冻结模型/checkpoint、tokenizer、chat template、renderer、资源 overlay、排序、生成参数和评分协议。输入变化必须产生新 identity。renderer 改动使旧生成失效；仅评分协议改动时保留原生成并重评；仅汇总口径变化时重算统计。旧缓存和报告不覆盖。

示范要覆盖正确使用、明确不确定、忽略无关资源、处理冲突和不把意向写成结果。核验者可以用严格 as-of 的完整公开来源检查是否真实，但目标回复只能依赖该条件实际交付给执行器的信息；不得把核验者额外看见的事实写进标签。

接纳记录包含 teacher 身份、可见输入、来源核验、修复次数和拒绝理由。自动核验始终称弱监督。旧标签只有在新版实际输入下仍获支持且 identity 重建后才能复用。

在最多 576 个 train 条件内，先为每个合法剂量档 0–4 争取跨至少 6 个 train owners、至少 12 个独立前缀的接纳示范；同类多取也按此覆盖检查。未达到时，只处理预留的未完成候选和允许的一次修复。最终不足必须报告，不能无限扩容或造证据；有限数据训练仍可作为受限候选，但不能宣称全域覆盖。

### 6.2 训练与 checkpoint

沿用 LoRA 起点：r=8、alpha=16、q_proj/v_proj、dropout=0、BF16、lr=1e-4、microbatch=1、accumulation=16、seed=17，最多 3 epochs，仅当前回复与 EOS 参与损失。记录真实有效 batch、步数、接纳数和各条件分布。

训练前冻结一份 12 个 dev 输入的行为回归清单，涵盖身份、过时状态、意向/结果及无关资源，允许复用 C01 的案例。每个 epoch 在同一清单生成；严重错误必须有具体输出与证据，不能只靠关键词判定。

选择规则：先排除在该回归清单出现明确严重身份/主体/时间/行动结果捏造的 checkpoint，再从剩余者按 dev response NLL（含 EOS）最小选择，平局取较早 epoch。报告全部 epoch 的 NLL、EOS、回复长度和回归结果。该清单是开发条件，不是一般错误率为零的证明。

若 3 个 checkpoint 均失败：本轮 X_l 记为未通过，保留全部结果；先继续 X_g 下的测量与 PM 主线，不把失败 X_l 当正式增强器，也不偷偷再做无上限 SFT。最多允许一次明确的代码/标签错误修复重跑，必须能指出实际缺陷；单纯效果不理想不触发第二轮大规模调参。

**C02 完成条件**：得到冻结的合格 X_l，或明确记录此次适配失败；两种状态都能进入下一步。X_l 失败时 RQ-X 的结论受限，后续双执行器矩阵相应缩减并说明。

## 7. C03：让反馈足够支持本轮训练

### 7.1 只保留一套主反馈协议

默认使用服务器已具备、上下文容量足够的本地指令模型建立新版结构化评分协议。若复用 Qwen，必须登记为新的具体 checkpoint/prompt/protocol 组合，不能把旧失败状态改写成已通过。Prometheus 和 Skywork 旧配置仅作诊断参照，不再轮流搜索到出现喜欢的结果。

评分输入包括当前任务、候选回复和严格 as-of 的共同公开事实依据；同一前缀所有方法使用同一依据构造规则。隐藏方法名、checkpoint、资源数量、成本、训练 seed 和已选计划，避免裁判按资源数量或方法身份打分。资源交付明细只用于评分之外的误差归因，不能悄悄进入主评分输入。完整依据超过窗口时必须显式失败或采用事先验证的来源审查分步协议，不得静默截断后判断事实。评分器看到的核查证据不进入 actor/critic。

仅评价新生成的当前回复，不能用历史优质回复平均掉末句错误。每个回复输出带证据的两个量；整数是训练效用编码，不假设人类效用天然等距：

- `q ∈ {0,1,2,3,4}`：与当前表达相关的支持适当性。0=明显不当/偏离；1=主要泛化套话；2=部分贴合但缺少有效回应；3=贴合、尊重且有帮助的回应；4=在本例有清晰依据支持的更充分回应。长度、建议条数、资源引用数量不直接加分。
- `m ∈ {0,0.25,1}`：有明确证据的身份、用户事实、主体、时态或行动结果问题。0=未发现可确认问题；0.25=有限的过度确定或次要事实偏差；1=实质性捏造、主体错置，或把意向/旧状态当成已完成结果/当前事实。

每个非零 m 必须引用候选中的主张和对应来源/冲突依据；“来源没有提到”与“来源否定”分开。`m=0` 只表示未检出，不表示所有事实已由人认证。q 与 m 可能相关，显式风险扣分是研究者有意设置的额外权重，不能声称两个正交心理维度。

不确定、缺证据或格式失效输出结构化状态，不强制变成 0 分。缺少充分事实仍可能允许泛化但合适的支持；不得把所有非逐句可引用的共情判错。

### 7.2 一次制作人工校准包

在 train/dev 内完成，默认 40 对，另预先锁定最多 8 对备用自然样本；一次性准备完整材料。两部分用不同 dev 前缀，按 owner 尽量平衡：

| 部分 | 默认数量 | 用途 |
|---|---:|---|
| 开发部分 | 8 对自然回复 + 8 对诊断控制 | 澄清评分锚点，最多修改一轮评分协议 |
| 封存验证部分 | 16 对自然回复 + 8 对诊断控制 | 协议锁定后首次揭封，用于决定是否进入训练 |
| 封存备用 | 最多 8 对自然回复 | 仅当验证中明确偏好少于 8 对时补充；不能因模型得分不高而追加 |

自然回复来自固定计划与 X_g/X_l，且与 q/m 评分结果无关地选择。诊断控制覆盖 AI 自传、主体错置、时效误读、意向变结果，并包含相同文本、仅长度变化和合理不使用资源；自然样本与人工构造控制分开统计。

每对提供：当前前缀、A/B 回复、相关来源卡片、按 as-of 截止的完整公开依据入口，以及“考虑事实风险后的整体支持偏好 A/B/平局/无法判断”和事实风险标注。隐藏方法、checkpoint、自动分数与左右原始顺序。最好由 2 名独立人类评价；若现实只能 1 人，明确作为单人校准，不能叫人际一致性。不同评审分歧保留，能依据来源裁决的事实问题单独裁决。

人工不负责逐条清理全部训练数据。提交的是已经完成的有限包、预计工作量和需要支撑的具体结论，不要求用户重做旧 96 题，也不把旧 AI 评审 B 标为人类。

### 7.3 进入训练的操作标准

这些是本轮容忍度，不是统计学保证；必须在看到封存标签前写入 manifest：

1. 固定技术检查集中有效结构化输出率至少 95%；失败允许一次同协议修复，分别报告初次与最终比例。
2. 同文和重复控制不得产生明确、有实质内容的偏好幻觉；验证中的严重事实方向控制不允许把已确认的严重错误判成更好且无风险。
3. 在封存自然样本中，人类明确偏好的可判项目至少 8 对；自动 `U` 的方向一致率至少 75%。分别报告平局、无法判断、类别分布及总是选同一侧/总是平局等简单基线，不能仅报总准确率。
4. 固定 12 对双向配对诊断中，交换 A/B 后至少 11 对保持映射回来的偏好一致；这是配对诊断稳定性，不声称单点评分因此无偏。

验证阶段不再按结果修 prompt 后重复宣称独立通过。若失败，标记 `MEASUREMENT_UNQUALIFIED`，交付具体失败表；继续完成环境、基线、数据与论文材料等独立工作，但不把未合格自然奖励投入正式 PPO 并宣称有效。若要转成纯事实核验奖励或人工直接奖励，那是研究目标/标注成本变更，需要提交具体替代实验，而非默认替换本方案。

校准包等待人工时可先跑格式、同文、换序和证据定位检查，开发性短试跑要明确标为诊断，不能提前占用正式 PPO 结果身份。

### 7.4 正式奖励

沿用可解释的起点，不做大网格：`U = q/4 − m`，α=1、λ=0.05、γ=1。

```text
GET reward  = -0.05 * (resource_tokens_after - resource_tokens_before) / 2048
STOP reward = U(reply_with_resources) - U(reply_OFF)
episode_R   = U(on) - U(off) - 0.05 * resource_tokens_final / 2048
```

q/m 采用冻结的单回复评分协议；同 prefix、executor 和协议的 OFF 生成与评分只做一次并复用，不能在不同配对中改变 OFF 标尺。配对换序检查用于校准和独立评价，不替换单回复训练分值。

报告 q、m、增量、token 成本和混合回报各自的结果。λ=0.025/0.10 只能作为已观测结果的事先声明敏感性重算；不能把重算当作重新训练的策略性能，也不能按 test 挑 λ。

## 8. C04：完成公平基线与真实策略训练

### 8.1 共同训练反馈

先选 24 个 train 前缀，12 owners 各 2 个，选择只依赖库存与固定 hash。每个最多 15 个计划，X_g/X_l 分别生成和评分，上限 720 个终值反馈记录：

- OFF 1 个；四头各 Top1、Top2 共最多 8 个。
- 另外 6 个槽位：2 个跨类型双资源、2 个三资源、2 个四资源计划；在 owner 内平衡类型与同类多取。
- 预定不可行项可从相同剂量的合法计划按 hash 补入；没有合法项就标缺失。去重后不强行补满 15。

这是对旧“六个双类型 Top1 组合”的明确修订，用来覆盖三、四次获取。所有选择在生成与评分前冻结。未测计划没有奖励标签；不得填零、假装全空间最优或用不存在的 gold 跑 oracle。

对已测计划选择最高观测净回报作为 BC 初始化示范；展开到合法获取路径，路径顺序用固定的规范/平衡规则，不使用未获取内容决定下一动作。该标签只是已测支持集内的优选计划，不叫真实最优策略。

### 8.2 网络、初始化和 PPO

- 冻结 BGE-M3；编码公开前缀和至多 4 个已获取资源槽位，并加入共同 metadata、预算、计数、缺失 mask、初始可行计划 mask。
- 128 维投影、两层宽 128 的 MLP；5 个动作 logits 与 1 个 value。相同集合按规范顺序编码，不加隐藏的检索路径标识。
- BC 初始化 policy；critic 只拟合真实已测回报。保留 BC-Seq checkpoint，正式 PPO 不覆盖它。
- 分别训练 P_g、P_l；X_l 未通过时仅训练 P_g，并在矩阵中明确缺项。
- 每个 executor 3 seeds：17、29、43；每 seed 128 episodes。均匀 owner→合法 train prefix 抽样；首 32 个正式身份 episode 可承担 smoke，不额外增加一轮重复训练。
- Adam lr=3e-4、clip=0.2、γ=1、GAE λ=1、value 系数=0.5、entropy=0.01、grad clip=0.5；16 个完整 episodes/batch、4 epochs、minibatch 4 episodes。
- 开发检查只在 64 与 128 episodes，使用同一 18 个 dev 前缀；主比较固定 128 终点，不按 dev 峰值为每组挑不同 checkpoint。若 C00 实测计算预算不足，可在正式效果标签产生前统一改成 64，并注明是较小预算实验。

每个 batch 必须具有完整奖励后再更新；forced STOP 不进入 policy/entropy loss。技术失败按同 identity 至多 2 次重试，不更换例子补齐。仍失败时保存原始 rollout 与模型状态，暂停受影响的 batch，修复后恢复；不丢掉困难样本、填零或为缺失奖励 bootstrap。

若动作熵坍缩或全 STOP，先检查合法 mask、reward 分布与实现。没有实现错误且回报确实支持 STOP，也是一种结果，不能为了“看起来像学习”改奖励或强迫获取。

### 8.3 基线与公平性

| 方法 | 定义与用途 |
|---|---|
| OFF | 不取资源；每个 executor 独立基准 |
| Fixed-Dev | 在 OFF 与四头 Top1/Top2 共最多 9 个固定计划中按 dev 选一个；不按 test 或当前回复结果选择 |
| Matched-Random | 根据 PPO 在 dev 上的计划分布建立固定随机分布；当前前缀只做合法性筛选并归一化，不看资源正文；报告实际成本差异 |
| OneShot | 一次预测所有可行终值计划的回报并选优；同初始信息、最多 70 个计划和同预算。用初始特征与计划计数/交互编码回归已测净回报 |
| BC-Seq | PPO 更新前的监督策略；分辨预训练/反馈数据贡献与 RL 更新贡献 |
| PPO-Seq | 可以读取已 GET 正文并继续取或 STOP 的主方法 |
| PPO-NoText | 保留前缀、metadata、计数、mask 与预算，将已获取正文编码置零；在 X_l 下训练 3 seeds，X_l 缺失时用 X_g |

OneShot 与 BC/PPO 采用匹配的前缀编码器和相近隐藏层规模，报告参数量、输入和调参机会；不声称仅参数量相近即可排除全部优化差异。

完成全部 train 轨迹后，构造每个 executor 的**共同 train 反馈 union**，供 OneShot 与最终 BC 基线拟合。PPO 也允许按冻结流程从共同 union 重做同一 BC 初始化并进行同预算训练，但这会增加一轮成本，默认不自动开启。默认结果应准确标为“静态基线可访问最终共同数据，PPO 的在线轨迹按当时反馈训练”，避免把静态基线的数据劣势误认为序贯优势。

保留两种 BC 结果身份：`BC-init` 为各 PPO 实际出发点，`BC-union` 为最终共同数据基线；主表用 BC-union，补充表用 BC-init 与其对应 PPO 衡量本轮更新的净变化。不得将重训的 BC-union 冒称 PPO 的实际初始 checkpoint。

PPO-NoText 使用相同初始化数据、每 seed episode 预算与超参；其独立训练的请求需额外计入总账，不能称为免费消融。顺序策略超过 OneShot 只能支持本设置中的条件性证据，还需结合正文消融判断；资源互补本身不证明必须顺序获取。

## 9. C05：冻结、正式评价与独立证据

### 9.1 test 前冻结

完成 manifest 与 dev 选择后锁定：全部 checkpoint、renderer/overlay、score 协议、预算、Fixed 计划、随机分布、seed、指标、人工抽样规则、失败与缺失处理。之后不再用 test 内容修 prompt、调 λ、挑 checkpoint 或改资源。

发现真实 test 泄漏或协议错误时，暂停相关实验，标记已受污染身份；修正后如需重跑，保留原记录并说明，不能称其新鲜 test。

### 9.2 默认矩阵与工作上限

| 范围 | 策略实例数 | 每例前缀数 | 生成上限（未扣缓存） |
|---|---:|---:|---:|
| 每个 executor：OFF 1、Fixed 1、Random 3、OneShot 3、BC-init 3、BC-union 3、PPO 3 | 17 × 2 | 48 | 1,632 |
| 正文消融 PPO-NoText | 3 | 48 | 144 |
| 次要交叉 P_g→X_l、P_l→X_g | 3 × 2 | 48 | 288 |
| RQ-X 的共同计划比较：固定 OFF、RS-only、memory-only | 3 × 2 | 48 | 最多 288 |

核心策略表加正文消融上限 1,776 个回复。RQ-X 的共同计划不能由两边策略各自选择；按库存/hash 预先选择三类计划，两边完全一致，不可行时保留缺失。OFF 和其他同 identity 回复复用缓存。连同 RQ-X 与次要交叉，上述表的保守总上限为 2,352 个回复，并非实付调用数；不存在的 X_l 条件整体删除并显式报告。

Fixed 的 dev 选择最多 9×18×2=324 个计划评价，先扣已有缓存。OneShot/BC 等训练及 dev 评估开销另外登记。C00/C04 实际 manifest 必须逐项计入 SFT 生成、核验、修复、评分、OFF、重试与人评材料，不能继续沿用旧 8,496 调用估算。

BC-init 与 BC-union 都保留正式 test 结果，分别回答“PPO 相对实际初始化改进多少”和“更多共同反馈能否由监督学习解释”。正文消融也是一次真正训练，需另计 3×128=384 episodes，不能只在测试时关闭正文便称训练消融。双执行器主 PPO 共 768 episodes，加该消融最多 1,152；每次实际 G/J 调用按缓存和尝试单独统计。

### 9.3 独立评价

最终人工盲审默认 48 对，2 名人类优先，分两类各 24 对：

1. RQ-X：在共同固定计划下 X_g 与 X_l；按 3 owners 平衡，OFF/RS-only/memory-only 每类 8 对，在可行池内预先 hash 抽样。
2. RQ-S：同 executor 下 PPO 与 OneShot；优先 X_l，若缺失则 X_g。3 owners 各 8 对，seed 预先轮换。

校准样本和最终样本分离，最终标签不回流训练；评审看不到方法、seed、自动分数。尽量避免同一个前缀在同一比较中重复；若分层可行池不足，记录短缺，不按效果换抽。若只能一名人类，按单人盲审报告；如只能另一个模型，必须称模型复评，不能替代为人类验证。

人评前应自动核对包内来源和左右映射，避免让人承担工程纠错。不同人分歧、平局及无法判断保留；少量人评用于限制主张，不保证统计充分。若 X_l 不存在，RQ-X 的 24 对不自动转作别的成功比较；保留为未完成项或单独申请明确替代用途。

至少报告：

- q、m、U 与 OFF 增量，PPO 相对 OneShot、BC-init、BC-union、Fixed 的配对差异。
- 获取次数、四类剂量、完整资源 tokens、初始库存不可用比例、预算阻止比例和主动 STOP 比例。
- 生成与检索/编码的实际耗时；预计算检索与缓存不能当成每次在线推理的真实耗时。
- 人类偏好、风险、平局及无法判断；自动与人类方向不一致的具体案例。
- 技术失败、缺失、重试、缓存命中、实际请求和费用。

统计以 prefix 内配对，先按 owner 汇总，再报告 3 seeds 和逐 owner 差异。同一前缀的多个资源条件、种子、左右顺序不是独立用户。只有 3 个 test owners，区间和显著性外推都很有限；不靠上千条回复扩大独立样本量。

质量—成本同时报告。共同最大预算不等于实际等成本；成本相近的比较是补充描述。不显著不能当作非劣效或等价，未预先定义界值与相应设计时不得这样写。

## 10. C06–C07：按证据收口论文

### 10.1 结果决定主张

| 观察结果 | 可以写的结论 | 不能写的结论 |
|---|---|---|
| X_l 同计划更好、风险不增加，独立评价方向支持 | 本设置下执行器适配提高资源使用或支持适当性 | 已改善真实用户长期心理状态 |
| 学习策略胜 Fixed，未胜 OneShot | 情境化资源规划有价值；顺序观察的额外收益未建立 | PPO/顺序决策必不可少 |
| PPO 胜 BC-init，但不胜 BC-union | 本轮在线更新有改进，但更多共同反馈或监督学习可解释优势 | RL 独有贡献已被隔离证明 |
| PPO 胜 OneShot，正文消融变差，独立评价一致 | 支持本设置下利用已获取信息继续决策的价值 | 已完全排除容量、优化和数据收集差异 |
| 自动分提升、人评不支持或风险更高 | 存在代理目标偏差，应收缩效果主张 | 挑自动指标宣称全面成功 |
| 主要效果为省资源、质量变化不确定 | 报告观察到的成本下降及质量不确定性 | 直接称质量不损失或非劣效 |
| 核心比较无优势 | 给出边界、失败机制及可信负结果 | 延长落后组、换 test 或修改指标直到显著 |

### 10.2 论文材料必须随实验同步生成

最终交付包括：

1. 一页研究问题与贡献边界，按最终证据写，不沿用最初宏大目标。
2. 数据与可见性说明：公开合成来源、版本差异、split/来源隔离和历史 test 暴露。
3. 方法：单轮信息获取环境、四类资源、事实/时间表示、执行器适配、PPO 与反馈协议。
4. 主表：共同资源下执行器比较；同 executor 的策略比较；风险与成本；独立评价。
5. 必要消融：BC-init/BC-union、OneShot、已获取正文；次要交叉结果可置附录。
6. 失败案例与局限：角色、时间、结果稀疏、奖励偏差、小 owner 数、合成数据与长期效果不可识别。
7. 可复现清单：运行身份、配置、数据来源、可发布代码、原始结果索引和重算入口。

QA 最多作为单独附录任务：只有主线完成且剩余资源允许才做；先说明目标、来源截止与正式官方协议的区别。不能让 QA 修复队列阻塞主线，也不能用 QA 准确率替代自然支持质量。

建议新文档目录：`project/docs/pm_rl1_continuation_v1/`。大型数据与模型保留服务器既有非 Git 产物目录，文档只存 manifest、摘要和可追溯路径。遵守现有公开数据和日志发布规则。

每个阶段结束只汇报五项：完成的具体产物、关键结果、未解决问题、下一步、是否需要用户提供什么。区分 `COMPLETED`、`COMPLETED_WITH_LIMITS`、`WAITING_FOR_HUMAN`、`MEASUREMENT_UNQUALIFIED`、`BLOCKED_TECHNICAL`。人工未到位时只阻塞依赖标签的阶段，不把整个项目设成停止。

只有下列情况需要暂停受影响动作并提出具体问题：

- 原始来源或真实服务器资产无法取得，无法完成必要输入；必须说明缺哪份文件。
- 新发现的数据泄漏、身份混淆或协议错误会污染正式结果；先保护产物并给修复方案。
- 人工校准或最终评价需要实际人类作答；先交付已经可填写的包。
- 共享预算/真实资源不足，或行动超出现有授权；先给剩余额度、具体候选取舍及工作量。
- 单次有界修复后测量仍不合格，或需更改研究目标/主假设；先给失败证据和可执行替代方案。

下列情况不构成停工理由：旧文档曾将 RL 列为未来工作、当前效果不显著、PPO 没胜 OneShot、少量计划不可行、dev 只有 18 个、文件名与建议不同，或尚未证明时序方法一定有价值。

## 12. 验收清单：达到这些程度就收口

- [ ] 使用实际活跃分支与服务器状态，旧成果与旧失败都有独立身份。
- [ ] 角色、事实主体、可知时间、确认时间、行动阶段与结果有一致表示。
- [ ] 未取资源正文和细粒度语义未泄漏给策略；所有方法初始可见信息和动作域一致。
- [ ] SFT 数据覆盖剂量与同类多取；未达到的覆盖如实记录；X_l 选择规则先于结果冻结。
- [ ] 奖励有有限的人工校准与封存验证；未合格不冒称通过；最终人评独立。
- [ ] 同计划 X 对照，以及 Fixed / Random / OneShot / BC / PPO 的关键比较可追溯。
- [ ] BC-init 与 BC-union 区分；PPO-NoText 是相同预算训练消融；相同终值计划只有一个规范生成身份。
- [ ] test 前冻结、失败不补零、不换样；不把旧 test 暴露隐去。
- [ ] 逐 owner、seed、风险、成本和缺失均报告，不把回复条数当受试者数量。
- [ ] 有可复现主表、独立证据、局限和论文草稿；没有正结果也保留真实结论。

完成以上工作后，优先写完并审阅论文。只有主结论确实依赖的证据缺口才追加实验；不再因为“还能做一个模型/多一个裁判/再清理一种数据”无限延长本轮。
