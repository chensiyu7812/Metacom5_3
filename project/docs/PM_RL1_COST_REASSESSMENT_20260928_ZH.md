# PM-RL1：输出结束策略与费用重估

核验日期：2026-09-28。离线报价，可复算脚本：`project/scripts/rl1/02_reprice_plan.py`；明细：`project/outputs/pm_rl1/engineering_20260928_v1/cost_reassessment.json`。

## 输出上限的结论

同意在 PM-RL1 自然支持任务中取消人为的 60／256 token 回复硬截断。旧自然结束诊断中，同一批 Summary 的 OFF 有 11/13 触顶、ON 有 1/13 触顶；给两组同一个短上限并不能消除差别影响，比较里会混入不同程度的截断。这是旧任务的诊断证据，不是新单轮任务已经测得的效应。

新接口应让模型自己发出 EOS/EOT。资源输入预算和模型原生上下文上限仍需保留；超时/循环中止单列为未完成。仅删除生成参数并不可靠：Transformers 的 `max_length` 有默认值，`forced_eos_token_id` 还可能在长度边界强行制造结束标记。[Transformers 生成文档](https://huggingface.co/docs/transformers/v4.57.1/en/main_classes/text_generation)

因此新本地接口显式使用原生上下文剩余长度，禁用 forced EOS，按实际 token 和中止原因分类。旧 HTTP 服务不再作为 PM-RL1 后端，但保留其历史协议用于旧结果复现。旧 1,924 条批处理本来已走自然结束，不能把它们误说成仍需取消短 cap 后全部重跑。

自然结束后，输出长度、时间、异常率仍应逐 arm 报告。正文更长可能影响裁判，后续测量检查要验证内容保持的风格改写；不能把自然结束自动等同于更可靠的 reward。

## 新主线的调用量

| 阶段 | 核心本地调用上限（缓存去重前） |
|---|---:|
| 执行器弱监督数据：候选、核验、一次修复及复核 | 2,160 |
| 24 前缀 × 15 计划 × 2 执行器的共同初始化，G+J | 1,440 |
| 2 执行器 × 3 seeds × 128 episodes，G+J | 1,536 |
| 两次 checkpoint 开发评价，G+J | 576 |
| 正式执行矩阵，G+J | 864 |
| 正式策略交叉，G+J | 1,920 |
| **默认核心合计** | **8,496** |

另外预留至多 672 个 OFF 基线调用，与已有相同身份的 OFF 去重；测量检查另有 60 次评分。因此三项名义合计 9,228，并非全项目严格上界：测量用回复、SFT dev 生成诊断、独立复核、时延测量、重试、训练本身都另计。

不默认执行 1,728 次 SFT 数据追加、9,744 次全量 ESC-RANK 七维重评、144 次时延重复。GET 不调用 G/J，不默认穷举每个前缀的全部 70 个计划。

这些核心推理计划本地执行，新增 API 账单为 0；本地机器运行时间和电力不能称为零成本。旧 1,924 条短 QA/Summary 的平均速度不能直接用于预测带完整合法历史的新 J 工期。先测实际 G/J 吞吐和 LoRA，再用：

`1080*t_teacher + 1080*t_verifier + 3168*t_G + 3168*t_J + OFF + measurement + embeddings + loads + training + retries`。

该式是各阶段计算工作量，双卡如何交叠还影响实际工期；GPU 显存也不能简单相加。

## 外部 API 单独报价

报价参照 GPT-4o：每百万输入 tokens USD 2.50、输出 USD 10；Batch 按同步费率的 50% 计算。本次只选它作沿用旧配置的价格情景，没有据此宣布它已合格为新 reward。[GPT-4o 官方价格](https://developers.openai.com/api/docs/models/gpt-4o)、[Batch 官方说明](https://developers.openai.com/api/docs/guides/batch)。

168 个候选前缀的完整合法过去历史＋当前前缀，按 GPT-4o tokenizer 实测中位数 6,671、P95 13,168、最大 19,001 tokens。暂再加 2,048 tokens 估算 rubric、格式和两条待比较回复；这些额外输入尚未形成最终 payload。下表输出长度是**报价情景，不是输出上限**。

| 付费项 | 情景 | 同步预期 | Batch 预期 |
|---|---|---:|---:|
| 12 对测量复核＋24 对最终独立复核，共 36 次呈现 | 每次输出 512 tokens；历史取中位数到最大值 | $0.97–2.08 | $0.48–1.04 |
| 同上，较长解释 | 每次输出 1,024 tokens | $1.15–2.26 | $0.58–1.13 |
| 可选官方 QA，48 targets × 4 arms = 192 | 旧 payload 输入均值 388；输出 8–64 tokens | $0.20–0.31 | $0.10–0.15 |

复核如果额外做全体顺序反转，36 次这一行翻倍。最终请求形成后须按其真实全文重算输入；QA 新回复尚未产生，旧输入均值只是估算锚点。人的审阅时间也没有折算成美元。

**工作安排：核心走本地，外部复核及可选 QA 先按约 $1–3 的预期规划，保留原来的 $10 总目标与 $20 硬上限。** 不是提前承诺全部 API 一定在 $3 内完成。

预期账单与调用前的最大责任额必须分开。按 GPT-4o 原生最大输出 16,384 tokens 估算，同一批 36 次复核的 Batch 责任额约 $3.34–3.90；192 次 QA 单独全批责任额约 $15.82。后者即使预期只花几角钱，也不能把在途责任额当几角钱。实际按剩余额度分批、逐批结算，保留异常和必要重试空间；不能为了让整批“看起来便宜”给回复再加一个短 cap。[GPT-4o 模型输出边界](https://developers.openai.com/api/docs/models/gpt-4o)

## 旧工作与当前余额

旧 1,924 行生成对应 1,631 个去重评分请求（QA 903，Summary 728），输入含原有 framing reserve 共 990,612 tokens。以 QA 输出 8、Summary 输出 1,024 的长度情景估计，同步约 $10.00，Batch 约 $5.00；如果按原生最大输出预留整个 Batch，则约 $134.85。它属于旧路线收口，**不再是 PM-RL1 的前置采购**，也不能在本次 $20 内整批预留。

本次核账：旧累计记录 USD 1.50724291，恰等于 2026-09-18 固定边界；边界后新增承诺为 0，尚余总目标 $10、硬额度 $20。旧账本没有重置，本次没有付费请求。报价不能替代 provider 对账；所有新付费入口接入共同原子预算、清点 UNKNOWN/在途金额以后，才能执行相应已授权清单。
