## 3. 官方 parser 复刻 + 一个 upstream 细节

按固定 commit `6926242` 复刻，不导入也不执行 upstream 代码：

- QA：`re.search(r"[0-2]", 回复全文)` 取首个匹配。主指标 = 该 0–2 分 ÷ 2。
- Summary：`json_repair.loads` 取 `score` 和三个事件计数，再按 upstream 公式算 precision／recall／F1。主指标 = Event F1。

需要 `json_repair`，冻结环境里没有。做法是按 upstream `requirements.txt` 的 `json-repair==0.52.4` 原样钉版本，`pip install --target` 装到 `outputs/paper1_calibration/vendor_python/` 旁置，评分模块按需插 `sys.path`。**已验证冻结环境 `paper1-py311` 直接 import 仍然失败，即环境没被改动。**

一处如实记录的 upstream 细节：官方 Summary parser 写的是 `except ValueError | json.JSONDecodeError`，这不是合法的 except 表达式，所以 upstream 在内容畸形时抛的其实是 TypeError 而不是返回空判定。我们保持相同的输入—输出行为（解析不了就没有分数），但把每次失败显式记下来，不复刻那次崩溃。
