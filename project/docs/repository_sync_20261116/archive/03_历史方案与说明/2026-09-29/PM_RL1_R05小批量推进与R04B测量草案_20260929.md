## 2. 仍需修正的建议

1. “稳定就开正式 PPO”不充分。重复稳定是必要检查，不能证明评得对；固定开发卷也不能变成独立资格卷。应先限定可支持的自动代理范围，再作有限真实训练检查。
2. 风险型 RL 不是自然支持奖励失败后的自动后备。若 OFF 误用为零，目标只有负误用和负资源成本，始终 STOP 已是最优。必须存在可验证的风险降低或其他明确任务收益，才有非平凡的资源选择问题。
3. veto 和固定惩罚不同。STOP 后发现重大误用应留作有效负面结果；不能删除轨迹、把错误当协议失败，或重生成直到过关。执行前 veto 若依赖未生成回复或未 GET 信息，会改变原动作语义与信息边界。
4. 不能要求两个候选共享全部测试接口。Prometheus 接收 A/B 两回答，需检查反序；Skywork 原生对单回答打标量分，不产生 A/B 位置或理由，相关指标应为“不适用”，而非自动通过。其分差需另定义实质等价边界。
5. QA 答案短不代表判分可靠。须逐类核对 gold、合法历史截止点、别名、时间参照、否定与答案集合；token F1 不能自动等价于事实正确性。按预先规则选样，不按哪种方法更容易胜出选样。
6. 没有合格自然支持反馈时，OneShot / finite-plan 也不能凭空得到可靠监督。可继续实现算法，或在独立 QA 任务中训练，但不能把这些方法写成已具备自然支持效用标签的保底成果。

## 3. R05 的具体小批量建议

目标是先得到有可追溯弱监督和真实训练证据的 `X_l_pilot`，不是直接宣布完整 R05 或正式 X_l 已冻结。

### 样本与输入

- 建议总计 18 prefixes：12 train（每 train owner 1 条）与 6 dev（每 dev owner 2 条）。这是待执行的小批量方案，不是已经抽取的名册。
- 从现有合法池按预先固定顺序选取，检查来源家族和既有暴露；不改变 owner split，不读 test outcome，不根据生成质量换题。
- 每 prefix 三条件：OFF、预先审查为相关的合法资源、合法但低相关或冗余资源。资源均须属于现有动作/预算域。相关性不是实际收益标签；没有适合条件时记缺失，不使用 wrong-owner 或未来资源补齐。
- 每条件最多两个候选，完整覆盖时最多 108 条 teacher 回复。记录资源类型、完整渲染和精确可见输入。
- T_X 使用现有本地模型，执行前绑定 checkpoint / prompt / decode / seed / runtime；不为本阶段展开新的作者模型竞赛。身份尚待实际绑定。
- 作者只见该条件的实际 G 可见输入；不见完整未 GET 历史、原未来回复、旧 q/m 或标签。

### 数据准入

逐条记录 `accept / reject / uncertain`，并核对个人事实与预设、说话者、时态、来源、当前诉求、边界和是否强行使用资源。程序检查机械合法性，开发审查承担语义判断；现有 Qwen q/m 不能自动决定准入。

核验记录须有身份和依据。当前开发助手参与的逐项审查属于 AI 辅助弱监督，不是人工真值或独立验证。生成理由、核验理由和完整评价证据不进入 SFT 输入/目标。

首批默认保留拒绝/不确定，不自动修复。若后来启用原方案允许的一次修复，不能把仅核验者可见的事实、引文或未来信息交回作者；修复与复核另记调用和版本。

报告尝试、接受、拒绝、不确定及技术失败全分母，并按 owner / 条件 / 资源类型列覆盖。若只剩 OFF 或泛化安慰回复，不称为“已获得资源执行学习数据”。不能为保证训练发生而放宽准入。

### 训练与核对

复用原定 LoRA r8 / alpha16 / q_proj+v_proj / BF16 / dropout0 / lr1e-4 / microbatch1 / accumulation16 / 最多3 epochs / seed17。具体有效样本数、训练步数和设备容量在准入后确定。

训练前先计算同一 dev 弱监督目标上的 X_g response NLL。训练仅计算当前回复和 EOT 的损失；按 dev 总目标 token 加权 NLL 选 checkpoint。核对基础权重冻结、adapter 更新、optimizer 步数、保存恢复及新进程重载后的结果。

开发生成诊断建议覆盖 6 dev prefixes × 3 条件 × X_g/X_l，共最多 36 条回复。保持推理提示逐字相同，保存完整输入和生成身份。分别分析 OFF 能力变化、相关资源增量、低相关资源干扰与来源错误；不使用 q/m 宣布提升。

交付至少包括：名册与输入 manifest；原始候选和准入记录；接受数据及哈希；训练/optimizer 记录；adapter 与重载记录；dev NLL；配对生成诊断；完整成本。样本不足、训练失败和未发现改善是不同结果。

### 本阶段费用口径

完整覆盖情景：108 次作者生成；若每候选调用一次本地核验模型，则另有 108 次核验；上述开发行为诊断最多 36 次生成。合计最多 252 次本地请求是该特定安排的基础情景，不是实际消耗或硬保证。

若核验由开发助手逐项审查，核验工作仍有成本，不能伪装成 108 次已发生的本地模型调用。修复、技术恢复、模型加载、训练和 NLL 前向分别核账，不包含在 252 中；严格身份相同的缓存复用单列。先用批次内最小子集实测吞吐再估算 GPU 时间，不沿用旧 Qwen 38.5 小时情景。

自然 EOS/EOT 继续有效，不恢复 60/256 输出截断。资源预算、原生上下文和技术保护是不同约束；中断保持缺失，不能作为成功样本。

## 4. R04B：先确定记录，不先决定最终奖励

以下是测量合同草案。采用全新运行身份和缓存，旧 Qwen/Compass 收口及用途决定保持不变。

### 最小记录

| 层次 | 应记录内容 |
|---|---|
| 输入与身份 | prefix/executor/response 的审计哈希，共同合法证据哈希，模型/提示/解析/解码身份；方法和成本不进入评审提示 |
| 机械合法性 | owner/cutoff/GET/rank/预算/上下文，协议错误与生成技术状态 |
| 语义核验 | response span，事实断言或内嵌预设，source IDs，supported/contradicted/unsupported/uncertain，时间与人物错误子类，影响说明 |
| 支持质量比较 | better/worse/equivalent/uncertain，以及基于当前诉求的具体差异；单列“未实现此接口”的候选 |
| 稳定性 | 适用时的反序一致、重复结果、理由与结论一致；不把自报 confidence 当校准概率 |
| 覆盖与成本 | 证据完整性，各模型实际 tokens，分块/遗漏与技术失败，运行时间、调用与重试 |

实体、时间和支持关系不是互斥枚举；应避免把所有错误标签硬塞进一个唯一分类。严重度由任务影响决定，不能简单写成“所有 unsupported 都是重大错误”。

Pairwise 的建议主问题是：在同一当前诉求与合法已知约束下，哪一回复存在实质的支持质量优势。更多字数、建议、个性化和记忆引用均不自动加分。事实误用及其对可用性的影响单列；是否另外施加风险惩罚在 scalarization 阶段显式决定。

`equivalent` 表示已有充分依据认为没有实质优劣差异；`uncertain` 表示证据或判断不足以定论。两个同样差的回答也可能 equivalent。技术失败单列，不等同于上述两类。

### 两个公式只保留为待选择设计

令 C=c(E)/B。R_A 可采用质量偏好加误用差分；R_B 可采用综合偏好，并另行明确重大风险惩罚或约束。两者均需绑定 OFF、严重度、权重与 missing 处理；不在测量尚未支持时先运行两套 PPO 再挑赢家。

若综合偏好已考虑误用，追加处罚是显式风险加权，不是自动正确的修补。固定惩罚须写清范围；约束式目标须写明何时、对什么施加约束及可用信息，不能把两者统称 veto。

UNKNOWN 不填零，整条缺分 episode 不进损失，同时记录按条件、历史长度和资源类型的选择性缺失；不无限补样凑齐好评的完整 batch。先保存原始分项，正式 scalarization 在自然支持训练前单独冻结。

### 候选实验范围

最多考察 Prometheus-2 7B 与 Skywork-Reward-V2-Llama-3.1-8B 两个候选。接口不适配可以不进入 live 试验，不必为了凑两个模型建立复杂补丁。没有预设双模型投票或共识准入。

Prometheus 的官方配对输出为 A/B；tie/uncertain 是待验证适配。Skywork 单回答输出标量、官方建议 16,384 tokens 内且不使用 system prompt。它不输出理由，不能将无理由视作“理由核验通过”，也不能给其虚构 A/B 反序分母。

已有 67 次 pointwise 调用记录不是 67 个独立配对；新的 pair、反序和重复请求须重新列 manifest。旧卷仅作已见开发压力集；两个已知语法损伤的风格变体不能仍按纯风格不变性计分。修正题如另存仍属于开发材料，不变成独立确认。

报告自然配对分布与错误类型，不以 ON 胜率选裁判。正确引文不等于推理充分；模型共识不等于独立真值。没有未参与适配的新材料或外部依据时，资格主张限定到实际完成的开发检查。

## 5. QA 桥接与最终评审的安排

QA 准备可独立于 R04B 候选实验；它不是必须等两模型实验结束才能开始的依赖，也不是本轮默认扩大成第三个完整训练项目。

第一项交付是 train/dev QA 的可判分性 census：题型、答案结构、别名规则、证据截止点、来源家族、可覆盖数量与排除原因。仅靠答案长度或 F1 不能完成资格判断。原 test 外部验证池保留，不用于训练或调整规则。

若形成可信子集，再作有限计划真实生成检查，区分资源是否包含答案、Generator 是否能用证据、评分器是否判对、PM 是否会选择。QA 学习成功只支持相应子任务；对 sequential 方法的额外价值仍需 OneShot/Fixed/Random 等共同条件比较。

暂不新增训练前人评。保留系统冻结后的原定独立盲审用途；最终样本量、人员、实际完成情况据实报告。自动测量通过开发控制只能支持相应自动代理主张，不能替代人类支持效果或心理疗效证据。

下一项实际工作优先完成 R05 的名册、作者/核验身份与逐项准入，然后进行小批量参数更新和重载；R04B 先交付输入输出及实验清单。自然支持 PPO、纯风险 RL、QA 主研究改题均不是本文件已经执行或自动选定的结果。
