对"怎么说"这一类 RS，换成 Agent 不会改变结论。对"G 缺的信息"这一类资源，Agent 是最合适的形式，而且和之前的建议 2、3 方向一致。
Agent 比现在多出来的能力，我们基本都已经用"上限"的方式测过了：
Agent 改变的是"什么时候拿、怎么拿"，改变不了"拿到的东西里有没有 G 缺的信息"。卡住我们的是后者，再加上尺子分辨不出来。
1. 框架更自然。 RS、MP、ME、MS 都变成工具，PM 的开和关就是"调不调用工具"。"工具过度调用"是 Agent 领域公认的问题，动机比"开关一段提示"好讲得多。
2. 延迟重新有意义。 Agent 每多一步（检索、推理、再生成）就多几秒。前提是工具真的有价值，否则 PM 还是会学成全关。
3. "关"可以有负收益。 在纯情绪的轮次上调用信息类工具（塞资源、讲流程），很可能反而损害 ES。这比"开了也没用"更有说服力。现在只有一点迹象：Qwen 判通用策略在困难时刻 −0.35，但只有一个裁判，需要专门测。
4. 多了一个必须对比的强基线：让 G 自己决定调不调工具。 PM 要在决策正确性和延迟上赢过它，审稿人一定会问这个对照。
- "学会何时检索、何时调用工具"已有大量工作（Self-RAG、Adaptive-RAG、工具过度调用等）。原创性必须落在 ES 特有的地方：情绪轮次上调用工具的代价、记忆和共情怎么配合、实时延迟。
- 工具的内容仍然必须是 G 没有的信息：
  - 用户历史，即记忆，已证实有用；
  - 场景知识，即重新定义的 RS，还没测。
所以 Agent 不是一条新路，而是建议 2 加 3 的包装方式：
- PM = ES agent 决定调用哪些工具的策略；
- 工具 = 记忆（MP/ME/MS）+ 场景知识库（新的 RS）；
- 评价 = 调用是否正确 + ES 质量 + 延迟，并和"G 自己决定"对比。

你的设想可以拆成"案例 → G 读到 → 回复更好"这条链，它要成立，需要三个前提同时满足，而 ESConv 一个都不满足。 所以准确的说法是：不是 G 不需要案例，而是 G 用不上 ESConv 这种案例。
我们试过三种形式：按真实结果挑出来的好转案例、真人对话示例、好坏对照的案例。结果都约等于占位提示。按情境相似度检索，也不比随机取一个案例好（−.001）。
一句话说，G 从 ESConv 案例里能学到的只是：一个水平不如它的人，在一个它很熟悉的情境里，遇到了一个本来就会好转的求助者。 这样的案例对 G 当然没有信息量。
- 示范者比 G 强：真正的心理医生，而且案例里有他们的判断过程，不只是说了什么话。
- 结果能归因：有长期随访，或者同一个人前后对比，而不是聊完马上自评。
- 情境是 G 不熟的：特定人群、特定文化、少见的困境。
- 最强的版本是这个用户自己的案例。 比如"上次你难受时，先陪你把事情经过理一遍对你有帮助，直接给建议你不太接受"。
  - 同一个人前后比较，正好消掉"结果由求助者决定"这个混淆，因为求助者是同一个人。
  - 这就是你的案例设想和记忆模块交汇的地方：案例不是"别人怎么好转的"，而是"这个人过去什么做法对他有效"。
  - 缺点是数据少：EvoEmo 里这类和支持方式有关的偏好只有 4 条。
- "G 不需要通用支持策略"：对 12B 的 G 基本成立。但这是按自动裁判得出的，人评还没回来。
- "G 不需要案例"：不成立。只是 ESConv 提供不了满足这三个前提的案例。
- 公开数据里，同时满足前提 1 和 2 的（专业人员示范 + 能归因的结果）几乎没有。最接近的是同一用户的跨会话历史，也就是记忆线。
- 所以合理的分工是：RS 提供专业框架（怎么做个案概念化、会谈怎么组织、怎么跟进作业、风险时走什么流程），记忆提供这个人的案例史（包括过去什么做法有效）。这和上一条建议里的第 3 项一致。
