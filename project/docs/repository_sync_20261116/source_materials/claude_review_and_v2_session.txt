# PM-RL1 会话摘要与长期记忆设计

2026-11-16（Asia/Tokyo）。用户明确提出加入“本次完整会话结束后的 summary”尝试，并要求从问题定位推进到解决机制。本文件将 MS 会话摘要纳入新候选版本，保留旧实验原文身份；不再将完整原文规定为唯一可用的运行时表示。

## 1. 当前实现与设计修正

当前每个 MS 是**一个被取得的完整过去会话**，不是自动将全部历史注入 G。候选生成直接使用 `document.transcript`，新目录中的 `summary=None`；GET_MS 每次取得排名首项，renderer 只交付已取得的条目。11/11 的短视图是引用前后相邻轮次的摘录，不是完整会话的总结。

已核对两个 train 实物：p2_conv_10 为21轮，esc242 为43轮，当前 MS 正文与冻结完整来源逐字符一致，没有 summary。原对话正文分别为327和788个空白分词；加入每轮角色标签后的旧载荷计数为348和831，二者口径不同。代码入口：[候选物化](../../../../src/metacom_pm/paper1/multi_view_memory/candidate_adapter.py)、[MS封装](../../../../src/metacom_pm/rl1/representation.py)、[获取与交付](../../../../src/metacom_pm/rl1/resource_organization.py)。

原文完整能保证来源可追溯，但不保证模型读起来最好。长会话会产生阅读成本、重复内容及关键信息埋没；会话数量增加还会增加检索难度。新设计分别处理“每个单元过长”和“单元越来越多”两个问题。

## 2. 推荐结构：会后写摘要，运行时按需读，原文可回查

```mermaid
flowchart LR
  A[一次会话完整结束] --> B[不可变原文归档]
  B --> C[该会话独立摘要与来源锚点]
  B --> D[MP时点档案与ME事件更新候选]
  C --> E[按人物 主题 时间建立索引]
  D --> E
  F[后续会话当前前缀] --> E
  E --> G[PM获取相关记忆或停止]
  G --> H[已取得摘要与其他资源]
  H --> I[需要时显式获取对应原文]
  H --> J[STOP后G回复]
  I --> J
```

图中摘要写入与父文定向获取为新设计，尚未接入当前运行器。建库不属于在线GET；原文回查也不能免费发生。

### 2.1 写入时机与更新规则

每次会话结束，冻结原文版本，再生成该会话的摘要。第t次会话的完整摘要供第t+1次或更晚会话使用；第t次内部的任一待回复前缀都不能看到它。离线实验可以从已完成的过去会话重建摘要，但生成器不得看到后续测试问题、答案、回复或收益。

保存两种时间：来源结束/逻辑顺序，以及真实生成与就绪时间。历史数据只有日期/会话rank时，使用经过验证的严格过去rank，不伪造秒级结束时间。离线今天重建的摘要不声称历史当天已实际存在。在线摘要任务若尚未完成，条目仍不可取得；系统按已声明的RAW或无摘要路径工作，不暗中等待且漏计成本。

摘要按每段原会话独立生成并保留版本。更正摘要从相应原文重建，不不断用“上一次总摘要＋新对话”覆盖唯一记忆。新会话报告事实变化，应生成新证据，更新当前MP投影或ME事件关系；旧会话摘要仍表示当时说过什么。会话重新打开或原文修订会改变来源hash，旧摘要不得自动绑定新全文。

### 2.2 摘要应保留什么

MS-SUM保持会话过程，不能退化为一串无关系事实。主体是一段可读的英文总结，必要时附简短条目：

- 本次主要处境、明确情绪表达、人物关系、时间和重要转折。
- 用户明确的诉求、现实限制、拒绝或偏好，保留它们的适用范围。
- 支持者提过什么；用户只是考虑、已经尝试，还是明确报告了反应。
- 哪些困难仍未解决、哪些事项只是计划或待确认。
- 对理解有影响的否定、更正、矛盾和未知。

每个重要命题有原文轮次/跨度锚点，索引保留人名与关键实体。机械引用校验只证明锚点存在，不能证明概括忠实，仍需语义检查。G的紧凑正文不附全部引文与审核日志；这些放在来源侧表，否则“摘要＋所有原文引用”可能比原会话还长。评估必须量实际交付正文，不能只量其中的摘要段落。

不预设固定200字或固定压缩比就是最优。先保留支持判断所需信息，再比较长度与质量；困难会话允许更长摘要。特别长的原会话若超出写入器上下文，后续采用保持话题/事件边界的分段，保留指代和源跨度；不把任意等长切块再合并视为已解决保真问题。

示例：历史说“挂过电话，但朋友很生气”，摘要保留尝试及不良反应；不能写成用户避免挂电话。结尾致谢不能被总结成问题已解决。一次“画画不适合我”不能推成永远排斥所有创作活动。

### 2.3 与MP、ME的分工

| 视图 | 回答的问题 | 更新方式 |
|---|---|---|
| MP | 截至此刻哪些个人事实仍成立？ | 从原文证据更新时点投影，保留更正/冲突 |
| ME | 发生过什么、做到哪一步、本人报告什么反应？ | 追加或连接有依据的事件状态 |
| MS-SUM | 那一次对话整体谈了什么、怎样发展、留下什么？ | 每会话独立生成；原文、摘要内容或写入器配置改变时另立版本 |
| MS-RAW | 当时具体怎么说，摘要省略了什么？ | 完整归档，按需取得 |

不先把原文压成摘要再仅从摘要提取MP/ME，否则一个遗漏会传播到全部视图。可以共用一次建库生成来降低成本，但各视图的命题都应直接绑定原文，语义和身份分别验证。重复信息通过来源关联处理，不因为同源而删除不同语境。

## 3. 长历史增长的实际处理机制

**第一，摘要减少单次会话的阅读体积。第二，检索和停止控制本轮读取哪些会话。第三，档案/事件视图使简单需求不必每次重读会话。**三者共同处理增长问题，仅把全文改成摘要而继续全部拼接，仍会越来越长。

最初保持固定共享BGE与来源/时点过滤；同时保留原文关键词和实体的检索入口，避免摘要删掉的罕见信息永远无法被找到。检索器内部可以使用完整合法索引，但不向PM免费暴露候选正文/向量。索引成本单列；不将一次查询必须扫描全库当成最终实现。

运行时检索相关单元，PM决定继续取得还是STOP；原生上下文边界保持不变，不借本次摘要设计偷偷恢复top-4或四次GET硬限制。需要实际部署的延迟操作点时，根据共同质量—等待曲线选择，不能把未经测试的任意长度写成最佳。

不默认“越旧越无用”，也不靠删除旧原文控制上下文。旧信息可以退出常用工作视图、进入归档索引；事实的当前有效性与来源的新旧分别处理。高频跨会话主题的专题总览是后续候选，不先增加一层可能失真的滚动总摘要。若新增专题总览，必须从可追溯来源重建，按目标时点版本化。

## 4. 用可实施的机制修复问题

| 问题 | 本次设计的解决机制 | 验收 |
|---|---|---|
| 完整会话冗长、关键信息埋没 | 会后独立生成任务相关但不看未来问题的会话摘要 | 同源RAW/SUM下的保真、帮助性及真实在线成本 |
| 历史越积越多 | 分层索引、按需读取、MP/ME直接读取常用事实/事件 | 随合法历史量增加的召回、成本与漏用曲线 |
| 压缩丢失指代、否定和行动阶段 | 自足陈述、原文锚点、保留未知；不合格摘要拒收 | 固定反例与实际源文语义审查，不以引用命中率冒充保真 |
| 摘要遗漏，后续无法恢复 | 保留原文索引与显式同源回查 | 查回正确父文、恢复所需信息、实际计入读取与生成成本 |
| 多次归纳产生漂移 | 每会话原文独立写入；修改从原文重建 | 版本hash绑定，旧摘要不被未来事实污染 |
| 原文中的建议被写成执行结果 | 写入schema区分建议/意向/行动/自报反应 | 挂电话、工作坊、社群等已发现反例通过 |
| G仍把旧记忆当现在事实 | 渲染时保留“当时报告”、时间与当前未知；必要时条件监督 | 同前缀相关/无关资源下事实误用及帮助性 |
| 资料正确但效果仍一般 | 在同版本实验中查是否需要不同表示/取量/执行适配 | 不把低质量单一摘要器的失败概括成所有摘要无效 |

RS沿用方法—案例两层设计。新的MS摘要保留过去支持行动及用户反应，使后续RS能结合已尝试/拒绝的方式调整建议；但不能将个人历史变成某种方法的因果疗效标签。

# PM-RL1：单轮资源选择与执行学习——环境及训练实施方案

版本：2026-09-28；范围：第一版有限步资源决策。本文是研究与实现设计，不是已经运行的 RL 实验报告。

## 0. 最终建议与近期边界

近期研究只回答：给定当前对话前缀与合法历史，系统能否按需获取资源、正确使用，并改善当前回复质量、误用风险和资源成本之间的取舍。

一个 episode 从真实数据中的合法 pre-supporter 前缀开始，经历至多四次资源 GET，STOP 后生成一次回复、评分并结束。**没有模拟用户，没有下一轮用户话语，没有心理状态转移，没有跨会话写回，没有联合在线更新。** 使用多会话历史不等于研究多轮未来回报。

先训练执行器的监督适配，再冻结执行器训练小 PM。两模块都有真实训练与评价，但按阶段学习。旧四头及其结果继续保留；v3.1 作为长期路线图，当前不执行其中跨轮环境、seeker、重访和联合训练网格。

三项优先级：

1. 定义并验证真实的数据与程序转移；
2. 建立能分辨当前回复差异的评价证据；
3. 在这个环境上比较监督选择与有限步 RL。

如果可靠标签与有限计划监督选择已经解决问题，保留这个结果，不为 RL 名称增加无意义调用。若奖励只反映模型裁判偏好，结论必须限定为该代理目标。

## 6. 动作与确定性转移

### 6.1 首版动作

`STOP=0, GET_RS=1, GET_MP=2, GET_MS=3, GET_ME=4`。

各类最多取4条，**总 GET 最多4次**，因此至多5个决策点（包含最后 STOP）。QA/Summary 的旧兼容测试固定 RS OFF；自然前缀允许四类。第一版不增加任意 item-ID 选择、重排、删资源、改 query、草稿重写或自问自答动作。

GET_h 取该类尚未取得的下一条，取得后承诺完整交付给 G。Step‑2 可以语义上不采用，但不能把该条从 prompt 删除、退还 token 或改称“没有取过”。上一轮讨论的“排除资源”在本版落实为合理不采用；显式丢弃/重排是后续单独动作协议。

这版主要学习类型、数量、组合和停止，不保证找出所有候选中的最佳任意子集；相似度首条不合适且挡住后续资源，是明确限制。

### 6.2 合法性与预算

资源预算初始候选 B=2,048 个 Generator tokens，包括整块说明、来源、分隔符、正文；同时检查完整 chat template/context 容量。此数是工程起点，不是实验结果。先用无 outcome 的容量 census 检查1,024/2,048/4,096档；若需变更，在任何新效果标签前统一冻结。主实验所有方法同 B。

GET_h 只有下一条存在、j<K、完整新增计划不超 B/上下文时才合法。rank1 超预算时不能偷偷跳到 rank2；该头当前 mask 为 false。非法动作必须报协议错误，不自动映射 STOP 或返回有意义的负样本。

STOP 始终合法，E=空即无资源。K 达到4或没有合法 GET 时只剩 STOP；这是研究任务的正常终止，不是 timeout。不得再另加一次“第5条探测”。

完整四类、总量≤4时最多70个终值计数计划；三类 memory 最多35个。它们只是理论上界，预算/候选缺失后更少；不同取得顺序不应制造额外终值 treatment。

### 6.3 转移函数 T

GET_h：

1. 验证旧 state hash、action mask、episode/version；
2. 从冻结 I_h 取索引 n_h 的真实条目；
3. 更新 n_h、E、j，按固定 RS→MP→MS→ME 与类内 rank 渲染；
4. 重新计算真实 tokens 和新 mask，返回新的公开 observation；
5. 记录 transition receipt。**不调用 LLM 来想象新状态，不产生用户反应。**

STOP：

1. 冻结 plan 与完整 prompt；
2. 用冻结 X 实际生成一次回复，或读取身份完全一致的已生成训练缓存；
3. 完整性检查后交独立评分接口；
4. 保存原始回复、评分/证据及成本，返回 reward，episode 结束。

任何评分缺失进入 pending/technical_failure，不能用 reward=0 冒充成功。训练中的缓存是“已观测终局反馈的复用”，不是一次新独立生成，也不是部署延迟测量。

## 7. Step‑2：研究对象与环境部件的边界
## 8. 奖励测量：最大的实际缺口

### 8.1 四层必须分开

1. 来源/时间合法：程序与 source span 核验。
2. 内容相关/适用：与当前需要的关系，需要语义判断。
3. 输出是否误用：事实、时间、人物、意向、已观察结果、边界等。
4. 最终增益：同一执行器下，相对无资源或另一计划，回复是否更好。

原 Gemini 资格不足、现有 ordinal 分数有压缩和裁判误差，不能把 old effect labels 直接连上 PPO 就宣称 reward 可信。

### 8.2 主线 reward record

自然支持任务使用一个新绑定的本地 current-turn evaluator：一次调用联合返回 q、misuse、证据与不确定性；不新增一套 LLM reward model 的梯度训练。

`q ∈ {0,1,2,3,4}`：0 严重失配/不能使用；1 明显问题；2 基本回应但存在重要不足；3 贴合、连贯、适当；4 充分回应当前需要并尊重已知约束。只评价新生成的当前回复，相同历史作为语境；不能用此前优质原文把末句错误平均掉。分数是训练效用编码，不假设人类效用天然等距。

`m ∈ {0,0.25,1}`：0 未发现资源相关误用；0.25 局部不影响核心建议的失准；1 实质性误用，如把未执行说成已有效、把过时限制当现在、将示例人物当用户、违背当前明确边界。所有错误带 response span、source span 与理由；unsupported/contradicted/uncertain 分开。没有声称事实时 precision=NA，不自动“资源使用满分”。

同一评价材料构造规则用于所有 arms：x＋严格合法历史形成的评审证据＋被评价回复。评审可读完整合法证据来发现未取资源造成的遗漏，但看不到策略名、k、相似度、成本、训练 seed、Ours/baseline。actor/G 不读这些评价侧材料。

m衡量输出中的资源相关错误风险；另记来源本身语义错误、检索不适配、生成扭曲、合理不采用、遗漏及无法确定的归因。若G忠实复述了一条编译错误的资源，不能仅因最终回答错了就断言是执行器误解。相同合法资源条件的配对实验用于减少这类混淆。

若评审证据超出可用 context，先解决统一证据组织或标测量缺失，不能只向裁判提供某个方法取到的资源。无足够依据的错误或质量判断保留 uncertain，不填0。

### 8.3 必须先做的小型测量检查

从 train/dev 取12个真实前缀；每个构造4个回复：真实无资源/真实有资源、对其中一个做单点来源或状态损伤、内容保持的风格改写，共最多48个 score payload。自然差异是主体，故意损坏控制不是全部证据。

检查：格式完整；来源证据能被复核；明确损伤是否被识别；风格变化是否无故主导；普通资源差异是否全平局；长回复是否得到无依据高分。预选12个 payload 重复一次只测稳定性；独立人工/不同评审盲看12个配对用于定位具体偏差。人和模型的审核身份分别记录；没有人工时不得声称 human validation。

只允许一次针对明确问题的 train/dev rubric 修订，旧新版本不混标。不得按 PM 得分最高选 evaluator。没有足够分辨率时先做来源/执行错误研究；环境工程继续可完成，但不扩大“有帮助性优化”的 RL。

这不是重做旧96题。是新任务的小型测量诊断；不存在自动保证可信的样本数或一致性阈值。需要扩大人工证据时先交付具体待审材料与其要支撑的主张，不要求用户先批准抽象大项目。

### 8.4 训练奖励与正式测量分开

J_train 固定本地模型、revision、prompt、decode、parser；X teacher 和 J_train 若同家族明确披露。正式保持独立来源核验和一份冻结的盲审子集；ESC-RANK 可作能力范围经检查后的补充维度，不能把新单轮 prompt 叫官方 ESC-Eval 复现。

正式盲审的起始上限为24个配对：12对比较同资源下X_g/X_l，12对比较X_l下RL/OneShot；按3个test owners平衡、按hash选取、PM seed在结果前轮换，均隐藏方法身份。优先由独立人工做来源及适当性判断；若只有独立模型则准确标明。24对只是有界证据补充，不能保证统计充分或据此声称人类普遍偏好；评审不回流训练。

可选小型官方 QA 外部验证：最多48个 outcome-isolated test targets×OFF/Fixed/OneShot/RL，共192个答案，用原官方 scorer；不需要 seeker。训练所有自然支持 reward 不用官方 API。QA 改善不能替代自然支持质量证据，旧完整 Paper‑1 官方对照另行收口，不与本版范围混同。

无独立有效评价时，最终只能说模型学会优化已声明的代理，不说已经提高真实支持效果。

## 9. 奖励函数与信用分配

令 `U_X(x,E)=q_X(x,E)/4 − α m_X(x,E)`；初始 α=1，表示重大误用的惩罚与完整质量区间同量级。这是研究者定义的偏好，不是数据推导的心理常数。

令 c(E) 为规范渲染后完整资源块的 G-token 数，空集为0；B 为共同 cap。初始 λ=0.05，γ=1。

```
GET:  r_j = -λ * [c(E_next) - c(E_now)] / B
STOP: r_j = U_X(x,E_final) - U_X(x,empty)
```

于是完整回报严格为：

`R = U_X(x,E_final) - U_X(x,empty) - λ*c(E_final)/B`。

无资源基线每个 prefix×executor 只实际生成并测量一次，按完整身份缓存；在部署时不额外生成无资源答案。它在同一 episode 的所有动作计划之间是常数，因此不会改变最优计划，但有利于解释资源增量。若基线缺分数，先进入待处理，不把基线当0。

STOP 不再扣第二次资源成本。tokenizer 的组合长度并非数学保证逐条单调，因此保存精确差值；无删除/重复 GET，状态无环，不存在来回领 token 奖励的路径。若改为非负逐次付费成本，必须重新定义总目标，不能一面裁差值一面声称上述等式仍成立。

不把“相邻 k 的质量差”作为免费的 GET 奖励：它需要额外生成，而且第1条暂时没收益不意味着第2条无法形成互补。GET 后不调用 G/J，只有 STOP 时实际生成评分。γ=1 保证多一次 GET 不会额外折扣最终质量。

λ 从小规模 dev 的质量/成本量级检查，不按 test 调整；初版不跑大网格。α、λ、评分锚点、技术失败规则需在真实训练前冻结。正式分别报告 q、m、质量增量、实际 tokens、延迟，不能只报混合 R。

真实延迟首版不直接放进 reward：排队、加载、输出长度、并发噪声会混入硬件负载。先测端到端与各段成本，之后有稳定预测器再做独立 latency-aware 扩展。该版直接优化的是资源输入成本，不承诺实际延迟必降。

其他计费/计算（PM 编码、固定检索、G 输出、训练 scorer、加载交换）全部记录。不能只报告 c(E) 就声称总算力减少。QA/Summary 若做环境桥接，仍用各自任务测量；不同任务数值不混成共同论文总分。

## 10. 可控、可审计与可信分别怎样验证

### 10.1 必须有的记录
## 11. 先建立可验证的非 RL 基线

### 11.1 单头完整剂量表是第一座桥

对一个固定 head、prefix、executor，k=0..4 的反馈若齐全，整条停止路径只有5个可能终值。可精确算出哪个终值最优、每一步继续与停止的目标；这是检查 reward、停止规则和训练器的理想小环境。

精确最优只供 train 教师或 sealed 后的 oracle 诊断；测试部署不能读取各 k 的真实分数。单头相邻量的实测差异可以诊断，不意味着线上策略可以免费读取。

全部动作反馈已知时先用监督学习获得情境化剂量选择。称它为离线计划/监督选择，不能因把表格包进 env 就声称 RL 比监督更省标注。

### 11.2 一次性计划对照

OneShot-Dose 使用与顺序策略相同的初始公开前缀和 metadata，一次预测终值计划。最大动作集合与 RL 可到达集合相同，排除预算不可行项；不能让它只选5个计划而 RL选70个，再把差异全部归因顺序观察。

用 train 中实际测过的 `(prefix, plan, q, m, cost)` 拟合效用预测器；未测计划不是0，也不是负例。特征可包括各类型剂量、相似度/长度及乘积项，但不偷看未 GET 正文。小样本中未测组合属于外推，需如实报告。

最终 OneShot 与其他静态基线可以使用相同 executor 下**本轮所有训练方法已获得反馈的共同 union**，并报告数据来源；这样不让 RL 独占更大标注集。dev/test反馈不加入该包。另记录在线探索总调用与各方法的训练成本，不把自适应收集数据当无选择的总体样本。

## 12. RL 训练方法：一套小策略，不先做算法网格

### 12.1 主建议

真实有限步训练首选 **masked feed-forward PPO**，取消上一版跨轮 recurrent PPO 的 GRU 和长轨迹状态。原因是：动作只有5个、每条最多5个决策点、实际 reward 来自冻结 X/J；on-policy 更新边界清楚，避免第一版把离线缺标签、Q值外推和循环 replay 一起引入。

这不是 PPO 最优的理论判断。Double DQN 适合离散动作且能复用 transition，值得后续在真实调用成为瓶颈时研究；它需要特别检查未测动作的 bootstrap 和过估计。GRPO/token-level RL 不适合作为这一步小资源策略的默认实现。只因为 ESCA 用 PPO 或 RLFF 用 GRPO，不能决定本项目算法。

缓存让已测终值可以反复用于采样，但缓存不让旧策略的动作 log-prob 变成当前策略。每个 PPO batch 的动作轨迹必须由该 batch 的冻结 behavior policy 重新采样；旧轨迹仅用于监督初始化/诊断，不放入未经校正的 PPO surrogate。

### 12.2 网络与信息

冻结 BGE‑M3；公开前缀编码＋已取得条目编码（按类型/rank最多4 slots并保留mask）＋原始 metadata/预算进入128维投影和两层128宽 MLP；5维 policy logits＋1维 value。相同 acquired set 用规范顺序编码；不输入 retrieval-order 决策路径作为额外暗示。

全部标准化只fit train；owner/target/schema hash等不是网络特征。编码器不更新；已取得文本的编码可按identity缓存，但线上也必须在合法取得之后才释放给actor。缓存命中不代表真实首次部署编码成本为0。短前缀/条目长度上限、截断/分块规则在首次训练前统一冻结，不偷偷裁掉关键证据。

### 12.3 共同初始化与训练额度

首批24个 train prefixes，按owner平衡。每个最多15个计划：OFF 1、四类k1和k2共8、六种两类各Top1组合共6。X_g/X_l分别真实生成和评分，最多720个终值反馈对。低覆盖/超预算计划标不可行，不补0。

利用这些**已测**终值建有限支持图，做 masked BC 初始化：只在能到已测终值的路径产生监督，合理并列保留。不得把未测 STOP 标负、也不得把未测组合填0。这个支持图是初始化来源，主 RL 仍可在合法动作域探索其他计划。

P_g 在 X_g 上训练；P_l 在 X_l 上训练。网络、train/dev来源、初始seed、batch和 episode 额度相同；BC标签分别来自对应X。该比较包含监督与RL整体适配，不能独立声称在线RL再适配贡献。

默认各128 episodes×3 seeds（17/29/43），合计768训练episodes；初始32同身份 smoke可计入128。均匀owner→该owner合法prefix抽样，所有重复标明不是独立样本。128是预算而非收敛保证；零信号/极低动作熵先诊断，不自动扩量。

PPO起点：Adam lr3e-4、clip0.2、γ1、GAEλ1、value系数0.5、entropy0.01、grad clip0.5；16完整episodes/batch、4epochs、每minibatch4episodes。每个batch全部 reward 齐备后更新。forced STOP不计policy/entropy损失，可计value；初始化中未拟合的critic不得伪装已知oracle。

开发评价只在64与128，各用同24dev前缀；主比较固定128终点，不各挑峰值checkpoint。训练前若计算预算不足，所有组统一降64×3并写清；不看test后延长落后组。第二RL算法不是近期必做。

### 12.4 开真模型前必须验证的学习行为

程序构造 E0：包含无需资源、取一条即可、首条暂时无收益但两条互补、错误/冗余资源、预算阻止行动等案例。真实训练小策略，而不只断言 reward 算式；与随机/Always STOP/精确DP比较，记录3seeds曲线。

检查合法动作概率、log-prob重算、参数真实变化、critic target、γ=1 credit、终局无bootstrap、保存恢复与相同batch版本。若PPO无法在可解小任务学习，先修实现；本次文档检查没有替代这项服务器训练验收。

## 13. 正式实验的最小结构

### 13.1 执行实验

48 test prefixes×OFF/相关合法/低相关合法三条件×X_b/X_g/X_l三个执行器，最多432个回复。相关性在生成前冻结；缺条件如实记录。X_g/X_l同提示，事实/适用性与q分开评价。

比较无资源能力、资源增量 `q(E)-q(empty)`、重大误用及不采用。X_l在OFF也提升但资源增量不变，不能说学会了更强资源利用。单个SFT seed限制结论稳定性；若执行训练成为强主张，优先复现实验seed，而不是先增加第二RL算法。

### 13.2 策略与执行交叉

| 方法 | X_g | X_l |
|---|---|---|
| No Resource | 1 | 1 |
| Fixed-Dose（dev选） | 1 | 1 |
| Matched Random（dev定分布） | 1 | 1 |
| OneShot-Dose（对应X训练） | 1 | 1 |
| P_g | 3 PM seeds | 3 PM seeds |
| P_l | 3 PM seeds | 3 PM seeds |

共20个checkpoint/策略实例×48 test prefixes=最多960个回复。Fixed包含在共同动作/预算域中；匹配随机按dev的类型/剂量分布构造，test实际成本仍需报告，不宣称精确等成本。旧四头若已有可比checkpoint，可增加补充行，不能用新proxy冒称旧模型。

与执行实验只有完全相同输入/模型/解码的请求才去重。去重共享结果保留统计相关性；不同seed/重复目的不能随意合并。

### 13.3 可得结论

- RL超过Fixed但未超过OneShot：说明自适应资源计划有价值，尚未证实逐步观察/继续决策的额外收益。
- RL超过同数据、同动作域OneShot：支持本设置下序贯信息利用价值；还需排查模型容量、优化与可见信息差异，不能只由算法名称归因。
- P_l/X_l超过P_g/X_l：支持针对执行器重新适配的整体价值。
- X_l资源增量与来源指标改善：支持所测分布上的利用改善。
- 训练reward涨而独立评分不涨：代理优化成功，真实任务收益未证实。

主结果包括质量、误用/伤害、正收益捕获、无效取用、ON/GET分布、tokens、全链延迟和失败。正收益捕获与local regret只在有足够成对反馈的诊断子集定义；未测全计划不称全局oracle。无正收益分母记NA。

This is a development census, not a claim of unexposed test data. Exact shared
transcripts are reported for source-family adjudication before dataset freeze.

from collections import defaultdict
from dataclasses import asdict
from hashlib import sha256

def stable_hash(text: str) -> str:
    return sha256(text.encode()).hexdigest()


def owner_split(users) -> dict[str, str]:
    owners = sorted((u.owner_id for u in users), key=lambda s: stable_hash("pmseq-v2-owner|" + s))
    if len(owners) != 18 or len(set(owners)) != 18:
        raise ValueError("the declared 12/3/3 split requires 18 unique owners")
    return {owner: "train" if i < 12 else "dev" if i < 15 else "test"
            for i, owner in enumerate(owners)}


def build_prefixes(users) -> tuple[tuple[PrefixSpec, ...], dict]:
    split = owner_split(users)
    all_prefixes, selected = [], []
    source_groups = defaultdict(list)
    for user in users:
        eligible = []
        for session in user.sessions:
            source_groups[digest([(t.role, t.content) for t in session.turns])].append(
                dict(owner=user.owner_id, split=split[user.owner_id], session=session.session_id,
                     rank=session.chronological_rank))
            if session.chronological_rank < 1:
                continue
            cuts = [i for i, t in enumerate(session.turns[:-1]) if
                    t.role == "seeker" and session.turns[i + 1].role == "supporter"]
            if not cuts:
                continue
            cut = min(cuts, key=lambda i: stable_hash(
                f"pm-rl1-census-prefix-v1|{user.owner_id}|{session.session_id}|{i}"))
            prefix = PrefixSpec(user.owner_id, session.session_id, session.chronological_rank,
                                cut, session.timestamp, split[user.owner_id],
                                tuple(PublicTurn(t.role, t.content) for t in session.turns[:cut + 1]))
            eligible.append(prefix)
        all_prefixes.extend(eligible)
        selected.extend(sorted(eligible, key=lambda p: stable_hash(
            "pm-rl1-census-session-v1|" + p.owner_id + "|" + p.session_id))[
                :16 if split[user.owner_id] == "test" else 8])
    shared = [rows for rows in source_groups.values() if len({r["owner"] for r in rows}) > 1]
    return tuple(selected), dict(status="DEVELOPMENT_CENSUS_NOT_FROZEN", owner_split=split,
        eligible_sessions=len(all_prefixes), selected_by_split={s: sum(p.split == s for p in selected)
        for s in ("train", "dev", "test")}, shared_transcript_groups=shared,
        pending=["fact-family grouping including descendants of shared sessions",
                 "historical exposure manifest and held-out interpretation",
                 "capacity census with RS before resource-budget freeze"])

## 1. 研究目标、问题与完成标准

### 1.1 目标

在情感支持对话的每一轮回复前，PM 决定取得哪些外部资源，或者直接停止：

- RS：有出处的方法与案例；
- MP：个人档案；
- ME：事件经历；
- MS：过去的会话。

冻结的 G 用已经取得的资源生成一次回复。要做到的是：回复对此刻的用户更有帮助、更恰当，资源误用更少，等待可以接受。

一个 episode 只包含“获取 → 停止 → 一次回复”。不模拟用户后续反应，也没有多轮未来奖励。

### 1.2 研究问题

| 编号 | 问题 | 回答方式 |
|---|---|---|
| RQ0 资源价值（前提） | 资源组织优化后，各类资源在哪些情境让回复明显更好或更差？瓶颈在链条的哪一段？ | S3 试点（必要时 S4 修复） |
| RQ1 情境选择 | 学到的 PM 在质量–等待取舍和决策正确性上，是否优于最强固定子集、规则、LLM 门控、匹配随机、全开、全关？ | S5 主表 + S6 |
| RQ2 顺序与 RL | 读后再决定是否优于一次性承诺（OneShot）？PPO 是否优于同数据下对精确最优的监督模仿？ | S6 |
| RQ3 执行器适配（条件） | 用相关/无/无关资源对 G 做成组监督，能否提高资源带来的增益、减少误用，同时不降低无资源时的质量？ | S7 |
| RQ4 G–PM 配对（条件） | 换了 G 之后，重新适配的 PM 是否优于直接沿用？ | S8 |
| 外部验证 | 官方 ESC-Eval、ES-MemEval；参考客户端与 Tokkio 实测等待 | S9、S10 |

### 1.3 完成标准

**研究完成**需要同时满足：

- S0–S11 每一步为 `completed`，或为 `not_run_with_reason`，且理由属于本文预先写定的分支；
- RQ0–RQ2 有结果（正或负）；
- RQ3/RQ4 有结果，或按触发规则未运行；
- 外部评价与等待测量已完成，或明确记录了缺少的外部条件；
- 论文草稿与复现包完成。

- **18 个 owner 全部进入主表。**试点前缀与主表前缀不重叠。另报告“排除 6 个试点 owner、只看 12 个 owner”的敏感性分析。

### 4.3 候选前缀普查（S1）

- 对 `chronological_rank ≥ 1` 的会话，每个“seeker 发言之后紧接 supporter 回复”的位置都是候选切点。
- 前缀 = 该会话开头到这句 seeker 发言。
- 合法记忆 = 同一 owner、rank 严格更小的完整会话，以及由它们派生的资源。

### 4.4 需求筛选（只用生成前可见的信息）

1. **确定性特征**：
   - 回指线索正则，如 `last time | I told you | remember | still | again | update | as I said | since we talked`；
   - 与过去会话的实体重叠数；
   - 求助线索，如 `what should I | any advice | how do I | I don't know what to do`；
   - 前缀与过去会话的 BGE 最大相似度。
2. **Qwen 筛选**（提示见附录 B）。
   - 输入：前缀最后 6 轮；过去会话清单，每个会话给出日期/序号、前 120 词和实体。
   - 输出 JSON：`need_type ∈ {memory_specific, memory_general, method, ordinary}`；`need_spec`（需要的具体过去信息，一句话，附源会话 ID）；`confidence`。
3. **Codex 核对**：对入选试点和主表的每个 `memory_specific` 前缀，打开源会话核对 `need_spec` 是否存在且严格过去，标为 `assistant_verified`。不成立的改标为 `memory_general` 或 `ordinary`。
4. **研究者抽查**：抽 20%，附在第一个 T2 批次中。
5. **分层**：记忆需求 = `memory_specific ∪ memory_general`；方法需求 = `method`；普通 = `ordinary`。

### 4.5 抽样配额

在每个 owner 内按层排序（`sha256("pmrl1v2-sample|"+集合+"|"+prefix_id)`）取前 k 个。同一会话最多 1 个前缀；不够时放宽到 2 个并记录。

| 集合 | owner | 每 owner 数量 | 层配额（记忆 / 方法 / 普通） | 合计 |
|---|---|---|---|---|
| 试点 P | 6 个试点 owner | 6 | 3 / 2 / 1 | 36 |
| 复查 R1、R2（条件触发） | 6 个试点 owner | 3 | 2 / 1 / 0 | 每轮 18 |
| 主表 M | 18 | 8 | 4 / 2 / 2 | 144 |
| 执行器监督与评价（条件触发） | 6 个试点 owner | 剩余池 | 见 S7 | ≤ 156 |

**某层不够时**：先用相邻层补（记忆不足用方法补，方法不足用普通补），记录实际数量。不读取未来内容，不复制样本。

普查给出各层占全部候选的比例。主报告按层分别给出；次要报告用这个比例做“自然混合加权”。

## 5. 资源与检索（S2 构建）

### 5.1 RS

**方法单元**

- 数量：目标 24–40 个。
- 来源优先级：
  1. 公共领域的美国政府材料：SAMHSA TIP 35（MI）与 TIP 57（创伤知情），NIMH、CDC 的应对指南，NCPTSD/NCTSN 的 *Psychological First Aid Field Operations Guide*；
  2. 其次是 CC BY-NC-SA 许可的 WHO 材料，如 *Doing What Matters in Times of Stress*。
  每个单元都记录许可。
- 覆盖主题：反映式倾听与核对、情绪确认、开放式提问、问题解决步骤、行为激活、落地与呼吸技巧、睡眠基础、动员社会支持、温和的认知重评、价值澄清、决策权衡、引出改变语言、面对阻抗、悲伤支持基础、自我同情、担忧时间、边界与自信表达、危机安全检查与转介（如 988）。
- 字段：`method_id, name, when_to_use（情境线索）, when_not_to_use, action_options（2–4 条）, example_phrasing（改写，不照抄原文）, limits, source{title, url, section, license, quote（不超过 2 句）}`。
- 由 Codex 依据原文撰写。11-15 的 3 个 TIP 35 草稿并入。

**案例**

- 每个方法最多链接 2 个 ESConv train 完整案例。每个案例包含：前情（不超过 6 轮）、体现该方法的支持者连续行动、紧随其后的 seeker 反应、原始反馈分。
- 召回：用 BGE，以方法的 `when_to_use + action_options` 去匹配支持者轮次，取 top-20。
- 核对：Codex 逐条确认该案例确实体现了这个方法，且不含不安全内容或虚假承诺，然后取最多 2 个。
- 11-15 的 12 张候选卡按其逐卡审阅结论处理：标为“暂停正向使用”的不入库。

**F（常驻紧凑方法）**：全部方法单元的“名称 + 一句何时使用”列表，作为基础提示的可选附加部分。

**专业审核（T5，可选）**：有审核人时，逐单元给出“适用 / 需改 / 不适用”，并据此修改。没有审核人时，在论文中列为局限，不阻塞后续步骤。

**检索**

- 查询：当前前缀最后 3 轮的文本。
- 方法索引文本：`name + when_to_use + action_options`。
- R_m：top-1 方法单元。
- R_p：top-1 方法单元，加上它已链接的案例中与查询最相似的一个。
- D_R：相似度最低的方法单元。

### 5.2 MP

- 用现行 Multi-View 编译结果（713 个 MP 版本），在切点时刻物化当前档案（`materialize_multi_view_candidates`）：先做严格过去过滤，再取最新版本，冲突保留。
- 应用 11-15 的 3 条候选修复：`outputs/pm_rl1/research_preparation_20261115_v1/memory/CANDIDATE_VIEW_REPAIRS_PRIVATE.json`。
- 渲染：事实列表，每条附“报告于 <日期或会话序号>”。
- 超过 350 tokens 时，按与查询的相似度取前 10 条（固定规则）。

### 5.3 ME

- 来源：现行编译的 ME（1,523 条），严格过去。
- 检索：按 BGE 相似度取 top-3。
- 渲染：日期、事件、阶段（建议 / 打算 / 尝试 / 自报反应 / 未知）。编译字段缺少阶段时，附上源原话一句。

### 5.4 MS

- **RAW**：完整的过去会话逐轮原文（现行实现）。
- **SUM**：对 401 个会话分别生成会后摘要，写入器只读该会话全文。保存源 hash 与写入器身份。
  - 忠实性检查：Qwen 逐句判断“是否被原文支持”。有不受支持的句子时，带反馈重写一次；仍失败的，该会话的 SUM 标为 `unusable`，SUM 条件下该会话改用 RAW 并记录。
  - Codex 人工审阅 24 份，必须包含已知的 3 个反例：挂电话、写作工作坊、线上社群支持。
- **检索**：对 SUM 文本建 BGE 索引；RAW 条件也用 SUM 索引排序，保证 RAW 与 SUM 比较的是同一个会话。只检索同 owner、rank 严格小于当前会话的会话。
- **MS 单元**：top-1；若 S3 预写规则判定，则改为 top-2。
- **D_MS**：同 owner 合法过去会话中相似度最低者的 SUM。没有第二个可用会话时，该前缀不设 D_MS，并记录。
- **MS_ORACLE**：`need_spec` 所指源会话的 SUM。只用于已核对的记忆需求前缀。

### 5.5 存储（精简）

- 目录：`outputs/pm_rl1/v2/bank/`。
- 文件：`rs_methods.jsonl, rs_cases.jsonl, mp_versions.jsonl, me_events.jsonl, ms_raw.jsonl, ms_sum.jsonl, embeddings/<head>.npy, embeddings/<head>_rows.jsonl, MANIFEST.json`。
- `MANIFEST.json` 记录每个文件的 sha256、生成代码的 commit 和所用模型身份。
- 每条记录的字段：`id, head, owner, source_session_id, source_rank, source_sha256, text（读者视图）, provenance（原话或跨度）, version`。
- 不要求实现 11-16 完整的 JSON Schema。

### 5.6 资源侧必须有的 CPU 测试

1. 同一 owner。
2. `source_rank` 严格小于当前会话 rank；同一会话的摘要不能用于本会话内部的前缀。
3. RS 不含与当前 owner 来源重叠的 ESConv 对话。
4. 渲染后的 prompt 中没有 gold、未来内容或评价字段。
5. token 数用 G 的 tokenizer 计算。

用反例写测试：未来会话、错误 owner、同会话摘要、重叠的 ESConv 对话。

## 6. 决策环境（终点表）

1. **动作**：`STOP, GET_RS, GET_MP, GET_ME, GET_MS`。每类最多取一次；某类没有合法单元时不可选；最多 4 次 GET。
2. **终点确定性**：单元内容只取决于“前缀 + 资源类”，渲染顺序固定，所以终点回复只取决于取得的子集。终点数最多 2^4 = 16（含 OFF）。
3. **观察**：
   - **初始**：前缀嵌入（BGE，最后 3 轮）；各类可用标志；各类 top-1 检索相似度；各类单元的 token 数。这些是读取前就能看到的检索元数据。
   - **每次 GET 之后**：增加该类单元正文的 BGE 嵌入（即内容可见）。NoText 消融不提供这一项。
4. **奖励**：r(S) = y(S) − λ·ΔC(S)。
   - y ∈ {+1, 0, −1}：人工对子集 S 的回复相对 OFF 回复的判断；
   - ΔC：附加秒数（§8）；
   - γ = 1，中间步骤奖励为 0。
5. **性质**：这是一个有限、确定、所有终值都已观测的 MDP，可用动态规划精确求出每个前缀的最优策略。训练折用它做监督；测试折只把它当作诊断上界。

## 7. 人工标注协议

### 7.1 评审

- A：研究者；B：第二评审（T1 确认）。
- 两人都不知道各条回复属于哪个条件。

### 7.2 页面（复用 11-05 的页面与导入机制，改成列表式）

每个前缀一屏，包括：

- **当前对话**：英文原文，附中文阅读译文（标明只是辅助）。
- **“这位用户的相关背景”面板**：该前缀所有条件用到的资源单元的并集，中性编号，D 单元也包含在内。RS 单元显示为“可参考的方法说明”。
- **回复 0**：即 OFF，页面不说明它是 OFF。
- **候选回复 1..n**：随机顺序；完全相同的文本只出现一次。

每个候选回复相对回复 0 选择一项：**明显更好 / 差不多 / 明显更差 / 无法判断**。

可多选的标签：

- 正确用到用户过去信息
- 过去信息用错、过时或张冠李戴
- 插入不相关的过去话题
- 重复追问已知信息
- 给出具体、适合的帮助
- 建议过早或不合适
- 不安全或不当
- 太长或不自然
- 其他：___

页面自动保存，可分批导出 JSON。导入脚本校验 `reply_sha256` 与前缀的绑定。

### 7.3 锚点

完整文本见附录 A，要点如下：

- **明显更好**：对此刻这个人的体验有可感的改善。例如：正确用上相关的过去事实或事件；避开用户已说无效的建议；不重复问已知信息；在用户求助时给出具体、适用的帮助；更恰当地处理敏感点。
- **差不多**：只是措辞、语气、长短不同，或者只是提到了历史，但帮助程度没有变化。
- **明显更差**：历史用错、过时或张冠李戴；插入无关的历史；用户想被倾听时急于给建议；内容不安全；明显过长或不自然。
- **无法判断**：只用于无法核实的情况。

### 7.4 校准

- S3 的第 1 批（6 个前缀）由两人都标。
- 对比分歧，讨论 30 分钟，可以修订锚点一次（v2）。此后不再修改。
- 分歧项按 v2 重新标注。

### 7.5 信度

在两人都标的前缀上，报告：三分类一致率、Cohen κ、非平局项的方向一致率。

### 7.6 “无法判断”的处理

1. 交给另一位评审标一次。
2. 仍无法判断，或没有另一位评审：y = 0，标记 `imputed_tie`。
3. 评价时对这些项给出 y = −1 与 y = +1 两个方向的上下界敏感性分析。

### 7.7 工时估计

按每个前缀约 5 分钟阅读、每个候选 30–45 秒估算：

| 阶段 | 内容 | A | B |
|---|---|---|---|
| S3 试点 | 36 个前缀 × 约 11 个候选；B 重叠 18 个 | 约 7 h | 约 3.5 h |
| S4 复查（每轮，条件触发） | 18 个前缀 × 约 5 个候选 | 约 2.5 h | 约 1 h |
| S5 主表 | 144 个前缀 × 最多 15 个候选；A、B 各 72 个，另有 24 个重叠 | 约 22 h | 约 22 h |
| S6 直接对比 | 最多 60 对 | 约 0.8 h | 约 0.8 h |
| S7 RQ3（条件触发） | 36 个前缀 × 7 | 约 5 h | 约 1.5 h |
| S8 RQ4（条件触发） | 48 个前缀 × 15 | 约 6 h | 约 6 h |

所有条件模块都触发时，每人合计约 40–45 h。

**只有 A 一人时**：主表全部由 A 标注（约 36 h），没有信度估计，论文中注明单评审。

## 8. 奖励、成本与 λ

1. **y**：见 §7。
2. **成本 ΔC**：用户能感到的附加秒数，即终点 S 相对 OFF 在“客户端发送 → 首个可见文本”上的增加量，包含 PM 决策、检索、编码和 G 预填充的增量。
   - S0e：在参考客户端上实测至少 80 个请求，覆盖从 OFF 到全部取得的 token 范围。
   - 拟合 `seconds = a + b·input_tokens + c·n_GET`，用留一前缀交叉验证计算 MAE。
   - 用该模型给表中每个终点赋 ΔC。完成时间作为次要指标同样建模。
   - S10 用实测数据校准。
3. **λ = 1/X**：X 由研究者在 T1 给出。没有回答时默认 X = 3（研究者此前说过额外超过 3 秒不可接受）。
   - 另外报告 λ ∈ {0, 0.1, 0.2, 1/3, 0.5, 1} 下的质量–等待前沿。
   - 硬约束：ΔC 的 p95 超过 3 秒的终点在部署域中不可选。
4. **训练与评价用同一个 r**，同时分别报告 y 和 ΔC。

## 10. 方法与训练细节（S6 前全部固定，不在测试折上调）

### 10.1 共享特征

- **初始观察 x0**：BGE（前缀最后 3 轮）1024 维；每类资源的可用标志、top-1 相似度、token 数 / 1000，共 12 维。
- **顺序方法额外的观察**：每类资源一个是否已取得的标志；已取得单元的 BGE 嵌入，经共享线性层 1024→64 投影，未取得时为 0；再加步数 / 4。
- 数值特征只在训练折上标准化。

### 10.2 方法

| 编号 | 方法 | 定义 |
|---|---|---|
| M1 | Always-OFF | 始终 STOP |
| M2 | Always-ALL | 取全部可用资源 |
| M3 | Fixed-best | 训练折上平均 r 最大的固定子集 |
| M4 | 单头固定 ×4 | 每次只取某一类；仅报告，不作主比较 |
| M5 | Screen-Rule | 依据 S1 的筛选标签：记忆需求 → 取 MS+ME（有 MP 线索时加 MP）；方法需求 → 取 RS；普通 → STOP。规则在 S0 写定 |
| M6 | LLM-gate | Qwen3.5-9B 零样本：给出前缀、各类资源的说明和 top-1 相似度（不给内容），让它选择子集 |
| M7 | Matched-Random | 子集大小按 M10 在训练折上的选择分布抽取，资源类在可用类中均匀抽取；取 100 次平均 |
| M8 | OneShot | MLP 学习 f(x0, onehot(S)) → r̂，在训练折全部终点上用 MSE 训练，3 个种子集成；在可用子集中取 argmax |
| M9 | Seq-SL | 在训练折每个前缀的全部可达状态（16 个）上，模仿 DP 最优动作，交叉熵训练。平局时取 ΔC 更小者，再平局取 STOP |
| **M10** | **PPO-BCinit（主 PM）** | 以 M9 初始化，再用 PPO 训练 |
| M11 | PPO-scratch | 随机初始化的 PPO |
| M12 | PPO-NoText | 不提供已取单元的嵌入，以 NoText 版 Seq-SL 初始化 |
| M13 | Oracle | 测试折 DP 最优，仅作诊断上界 |

### 10.3 网络与超参数

- **网络**：MLP 2 × 128，ReLU，dropout 0.1，weight decay 1e-4；策略头输出 5 个 logits 并做 mask；另有价值头。
- **Seq-SL**：Adam，lr 1e-3，100 epochs，batch 64。
- **OneShot**：Adam，lr 1e-3，200 epochs，batch 64。
- **PPO**：Adam lr 3e-4，clip 0.2，γ = 1，GAE λ = 1，价值系数 0.5，熵系数从 0.01 线性降到 0.001，梯度裁剪 0.5；每次 rollout 256 个 episode，4 个 epoch，minibatch 64；每个种子每折共 30,000 个 episode；训练前缀均匀抽样。
- **测试**：取 argmax 动作。
- **种子**：17/29/43。报告均值和每个种子的结果。

## 11. 评价与统计

### 11.1 单位

- 分析单位是前缀，聚类单位是 owner（18 个）。
- PPO 与 Seq-SL 先在每个前缀上对 3 个种子取平均。

### 11.2 指标

- **策略价值**：V(π) = 测试折前缀上的平均 r，汇总 6 个折，每个前缀只在折外评价一次。
- **质量与等待**：质量 Q(π) = 平均 y；等待 W(π) = 平均 ΔC。另报告“更好率”和“更差率”（伤害）。以上都按层报告，并给出自然混合加权版本（§4.5）。
- **决策正确性**：按 `paper1_decision_correctness_evaluation_v1.json` 的指标定义，以单头终点的标签 y({h}) 为每类资源的“开启是否有益”真值，计算 ON-benefit recall、OFF-nonbenefit specificity、unnecessary-open、missed-benefit、balanced accuracy。平局视为“非有益”，单独报告。
- **行动正确性**：遗憾值 V(Oracle) − V(π)；策略达到 Oracle 值的前缀比例。

### 11.3 主比较（预先写定，Holm 校正，3 项）

- **P1**：V(M10) − V(M3)
- **P2**：V(M10) − V(M8)
- **P3**：V(M10) − V(M9)

做法：

- 按前缀配对；
- owner 聚类 bootstrap 10,000 次，给出 95% 区间；
- 用 owner 层面的符号翻转置换检验求 p 值（2^18 种，精确计算）；
- 判为“支持”的条件：Holm 校正后 p < 0.05，且区间不含 0。

### 11.4 次要结果（描述性，给出区间）

- 与 M1、M2、M5、M6、M7 的比较；
- M10 对 M12：读后内容的价值；
- λ 前沿；
- 按层的结果；
- 敏感性分析：
  - 排除 6 个试点 owner；
  - `imputed_tie` 的上下界；
  - 分别只用 A 或只用 B 标注的前缀；
  - 判官扩充训练臂（若有）。

### 11.5 直接对比

### 11.7 精度预期
