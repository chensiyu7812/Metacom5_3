# G4 语义能力系统对照：实际结果与错误归因

日期2026-11-27（JST），Claude Code。授权：研究者“下一阶段研究执行指令”第3节（修订后G4批准；G5不批准），原文另存为`authorization/G4_RESEARCHER_APPROVAL_PRIVATE.txt`（不复用G1/G2-R授权）。公开数字在`g4_v1/`。本实验是**固定合法证据条件下的系统诊断**，不是完整动态Agent实验；全部质量判断为助手开发审阅，不是真人评价。

## 一、结论摘要

| 问题 | 结果 |
|---|---|
| 运行是否在预算内 | 是：96次LLM调用（上限112）、1次加载、868.7 s（上限1,800 s）、0 warmup、0 retry、0运行错误 |
| 专业语义能力是否改善了回复 | **没有可观察的改善**。RAW直接回复（A）在16个状态的冻结检查项上已16/16无违反；B 16/16，N 15/16，C 15/16。本组状态对Generator没有留下改进空间 |
| 代价 | B比A多一次命题形成调用，本地等待中位数+9.5 s（P95 +11.9 s）；N +16.2 s；INSPECT_CLAIM本身合计4.8 s/48命题 |
| 按需调用 | C在16个状态中**一次也没有调用检查**（S/U/H组也都直接回复）；C与A等待相同（+0.03 s），这是“从不检查”的结果，不是有效的按需决策 |
| 瓶颈在哪里 | 不在T1i判断（运行时命题上T1i 41/48、T0 38/48），而在：①命题形成多为复述已明确的事实，少有指向风险预设的命题；②证据选择（当前用户话语没有证据ID、问句话轮常未被引用）；③Generator不会自发使用检查工具 |
| 下一步 | 不继续NLI微调（G5维持不批准）；先修证据接口、研究命题形成与调用决策，并在确有改进空间的状态上重测（见[NEXT_RUN_REQUEST_V3_ZH.md](NEXT_RUN_REQUEST_V3_ZH.md)） |

## 二、GPU前完成的CPU检查与设计冻结

### 2.1 身份与证据接口（新版本，冻结执行器未改）

| 要求 | 实现与实际检查 |
|---|---|
| A/B/C/U交付给Generator、语义技能、Memory Writer | 新增`semcap/g4_context.py`（`semcap-g4-context-v1`）：三者共用同一份带ID的记录投影；每条记录写明报告时间与说话人标签（`identity.attribute_history`），Generator系统提示附对应身份合同；任何历史supporter话轮都不作为原生assistant；Memory Writer投影`memory_record()`给出`speaker_label/situation/is_current_user` |
| 外部案例与用户历史混合时逐条隔离 | `agent_skill` v2：标记为外部案例的条目即使混在用户历史中也不进入用户命题判断；全部为外部案例时返回unprocessed（测试覆盖） |
| subject、time_scope是否真正参与 | **不参与**：改变二者T1i判断4/4相同。它们只被记录；主体与时间必须写在命题文本中。不声称已实现基于这两个字段的能力 |
| 报告时间/事件时间/相对时间 | 每条记录显示“session reported <日期>”或“current conversation”，并说明相对时间以报告日期为准；当前日期单列。INSPECT_CLAIM沿用训练格式，只给宿主按报告时间排定的会话序号（不给日期） |
| WM修订、冲突、未处理 | `evidence_state` v2：逐条判断中同一会话内支持与反对→`conflict`；仅跨会话不同→`change_over_time`（不当作逻辑矛盾）。实测“先喜欢后不喜欢”例中T1i把较早一条判为implied，未触发该标记，整体判断跟随后一报告——按实际记录 |
| 共同输出过滤 | 去除泄漏的“thought”思考标记（原文另存）；本次1条A回复被过滤 |
| 合法evidence_id枚举 | 提示中列出全部合法ID；解析时只保留合法ID，非法ID丢弃并登记；无合法ID的命题拒绝（不修补）。本次非法ID 0 |
| 模型容量与运行时异常 | INSPECT超过512 token时按顺序分窗判断并标记（实测950 token→2窗）；单条超容量为unprocessed；每次调用与每臂独立捕获异常、不重试 |
| 环境一致性 | T1i在G4环境（transformers 5.17，CPU）与训练环境预测152/152相同，概率最大差0.016 |

测试：`tests/test_semcap_g4_context.py`（5项）＋既有semcap测试，共22项通过。

### 2.2 样本（预测前冻结，`g4_v1/G4_DESIGN_FROZEN_PUBLIC.json`）

- 候选池：ESConv训练家族787个、EvoEmo训练owner 394个。排除fold6；排除GSWS、event32、speaker32、G1、DCS全部家族；EvoEmo只用历史训练owner，并整体排除已用过的p13/p18（GSWS）与p5/p6（event32/speaker32），共9个owner可用。EvoEmo证据为同一owner此前最多两个会话（带报告日期）＋当前会话前文（U情形）；ESConv为同一会话导入前文（A情形）。
- 归组：按加盐哈希顺序逐个阅读，按书面标准首个适合即入组，每组每来源2个、EvoEmo每owner 1个；跳过8个并登记原因。四组：S 明确支持、U 证据不足或反证、H 主体/时间/阶段困难、O 普通聊天无需核验。共16个状态（ESConv 8、EvoEmo 8，8个不同owner）。
- 每个状态预先写好“不得断言”与“应当”检查项和评价规则；预先固定8对B对A盲评材料。按研究者要求，人工参考命题**没有**在预测前写，只在预测后作为诊断参照独立写出，未回流运行时。

### 2.3 四个条件与LLM调用

| 条件 | 每状态LLM调用 | 说明 |
|---|---|---|
| A RAW→G | 1 | 记录＋身份合同＋最新用户话语 |
| N 普通Notes | 2 | 独立笔记调用（≤8条、要求区分计划/已做/未知并引用ID）→ G带笔记 |
| B 固定INSPECT_CLAIM | 2 | 命题形成调用（1–3条，系统自己形成）→ T1i逐条判断（CPU，非LLM）→ G带简短核验说明 |
| C 按需INSPECT_CLAIM | 1或2 | G首轮可输出CHECK行；直接回复即结束（真正省掉一次LLM调用），否则核验后再生成 |

四条件同一记录、同一身份合同、同一Gemma权重与解码（greedy，320）。固定与按需**不是**同数量LLM调用：C的直接回复路径确实少一次LLM调用；但本次C从未走检查路径，所以没有检验“检查后回复”的C。

## 四、结果

### 4.1 回复（助手开发审阅，冻结检查项）

| 条件 | 无违反 | 违反数 | 应当项满足 | 支持适当 | 自然 | 身份问题 |
|---|---:|---:|---:|---:|---:|---:|
| A | 16/16 | 0 | 23/25 | 16 | 16 | 0 |
| N | 15/16 | 1 | 23/25 | 16 | 16 | 0 |
| B | 16/16 | 0 | 23/25 | 16 | 16 | 0 |
| C | 15/16 | 1 | 22/25 | 16 | 16 | 0 |

- N的1条：笔记列出了早先的恋爱受挫，回复把它当作当前紧张的一部分（O组）。C的1条：把“正在考虑换研究方向”说成“转向新研究方向的过程”（U组）。两条都较轻。
- 各条件回复内容高度相似；B的核验说明在16个状态中都没有带来可观察的回复差异。
- 共同未满足的应当项：没有提到“已试过一份新工作但没成功”（G07，四条件均未提）；没有回应“被两个朋友排斥”（G02）。

### 4.2 命题形成与证据判断（B；C未形成命题）

- 48条命题（每状态3条），全部可解析、ID全部合法。T1i运行时判断：supported 38、not_established 8、implied 2、contradicted 0。
- 事后参考（预测后由助手独立写出）：supported 43、not_established 5、contradicted 0。**运行时形成的命题绝大多数是已明确的事实复述**，语义模型几乎没有需要区分的困难情形。
- 对照冻结风险：U/H组8个状态中，命题直接指向检查项风险的2个，部分指向4个，完全没有2个（如“已邀请教会成员”“已经养了新狗”未被形成命题）。
- 同一命题、同一已读证据上的离线对比（不增加Generator调用）：T1i 41/48（隐含按严格或宽松计均为41），T0 38/48；二者不同的9条中：T0漏判明确支持4条、把时间范围错误的命题判为支持1条、把只含问句的证据判为矛盾1条；T1i漏判明确支持1条、把明确支持判为implied 1条、把部分超出所引证据的命题判为支持1条。二者共同的错误（非正式写法“i did tell them”、含“maybe”的计划等）各4条。

### 4.3 错误归因（研究者指定类别）

| 类别 | 数量 | 说明 |
|---|---:|---|
| 未发现关键命题 | 2个状态（另4个部分） | 命题形成倾向复述，不倾向写出回复可能误用的预设 |
| 命题主体或时间错误 | 1 | 用较早会话的证据写“当前正承受…”（时间范围错误） |

## 五、解释与边界

1. **本组状态没有改进空间**：在共享身份合同和明确交代“报告时间≠事件时间、计划≠已做”的记录投影下，Gemma直接回复已未违反任何冻结检查项。这与GSWS v3中A0的4条失败不同，但两者状态、渲染都不同；本轮没有“无记录说明”的消融，**不能**把这一可靠性归因于记录投影本身，只能列为待检验假设。
2. 也可能是助手选择的U/H状态与检查项对该模型不够难。归组标准与检查项都在预测前冻结，结果按实际报告，不因此改题重跑。
3. 因此G4**没有建立**专业语义能力的实际回复价值，也没有建立按需调用的收益；只确认了接口可在真实运行中稳定工作（0技术失败）及其真实代价。
4. 本轮不支持“继续训练T1i”：在实际系统形成的命题上，判断错误不是主要瓶颈。

## 六、对下一阶段的判断

- 不进入BC、价值学习或PPO；不接回SEARCH/EXPAND/STOP做动态实验——在固定证据条件下还没有可重复的能力调用收益。
- 应先研究：①证据接口（当前用户话语也给ID；引用问句与回答成对）；②**风险命题形成**：让系统写出“回复将要依赖、但记录可能不支持”的预设，而不是复述；③调用决策：仅在提示中暴露工具，Gemma不会自发调用，需要明确的决策机制或可学习的触发信号；④在确有改进空间的状态上评价（先用A筛出真实失败状态，再在独立留出状态上确认，避免按结果选题造成的乐观偏差）。
- G5（T1i再训练）维持暂缓；CPU准备已完成INLI官方测试集核查（未使用过；与训练集仅1个前提、8个假设重叠，去重后可作一次性确认评价）。独立来源扩充、四类错误对照与独立审阅尚未开始。
