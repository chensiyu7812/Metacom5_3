## 二、身份合同修正与G1

### 2.1 代码修正（`semcap/identity.py`）

- 原`attribute_history()`把外部案例中的seeker也标为user。现按情形给出说话人标签：A 当前用户／此前人类支持者（不是你）；B 当前用户／本AI此前回复；C 外部案例求助者（不是当前用户）／外部案例支持者（不是你）。新增`is_current_user()`：外部案例中的话语永不作为当前用户事实。
- 新增U（来源身份未确立）。`classify_source()`只依据宿主来源：ESConv→A；EvoEmo默认U（同一supporter角色不能证明是同一真实Agent），只有实验设计显式声明时才作为B，并标为`experimental_assumption`；部署日志绑定才是`host_provenance`的B。U场景下历史supporter话轮不作原生assistant，也不说“不是你”。
- 回归测试：`tests/test_semcap_identity.py`（7项）。三条通道的身份交付现状：Generator经`renderer.py`原生映射（A场景错误来源，见上一轮报告）；语义模块经`claim_support`/`evidence_state`以“the user / the supporter”交付，外部案例由`agent_skill`拒绝作为用户证据；Memory Writer（`ge2_memory`、`pomdp_memory`）只写裸`seeker/supporter`，尚未接身份情形——列为下一步接线项，不在本轮改冻结代码。

本地生成时间（每臂12条）P50/P95：冻结G0e 9.59/21.82 s，身份合同 9.60/14.25 s；合同使输入多约110–120 token，未增加等待。

判断：

1. 本模型在冻结身份下并不像10-19的P07那样第一人称认领；它的问题是另一种：原生assistant话轮里写着“我出过车祸”，回复却说“作为AI我没有出过车祸”，与自己“说过”的话矛盾；或把人类支持者的话当成自己的失言道歉。这正是“别人的话被当成自己输出”的结构后果。
2. 身份合同消除了“认领他人原话”，并在2/6中做出研究者要求的简短归属澄清；其余仍多是笼统AI声明。自然支持质量两臂相当（各5–6/6 adequate）。无误认时没有增加多余身份声明。
3. 样本为6+6，属于有限对照；结论是“合同＋正确角色渲染应作为后续所有方法共享的系统上下文”，不是语义能力突破，也不追改旧评分。B、C场景只做了CPU接口回归。
4. 两臂各1条“thought”思考标记泄漏，与GSWS v3的Q08同类，是解码/后处理接口问题，应在共同输出过滤中处理。

### 3.1 场景对话对照集DCS（弱监督，助手编写）

- 来源：ESConv训练家族（fold6封存；GSWS、event32、speaker32、G1家族排除），按加盐家族哈希先分train/dev（家族不相交，再选种子），共64个自然用户话语（train 48、dev 16）。
- 每个种子保留真实话语与前一话轮；助手编写最小语义变体（已做/没做/仍是计划/第三方做了/支持者建议），同一命题在不同证据下标注；含否定词却支持、无否定词却矛盾、主体互换、尝试≠结果、普通情绪状态；train另有23条、dev 6条“先计划后结果”的两会话序列；dev 73条同义改写用于一致性。
- 约定：事件命题问“截至最新证据是否已发生”，计划只给出not_established；意向/状态命题指最新报告。歧义格标`?`不用。
- 规模：train 312条，dev 152条（73对＋73改写＋6序列）。全部是助手在任何模型预测前写成的弱监督；自然话语、编写变体与序列分别登记来源；不是独立真人真值。
- 捷径对照：只看命题的TF-IDF逻辑回归在DCS-dev只有macro-F1 0.40（INLI-dev 0.68，说明INLI本身存在一定命题侧捷径）。

基座`cross-encoder/nli-deberta-v3-base`，实际`id2label`={0矛盾,1蕴含,2中立}，保留其NLI头并绑定为contradicted/supported/not_established（`evidence_state.HEAD`）。单一配置：2 epochs、lr 2e-5、batch 16、max_len 320、warmup 10%、seed 42；最终取最后epoch（运行前声明，未按开发集挑选）。A4500。

### 5.4 剩余错误（T1i，DCS-dev）

1. 主体互换判成矛盾而非未确认（如“朋友说她要离开丈夫”对“用户告诉朋友自己要离开丈夫”）：INLI矛盾假设常是角色互换，模型学到“互换=矛盾”。
2. 结果失败被读成尝试未发生（“试过了但没用”→“已经试过”判矛盾）：尝试与结果未分开。
3. 对问句的肯定回答中的计划未被判支持（“是的，今晚视频”→“计划今天视频”判未确认）。
4. 需要跨话轮指代的支持者自述（“我的家人在外州”中的“mine”）未被判支持。

## 六、主任务与MAVEN辅助任务的真实区别

- 主任务判断“给定可见证据，这个命题的信息状态”；MAVEN是“给定已标出的触发词，文本断言该事件的事实性”，前者有主体、证据范围和缺证据，后者没有。
- T2在相同主任务数据、相同调度下加辅助头：主任务DCS-dev 0.873（T1 0.878）、INLI-dev 0.949（0.951）、回归集相同；辅助头MAVEN internal_dev macro-F1 0.426（CT+召回.95、PS+.75、CT-.78、PS-.02、Uu 0），比冒烟“全判Uu”实际学到了主类，但PS-与Uu在√频率采样后仍只有240/101条，无法学会。
- 结论：辅助路线本轮无增量，停止，不阻塞Agent接续；“计划/未发生”这类事件阶段信息改由主任务的场景对照数据直接监督。

## 七、对Maverick与MiniCheck既有解释的纠正

1. 上一轮“只核对报告者本人话轮”只适用于“The seeker/supporter says…”这类明确自报型命题，命题主体来自构造好的命题字符串（条件化能力测试），不是系统从自然话语中自己形成的。事件主体判断不能机械地只读该主体本人的话轮：他人的合法报告与跨话轮上下文必须保留（如用户转述家人行动）。
2. Maverick在speaker32消除最后1条误支持，但支持召回1.00→0.875、Macro-F1 0.751→0.734，event32加入后还出现新的误支持；它是按需候选能力，不是每轮默认组件。
3. MiniCheck没有输出矛盾，不等于它掌握了矛盾与未确认的区分；本轮D组合在DCS-dev上也低于T0。

## 八、Agent接线（`semcap/evidence_state.py`、`semcap/agent_skill.py`）

- `INSPECT_CLAIM`动作：`{claim, evidence_ids, subject, time_scope}`；evidence_ids必须是Agent实际读过的合法观测（经`event_understanding.evidence_input`），未读ID拒绝；外部案例拒绝作为用户证据；会话序号由宿主按报告时间确定。
- 输出：judgement（supported / contradicted / not_established / implied / unprocessed）、概率、所用证据、逐条结果与冲突（同时存在支持与反对时保留双方ID）、未解决说明、成本（模型调用数，LLM调用0）。
- `revise()`：保留完整历史与转变（如`not_established->supported`），不删除、不按“较新即真”覆盖；理解修订与用户真实状态变化分开（时间范围由命题自身表达）。
- `generator_note()`：给Generator的简短注记（每条一行），代替512 token GSWS JSON。
- CPU机制演示（6条dev序列）：先只读会话1→全部not_established→补读会话2→全部正确转为supported/contradicted。由于这6条都需要补读，按需与固定策略都6/6，按需未省调用（含逐条冲突检查时调用更多）；**命题形成未测试**（命题来自助手编写），不是回复质量实验。
- 测试：`tests/test_semcap_evidence_state.py`（6项，含修订、冲突、未读拒绝、外部案例、动作模式）。
