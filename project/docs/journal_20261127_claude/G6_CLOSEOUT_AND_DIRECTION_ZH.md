## 二、对G4解释的纠正（接受）

1. A在G4为16/16无违反，但应当项只满足23/25，存在内容遗漏；“无违反”不等于交互目标完全完成。

3. C实现了一次LLM调用的直接回复路径；需要检查时的切换路径从未被验证。
4. T1i 41/48对T0 38/48是有限开发证据；命题形成、证据选择、分类器判断三类错误已分开报告。
5. G4与GSWS样本和上下文不同，不能认定身份合同、时间说明或记录组织已解决此前问题。

## 三、CPU准备

### 3.1 接口v2（`semcap/g6_context.py`，`semcap-g6-context-v1`；`g4_context`未改）

- 当前用户话语作为可枚举记录`U0`（用于命题形成与核验；Generator仍只把它作为最后一条原生用户消息）。
- 问答证据关联：引用回答时自动带上紧邻的对方问句，引用问句时带上紧邻的回答（宿主按记录顺序的确定性规则，记录`auto_added_ids`）。
- 风险命题形成：系统自己写出“回复可能想当然、但记录未必支持”的陈述；允许输出`NONE`；明确要求不复述无争议事实；ID只能来自枚举，非法ID丢弃登记。
- P与B′共享同一次命题形成输出与相同证据ID；B′只多出每条的T1i结果短语；NONE时P、B′提示与A相同，直接复用A的回复（不调用）。
- `evidence_state` v3：跨会话的支持/反对差异改名为`cross_session_difference`，语义为“可能是状态变化，也可能是历史报告冲突，不作判断”，不再暗示用户真实状态已改变（v2在G4中出现0次）。
- 测试：`tests/test_semcap_g6_context.py`（4项），连同既有semcap测试共26项通过；CPU演练覆盖继续、NONE复用、停止三条路径。

### 3.3 设计冻结（预测前）

- 48个状态按加盐哈希顺序自然抽取，不按难度人工归组（筛查用于测量真实失败基础率，不是寻找有利个例）。
- 每状态的“不得断言/应当”检查项、失败分类（事实与阶段、主体与时间、信息不足、重要遗漏、目标与支持需求、生成器使用）、门槛规则、留出方案与8对B′对A盲评状态均在预测前写入冻结文件（`g6_v1/G6_DESIGN_FROZEN_PUBLIC.json`）。
- 阶段审阅在同一Gemma进程内完成：筛查结束后进程保持加载并等待决定文件；决定文件必须携带审阅文件的SHA-256；等待时间计入2,400 s。

### 3.4 Memory Writer真实接线状态

- **已实现**：身份感知投影接口`g4_context.memory_record()`（speaker_label、situation、is_current_user、报告时间），只在G4/G6运行器中使用。
- **未接入生产写入路径**：`journal/ge2_memory.py:171`与`journal/pomdp_memory.py:174`仍以原始`speaker: exact_quote`写入，没有身份情形；仓库中没有任何生产模块引用`semcap`。二者不能混为一谈。

- 32条回复全部EOS结束（P50 7.1 s，P95 11.3 s），1条思考标记已过滤，0运行错误。
- 冻结“不得断言”项违反0。审阅中4条疑似问题回到记录核对后均有原文支持（如对方“有暴力倾向”、“市场饱和”、“家庭重视教育”、“英国等候名单”），不计为失败。
- 记录的问题：1条在丧亲回复中加入未报告的“漫长病程”（信息不足，轻微，不误导用户处境）；2条遗漏应当项（未回应用户自身的悲伤；未回应想与人相处的愿望）。目标/支持需求误解0，生成器使用错误0，身份冒认0（含多个“前支持者自我披露”状态）。
- 适合INSPECT_CLAIM修复的实质性失败：0个状态、0个来源家族。

## 五、解释与边界

1. 在当前共享身份合同与记录投影（明示报告时间、计划≠已做）下，G4（16）与G6筛查（32）共48个自然或按组抽取的状态中，Gemma直接回复都没有出现可由事实核验修复的实质性错误。对在线回复而言，INSPECT_CLAIM目前没有可证明的作用对象。
2. 不能据此认为：语义理解已解决；身份合同或记录组织已解决GSWS中的问题（无消融，样本不同）；T1i离线无价值；用户目标与支持需求理解已足够（遗漏仍存在）。
3. 局限：单一助手审阅，检查项也由助手编写，可能偏宽；EvoEmo owner重复；状态由固定规则抽取，可能低估更长、更复杂历史下的失败率。这些都不构成继续扩大筛查的理由（按指令不扩大）。

## 六、T1i的非实时价值（研究设计评估，不启动）

- 适合的位置：离线Memory Writer整理与历史语义整理——在把“用户已完成X”“用户现在仍Y”写入长期记忆前，用T1i在原文证据上判断supported/not_established/contradicted/implied；只有supported进入确定事实层，not_established与implied进入“未确认”层，跨会话差异保留为`cross_session_difference`，不覆盖旧记录；判断结果本身不自动写入确定事实库。
- 成本：CPU约60–100 ms/命题，不占用户等待。
- 评价前提：需要独立冻结的记忆审计集（含计划→结果、第三方、跨会话变化），以及独立审阅；目前未建立，不启动训练或GPU运行。
