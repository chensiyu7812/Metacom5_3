## 评价与普通 SFT 公平对照

`data/short_protocol.py` 提供无 gold 的 B 运行接口；`evaluation/short_mcq.py` 只接受单行 `Final Answer: A` 等。括号、裸字母、额外推理均拒绝；另记官方 parser 诊断，旧官方评分不变。WP3、跨模型和旧协议衔接按固定同题配对，保留结构性、技术失败、未执行、解析失败、有效错误、完成率、固定分母敏感性和 unknown 界限。代码和 `WP3_POLICY.json` 已冻结于任何新输出之前。

主 Qwen 六个预定差异、跨 G 三个差异、协议衔接四个差异分别处理 Holm；CI 按 owner/family 配对 bootstrap。5pp 实际意义和 −5pp 非劣边界不等于有足够功效：在 discordance=0.3 时，140 人的近似 80% 功效 MDE 约 13pp，60 人约 19.8pp。不得以不显著或 60 题排序相近声称等效。

U2/U3 共享 chosen 样本、输入、初始化、顺序、步数和 token cap。U3 加 `0.1 * softplus(0.5 - chosen_action_logp + incompatible_action_logp)`，仅作用于明确不相容的行为 token；不把其他合理自然回复当负例。U2 使用相同两个辅助前向/反向分支但系数为 0，梯度仍为普通 SFT，B 须保留实际计算以匹配成本。原生编码与梯度测试为 CPU 工程证据，不是模型能力。

开放评分要求两位不同评审对相同输出 hash 评分；分歧和未评保持 unknown。JSON action 对不代表自然回复成功；分别报告任务完成、适当使用、误用、必要澄清、过拒和自然质量。构造组与原 60 道自然 benchmark 开放任务不混总分。
