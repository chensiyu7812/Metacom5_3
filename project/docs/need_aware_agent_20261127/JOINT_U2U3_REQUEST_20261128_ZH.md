## 3. B 的审核发现（批准前需要知道）

1. **按现在的数据，U3−U2 这个主要比较基本测不出东西。** 排序项只作用于 2 行（0.9%）。30 步里最多 2 个累积组的梯度与 U2 不同，而且系数只有 0.1，会再被组内平均进一步稀释。所以 U3 和 U2 实际上几乎是同一次训练；结果不显著也不能说明“回复级排序监督无效”。原因是 A 只保留逐条核查过的非首选回复（官方错误选项在 review50 中只有 22% 可辩护），这个做法本身是对的，但让 U3 失去了作用。
2. **训练规模很小。** 只有 30 个 optimizer step、LoRA r8、lr 1e-4。这次能回答的主要问题是 U2−U0：回复级 SFT 是否改变同证据下的行为。
3. **训练提示与 MCQ 评测提示的版式不同。**
   - 训练用 `reply_protocol`：系统提示为通用助手，不带回忆后缀，不给选项；
   - W4-0 / W4-E 的 MCQ 沿用已冻结的 WP3 版式：情境系统提示 + 回忆后缀 + 选项指令；
   - 开放回复评测与训练版式相同。
   因此 MCQ 上的迁移效果会被这一差异削弱。这是有意保留的（MCQ 协议已冻结），报告时会写明。
4. **8.4k token 的反向传播耗时和显存都没有实测。** 每种方法 1,494 s 的上界是按 4 倍前向估算的。前 20 步烟测（占 30 步的三分之二）会实测；如果预测会超出上限，就停止并报告。
5. **研究者要求的 NoMem/OptOnly 训练后诊断，A 的候选没有包含。** 原话是“检查训练是否利用历史，而非仅学习选项风格”，只能在训练后的模型上回答。B 把它列为可以单独批准的小块（§5 W4-E-diag）。
