> # NAA v1.1 — B 工作线继续实施与真实运行指令
>
> ## 一、研究方向及最终系统边界
>
> 继续沿用 NAA v1.1 和原三个 RQ，不更名，不重新设计整体研究路线。
>
> 研究者已明确：第一篇期刊最终必须交付一条完整、可运行的文本型长期陪伴 Agent 链路，而不是仅仅提供一个记忆检索系统或微调模型。
>
> 最终链路：
>
> 当前用户输入 → 需求理解 → 按需获取 Memory/适用外部能力 → 适用性判断 → Generator 实际回复及帮助行为 → 历史记录与后续交互。
>
> WP3 是证据供给基础建设，WP4 是记忆理解与利用能力研究。两者最终服务于完整 Agent。
>
> 保留历史 MP/MS/ME、RS/Support Skills、GE2、Writer/Reader、PM Step-1/Step-2 及其已有实现，不恢复已关闭的同类策略卡扩充、同步 GSWS、在线 INSPECT_CLAIM、G7 或 PPO。

> ## 七、一次性修复训练执行器
>
> A/B 已确认以下问题成立。请直接修复并进行针对性真实 CPU/小模型回归，不扩大工程范围：
>
> 1. 在 LoRA adapter 创建之前固定 seed；U2/U3 初始 adapter hash 必须一致。
> 2. 采用 qv_all_layers：q_proj、v_proj、in_proj_qkv，r8、alpha16，覆盖 Qwen3.5 全部32层。两种方法完全一致。
> 3. adapter 权重、配置、基座模型、训练身份均进入生成器 g_id 和物理请求 hash；严禁 U0/U2/U3 之间错误去重复用。

> 5. 前20步技术烟测实际实现。只核验运行、显存、梯度、有限值、速度及预算，不根据开发准确率改变训练配置。
> 6. 完成 U2/U3 adapter 的真实评估 manifest 构造及严格身份验证。
> 7. 完成自然开放任务评价接口，不将构造任务的 action 评分直接套用。
> 8. 核实训练输入模板、结束 token 和推理输入一致。当前只训练 Qwen，Gemma 训练兼容问题保留记录即可。
>
> 旧21,600秒训练预算基于短模板数据，不再有效。采用 A 的真实新训练数据、native token 长度和实际训练计算路径重新核算。

> 优先复用既有模型、索引和证据物化资产。不能直接把82秒/题的 CPU 重排套用到4,000条训练数据上，造成长时间无效等待。

> ## 八、恢复完整 Agent 的实际接线准备
>
> 在 WP3/WP4 工作同时，进行最小化系统接线准备，而不是再开发大型独立模块。
>
> 复用历史 Agent/PrefixPort、Memory Writer/Reader、GE2 和 RS SkillRecord/METHOD/PROCEDURE 等已有资产。
>
> 最终应能够：
>
> - 根据当前用户请求决定是否需要读取长期历史。
> - 使用合法历史理解用户本人、第三方、过时信息和当前约束。
> - 在外部支持能力确有适用条件时，调用合法、已有资格的 RS/Support Skills。
> - 根据当前需求进行实际回复、建议、澄清或不干预。
> - 将当前交互保存到可追溯历史中，供后续轮次使用。
>
> 上述职责不要求每项都是独立模型，也不要求一律调用所有资源。
>
> 先保留简单规则、固定方案及基座自主选择作为强对照。学习式 PM 或序贯 RL 只在实际存在决策收益时再研究。
>
> RS 不强行加入 PersonaMem MCQ，也不声称已有稳定独立增量。只在确实适用的任务中验证 Memory、RS 和 Generator 的完整配合。
>
> 复用现有 J06 和开放任务资产，最终要能够展示并评估完整文本交互链路，而不只是选择题分数。
