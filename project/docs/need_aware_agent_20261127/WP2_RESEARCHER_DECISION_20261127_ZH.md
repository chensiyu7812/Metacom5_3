## 2. 修复已确认的语义问题

重点检查 memory/reader.py、memory/writer.py 和 agent/arms.py。

当前适用性指令中的“Statements by the user describe the user”存在明显问题。

例如用户说“我妈妈喜欢钓鱼”，不能推断用户本人喜欢钓鱼。

必须区分：

- 信息说话人；
- 实际事实主体；
- 偏好持有者；
- 用户自己的经历与第三方经历；
- 原始陈述与系统推断。

时间更新规则也不能简单地认为较晚陈述必然覆盖较早陈述。只有涉及相同主体、属性和适用范围的明确变化，才可视为潜在更新。

对于遗忘请求，当前5,130条候选仅有112条词汇关联，不能声称已实现正确遗忘。未确认的关联保持未知，不擅自删除原始证据；本轮只研究模型对合法历史中约束的理解，不将其称为已实现生产级删除功能。

修改必要的确定性语义规则及 D 的使用指导，不新增在线 LLM、T1i、GSWS 或复杂语义模块。

A/B/C/D 的研究构念不变。C/D 必须仍然使用完全相同的原始证据。修改后的请求重新绑定 hash，并保留原版 manifest。

## 3. 纠正实验条件名称

不改变现有四臂，不重新挑题，不新增无关基线。

## 4. 修复运行器的预算停止逻辑

ChatGPT 检查 runtime/runner.py 后发现，目前单个模型产生 stop_reason 时，可能直接 break 整个模型循环。

这会导致 Gemma 耗尽其独立预算后，Qwen 完全无法运行。

必须区分模型级停止与全局停止：

- 单模型时间、加载或局部连续失败达到上限：记录该模型的未完成任务，安全释放设备，继续另一个模型。
- 全局 GPU 时间、总物理尝试、设备安全或完整性异常达到上限：停止整个实验。

保留现有断点续跑、精确请求去重、不可变账本及失败记录。

验证单模型预算耗尽时，第二个模型仍能在自己的预算内开始运行。

同时检查时间账本、加载失败、在途请求、重试及 supervisor 退出路径，确保不会重置或突破预算。

## 5. 处理实际机器风险

根分区只剩1.4 GiB，不适合直接开始长时间模型运行。

先实际检查根分区、数据盘、缓存、临时文件、日志目录与 GPU 状态。

尽可能将本实验所有临时目录、HF cache、Triton cache、PyTorch cache 和运行日志放在数据盘。目标是让根分区有至少5 GiB左右的可用余量。

不得擅自删除其他项目、旧实验、模型、私人数据和系统文件。如果需要机器所有者进行清理，明确列出安全可处理的位置、大小与原因，交给研究者决定。真实存储安全检查不得被绕过。

不得停止或抢占其他 GPU 作业。

## 7. 实际执行，不增加研究门禁

两个模型各自首次加载时执行前16次技术烟测，重点确认：

- checkpoint 正确加载；
- native tokenizer 一致；
- 真实输入与冻结请求一致；
- EOS、停止条件和解码设置正确；
- 没有明显运行环境错误；
- 实际吞吐和显存使用可接受；
- 请求、输出、计时和失败账本完整。

Qwen3.5-9B 的 HF 推理路径尚未实际验证，应在它自己的首次加载时立即检查，不能等全部任务执行后才发现问题。

普通技术错误在本次授权范围内直接修复并继续。若修复会改变模型、输入、解码或实验构念，则必须保留旧结果、明确新身份，不能把不同实验结果混为一谈。

不要根据前16题的正确率调整提示词、选择模型或更改冻结条件。烟测仅用于技术验证。

烟测技术正常后，直接继续剩余任务，不需要逐批征求批准。

达到硬预算时停止，并保留完整未完成清单。不得自动扩容。
