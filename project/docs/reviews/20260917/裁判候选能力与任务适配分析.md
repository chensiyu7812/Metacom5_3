# 裁判候选能力与任务适配分析（2026-09-17）

**目标应是找到最适合本研究判定任务、并能负担后续标注规模的裁判配置。只比较两个便于本地运行的小模型，不能据此断言找到了最佳裁判。** Selene Mini 和 CompassJudger-2 仍值得保留，但需要加入不同能力路线的比较视角，并利用已有强模型 AI B 的结果。

本次核对了 12 个公开模型仓库的配置、版本和模型卡，并阅读相关原始论文。没有下载权重或执行新模型调用。[模型配置及版本证据](candidate_capability_metadata.json)可核查来源；这是文献与接口适配判断，不是这些模型在本项目上的实测排行榜。

## 我们究竟需要裁判判断什么

PM 需要的监督是：在同一任务状态下，打开某项资源是否带来 **task-defined material positive effect**。对应的裁判必须结合任务、历史与参考，判断两条回答是否存在实质差异。四类含义仍由现有 V2 instrument 决定。

| 需要的能力 | 本研究的具体检验点 | 单看哪些指标容易误判 |
|---|---|---|
| 证据与事实核查 | 能发现突然出现、历史不支持的 dog；区分分手与关系加强；未知信息不能编成用户记忆 | “回答更完整”、泛化的 helpfulness 排名 |
| 实质差异判断 | 两种都合理的支持方式，若缺少用户偏好证据，不能只按直接建议、篇幅或措辞强行分胜负 | 普通 A/B 偏好准确率 |
| 相当与不确定的区分 | 能依据现有规则区分无实质差异与证据不足；不能把两次判断矛盾自动当作相当 | 总同判率、总 tie 比例 |
| 长历史与时间关系 | 读取完整严格过去历史，正确对应人物、事件、当前状态和信息来源 | 配置中写着 128K 或 256K |
| 任务适应能力 | QA 的语义正确性，Summary 的事件覆盖与不虚构，ESC/DG 的情境适当性均须处理 | 数学、代码榜单或单一情感支持榜单 |
| 稳定与可复核性 | 交换回答顺序后判断一致；理由确实对应证据；输出完整可解析 | 只看最终 verdict、忽略理由与失败 |

原始 A 的 80 个 base 中有 56 个 equivalent，恒定回答 equivalent 就有 70% 同判率。因此已有原始 A、六题复核和事实敏感性视图都要保留，不能按总 agreement 选模型，也不能追求裁判复制所有原始 A 的错误。已有 AI B 的理由和判定很有价值，应继续作为强模型探索性参照。

**缺少用户偏好时，模型更强也不能凭空补出偏好。** 当前 MP 是稳定画像，不包含回复偏好。对这类题，合理的裁判行为是按现有任务标准处理不确定性和实质差异；不能把“更会猜评审喜欢什么”当成判定能力提升。

## 候选模型的能力与缺口

以下“建议位置”是本次资料分析的推断，不是已测得的优劣顺序。

| 候选 | 公开能力证据 | 对本任务的主要缺口 | 建议位置 |
|---|---|---|---|
| [Selene Mini 8B](https://huggingface.co/AtlaAI/Selene-1-Mini-Llama-3.1-8B) | 同时训练绝对评分、分类和 pairwise；有自定义标准、事实性与格式变体评测 | 原生 pairwise 模板仍要求选 A/B；没有本研究四类和完整 DG 历史的验证；与 Generator 同属 Llama 家族 | **优先保留：可按 rubric 调整的专用裁判** |
| [CompassJudger-2 7B](https://huggingface.co/opencompass/CompassJudger-2-7B-Instruct) | 多领域数据与可验证奖励训练，保留较好的通用能力；JudgeBench 等结果有优势 | 原生示例为 A/B；32,768 配置窗口对最长题的输出余量需精算；其 JudgerBenchV2 参考含模型多数票 | **优先保留：跨任务判别型专用裁判** |
| [Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B) | 通用推理、指令跟随和长文能力；官方报告 IFEval 91.5、LongBench v2 55.2；支持 thinking 开关 | 这些不是裁判成绩；需要单独固定推理预算、适配新架构的 serving，并验证四类判定 | **建议加入：同一硬件范围内的通用推理对照** |
| [RM-R1 DeepSeek-Distilled Qwen 14B](https://huggingface.co/gaotang/RM-R1-DeepSeek-Distilled-Qwen-14B) | 先建立评判依据再比较回答；有推理轨迹蒸馏与 RLVR，已公开权重 | 训练和示例偏 A/B，输出预算较长；自行生成的标准可能偏离我们的 materiality 定义 | **推理型专用裁判备选** |
| [M-Prometheus 14B](https://huggingface.co/Unbabel/M-Prometheus-14B) | 多语言直接评分及 pairwise，论文覆盖 20 多种语言 | 论文训练序列上限 4,096；长历史迁移需验证；当前机器输入为英文，多语言优势不是首要瓶颈 | 中文评审或翻译敏感性扩展时更有价值 |
| [RISE-Judge 7B](https://huggingface.co/R-I-S-E/RISE-Judge-Qwen2.5-7B) | SFT+DPO 改善偏好判断，训练中交换顺序降低位置偏差 | 原生二选一；通用正确性和四类迁移仍需验证 | 备选，现有资料未显示必须优先于 Compass |
| [Skywork-Critic 8B](https://huggingface.co/Skywork/Skywork-Critic-Llama-3.1-8B) | 专门针对 pairwise 偏好和细微错误的训练 | 原生二选一；模型卡的领先表述有 2024 年时间范围；不能当当前四类最佳证据 | 历史基线或备选 |
| [GLIDER](https://huggingface.co/PatronusAI/glider)、[Flow-Judge](https://huggingface.co/flowaicom/Flow-Judge-v0.1) | 小型、可定制评分；GLIDER 支持 RAG/对话与证据解释 | 模型卡支持范围主要为 8K；GLIDER 称测试至约 12K，Flow 明确披露长文训练不足；均低于本项目最长输入 | 短题可研究，暂不作为覆盖全部 DG 的首选 |
| [Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B) | 较新的通用推理模型，支持可控 thinking 与长上下文 | 没有本任务裁判证据；完整 BF16 权重下限超出单 A6000，需量化、多卡或卸载配置 | **能力扩展候选，不能因运行更复杂就断言小模型更适合** |
| [CompassJudger-2 32B](https://huggingface.co/opencompass/CompassJudger-2-32B-Instruct)、[Selene 1 70B](https://huggingface.co/AtlaAI/Selene-1-Llama-3.3-70B) | 同系列大模型有更强或更广的公开评估结果 | 完整 BF16 权重明显超出单卡；量化后的精度、长输入余量与成本尚未实测 | 大模型扩展候选，不把原始权重成绩套给量化版 |

Selene 的实用价值还在于其[原始论文](https://arxiv.org/abs/2501.17195)测试了对话是否有足够信息支持结论，以及是否覆盖相关历史。这类能力比单纯比较回答长度更接近我们的证据判定需求；医学数据上的表现本身不构成情感支持有效性的证明。

Compass 的[论文 Table 2](https://arxiv.org/html/2507.09104v1#S3.T2)报告 7B 的 JudgeBench 为 63.06，而同表 RISE 7B 为 40.48；同文 JudgerBenchV2 使用多个强模型的多数票作为参考。这支持保留 Compass 的选型优先级，也说明不能把该成绩直接称作人类一致率。Selene 与 Compass 的论文日期、任务和统计口径不同，不能拼接两个总分来认定胜者。

[RM-R1 论文](https://arxiv.org/abs/2505.02387)支持把推理能力纳入候选筛选，但其自生成 rubric 不能替代我们的冻结标准。[J1](https://arxiv.org/abs/2505.10320)也研究了推理与换序稳定性；其部分实验把翻转和同分作为一个诊断量，而本研究必须区分两者。本次检索没有确认到可直接绑定的作者官方 J1 权重，暂不列为可立即运行的候选，这不等于断言不存在。

## 专业领域模型是否更适合

[ESC-Judge（EMNLP 2025）](https://aclanthology.org/2025.emnlp-main.811/)提供了很有价值的领域依据：应检查用户是否准备好接受建议、是否尊重自主性，以及支持方式是否适合当前阶段。它能帮助解释为什么“更快给建议”不必然更好。

但该论文使用的是 o1-mini 加领域 rubric 的评估框架，并非已验证可直接下载的统一裁判权重；其 agreement 计算排除了 tie，换序冲突也被合并为 tie。[论文第 3.4 与 4.3 节](https://aclanthology.org/2025.emnlp-main.811.pdf)的这些做法不能直接移植为我们的 equivalent 标签。它也不覆盖本研究全部 QA/Summary 任务。现有官方 ESC-RANK 继续承担官方评测角色。

2026 年的 [Outcome Accuracy is Not Enough](https://arxiv.org/abs/2602.04649)直接研究了“结论对了，理由却没有找对问题”的现象，支持我们检查证据与理由，而不仅统计 verdict。[Small Language Models as Judges for Rubric-Based Reinforcement Learning](https://arxiv.org/abs/2608.30005)展示了小模型 probe 的可行性，但任务是逐条 rubric 满足性，迁移到本研究需要新的监督和验证设计，当前不能将其当作现成四类裁判。

## 强通用 API 模型应放在哪里

**这次 Flash-Lite 的不适用，不能推广为整个 Gemini 家族或强通用模型不适用。** 强模型应进入能力参照范围；已有 AI B 可以先承担探索性比较，不需要为了增加模型名称而重复同一份工作。

若进一步需要可复现的强模型对照，应从实际可用的 API 型号中固定一个，而不是写“ChatGPT 网页版”或模糊的家族名。现有 [Google 官方模型与费率](https://ai.google.dev/gemini-api/docs/pricing)列有 Gemini 3.1 Pro Preview 与更新的 Gemini 3.8 Flash；[Anthropic 官方目录](https://platform.claude.com/docs/en/models/overview)列有 Claude Opus 5、Fable 5.1 等推理模型。这些是截至查阅日期的供应商定位，不是本研究中的优劣证明。当前没有调用这些模型，也没有检查账户对各型号的访问权。

付费强模型是否承担大批量标注，还取决于全流程可承受成本。以平均每次 6,000 输入、2,000 输出 token 的**假设**为例，按 Gemini 3.1 Pro Preview 的 Standard $2/$12 每百万 token，160 次约 $5.76；若平均输出含 thinking 增至 8,000，则约 $17.28。这里只是说明量级，未计重试、并非 provider countTokens 上界或预算申请，也没有用折扣扩大现有授权。当前 qualification 的 $0.10 和 formal residual 的 $2 均不足以自动涵盖这种扩展；不能占用后续研究预算后再补授权。

更有实际价值的安排可能是：强模型用于有限适用性参照，获得支持的本地裁判承担规模化判定；也可能某些任务只能使用强模型。须根据本项目结果决定，不能提前把前者写成已经成立的架构。

## 对下一轮比较的建议

`PROPOSED RESEARCH CHANGE — NOT AUTHORIZED`

建议把上一版“只测 Selene 与 Compass”的范围，调整为**先比较三条具有不同优势、面向本地部署的路线**：Selene Mini 8B、CompassJudger-2 7B、Qwen3.5-9B。RM-R1 14B 是有明确理由的推理型备选；Qwen3.8-27B、大型专用裁判和一个强 API 型号保留为能力扩展选项。这里的先后是以公开证据、适配成本和已有预算为依据的选型建议，不是模型能力排名。

1. 复用同一批 80 base 与双顺序材料，三名候选若各测 160 次，就是 480 次本地判定。现有 A、六题复核和 AI B 继续使用，新增人评为 0。当前只准备了前两名的 320 条旧提案请求，第三名尚未形成可执行调用包。
2. 固定相同的语义标准、证据、题目和分析计划；分别绑定原生 chat 模板、推理开关及合理输出预算。**不能用 256/1,024 token 的统一短输出帽就宣称比较了所有推理模型的最佳能力。** 最终给人的简短依据，与模型内部推理预算要区分；适配和 schema 验证用独立格式夹具，不能根据这批参考答案反复改语义提示。
3. 沿用原有 task-wise 比较顺序，检查各类召回、类别样本数、缺失、事实依据和换序稳定性。既要避免乱分胜负，也要避免所有题都回答相当。若两种顺序冲突，应保留不稳定诊断，不能未经新协议就生成 equivalent 标签。
4. 看完预先固定的一轮后报告任务适用范围；不能按 ON label 数或 PM 最终表现选择裁判，也不自动选一个“相对最好但仍不适用”的模型。必要时才提出有界的能力扩展，并说明增加哪个候选能解答什么不确定性。
5. 当前 80 base 已用于测量开发，不能声称其重新变成未知测试集。teacher 与后续 outer evaluation 的隔离决策仍要解决；这种局限不靠换更大的模型自动消失。

本提案改变候选数量、第三名 serving 配置和推理预算设计；理由是检验专用小模型与通用推理模型的实际适配差异。旧 Gemini 和两候选准备记录不失效；若采纳，只运行新批准的配置，不重做人评或 Generator。PM 主张与官方评测层级不变，不打开 outcome locks。具体 token 上界、时限、运行器与费用需在执行前绑定；前一版“两模型、4 小时”上限不自动扩展到新方案。

这一步的完成标志应是：能够说明选中的裁判配置在哪些任务上有证据支持、理由是什么、局限在哪里，并据此进入 amount/top-k 校准。文献调研能缩小候选范围，最终适用性仍需要本项目材料上的固定比较来判断。
