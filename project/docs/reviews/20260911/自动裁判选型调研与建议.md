# Paper-1 自动裁判选型调研（2026-09-11）

有可复用的专用裁判权重。建议优先比较 **Atla Selene Mini 8B 与 CompassJudger-2 7B**，M-Prometheus 14B 作备选，保留当前 Gemini 候选作为对照。第一步使用冻结权重和任务适配，不用现有 96 题微调。现有人评的作用是检验裁判在本研究中的可靠性。

这是依据论文、模型卡、原作者模板和实际输入长度得到的选型建议，**没有在本项目上运行这些模型，不能宣称其中任何一个比 Gemini 更准确**。没有发现已核验、可原样覆盖本研究全部四任务和四类判定的现成裁判。推荐顺序是试验优先级，不是实测准确率排名。

## 咱们需要测量什么

当前四头预测固定生成栈下、单一资源 ON 相对 OFF 的 task-defined material positive effect。裁判必须只看匿名回复和获准上下文，区分 `A_better / B_better / equivalent / uncertain`。成本不进入质量判定；更多共情、建议、个性化或记忆提及本身不加分。

人评共 80 个基础 pair、16 个反序，两人各 96 次呈现；192 次主评不是 192 个独立训练样本。DG 的 27 个基础 pair 共享九个情境。当前 Gemini 是尚未通过本项目人评验证的候选，而非已经证明可靠的裁判；原计划也没有从零训练裁判。

官方能力评测与 effect teacher 各有职责。仓库已经接入 `internlm/internlm2-chat-7b` 加 `haidequanbu/ESC-RANK` 七个英文 adapters。它本来就是基于人评训练的情绪支持领域评分器，继续承担 RQ1 官方评分。新选 teacher 不替换官方 ESC-Eval / ES-MemEval 指标，也不把二者的角色合并。[ESC-RANK 模型卡](https://huggingface.co/haidequanbu/ESC-RANK)、[ESC-Eval 论文](https://arxiv.org/abs/2406.14952)

## 与研究领域最相关的论文

**ESC-Judge（EMNLP 2025）**直接研究情绪支持的成对比较，基于 Hill 的 Exploration–Insight–Action 规则，实际判卷模型是 o1-mini。其约 83%–86% 的粗维度人类匹配率排除了 ties；反序冲突被合并为 tie，格式失败另有剔除。这些处理不能原样移植到需要区分 equivalent 与 uncertain 的本项目。适合参考维度设计和成对比较方法。[论文 §3.4、§4.3](https://aclanthology.org/2025.emnlp-main.811.pdf)

作者仓库除 API 判卷脚本外，当前还包含 Llama-3.1-8B / Gemma-3-4B 的蒸馏训练脚本；本次检查未找到作者明确链接、完成同等验证的情绪支持 judge checkpoint。因此可以参考蒸馏实现，不能把原论文一致率归到这些未验证的蒸馏模型上。[原作者仓库](https://github.com/navidmdn/ESC-Judge)

**EmoHarbor（2026）**强调通用共情与贴合具体用户需求之间的差异，对咱们“记忆提及不自动等于收益”的构念有参考价值。但其用户内部状态模拟和多代理评价属于另一套测量协议，不能把模拟出来的隐含想法作为本项目的真实参考。[论文](https://arxiv.org/html/2601.01530v1)

**An Empirical Study of LLM-as-a-Judge（ACL Findings 2025）**在其研究设置中发现，专门微调的裁判可在域内得分高，却在泛化、公平性、适配性上弱于 GPT-4。这不证明所有小裁判都差，但说明模型卡排名不能代替本任务验证。[论文](https://aclanthology.org/2025.findings-acl.306/)

**RewardBench 2**新增 Factuality、Ties 等测试，适合作为外部可靠性证据。其 Ties 评估多个正确答案的分差结构，不等于直接测试本项目的 equivalent/uncertain 四类判定。[数据卡](https://huggingface.co/datasets/allenai/reward-bench-2)

另检索了 Kardia-R1、OpenRS、EMPATH 等近期工作：前者主要训练支持回复模型，后两者分别是 rubric/RL 框架与危机场景审计框架；均未提供可直接替换本项目全部 teacher 角色的已验证权重。它们可进入相关工作讨论，不应仅因涉及情绪支持或 judge 就引入现行实验。[Kardia-R1](https://huggingface.co/papers/2512.01282)、[OpenRS](https://arxiv.org/abs/2602.14069)、[EMPATH](https://arxiv.org/abs/2606.30256)

## 实际发现的接口问题

**不能直接照抄官方二选一模板。** Selene 官方 pairwise 模板明确要求 “Do NOT say both / neither are good.”；CompassJudger-2 的公开示例仅接受 A/B。适配时必须保留本研究四类含义，不能在模型强行选完赢家后，靠字符串转换制造 equivalent/uncertain。提示词适配是否奏效仍需实测。[Selene 模板](https://github.com/atla-ai/selene-mini/blob/418c5ce2d8c4d89c5bd971ce60c7589eb8f9d8de/prompt-templates/pairwise.yaml)、[CompassJudger-2 示例](https://huggingface.co/opencompass/CompassJudger-2-7B-Instruct)

**长历史不能静默截断。** 我用三个 checkpoint 自带分词器，对现有 V2 96 个请求的共同四类提示词进行了长度预检，仅分词，未推理。保留全部参考与回复，外层使用各模型 chat template：

| 候选 | checkpoint config 上限 | tokenizer 声明上限 | 本卷最大输入 | BF16 纯权重理论 GiB |
|---|---:|---:|---:|---:|
| Selene Mini 8B | 131,072 | 4,096 | 25,653 | 14.96 |
| CompassJudger-2 7B | 32,768 | 131,072 | 25,817 | 14.19 |
| M-Prometheus 14B | 32,768 | 131,072 | 25,817 | 27.51 |

上述 config 与 tokenizer 不一致是实际文件检查结果。Selene 的 32 个 DG 输入都超过 tokenizer 声明的 4096。三者在模型 config 长度上均能容纳此次输入和示例性的 1024-token 余量，但这不是完整 serving 验证，也不证明长文判断准确；1024 只是长度余量示例，没有修改当前输出上限。显存数仅由参数数 × 2 bytes 计算，未含 KV cache、激活和引擎开销，不能当作实测峰值或速度保证。

证据：同目录 `context_length_preview.json`、`check_context_lengths.py`、`sources/candidate_metadata_summary.json`。模型文件原始 revision 和分词器哈希均已记录。分词脚本没有读入任何已填人评分数。

## 建议怎样推进

1. **人评继续用现有 V2，无须因选型重做卷子。** 两名主评及共识先封存；候选不看人类答案。
2. **预先限定首轮候选为两个本地专用模型，加现有 Gemini 对照。** 固定模型 revision、同义任务 rubric、全部 reference、A/B 呈现、解码及 parser，先做长度/字段/匿名化检查。不给候选各自改变质量标准的自由。
3. **首轮不微调、不用本卷作 few-shot。** 两个本地模型各评现有 96 presentations，共 192 次拟议本地判卷；现有 Gemini 仍按其既有预算和独立调用授权执行。这些均尚未运行。完整候选模型/适配流程必须在看人评结果前固定，防止根据答案挑提示词。
4. **按现行标准报告，而非追求统一高分。** 分任务/类别查看人类一致性、equivalent recall、uncertain 与解析失败、反序稳定性、位置偏好、覆盖和费用；错误实例关注编造/过时记忆、无必要干预及表面措辞偏好。报告所有预先指定候选，不能按 ON 率、PM 表现选赢家，不新增任意准确率 PASS 门。
5. **承认样本的用途和分组结构。** 此卷适合资格审查和探索性比较；若用它选赢家，其被选中后的同卷得分不能宣称为独立泛化估计。反序属于同一基础 pair，DG 共享情境及 memory owner 需要成组处理。
6. **只有发现明确、可修复的系统性错误后再考虑轻量微调。** 此时另设按用户/情境隔离的开发数据与验证数据，保留完整四类支持与人工理由。LoRA/SFT 技术上可行，但当前 80 基础 pair 加重叠情境不足以同时承担训练、反复调参和有说服力的独立验证；这里不是声称存在固定的最小训练样本量。

如果候选在 DG 上不可靠，就按已冻结的回退规则保留 uncertain 并缩窄可识别标签范围。不能因为换了现成权重就把所有问题都强行自动化。事实核查辅助模型也不能过滤 Generator 的真实 non-use/misuse/harm 样本。
