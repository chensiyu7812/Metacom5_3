# PM-RL1：RS、记忆组织与后续执行

2026-11-15。承接[研究审计与路线](../pm_rl1_research_audit_and_route/REPORT_ZH.md)，本文件记录用户接受该路线后的具体设计及离线准备。当前目的仍是：让冻结的 G 按需获得有价值的外部依据，由 PM 决定是否读、读什么、读多少、何时停止，在当前支持回复的质量、误用和实际等待之间取得更好的取舍。

## 1. 最关键的判断

RS 暂时没有收益，不能只靠继续换提示、换裁判或增加 PPO 更新来解决。应当先确定：提供的资料是否包含当前判断所需的具体依据，G 能否准确使用这些依据，以及帮助性评价能否辨认变化。个人记忆也走同一条链，但它与通用方法的增量来源不同。

“外部资源要补 G 本身欠缺的东西”是正确的研究方向，但不必证明某句话绝未出现在预训练里。我们能操作化检验的是：**在相同 G、基础指导和当前前缀下，取得这份具体资料是否增加了可用依据或可靠的执行能力，且优于把紧凑的通用指导直接常驻。**外置文件只是存储位置，不是增量价值的证据。

- 用户过去发生过什么、某项建议尝试后本人如何反应，通常是当前前缀没有的个体信息。
- “多共情、少说教”等通用指导可能已被 G 掌握。如果固定常驻即可达到同等效果，应纳入共同基础指导，而不是继续要求 PM 为它付出检索成本。
- RS 可以提供具体适用条件、行动过程、例外与失败案例，帮助 G 在含糊情境中作出更可靠的选择。是否真正补足能力必须实验确认，专业出处本身也不能保证增益。
- RS 与记忆可能互补。例如原文只支持“用户明确不喜欢画画”，就应避免重复该建议；不能扩大成“用户排斥所有创作活动”。方法资料负责说明如何协商其他支持方式，不能替代用户事实。

这不是预先决定四个资源头都要为正，也不是放弃 RS。研究要发现它们何时有用、何时无用、何时误导，以及 PM 能否据此减少不必要的获取。

## 2. 一套来源，四种职责

建议分为四层：不可变原始来源 → 带时点与出处的类型化视图 → 所有方法共享的检索与交付 → PM 获取、STOP 后 G 回复。原始来源和派生视图分别版本化，不再将四类资源维护成互相矛盾的独立知识库。

| 资源 | 存什么 | 必须保留的证据 | 不应混入 |
|---|---|---|---|
| RS 方法 | 适用情境、可选行动、限制、依据原文与审查状态 | 章节/段落、原适用领域、解释与原文的区别 | 模型自己写的专业结论、对目标用户的未证实心理判断 |
| RS 案例 | 完整先前情境、连续支持行动、紧随其后的用户反应 | 原对话/视频家族、原标签、反馈作用范围、未知项 | 只截一句“好回复”；把后续反应当某一句话的因果疗效 |
| MP | 截至当前切点有效、相对稳定的个人事实 | 原话、说话者、时间、槽位版本、冲突/更正状态 | 暂时情绪；从“提到过”推导喜欢；最终 profile 倒灌过去 |
| ME | 事件、经历、行动与主观反应的时间线 | 谁、何时、何事、建议/意向/已尝试/自报反应/未知 | 把“打算做”写成“做过且有效”；无依据的长期因果效果 |
| MS | 完整、严格过去的原始会话 | 原轮次、原文、owner、来源时点与哈希 | 冒充完整会话的摘要、拼接片段或固定窗口 |

### 2.1 RS 按“方法—案例”两层存储

方法和案例是关联实体，不要求一条 ESConv 策略标签恰好对应一个已验证方法。方法可以关联多个正向、无变化或不良反应案例；案例也可能包含多个行为。只有存在依据时才建立关联，AI 推测保持待审。

方法最小字段：`method_id / source / source_span / source_domain / applicable_cues / options / limits / evidence_status / review_status`。

案例最小字段：`case_id / source_family / split / complete_prior_context / contiguous_supporter_block / following_seeker_block / original_labels / turn_feedback / dialogue_feedback / outcome_unknowns / method_links / review_status`。

案例反馈不是收益标签。ESConv 的连续多轮 supporter 行动会共同影响下一次 seeker 反应，因此保留整个行动块；会话总体评分、即时 feedback、自报改善分栏，绝不相互替代。目标前缀自身的未来回复与反馈禁止进入资源；其他合法训练案例的后续观察可以作为案例内容，但必须排除目标同源对话、种子、改写及视频家族。

第一批优先使用完整 ESConv train 案例验证交付结构，用 AnnoMI 的行为标注辅助检查示范，再用有出处的窄方法补充条件与边界。不能将这三者合称“已验证专业疗效库”。[AnnoMI 作者仓库](https://github.com/uccollab/AnnoMI)与[SAMHSA TIP35 第3章](https://www.ncbi.nlm.nih.gov/sites/books/NBK571068/)提供的是不同证据层；TIP35 的原域是物质使用治疗，转用于一般情感支持需要明确限定。

机制实验 C 直接提供完整方法/案例组合，先检查资源有没有用；这不是自动检索成绩。自动阶段 E 优先保持 `GET_RS` 一个动作，方法和案例作为 RS 内部类型。第一版以来源完整的单元交付，并使用统一的、确定性的组装规则。若方法与案例打包为一个获取单元，必须在 manifest 冻结组成、去重、排除与成本，所有策略共用。不能给 PPO 自由拆包却让 OneShot 只读大包，也不能靠人为碎片化制造顺序收益。

### 2.2 MP、ME 是工作视图，MS 是原始依据

MP 的“当前有效”要按目标时点投影，不能简单取全局最后一条。确有更正才替换旧值；不确定或冲突保留其状态。显式的回应偏好可以作为带来源的经历/约束保存；不能从一次拒绝某建议推出永久人格特质。

ME 不限于应对方法或成功经历。它必须涵盖关系变化、事件、目标、限制及行动阶段。对同一行动分开存储 `suggested / intended / attempted / self_reported_response / unknown`，允许这些记录关联但不自动升级状态。主观报告仍是主观报告。

工作视图必须让读者理解其命题：补足说话者、对象、必要指代和前提；不能默认“命中句前后各一轮”总是足够。已有 T06 漏掉修车先行词就是反例。无法确认语义完整时，保留不确定性，并允许通过 `GET_MS` 获取完整会话；获取需真实计时、计 token。**当前 GET_MS 只取该头排名首项，尚不保证定向返回已读条目的父会话。**父文优先/扩读规则需在共享检索适配器中定义、冻结并用于全部策略，不能绕过共同排序。父会话链接只能来自已经取得的材料或检索器内部来源关系，不能向 PM 免费暴露未读正文。

同一来源可能同时支持 MP 与 ME，但同源不等于重复。精确重复的同一命题可标识关联；不同时间状态、不同约束和上下文不能仅因共享父会话而删除。原始来源永远保留。当前语义中，已取得正文全部交给最终 G，不能暗中丢弃、退还成本或以摘要替代完整 MS。

## 3. 检索、PM 和 G 的职责边界

检索器负责“在合法来源中找候选”，PM 负责“值得再取得哪类信息、是否停止”，G 负责“根据已经交付的依据回答”。三个问题分别测，不让 PPO 负责掩盖检索漏召回或 G 不会使用证据。

当前实际代码 `OrganizationCatalog.rank` 使用词集合重叠；BGE 已用于状态编码和某些 QA 实验，不代表已接入这个主检索路径。因此下一版需要明确的共享 BGE 适配器及独立身份，对照现有词重叠基线。

共同约束：

1. 先按 owner、时点、split 和来源家族过滤，再排名。所有策略共用同一候选库、同一查询构造与排序规则。
2. 第一版沿用固定 BGE，不同时训练新检索器。查询只取当前公开前缀及已经取得的正文。可评估保留原查询的分数融合来减轻读入内容后的主题漂移，但必须先固定并对所有方法相同。
3. 离线预编码可用于检索器内部索引；未取得候选的正文、向量、正确答案、实际收益与私有 ID 不进入 actor/critic Observation。内部 receipt 可保留 ID 用于审计。
4. 继续使用 `STOP / GET_RS / GET_MP / GET_MS / GET_ME`。不重新引入任意 top-4、最多四次 GET 或 2048-token 限制；合法性由冻结的新接口和模型原生上下文决定。若下一完整单元无法交付，如实记录不可行，不偷偷截断或跳到对某个方法更有利的单元。
5. 每次 GET 记录查询身份、实际正文及哈希、获取后状态、原生 token 差、检索/编码/控制器时间。GET 不调用 G/J；STOP 后仅生成当前一次回复，缺失评分保持 pending。
6. NoText 若只遮住 PM 正文而共享检索仍用已读正文，只能解释为控制器正文消融；系统是否需要更新查询须另设固定查询对照。

最少代码改动集中在资源视图编译器、共享检索适配器、renderer schema 和反馈连接。现有环境、缓存与恢复、BC/PPO、OneShot 程序接口继续复用。OneShot 搜索预算仍需冻结，不能称其当前候选搜索为穷尽最优。

| 版本换了却沿用标签 | 用本轮版本表精确连接请求、实际回复和评价 | 能精确复用才复用，改变输入/G只重算受影响项 |

目前不应再开启泛化的“找新裁判”“换一批短策略”“多训几轮”竞赛。新工作必须对应上表一行，写明将区分哪两个解释，以及什么结果会改变下一步。

## 5. 按什么顺序推进到研究完成

### 第一段：把可运行的同版本实验包收口

完成来源审查与方法候选，逐项对应现有记忆缺陷；登记目标前缀的来源家族和暴露；绑定一个开发 G、renderer、资源版本。建议先复用已实际运行的 Gemma 候选减少集成，但不得在比较资源结果后按“谁的RS收益大”挑 G。正式主 G 仍按基本支持能力和部署条件选择、冻结。

将12开发前缀与24诊断前缀按生成前可见的线索选定，保留普通情境与不同资源可能有用的情境；候选场景不是已知正收益样本。历史不足的条件标不适用，不能造数据填满。每个目标排除同源案例，明确是否有独立确认来源。八个条件最多288个生成位置是工程预算，不是统计功效保证。

在新生成之前完成配对盲评协议，固定帮助性实例锚点、主要比较、最小有意义差异、分组统计、多重比较、不确定处理与补测上限。机器生成判断与独立人评分开；不得由本轮助手自己生成资源、自己判好，再称已有独立证据。专业方法审查与普通帮助性评审职责不同。

### 第二段：只做一次完整的资源机制诊断

八个条件保持原方案：B无可选资源；F全部紧凑方法常驻；R直接提供完整RS；M相关个人历史；MF历史＋常驻方法；MR历史＋完整RS；D_R同话题不适用RS；D_M同owner其他话题历史。所有条件共用同一基础支持指导。

七项预定比较为R/B、R/F、M/B、MR/M、MR/MF、R/D_R、M/D_M。资源选择与适用性判断先于生成，不根据回复好坏挑资料。每个实际回复同时记录：资料是否包含所需依据、是否正确采用、是否帮助当前用户、是否引入误用、生成与完整路径时间。相关性或引用次数不能替代帮助性。

24诊断前缀的七项比较最多168对；若每对两位独立评审为336次判断。按每次2–5分钟估算约11.2–28小时，不含校准、专业审查及争议处理。可在实际可用人力下缩减预定比较或采用先校准后固定分配，但必须在生成/解盲前改清单，不能事后只评看起来赢的条件。自动裁判可减少工作，尚未核验的裁判不能被当作免费可靠人力。

### 第三段：修一个已定位问题，再测自动检索

若完整资料本身不足，修资料；若资料充分但G误用，做条件监督；若判断分歧来自量表，修锚点并保持原回复。根据明确证据修主要问题，不把三个模块同时换掉后丢失归因。新来源材料用于确认，旧样本仅证明开发修复。

随后把手工直接提供换成共享检索，测正确证据是否找得到、有效程度保留多少、额外等待多少。确认材料若不足，明确完成组外开发验证并继续补源，不能把“暂缺独立确认”伪装成已完成正式泛化。

### 第四段：训练选择器，再回答顺序和RL问题

用同版本、实际测量的资源结果表训练Fixed/规则、OneShot和BC；成本与质量分别记录。没有测量的状态/计划不填零。若使用有限人工终值表进行PPO，只在真实反馈覆盖范围内训练并披露范围。

先回答“情境化获取是否优于固定调用”，再回答“读后内容是否改善后续决定”，最后比较“PPO是否优于同数据监督方法”。全部方法共享反馈并使用同一完整成本路径。不能只训练PPO访问过的计划而不给OneShot/BC同样的反馈，也不能用旧70计划作为新无限制有序域的穷尽证明。

若条件监督产生可保留的 G1，另冻结原 G0 与 G1，分别训练 PM0/PM1；在相同分组测试前缀上比较 G0+PM0、G0+PM1、G1+PM0、G1+PM1，并为两种 G 保留相同简单基线。每个 G 的反馈绑定自己的实际回复，训练反馈预算公平，跨 G 不复制收益标签。这是回答 RQ-SX 所需的原配/交叉换配矩阵，**不在第一批288生成位置内**。若尚无合格 G1，只能报告 RQ-X 的开发/负面结果，RQ-SX保持未回答，不能用单G结果代替。

### 第五段：冻结外评、部署与论文

最终同一G/资源/PM版本完成：官方ESC-Eval支持能力外评；ES-MemEval QA/Summary/DG各自原协议的记忆能力外评；来源独立的自然支持帮助性与误用评价；客户端和Tokkio实际等待测量。DG鼓励记忆展示，与自然支持效用不同，结果分开报告。

论文应分别回答RQ-S（情境化/顺序获取）、RQ-X（执行适配是否提高资源增量）、RQ-SX（G变化后价值与PM配对）。正结论必须有质量与成本证据；若某个问题为负，写清范围与原因，不能通过反复改目标制造全正结果。长期真实心理效果不在当前单轮设计能够证明的范围。

**完成研究**意味着这些问题得到可信、可复查的回答并完成系统评价；**达到预期正结果**还取决于资源增量、可学性、泛化与成本，不能由路线图保证。上述顺序的价值在于尽早识别不成立的环节，并将后续工作落在真正缺失的部分上。
