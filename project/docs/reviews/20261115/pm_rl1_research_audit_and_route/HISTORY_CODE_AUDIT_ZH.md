# PM-RL1 本地历史、实现与结果审计

审计时间：2026-11-15。范围：当前 RL1 文档/关键接口、相关旧 Paper-1 已发布资产记录、Claude 11-11 至 11-13 分支代码与报告。只读源仓库；未读取封存 gold、未触碰废弃 11/80 用户合成数据、未加载模型、未运行实验或付费调用。下文是已发现的决策相关问题清单，不声称逐行验证整个仓库。

## 1. 结论

1. 研究目标基本稳定。变动最大的是资源表示与可达域、执行器、反馈协议和成本定义。PM 需要产生正面支持能力证据，不能拿“发现失败”预先替代成功目标；与此同时，公平比较结果不能预设 PPO 必胜。
2. 10 月 1 日已经完整写过“资源有用→情境选择有用→读后调整有用”的依赖关系。今天只重新提出这一原则，没有解决执行缺口。
3. 缺口是尚未形成足够的、身份一致的闭合训练单元：合法来源 → 实际检索路径 → 确定 G 的真实输出 → 可辨认的任务质量反馈 → 完整等待。已有大量资产各自真实，但不能跨 G、提示、资源版本、任务、不同实际回复直接拼接为奖励。
4. 不是没有训练过：P2 G 已训练；11/04 真实同回复成本负对照已有 BC→PPO、3 seeds、384 轨迹、24 更新、3 PPO checkpoints。尚未完成的是正收益自然支持训练、正式全部对照和独立泛化评价。
5. RS 已有负面证据的适用范围必须缩准：多数实验给 G 的是策略标签、短指令、单条风格示例；未充分验证“完整案例情境→选择→后续反馈→适用边界”的资源内容。另一方面不能因为这种版本尚未验证，就保证补长案例一定有效。
6. 主检索器与 QA 检索分支不同。当前组织域实际是词重合动态检索；QA 已通过的是普通 BGE top1/top2。新计划必须明确选择并冻结同一个检索器，不能把一个分支的命中率当另一个分支的能力。
7. 1,924 旧静态生成是真资产，但没有 1,631 份已完成的正式评分，也没有隐藏的一大批合格效用标签等待整合。

## 3. 为什么早就写了正确原则，仍在原地循环

`CAPABILITY_BACKWARD_DESIGN:43–55` 已列全部必要条件，`:85` 起的 A/B/C 已提出资源、情境化和读后价值；末尾执行顺序要求 P2/P3 用共同池及 40 对人评回答这些问题。但实际出现四处脱节：

1. **P2 验证的是可追溯和弱目标拟合，并没有先证明资源内容有价值。** 同一 Qwen 写目标和审核来源，采纳多种资源条件并不保证目标教会“信息改变支持决策”。NLL 用于弱分布选模。11/04 回查七段预选完整 MS，只有两段真正进入对应已接纳目标；N19 为零目标。见 `PM_RL1_P2_EXECUTOR_RESULTS_20261001_ZH.md:11–34,67–85`；`reviews/20261104/pm_rl1_executor_use_probe/RESULTS_ZH.md:9–24`。
2. **大量工作在修裁判接口与一致性，但资源差异是否具有实际意义仍未落地。** 来源可支持不等于建议适用；一般共情/提问又容易被当事实误用。粗 q/m 的最小档差与微小文本差异不匹配。反馈协议不断修订不自动产生任务价值。
3. **资源域重构后，旧效应表无法自然延续。** 原 425 MS 中 179 因限制不可达；解除限制后加入已合法隔离历史，当前顺序与动态排名改变。旧 586 回复虽可保存复用，却只有完整输入/来源/G/draw 一致的终点才可复用；新路径不能借旧偏好。
4. **真正直接检验价值后出现了有限负面结果。** 11/05 十情境 C/OFF/D 首次把直接相关与同人异话题控制放到人评里，联合胜出只 2 情境/2 owners，未达到事前 4/3 的开发规则。这不是执行者没有跑，而是核心假设没有得到足够支持；其选择规则又不能用来估计总体需求比例。

新方案的必要新增产物应是“版本统一的闭合证据包＋每类失败的原因与下游重跑范围”，而不只是再说先验证资源。必须说明已有 586 / 1,924 / Claude 回复哪些精确可复用、哪些仅作诊断，避免重复生成与错配标签同时发生。
