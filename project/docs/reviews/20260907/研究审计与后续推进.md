**一、我对完整研究方案的理解**

核心问题是：情绪支持系统已经检索到合法、相关的外部资源时，一个低容量、可审计的生成前 Policy Manager，能否学习资源带来实质增益的条件，并在官方任务质量得到保留或改善的同时，减少不必要的上下文注入及客户端等待。

方法名是 Policy Manager（PM）；Metacom5_3 是历史项目目录名。当前四头含义必须采用 9 月修订，不能照抄 8 月旧文档的 ME/MS 定义：

| Head | 当前资源定义 | 学习目标 |
|---|---|---|
| RS | 从 ESConv‑train Strategy Bank 检索的、固定校准量的 atomic‑move bundle | 该 bundle 是否产生实质正向效果 |
| MP | target-time Current Profile View：严格过去可追溯、当前有效的稳定槽位事实 | 当前 profile bundle 是否产生实质正向效果 |
| ME | 严格过去的 Atomic Event/Experience Timeline | 当前事件/经历 bundle 是否产生实质正向效果 |
| MS | 严格过去的一份或多份完整 raw session transcript；一个候选是一份完整 session | 当前 session bundle 是否产生实质正向效果 |

ME 的 action→user-observed outcome 只是子类型；MP 不包含 response-preference history。四头均为 standardized L2 logistic regression。训练一个头时，仅切换该头，其他 optional resources 全 OFF；运行时允许组合，但没有学习头间交互。

训练目标是 `P(task-defined material positive effect | visible state, eligible candidate, frozen stack)`。它不是逐请求收益幅度、期望效用、临床需求诊断、策略类别分类或 16-action 最优策略。动态 top‑k、收益幅度模型、bandit/RL 和全对话序列最优留在后续研究。

标签保留五类：`on_better→1`，`off_better/equivalent→0`，`uncertain→missing`，`invalid→missing+integrity record`。没有合法候选的 ineligible 状态直接 OFF，不作为 learned negative。Cost 不进入质量 label/loss；latency 在部署动作和 operating-point 选择中发挥作用。

| 研究问题 | 训练/资源来源 | 正式验证及识别逻辑 |
|---|---|---|
| RQ1：Strategy‑RAG 选择性打开是否有价值 | ESConv train/dev；Bank 仅 train，并排除当前对话完整来源链 | ESC‑Eval：R0、RS Fixed‑High、RS Matched‑Random、Learned RS‑PM；完整报告七维官方指标 |
| RQ2：Multi‑View Memory 选择性打开是否有价值 | ES‑MemEval/EvoEmo 公开数据，严格过去候选与 exact-evidence cross-fitting | No Memory、Full History、Official RAG Top‑4、Multi‑View Fixed‑High、Matched‑Random、Learned PM；按 QA/Summary/DG 分别报告官方指标 |

Learned vs Matched‑Random 在相同 ON rate/注入 token 预算下识别“打开位置是否有信息”；vs Fixed‑High 识别质量与效率取舍；component-minus 识别逐头贡献。只胜过 No Memory 不能单独证明 PM 学到了好的选择器。RQ2 属于 within-benchmark cross-fitted longitudinal adaptation，不能写成 unseen-user 泛化。

目前 RQ1 已冻结的 non‑ESConv English population 为 173 张：52 calibration、121 confirmatory。完整 331 张 English cards 属于更广的 secondary/overlap 报告面。RQ2 固定公开版本含 18 owners、401 sessions、1427 QA、125 Summary、34 DG，共 1586 targets，分成 477 exact-evidence components、5 folds。公开数据来自[固定 commit 的 ES‑MemEval 官方仓库](https://github.com/slptongji/ES-MemEval/tree/692624208acc077b8867698c1d6fcd998dee641a)；项目正确将其命名为 `ES-MemEval-Public-v1.0.0-1427`，不能声称精确复现论文的 1209 QA 行集合。

Natural-turn Appropriateness、dose-response、decision correctness、局部 regret/Benefit Capture 是补充证据，不能替代上述两个正式 RQ。官方 DG 有刻意唤起记忆的任务提示，因此其高分本身不足以证明系统在普通轮次懂得克制；独立 natural-turn 人评有单独价值。

当前主张来自[二元收益范围修订](../../PM_PAPER1_BINARY_BENEFIT_SCOPE_AND_API_BUDGET_AMENDMENT_20260903_ZH.md)及[当前配置](../../../configs/paper1_public_only.yaml)。旧文档只有未被后续覆盖的条款继续有效。

**三、按影响排序的问题和限制**

**1. 高：teacher reference 与未来 outer evaluation 的隔离未闭合。**

当前 13 QA+13 Summary+9 DG，共 35 个唯一记忆目标，全部出现在已经冻结的 RQ2 outer-fold manifest，且分布于全部五折。它们属于 35 个 exact-evidence components；按现有 exact-component 规则展开涉及 97 targets：69 QA、19 Summary、9 DG。抽样器未将这部分定义为专用 measurement-development 排除集，见[teacher 抽样代码](../../../scripts/paper1/56_build_pairwise_teacher_preflight.py#L278)。

这不是“gold 已泄漏给 Generator/PM”的证据。本次请求绑定检查没有发现该类泄漏。风险是：一旦用这些目标上的人评/Gemini agreement 选择 teacher、改变标签可识别范围或量表，再把同目标/同 exact-evidence component 写成从未参与任何选择的 sealed 证据，隔离就不充分。

应在使用人评结果作研究选择前冻结处理方法。优先建议把 35 个 components 标记为 measurement-development，正式主张同时给出不包含这些 components 的干净验证面；保留全部既有 rows 和冻结 fold 身份，不删除或悄悄重新分折。若将干净面提升为主分析，它剩余 1489 targets（1358 QA、106 Summary、25 DG），会改变原主分析人口，必须先版本化批准。另一种方法是将 teacher 选择也纳入 fold 隔离，但现有每任务小样本会限制可靠度。

`PROPOSED RESEARCH CHANGE — NOT AUTHORIZED`：上述开发集/验证面调整是审计提案，尚未执行。受影响的是未来 RQ2 confirmatory interpretation；现有 teacher 卷与生成内容不因此自动失效，也没有需要重训的 PM。

**2. 高：Summary 的 equivalent 编码有可复现的契约冲突。**

[当前 V2 契约](../../../data/paper1_authority/paper1_task_effect_coding_v2.json#L39)明确 directional primary + pairwise equivalent 应为 equivalent；共同语义也要求保留无可辨别实质优势的判断。但[编码实现](../../../src/metacom_pm/paper1/evaluation/effect_coding.py#L453)存在：

- Event F1 相同，LLM Score 有方向，pairwise=equivalent → 实际输出 uncertain。
- Event F1 有方向，LLM Score 反向，pairwise=equivalent → 在 equivalent 分支之前返回 uncertain。

两例已在审计脚本中复现。结果是本应为 0 的部分非正收益样本会从 likelihood 中丢失，改变训练分母。修复应遵守已批准的 equivalent 优先语义，保留真正机械 invalid 的优先级，并补这两个边界的回归测试。此处影响未来标签，未污染尚未生成的正式 effect labels；不需因此重做人评或本地生成。

**3. 高：旧 `$22` RQ2 envelope 已无法作为完整执行预算。**

[DG 最新执行修订](../../../data/paper1_authority/paper1_official_dg_execution_policy_amendment_20260904_v1.json#L76)已经记录：六系统、34 scenarios×10 turns，仅一次 seeker 尝试的 uncached 最坏预留就为 `$29.51055`，尚未包括 204 次整体 DG GPT‑4o scorer、QA/Summary 官方评分、校准、训练标签和 ablations。

`48.55821849−29.51055−5 retry reserve=14.04766849`，是按该最坏预留给其他所有阶段留下的空间，不是足够完成它们的证明。当前没有已完成的 exact whole-run call manifest 能证明预算闭合；不能把“账本会在 $50 停止”等同于“全研究能在 $50 内完整结束”。

需要在 calibration 前重算实际样本规模、复用、批处理适用部分、输出上限与主/次分析优先级。不能把预期 prompt caching 当作保证的 reserve 折扣；DG 后续 seeker 依赖各臂之前的 supporter，不能把一条轨迹跨系统复制来省钱。若需要调整已冻结主要人口或 arms，必须先提研究变更，不能运行到一半才裁掉不利样本。

两臂确实使用相同 cap，不是 ON/OFF 偷换预算。触顶也不自动等于无效；模型啰嗦、非使用或不遵循指令都是冻结栈下可观察的效果。应保留原卷和原始人评，报告 cap/finish 分布及相应 agreement 诊断，禁止按质量删掉、补写、换题或选择性重跑。正式栈的输出 cap 仍需在不看能力得分的工程规则下明确。如果未来版本改 cap，正式效果数据必须绑定新版本，不能混合当作同栈。

**5. 中：JSON parser 没有实现其声称的严格冲突拒绝。**

[parser](../../../src/metacom_pm/paper1/evaluation/pairwise_teacher.py#L89)对重复且矛盾的 `verdict` keys 使用普通 `json.loads`，会静默接受最后一个值。审计反例 `A_better` 与 `B_better` 同时出现，得到 `B_better`。应在 Gemini runner 启动前拒绝重复 keys，并把不合 schema 的类型统一转为可记录的 parse failure。这是机械修复，不需改变 rubric 或挑选 teacher。Gemini 尚未调用，因此没有这类历史判卷需要重跑。

**6. 中：相加各头 p95 不是已证明的保守延迟上界。**

[allocator](../../../src/metacom_pm/paper1/core/latency_policy.py#L99)称 `base p95 +各头 incremental p95` 为 conservative first-order approximation。其作为预先声明的近似可以保留，但“保守”没有一般数学保证。审计附有纯算术反例：三个各占 4% 的不重叠长尾，各自 p95 增量均为 0，相加估计为 5s，而组合实测 p95 可为 65s。这不是项目中已观察到 65s，而是反驳一般上界保证。

当前 full-pipeline pilot 没有训练后 PM、完整 RS/动态 DG 与足够 target/token-bin coverage。正式完成前要核对组合预测误差，最终 latency 结论取 raw client E2E samples；不能凭这个公式保证每个请求或总体 p95 永不超时。无需因此另外创造准确率通过门。

**7. 中：文档入口/状态仍有漂移，CI 绿不能代替研究准备就绪。**

[README](../../../../README.md#L7)仍把 8 月 blueprint 写成最新执行 authority，并保留旧 repeated-effect qualification 顺序；[当前 checklist 尾部](../../PM_PAPER1_EXECUTION_CHECKLIST_20260903_ZH.md#L77)仍说 sheet identities 待生成，和已生成并 hash-bound 的卷矛盾。部分历史 preflight 仍显示 pending 是合理快照，但当前导航面应明确指向完成结果。

当前 namespace 有 teacher prompt/parser 和 materialization 脚本，尚未形成新的 pairwise human ingest/qualification 执行器、当前四头 formal effect→fit 的完整流水线。[formal unlock helper](../../../src/metacom_pm/paper1/outcome_lock.py#L120)当前仍为始终拒绝的保护桩；旧 full-stack draft 有空 feature/bundle/call-plan，并绑定过期 hosted backend。不能认为 human JSON 填好以后有一个现成命令可安全跑完后续全部研究。

**四、人评审查之后如何推进**

**步骤 1：保存并机械 ingest 两份原始人评。** 每人独立完成原定 96 presentations；只改副本中的 verdict/rationale。ingest 按 presentation_id 对齐，检查缺题、重题、四类 verdict、非空理由，并验证任务输入、reference 和 A/B 文本均未被改写。原始 blank sheets、rated sheets、ingest manifest 分别 hash-bound；原始分歧永久保留。尚未完成的人评不由脚本或模型代填。

**步骤 2：先完成 human reference 分析及预先约定的裁决。** 192 个 primary judgements 与另加的 adjudication 分开计数。报告两人的逐任务一致性、四类混淆、equivalent/uncertain 比例；16 组反序单独衡量方向稳定性，不作为新增独立内容。对 disagreement 按预先指定第三人或 consensus 方案处理，不把 consensus 当作原始人际一致率；两人都 uncertain 也不强迫二选一。先闭合问题 1 的使用/隔离安排，避免用验证标签选择测量方法。

**步骤 3：进行已冻结身份的 Gemini teacher qualification。** 这是独立付费阶段，现有 identity 明确未授权调用。准备具体 96 请求的 prompt/parser/model-version/cost manifest，修 parser，接 cumulative ledger，确认 0.10 USD 阶段 cap 下的实际最坏预留；再申请该阶段授权。Gemini 只看匿名题目和授权 reference，不看人类 verdict/rationale。版本化记录返回 modelVersion、解析失败和唯一允许的 retry；不按人评逐条改 prompt。

2026‑09‑07 复查[Google 官方定价](https://ai.google.dev/gemini-api/docs/pricing#gemini-2.5-flash-lite)，2.5 Flash‑Lite standard 文本输入/输出仍为每百万 tokens `$0.10/$0.40`，与冻结价格快照一致；这不等于本次已验证账户模型可调用性或返回版本，后者仍由实际执行前的身份检查负责。

报告逐任务 human agreement、macro class 指标、equivalent recall、反序稳定性、位置偏差、parse reliability、成本和 clustered uncertainty。某类 reference 为零则相应 recall 记 NA。无需另外发明 75% 或其他通过门；但若 Summary/DG materiality 无法可靠识别，就保留 uncertain，收缩相应学习/论文主张。不能以 ON 更多或 PM 得分更高选择 teacher。Claude 只允许既有预算内替代，不另加全量判卷。

**步骤 4：冻结可执行 amount/top‑k calibration 方案，再开启相应 calibration lock。** 人评/Gemini 不选 k。当前 `{1,2,4}` 只是 teacher 输入量覆盖；active memory amount grid 已记录 `{0,1,2,3,4}`。正式 calibration 必须另写当前 RS 与各 memory task/head 的 exact grid、target/group、reference inventory、输出 cap、资源 cap、official primary anchor、选择规则、重复/失败规则与调用预算。

Top‑8 是已物化的检索深度，不自动授权所有 k；旧扩展到 `{6,8}` 的历史条款不能脱离当前版本直接复活。MS 不可套旧 384-token cap，也不可将完整 session 截成 event atom 以适配 cap。

RQ1 的 calibration 使用冻结 52-card calibration 部分，121 confirmatory cards 封存。RQ2 每个 held-out outer fold 的 amount 选择只能用 outer-training 数据。应冻结统一的规则及 `k*_{task,head,fold}` 这类适用身份，不能看全部 1586 个 outcome 后选一个全局 k 再称 outer OOF。具体 amount one-SE/成本取舍及网格扩展条款应在当前 calibration manifest 中重新明确；不从过期文档默默继承。

**步骤 5：amount/cap 完成后生成正式训练 effects。** 冻结精确 feature schema、候选和 packing、Generator/Step2/normalization、seed schedule、fold identity 及 effect coding 版本。只用独立 state/group 的 focal-head ON/OFF；保留所有官方原始分数、pairwise、五类 label、finish/latency/tokens。相同 prompt 的共享 OFF 可按身份复用，但不能重复加权成独立负例。

QA/ESC 可在 ordinal anchor 明确时走官方主锚点；Summary/DG 的连续方向按 V2 要求 pairwise materiality 确认，不能继续照旧“仅 tie/conflict 才付费”的 cascade 漏掉这些调用。reference/gold 仅进入 scorer。先修问题 2，再派生标签。即使资源被忽略或误用，也要保留有效实现效果。

**步骤 6：四头训练与内层 OOF operating-point 选择。** scaler、编码/缺失处理和 L2 learner 必须只 fit 当次 training fold。RQ2 采用 fold-specific 模型及 outer-training/inner-OOF 校准；保留完整 outer-held-out outcome 隔离。超参数、阈值和 label 确定不能回看当前 outer 目标。

先按 task/head 报 label prevalence、可识别比例、OOF 概率和校准诊断；某头没有可估计类别时不制造样本或强行 fit，也不把这个经验结果写成禁止整个项目继续的新门。Threshold V4 依次使用 60s catastrophic completion ceiling、所选 arm 官方质量 one-SE、client completion/TTFT、tokens、ON rate；fixed 0.5、eligible-always-on、always-off 保留为参考。

**步骤 7：训练完成后冻结部署/正式评测栈。** 补齐真实 PM+BGE+pack+Generator 的 client E2E timing，特别是 RS、动态 DG、组合 bundles 和 token bins；用 raw per-call latency 计算 p95，区分 warm/cold、successful fallback/terminal incomplete。只把它写成 reference-client text latency；没有浏览器测量就不写 browser render-ready latency。

冻结 checkpoints、task/head/fold thresholds、完整 bundle 可行则全开/碰撞全关的 allocator、matched-random 精确 ON-count/token-budget 构造和正式 call plan。matched-random 算法与允许的 strata 必须预先指定；具体 schedule 可由已冻结 PM 的 outcome-blind actions 构建，不能按能力得分选择随机种子。训练前冻结协议，训练后冻结学习得到的数值，避免要求“先有 threshold 才能产生训练标签”的循环。

**步骤 8：sealed audit，然后正式官方评测。** sealed decision-correctness 结果不回流训练/threshold；完整 stack 与预算闭合后才开启 confirmatory locks。RQ1 跑四 arms，RQ2 跑六 primary arms，按已批准优先级执行 component-minus 和必要 secondary。DG 保留官方 prompt/role/round/scoring 加明确 one-attempt amendment；正式 Mistral request manifest 在 scoring 前保存 hash，arm-balanced、显式 server seed 0，resume pending suffix 不 reshuffle。

最终按任务、head、contrast 报官方质量、selection value、Cost、client latency、failure/coverage 与 clustered uncertainty。效应幅度与 Benefit Capture 只复用已有 paired/OOF/sealed rows；不能跨任务拼总分，也不能为次要分析新增调用。

**步骤 9：单独完成 natural-turn 人评，支撑“知道何时不干预”。** 这套 80+16=96 slots 目前仍是另一份 proposal，不是本次 teacher reference。若论文要作 ordinary-turn restraint 主张，应在冻结样本/身份后执行其 human-only 分析。不能把 teacher agreement 或官方 DG 的记忆使用率移作这个证据。

人评结束后的最近一轮工作应具体交付：`human_ingest_manifest + raw agreement/adjudication report + teacher/outer-fold isolation decision + 96-call Gemini execution/cost manifest + refreshed calibration plan`。Summary/parser 修复和导航状态纠正可在原定方法内完成；样本主分析人口、amount 新规则或预算阶段分配若变更，应明确记为提案并经批准后执行。无需重新比较 Generator、重跑已通过的 401 compiler 或扩大新经验门。
