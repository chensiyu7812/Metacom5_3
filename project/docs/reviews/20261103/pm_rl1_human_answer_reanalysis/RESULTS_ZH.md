## 重复从哪里来，为什么没有形成足够推进

1. **10月19日的8条回复全部已经出现在10月14日配对题中。** 后来换成q/m、逐主张、主体、时间、行动阶段、来源编号等字段，因此既重复读材料，又增加标注负担。原作答已有“感觉场景和P01一样”“这题和P01和P02是一样的”“什么叫这条主张的理由与未决点”等直接反馈。更细问法可能补充信息，但没有先扣除已答内容、说明新增信息将改变哪项决定。
2. 10月20日又将原回复作为多个对照的共同端点；例如职场问题的原dev04B在两对里出现，论文场景原dev07A也在两对里出现。不同对照有其用途，但应合并展示共同背景与已读回复，只问新增区别。
3. 后续6条回归中，dev04B、dev06B、dev35B已有完整q/m；其中前两条还有直接澄清。继续让人重填这些判断没有必要。
4. 整体支持偏好、事实错误、身份归属和q/m锚点被混在同一个“是否正确”问题里。整体上“都可以”不等于每个事实都正确，也不等于两条奖励数值必须完全相同。此前重视精确新输入覆盖，却没有充分把旧理由用于检查当前评分机制。
5. **原未答8对没有找到完整同题或完全相同上下文的旧判断。** 这是对具体材料的核验结果，不是要求它们必须补齐的理由。这8对原本用于评分流程开发；全部填完也不直接证明新版PM学到了什么。

另一个容易漏用答案的地方是表单结构：8条单回复都填写了q/m和理由，但仅2条填写了`claims`数组。dev15B、dev35B的具体错误写在“遗漏／理由”里。**不能因为逐主张数组为空，就当作没标注或没发现错误。** 本轮按完整作答阅读，原结构化字段和文字理由同时保留；文字解释不会被伪造成额外的人类原子标签。

## 以后怎样问才有用

执行策略见[HUMAN_USE_POLICY.json](HUMAN_USE_POLICY.json)。这是后续工作安排，不改原模型评分、原付费调用协议或原问卷答案。

1. **先检索已答库。** 同一完整证据、回复、问题维度已有判断时直接带入。相同场景换回复，复用背景和规则，不能复制新回复分数。展示已有结论，避免研究者从头回忆。
2. **先写明答案会改变什么。** 例如决定两条回复是否都可用、一个错误是否足以改变ON/OFF选择、一个明确严重错误是否被漏掉。若不同答案都不会改变下一步，该题不发。
3. **分开问支持质量与事实问题。** 整体选项允许“两条都可用且无实质差别”“有明确更好的一条”“两条都有明显问题”“无法判断”。事实核验只围绕尚未解决的具体句子和可见来源；来源ID整理、重复去除和逐句定位由协调者完成。
4. **保留范围和个人偏好。** q范围不取平均，轻微文风偏好不自动变成训练优胜标签。“未决”保留，不能为了凑齐训练数据强迫选择。
5. **按决定组织小批次，不固定重复8对。** 完成现有材料分析后，若只有一处仍影响路线选择，就只提出那一处；相同背景合并展示。新的严重度问题也要说明与已答问题究竟差在哪里。
6. **每批立即回传用途。** 明确指出采用了哪条原判断、发现或排除了哪种错误、是否影响评分流程／研究决策。先完成这一步，再考虑下一批。
7. **开发参照和最终验证分别记录。** 重复出现的旧答案用于开发回归，不因重复导出而增加独立人数。后续资格验证仍要说明适用对象和覆盖；不能把“补满这8对”或“拟合这些旧题”直接称为合格。

本轮结论是：**旧人评足以先完成一轮实质性的评分诊断，当前不需要再向研究者派发任何题。** 已有375项新版训练输入没有精确匹配的人类答案，这只限制直接搬运训练标签；并不削弱旧理由对评分规则、错误定位和减少提问的价值。下一步先处理已定位的问句预设、支持策略区分和严重度问题，再决定尚缺什么证据。真实BC/PPO仍为0。
