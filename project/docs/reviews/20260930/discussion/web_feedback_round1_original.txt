你原方案其实已经把来源合法、语义适用、输出误用、最终增益分成四层了；只是后来又让一个 LLM 一次把它们都判完。:chatgpt-content-reference{index="4"} 现在的实验告诉我们：**这四层必须真的拆开。**

### 第一层：能程序判断的，一律从 LLM 手里拿走

我们可以做成：

```text
response
  ↓
claim extraction
  ↓
NON_FACTUAL
SUPPORTED_CURRENT
SUPPORTED_HISTORY
CONTRADICTED
STALE
WRONG_ENTITY
WRONG_TIME
UNSUPPORTED
UNCERTAIN
```

然后 `m` **由程序从这些状态派生**。

于是：

> “也许可以试试看……”  
> → NON_FACTUAL

而：

> “你上次已经通过散步解决了这个问题。”  
> → 进入 evidence verification。

这正好解决你们这次最棘手的“建议被当事实”“理由和 severity 打架”的问题。

## Quality 我建议正式放弃“单回复 0–4 作为训练主信号”

这一步我现在相当支持。

你的真正问题本来就是：

> **这个资源计划相对 OFF 有没有边际价值？**

所以直接比较：

```text
same prefix
same executor

A = OFF response
B = plan-E response

B materially better
A materially better
equivalent
uncertain
```

比：

```text
A = 4
B = 4
```

更贴近研究问题。

而且 pairwise 也要做得科学：

- A/B、B/A **反序两次**；
- 明确允许 `equivalent`；
- 明确允许 `uncertain`；
- 顺序反转后结论矛盾 → 不产生训练 reward。

这是有文献依据的。2025 年针对 LLM judge 的大规模研究发现，position bias 普遍存在，而且与候选答案质量差有关，所以不能只判一个顺序。:chatgpt-content-reference{index="6"} 对 tie 的研究也表明，把真实 tie 强行压成 win/loss 会系统性扭曲 preference strength。:chatgpt-content-reference{index="7"}

这特别适合你的 PM：

> **ON 和 OFF 真正差不多，本身就是一个非常重要的答案。**

因为此时有资源成本，PM 就应该倾向 STOP。

| 组件 | 推荐 | 负责什么 |
|---|---|---|
| Pairwise generative evaluator | **Prometheus-2 7B** | 按我们自己的正向 support rubric 做 A/B/tie |
| Preference reward model | **Skywork-Reward-V2-Llama-3.1-8B** | 给一个完全不同范式的 pairwise preference 信号 |
| 当前 Qwen v4 | 保留 | development diagnostic / claim extraction 候选，不再是 oracle |
| ESC-RANK | 保留原身份 | 冻结系统后的 ESC 外部评价，不做当前 PPO reward |

Prometheus-2 本身就是针对 evaluator 训练的，支持**自定义 criterion + direct assessment + pairwise ranking**，论文在多套 pairwise 人类偏好 benchmark 上表现强于其测试的其他开放 evaluator。:chatgpt-content-reference{index="8"}

Skywork-Reward-V2 则不是 prompted judge，而是 Bradley–Terry reward model；最新公开系列报告其在 RewardBench v1/v2、RM-Bench、JudgeBench 等多类 reward benchmark 上表现很强，并提供 1B/3B/8B 等不同大小。:chatgpt-content-reference{index="9"}

这两者放一起的意义不是“投票决定真理”，而是：

> **Prometheus 是显式 rubric reasoning，Skywork 是训练过的 preference RM。**

如果两种完全不同机制对某个自然 pair 都认为 B>A，而且 Prometheus 反序后仍稳定，那这个信号比当前 Qwen 的单次 `q=4` 强很多。

如果它们分歧：

> `uncertain`。

**不要硬给 reward。**

# 甚至可以把 uncertainty 本身用起来

这也是成熟 RLHF 研究已经在处理的问题。

Reward-model ensemble 的研究发现，直接优化单一 imperfect reward 很容易 overoptimize；用多个 reward 的 conservative / uncertainty-aware objective 能明显减轻 PPO 对 reward 漏洞的利用。:chatgpt-content-reference{index="10"}

我们不需要一开始搞复杂算法。

第一版只需要：

\[
s(E)\in\{-1,0,+1,\mathrm{unknown}\}
\]

表示：

- `+1`：资源计划明显更好；
- `0`：materially equivalent；
- `-1`：更差；
- `unknown`：裁判分歧/顺序不一致。

然后：

\[
R(E)
=
s(E)
-\alpha M(E)
-\lambda\frac{c(E)}{B}.
\]

`unknown` episode **不进入 PPO actor/critic loss**，继续沿用你原方案“reward 缺失不能填 0”的原则。

其实你原来的：

\[
R=U(E)-U(\emptyset)-\lambda C
\]

结构不需要推翻。:chatgpt-content-reference{index="11"}

只是把：

\[
U=q/4-m
\]

替换为更可信的：

\[
U=\text{pairwise support advantage}-\text{verified misuse}.
\]

> A better / B better / tie / uncertain。

这就是 reward 的 calibration anchor。

为什么我现在认为这一步值得？RLFF-ESC 自己并没有“相信 critic 就算了”。他们另外抽 100 个对话，让三名有心理学背景的评审和 critic 独立判断，最后才报告 critic 与 human majority 的 Krippendorff α=0.786、Spearman ρ=0.796。:chatgpt-content-reference{index="12"}

我们不用做这么大。

但如果完全没有 domain human anchor，而想声称：

> “这个 reward 代表 emotional-support quality”，

就会天然弱一截。

所以我的建议是：

> **现在不做人评；等自动 reward stack 先过机器可验证的资格，再一次性做 24 个 pair。**

和最后系统冻结后的 24 个 test blind pairs 是两批不同用途：

- 前者：**train/dev reward calibration**
- 后者：**final independent evaluation**

不能混。
