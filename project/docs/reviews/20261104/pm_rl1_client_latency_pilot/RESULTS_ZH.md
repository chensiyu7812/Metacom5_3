# PM-RL1：首轮真实客户端延迟测量

2026-11-04。研究者在明确“延迟才是目标”后要求继续推进。本轮已实现流式参考客户端、完整在线读取路径和独立秒数代价接口，并实际完成有限本地测量。**现在已有真实延迟成本观测；尚未形成完整的质量—延迟训练奖励，也没有启动自然PPO。**

## 已执行的范围

两个此前已检查的train情境C02、C03，各比较OFF、固定MS1、固定MS6和MS6顺序接口重放。每个情境/方法重复3次，按seed 17在情境微块内交错方法顺序；另2次全路径预热独立标记，不混入24次测量。

原Llama执行器及P2 epoch-3适配器加载1次，原BGE加载1次；实际26次G、56批单块BGE forward、56次未训练PM网络前向，全部自然结束。无优化器、裁判或付费API。G、BGE加载分别约21.17秒、4.78秒，发生在请求之前；这不是冷启动测量。

顺序重放使用真实5139维特征、原128宽三层MLP与公共mask。**动作预先固定为6次MS后STOP，网络权重未训练，预测不决定动作。** 它用于测量现有顺序接口开销，不能称作PPO、BC或OneShot的学习效果。固定程序不做PM编码；OFF不为了对齐时长而增加资源检索。

## 计时与部署条件

客户端在发送请求之前记录单调时钟，在收到第一个非空实际回复文本及最后一段实际回复文本时记录同一时钟。只有服务端确认完整自然结束且流式拼接文本与最终文本一致，才认定完整回复延迟。空输出、流式不一致、超时及部分输出不变成完成样本。

本次surface为**进程内队列的流式参考客户端**，单请求并发、A6000、模型常驻；不含尚未部署的真实网络或浏览器渲染，不冒称生产延迟。声明的技术客户端保护为900秒，原生成300秒逐步watchdog保留；没有移植旧Paper-1的60秒研究门槛。

合法目录及词项索引预建驻留，查询、排序、完整资源呈现、初始/逐次观察、BGE编码、PM前向、G输入准备与生成、文本队列交付均在发送之后。每次请求的特征缓存从空开始，只在同一请求内复用已编码的完整token块；不读取离线训练向量或旧回复缓存。GPU准入检查和实验落盘在测量区间外，不伪装成生产请求处理。

原生成代码字节保持；新流式适配器另绑定执行身份，保留解码参数、自然EOS及watchdog。26条实际回复的文本、输出token序列均与历史同输入回复完全一致，才允许继续使用相应的内容判断。这不是新增26条独立人评。

## 实际结果

单位：秒；表内为3次观测的中位数。

| 情境 | 方法 | 首段实际回复 | 完整回复 | G输入/输出tokens |
|---|---|---:|---:|---:|
| C02，同事感谢便条 | OFF | 0.115 | 2.127 | 346 / 70 |
| C02 | 固定MS1 | 0.266 | 2.262 | 1,231 / 65 |
| C02 | 固定MS6 | 1.097 | 4.290 | 5,213 / 81 |
| C02 | MS6顺序接口重放 | 2.082 | 5.277 | 5,213 / 81 |
| C03，工作边界 | OFF | 0.131 | 2.041 | 446 / 66 |
| C03 | 固定MS1 | 0.305 | 2.953 | 1,356 / 85 |
| C03 | 固定MS6 | 1.104 | 7.025 | 5,228 / 149 |
| C03 | MS6顺序接口重放 | 2.088 | 8.039 | 5,228 / 149 |

每个微块内先计算方法与OFF的差，再对3个差取中位数：C02固定MS6完整等待增加2.163秒，顺序重放增加3.150秒；C03分别增加4.983秒、5.997秒。它们是本机本情境差值，不能外推为所有用户的等待代价。

同样的MS6资源、G输入和输出，顺序重放相对固定程序的配对完整等待增加：C02约0.981秒、C03约0.979秒。G组件时间基本接近。顺序路径的阶段中位数显示：在线编码累计约0.366秒，读取/更新观察约0.70–0.71秒，PM网络前向累计仅约0.006秒。阶段中位数不要求加和等于总中位数。

这定位了当前实现中明显的额外开销：多次观察、检索及输入准备，加上逐次编码。不是“PPO网络计算很慢”，也不是仅靠输入tokens能解释。另一点是两情境MS6输入长度相近，输出长度不同，完整等待明显不同；不能为了低延迟直接截短回复，也不能把未来真实输出长度泄漏给在线策略。

每格仅3次，已保存的经验p95恰等于最大值；**未建立生产p95、并发/冷启动表现或跨情境统计结论**。两个情境是已检查材料中的有目的诊断选择，不是代表性样本。

## 这对收益与RL意味着什么

C02的OFF回复精确对应原人评B，两条MS6路径精确对应原人评A。研究者“相当、A略好、差距很小”的判断继续使用，不再重复询问。这次可以把它与实测多等约2.16秒或3.15秒放在一起；仍不把90/95类比转为q、固定效用差或毫秒价格。MS1和C03没有因此获得新质量标签。

顺序策略必须通过更好的质量，或更早停止/更少无效读取带来的等待节省，抵偿自身在线开销。固定6次重放没有给它任何自适应收益机会，因此不能据本轮判定顺序RL必然不值得。下一步学习比较要包含这笔开销，也要给策略改变head、读取数量和STOP的机会。

新增`seconds_return`按明确的部署条件和显式秒数权重构造候选终值：`已建立的质量增益 − λ_L × 实测完整等待秒数`。成本只扣一次，不叠加旧GET token成本；缺质量、缺时间、未完成或部署条件不匹配均不产生数值训练回报。没有默认λ，没有把这26条测量自动推广到其他程序。

**接口状态必须分开：** 客户端计时和独立秒数代价函数已实现并测试；原正式BC/OneShot/PPO协调器仍执行旧TokenCost，尚未迁移到秒数代价。秒数函数返回的是候选结果，不能授予质量评分资格，也不会自动开始训练。原质量反馈瓶颈仍存在，延迟测量不能替代它。

接续重点：先减少不必要的重复观察/渲染开销，保留全正文与相同动作语义；再把训练共同输入、监督目标和PPO终值统一迁移到同一秒数代价。正式取舍仍需有区分力的质量证据和明确的质量—等待取舍，不能为了启动学习把近似相当的人评填成确定零差。已有原答复和澄清优先复用，原8对不自动重发。
