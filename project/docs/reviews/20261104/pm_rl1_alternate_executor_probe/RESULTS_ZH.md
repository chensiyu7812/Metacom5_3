# PM-RL1：相同输入、更换本地 G 的诊断

2026-11-04。**已实际完成本地 Gemma4-12B-it 的36次生成，覆盖原41张卡/8个已暴露train情境，新增API费用0美元。更换G会改变历史采用和无关信息干扰，但尚未证明它提高了资源的实际收益。** 36条均自然结束，1条有格式泄漏；候选未取得整体胜任资格，也未替换正式G。新人评待答，新增奖励和PM更新均0；此前24次成本负对照PPO更新仍保留。

Claude的核心建议正确：先做同输入的跨G对照，比继续扩大少量自写示范更能定位问题。有限SFT已经证明能拟合示范文本，却没有证明学会条件性使用资源。其余结论需要收窄：PM的可达资源与选择尚未排除问题；两条OFF比较不能证明模型普遍更强；没有改善不能推出资源本身无价值；两个G都受干扰也不等于伤害与G无关。旧G缓存仍是有效的旧G证据，不能冒充新G缓存；旧人评原则和精确原回复判断也并非全部作废。不采用“0/1/2条实质改善”这种任意分支阈值。

## 已执行的对照

执行前固定36个去重输入，system/user完整消息、资源内容和次序均与旧实验逐字一致；不同模型使用各自原生模板和EOS，所以比较的是G运行配置，而非单独权重的因果作用。保留原A无资源、B首次检索、C定向完整合法资源、D其他主题资源、E同资源不同布局及N03的ME变体。新旧G分别比较同情境C−A，不能用新G的ON胜过旧G的OFF就归功于资源。每输入一次，未改提示追结果、未重试、未截短回复、未扩大数据范围。

| 情境 | 旧G→新G的可核对变化 | 对收益的限制 |
|---|---|---|
| N02 同事感谢 | 旧C围绕当前认可；新C明确提到历史上司不认可；两G的A/D均围绕当前 | 旧“略好”参照不能直接贴给新回复，背景增加未必更有帮助 |
| N03 请求倾诉 | 新OFF与两个ME变体逐字相同，B也只是倾诉邀请 | 当前没有具体顾虑，不用历史可能正合适 |
| N04 工作边界 | 旧C/E未提新工作；新C/E用了新岗位背景，A/D问拒绝任务的顾虑 | 边界问题当前已有；历史入职状态被当作当前，尚未重确认 |
| N05 申请调整 | 新C/E提旧负评；旧C与新C都能问具体调整；A/D仅当前背景 | 增加依据与改变帮助不是一回事 |
| N18 工作警告 | 旧D转向旧失恋；新D保持工作主题。新E询问警告是否与旧主管分歧有关 | C泄出`thought`和channel标记，属于格式失败；不清洗、不计零收益、不事后用E替换C |
| N19 考虑换工作 | 两G的C/E都未明确使用财务约束；A/D仍围绕当前自疑 | 此时未必应转向经济可行性；未采用不足以证明资源无价值 |
| N21 支持妻子 | 旧C没用互留休息，旧E用了晨跑；新B/C/E能采用互留休息和谈开 | 新OFF也已建议坦诚表达压力，C核心行动相近；历史尝试的当前持续状态未确认 |
| N23 朋友敷衍 | 两G都未明确使用主动邀请/最近两次被遗漏；新C认可情绪，A/E另问今后关系 | 不预设必须提历史或必须追问；帮助性仍待判断 |

逐条原文、源turn、引用位置与新旧回复哈希保存在`CONTENT_REVIEW_PRIVATE.json`，属于AI辅助观察，不是独立人评或q/m。最明确的机制证据是**N21的信息现在能被采用、N18的无关信息不再造成同样的主题转移**；这反驳了“G配置无关”，但没有证明新增实际收益。C是定向资源的可实现性诊断，不能直接当作当前PM可达策略；N04/N05的检索缺口仍要解决。

## 本地模型与延迟

| 本机候选 | 本轮用途 |
|---|---|
| [Gemma4-12B-it](https://huggingface.co/google/gemma-4-12B-it) | 已有完整权重与兼容环境，约23.92GB权重文件；BF16、SDPA、原生非思考模板，A6000上完成36次生成。选择先于结果，与原P2示范作者Qwen家族不同，不预设更强 |
| [Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B) | 已有完整权重，配置可加载；作为后备，本轮未运行。此前裁判校准未过，不等于生成能力不行 |

没有下载模型、安装环境或调用DeepSeek。API费用为0，不意味着本地算力没有成本。已有专用评分模型没有直接当作更强对话G。

研究者提出的**额外等待超过3秒通常不可接受**，已写入本轮协议作为暂定部署约束；3秒以内也不是自动值得。它不是普遍用户偏好或已标定的奖励系数，不追加1/2/4秒假设问卷。下一步应在常驻、同负载、同情境交错条件下测“用户说完→首段有效语音”的完整Tokkio链路及相对OFF的额外等待，同时检查尾延迟；有流式重叠时不能直接累加阶段耗时。

本轮仅测G组件：首token中位0.483秒、范围0.200—3.149秒；完整生成中位4.591秒、范围1.430—12.285秒。包含初次调用预热差异，单次配对也不足以估计稳定增量。**这些既不是Tokkio首句语音延迟，也不能证明已满足3秒约束。** 旧参考客户端延迟记录继续保留，不冒充新模型实测。
