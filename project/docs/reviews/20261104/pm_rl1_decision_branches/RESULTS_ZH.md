# PM-RL1：真实决策分叉、资源瓶颈与人评接入

2026-11-04。承接研究者“先推进，再分析人评怎样帮助RL学到目标能力”的要求。本轮使用已完成的真实G结果、合法历史与当前检索实现，不新增评分或训练。重点是把下一步从泛泛“补标签”收敛到有区分力的具体比较。

**结论：现在优先解决的是有用信息能否到达G、能否被正确使用，以及评价能否保留值得学习的差别。还没有真实PM训练失败的证据。人评应优先裁定会改变训练目标的差异，而不是不断复核同一条回复。**

## 从原文定位到的具体问题

**C01：倾诉邀请，不该为了读取而读取。** 用户仅问能否聊聊。OFF与一次ME的回复逐字相同；一次MS与MS→ME、ME→MS的回复也逐字相同，后两者多188 tokens。这些局部成本关系无需新的人评。不同措辞的其余邀请不擅自判成相同q/m。

同例ME的`past_report`写成用户已经向前任表达明确关系意图的要求，引用原文却是希望前任说得更直接。完整H004会话中，H004:T013表达愿望，H004:T017说的是和亲友谈过，不能据此写成已经向前任表达。已生成一个保留原引用、只修正该概括的独立候选记录，原资源及历史生成未改。

这说明上游压缩表述仍可能越过证据；`action_stage=unknown`不能消除`past_report`中的完成式断言。但本次一次ME回复等于OFF，**没有观察到这个来源错误改变该终点回复**，不能把它直接算作G误用或本例质量下降。

**C02：确实存在G把历史带进回复的实例，是否有用须区分。** 当前用户收到同事感谢。历史H012:T004、T016明确谈到不被上司重视。六次MS后的回复提到这一处境，OFF只回应当下感谢。它是“历史已经进入正文”的实例；质量增益还需判断。不是所有资源都被G忽略，也不能因出现历史细节就奖励它。

**C03：有相关历史，但当前已测路径没取到。** 用户说尝试过工作边界，仍觉得必须答应所有任务。第一次MS取到2025-02-02以汽车故障、通勤与同事冲突为主的会话。2025-06-05会话H014:T008明确提到建立更清楚的工作边界，但初始字面重合排名第13；本情境22条程序（包括连续6次MS）都未取到它。

这把“检索可能漏掉有关材料”落实成了可复查实例。它不证明那份历史会改善最终回复；当前前缀本身也已说到边界。读后排名会更新，不能把初始第13名解释成必须读13次，更不能说全动作空间不可达。应通过同条件下替换具体MS的诊断来区分检索选择与资源本身价值。

**C04：读后更换回应重点，还不是读后决策价值。** 当前用户因身体不适犹豫接受研究机会。首次MS主要谈家庭对专业和关系的意见，ME谈与伴侣相处的进展。回复在探索犹豫、减轻负担、联系伴侣之间变化；MS→ME与ME→MS在本例同成本、同回复。当前对话已提及伴侣，不能把再次提及当作获取了关键新信息。此次不对医疗建议作专业效果判断。

四例中，C01能确定一些无效追加，C03能确定一处检索覆盖缺口，C02能确定历史被G使用；**还没有依据把某条读后动作判为有质量优势的赢家**。这比“程序没变化”“G完全不看资源”或“PPO学不会”更接近实际问题。

## 人评具体怎样加入

旧23组偏好、8条q/m及3条澄清继续作为原输入上的参照。关于策略多样性、说话者归属、行动阶段等结论用于审查新材料，不复制旧分数。来源能直接核实的问题先核实；相同完整证据和回复只评价一次。

本轮先制作了三个情境的备用比较页：15个程序去重为13份回复，共享来源一次展示，方法和成本折叠在质量判断之后。它是**备用草稿，不是要求补完的13份新问卷，也不设为训练前置**。

进一步读完内容后，优先级缩成了**C02一个新比较**：六次MS后明确带入“上司不重视”的回复，与真实OFF比较。选择这个对照是看过回复后的针对性诊断，不宣称随机盲选或代表全体。页面保留完整当前对话、全部合法历史和实际回复；不需要人工填写来源ID、穷举claims。

这一个问题已经通过会话提出，实际答案尚待接收。旧8对问卷不重发。备用两个情境继续保留，不自动派发。

| 人评结果 | 直接改变的决定 |
|---|---|
| 带历史的回复明显更好 | 留作正向资源候选，检查原q/m能否表达该优势；再沿已测分支寻找更便宜的取得方式 |
| 相当 | 未确认质量增量，不追加GET奖励；整体相当不擅自换算成两个完全相同的U |
| OFF更好 | 留作负向候选，检查G对历史的适用性，而非继续加强读取 |
| 两者有问题 / 不确定 | 记录具体不足或缺失，不强造赢家 |

**人评有两个用途，不能混用。** 偏好与理由可立即用于排序诊断、监督候选和裁判错误分析；它本身没有与token成本同尺度的数值差。若同时给出可信q/m，则可在这些精确输入上直接形成`U=q/4−m`的局部人类反馈，不必等付费裁判先成为全域合格教师。区间保留原样；没有唯一标量时，不取中点塞入当前PPO。

若人认为有重要改善，但所有相关回复仍落在相同q/m档位，瓶颈就是现奖励不能表达这个偏好。应版本化比较偏好模型/更有辨别力的质量目标，验证其排序和与成本的尺度，再接PPO；不能暗改分数、直接把A胜B赋成任意+1，或把“多用历史”当奖励。几条偏好也不足以训练出可外推全池的可靠奖励模型。

## 怎样提高学到目标能力的机会

**先证明有可利用的决策信号，再扩大训练。** 对候选情境分别检查：当前任务需要什么、取回资源是否增加关键内容、G是否正确使用、所得质量/误用变化能否超过新增成本。应同时保留不必读取、读一类足够、需要组合、读后发现不适用应停止等实际情况。寻找自然例子或做明确标为构造诊断的受控比较，不能为了让RL获胜伪造正例、改原用户意图或预定每类均有正收益。

**把反馈落到同一状态的后续选择。** 对已读状态h，比较继续程序p与停止的差值：

`Δ(h,p) = U(G(h+p)) − U(G(h)) − [tokens(h+p) − tokens(h)] / 40960`。

已花成本在这里相消。初始OFF是否最优，与读到h后是否值得继续，是不同问题。先用现有250组直接比较及其他完整后缀；不因缺失分支而把它填0。不同程序若实际取得相同资源状态，也要按观察和请求身份正确合并。

**监督不仅保留一条完整赢家，也保留已核验的分叉信息。** 有可靠反馈后，可在已测后缀内构造行动偏序或允许的动作集合，覆盖“继续哪类”和“何时停”，减少少数终局赢家对BC的限制。已测后缀中的最大值只代表菜单内的乐观监督目标，不是全环境Q*，更不是当前随机策略的真实V。

**用真实BGE表示先检查能否拟合，再看PPO。** 在反馈完整的小批实际状态上检查BC动作概率、允许动作集合及收益；训练拟合和按owner留出分开。若真实语义目标拟合不动，再对比能保留资源顺序、说话者和关键单条信息的表示。若BC能拟合而PPO退步，查初始价值偏差、探索和更新幅度，不能直接加轮数。此前REDD/BLUE受控成功不替代这一检查。

**首次真实PPO可以是明确的小样本实验，不必等待全研究完成。** 在选定诊断范围内，用直接人类q/m或经过范围验证的反馈，覆盖该实验所有可能采样到的终点和OFF，再按原16完整轨迹更新一次、重新采样，检查回报与动作变化。若需要限制到一个小程序树，必须另建有明确动作范围的诊断运行，不冒充原487程序完整训练，也不删除原计划缺失项。现有13份备用回复或一个偏好本身尚不满足这一条件。

训练时不把完整历史、候选全集、裁判理由或人评标签放进actor/critic输入；这些是离线监督依据。修改G/检索/资源版本会改变环境，必须分别标明新身份、生成与反馈需求，同条件给OneShot和其他基线，不能只让PPO享有改进后的资源。

**读后适应需要额外验证。** OneShot共享内容自适应检索。只有按读到的信息改变后续head/数量/STOP，且在不同owner或受控信息变化下优于预先固定程序，才支持额外的读后策略价值。四个不同前缀的最佳程序不同，或动作顺序改变回复，都不够。若OneShot已充分解决任务，应保留这一结果。

## 方法依据与适用边界

从少量人工偏好学习奖励是已有研究路线，但它包含奖励模型学习和策略验证，不是把单个偏好直接换成通用标量真值。[Christiano等，Deep reinforcement learning from human preferences](https://arxiv.org/abs/1706.03741)。

PEBBLE采用主动请求偏好、学习奖励及随奖励变化重标旧经验，说明既有轨迹可以持续复用。本项目可借鉴反馈复用；它的off-policy训练不能直接搬到当前PPO。PPO的行为策略、log概率和奖励版本仍须一致管理。[PEBBLE](https://proceedings.mlr.press/v139/lee21i.html)。

Self-RAG对按需检索、资料相关性和生成反思的研究支持把“取到什么”和“怎样使用”分开检查；它在QA等任务上的结果不保证当前支持对话和小PM一定获益。[Self-RAG](https://arxiv.org/abs/2310.11511)。上述文献是方法参考，本报告的故障归因来自本地实际产物。
