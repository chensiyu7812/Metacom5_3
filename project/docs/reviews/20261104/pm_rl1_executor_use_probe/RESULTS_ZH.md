## 训练实际上教了什么

核对实际冻结数据与1018个绑定文件：493条弱目标中train413、dev80；train覆盖92个前缀，包含345条ON、68条OFF，68个前缀同时有ON/OFF目标。训练损失是完整回复＋EOT的监督NLL，选模是排除确证严重错误后按弱目标dev NLL选择。来源接纳、NLL下降及同前缀有不同条件，都不等于验证了资源增益；这也不是说SFT必须有成对损失才可能学到资源使用。

来源审核对345条train ON自报ignore281/use38/none26。这些字段此前已知会把当前信息当资源使用，也会漏记使用，**不能当实际使用率**。本轮对固定8例对应的26条目标逐条读内容；没有声称全部413条都做了语义判断。

## 有界执行器对照的真实结果

仍用原Llama-3.1-8B + P2 epoch-3、同解码/自然结束、原加载器和GPU守卫。沿用前轮8个已暴露train情境，每例对OFF和一段完整MS各增加同一版通用指导：信息应帮助回应当前需要；可用于尊重限制、避免重复建议、接续已有尝试；不要求引用、建议或变长，不由过往活动推断稳定偏好。

16个干预输入各增加137 tokens，当前对话和资源正文逐字保持；原16个回复精确复用。另加N02/N19两个原提示ON输入重放，总计18次新G、1次加载，全部自然结束；两次重放的文本和输出token IDs均与旧记录一致。OFF是真正空资源，没有用虚假资源绕过工厂限制：新增适配器明确构造原执行器支持的OFF消息请求，并检查空资源/来源绑定。

OFF与ON各7/8条回复变化，只有N03各自逐字相同。**14次文本改变不是14次改善。**

- N02/N05的ON更明确提到此前主管经历，来源可支持，增益尚未测量；OFF也发生措辞/策略变化。
- N04仍未明确采用新工作/灵活时间/此前冲突信息；OFF转为建议工作沟通，长度66→103 tokens。
- N18把具体主管分歧改为较泛化的工作冲突；N19提起想换工作，但这是当前对话已有信息，不是新增记忆收益。
- N21再次引用晨跑，随后转向其他自我照顾方法，仍未接续互留休息时间。这与旧人评指出的有限收益/可能过早转向自我照顾相呼应；旧意见可指导审查，不能复制成这条新回复的精确标签。
- N23调整了澄清或建议选项；N03没有强迫使用历史。两者都没有据此获得数值收益标签。

本轮保留所有输出，停止这一版提示试验，未继续改提示追求赢家，也未推广为生产版本。这8例不足以断言一般提示指导永远无效。此处ON是诊断性定向完整资源，并非自动PM可用的新动作；OFF/ON同时改变指导，是为了避免把一般回复改善误归因于资源。

## 已做出的示范修订候选

已制作5条可查看的草稿，全部绑定**原P2实际输入、原目标、当前/历史来源**，没有向学生输入加入私有需要标注或理想回复：

1. N04仅修“我们之前讨论”这一归属措辞，保留其余内容。
2. N18去掉缺乏适用依据的“帮助主管处理工作量”，转向澄清绩效警告与当前感受。
3. N21的RS条件不直接增加兼职负担，改为探讨能承担的支持及自身需要。
4. N21的完整MS条件尝试接续“过去说在尝试互留休息时间”；保留“如果现在仍适用”，不声称已有效或一直持续。
5. N23的完整MS条件尝试连接“曾努力邀请朋友却被遗漏”和当前关系选择；不认定所有朋友始终相同，也不强迫立刻采取行动。

草稿由Codex在看过这些开发材料后编写，**没有人评收益标签，没有接纳训练，没有改旧493条目标或适配器**。来源可见和引用核验只验证事实依据，不验证帮助更大。完整旧/新回复、输入和来源可在本地产物`REVIEW_ZH.html`查看；它是浏览页，不是新问卷。

## 接下来怎样接回学习

下一步把这些修订做成有限的配套监督试验：同时保留OFF、适当忽略以及同当前需要下不同资源条件，核对只在输入确实支持时才出现个人化内容；不要只加入“用了记忆”的正样本，也不要把281条自报ignore全部删掉。先完成这些条件的训练输入/示范配套，再做有明确范围的Step-2修订及与原执行器比较。候选仍属于有披露的弱监督，不新设必须大量人评才可试验的门槛；独立质量判断用于评价和收益资格，不能由弱目标拟合代替。

PM的目标继续是实际回复质量与用户等待的取舍。现有小收益/近似参照继续约束评分，不能为了启动PPO给记忆引用加分。本轮为“该改哪些示范、单靠提示是否足够”增加了具体证据；尚未解决可扩展收益反馈，也没有形成可证明有益读取的RL结果。
