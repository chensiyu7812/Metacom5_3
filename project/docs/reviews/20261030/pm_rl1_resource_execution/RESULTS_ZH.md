首先发现的是采样顺序问题：三个加载前回执中，较早的CSV利用率均为2%，较晚的XML均为0%，显存空闲48,551 MiB、无可见进程；原实现用较早读数决定准入。新固定比较入口明确使用最后采集的XML快照，保留全部早晚读数。仍要求利用率0%、空闲至少45,000 MiB、没有其他可见GPU进程。测试确认：较早0%而较晚2%时必须拒绝；最新显存不足或快照缺字段也拒绝。不是选择两者的较小值，不放宽阈值。历史调用方默认仍使用原采样方式。

该修复发生在任何模型加载前。原 `1f3b5d15` 包以0加载/0生成封存，新包仅更新技术采样实现身份，43个输入消息、原G及解码、总加载/调用上限均核对不变，沿用同一次研究者操作授权；没有把它算成新增加载额度。前三次加载前拦截与原批准记录完整保留。
