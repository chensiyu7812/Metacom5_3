# PM-RL1 P1 实施结果与接续（2026-10-01）

P1 已完成有限来源修复、表示实现、实际容量复算和开发回归。当前采用 `DirectReplyRenderer`：历史带说话者作为引用背景，最新一句保留原生 user 消息。可以进入 P2 执行器适配；尚未获得自然任务 reward 资格，也没有自然任务 PPO 结果。

事前依据：[可行方案 v2](PM_RL1_FEASIBLE_COMPLETION_PLAN_20260930_ZH.md)、[能力反推](PM_RL1_CAPABILITY_BACKWARD_DESIGN_20261001_ZH.md)。本报告记录真实执行，包括原定72条之外的16条接口修复，不回写事前计划伪装成没有偏离。

## 已处理到什么程度

| 缺口 | 已落实 | 保留的边界 |
|---|---|---|
| 谁说的、谁的经历 | 历史 supporter 不再映射为当前 AI 的 assistant 消息；源引用保留说话者 | 提示和表示不能保证模型完全遵守；旧 LoRA 仍有一例“当我刚才说……”的错误归属 |
| 过去事实是否仍成立 | MP 交付为过去报告；报告时间、事件时间、再次确认时间分开；未知不填确定值 | 未做全量事实时效重标；引用支持也不等于客观真实或今天仍然成立 |
| 打算、行动、结果混同 | 固定24个 ME 片段逐条绑定来源，区分意向、尝试、完成、假设和结果 | 其余 ME 不自动推断行动阶段或效果；未审摘要仍可能有语义问题 |
| 缺证据的 MP 更新 | 完成剩余72条 train/dev 审查，继承旧101条；抑制证据不足的新版本 | 抑制新版本后不自动把更旧版本恢复成当前事实；28条 test 待审不进入开发审查 |
| 资源成本与公平观测 | 新证据字段计入真实 token 成本；新增共同70计划合法性特征，旧特征身份保留 | OneShot／自然 PPO 的完整训练 runner 仍待后续实现；当前不是已经训练的策略 |
| 回复接口 | 整体 JSON 输入的失败被记录；最新一句恢复原生 user 后做一次有界回归 | 本轮是开发修复，不是独立泛化实验，也不证明支持质量提高 |

RS 的真人自我披露改为明确的 AI 兼容动作：可用假设例子或一般观察，不继承真人家庭经历。MS 仍保留完整历史会话，没有用摘要替代或为预算截断。MP／ME 的来源字段只随已获取正文交付，未取正文、owner、审查理由、奖励标签不进入策略观测。

## 来源核查的具体结果

新增72条 MP 中，10条引用足以支持该次完整属性重述，48条只支持其中一部分，14条与该属性不相关。后62条按既有规则抑制更新。**这不是62条事实为假的结论，更不是整个数据集的错误率。** 加上旧101条，目前合计173条有记录。

例如，“收到大学录取”不足以重新确认“18岁”；“某人回家了”不足以重新确认完整亲属关系。对这类更新，我们处理的是证据与断言不匹配，不凭没有提及就认定事实发生变化。

24个 ME 按源片段 hash 和已有结果／行动／事件字段分层预选，全部来自 train/dev。经 AI 辅助来源审查，行动阶段为意向7、尝试4、完成6、假设1、不适用6。典型修正包括：

- “考虑夫妻治疗”“明天找经理谈”保留为意向；没有原文依据的效果不保留。
- “冥想和散步有一点帮助”“散步没多大帮助”保留有限或混合效果，不提升为成功／完全无效。
- 必要的指代上下文来自同一源会话，交付时也计费；原始数据不改写。

这96个新增来源条目的审查是 **AI 辅助弱标注**，不是用户新做人评，不是独立人工真值，也不用于给训练回复直接发放 reward。脚本75绑定了本地已准备队列的字节哈希；它记录审查结果，不声称能仅凭远端代码自动重建所有私有队列。

## 数据特征确实怎样用于实现

重复属性与引用特征定位 MP 更新问题；ME 行动／结果字段定位混淆并固定有限核查范围；历史说话者特征定位身份案例；真实长度与可达性决定训练条件。这些特征已改变数据交付和执行流程，没有把“风险特征高”直接当作低质量 reward。

对96个 train、18个 dev 前缀，来源过滤后重新计算记忆检索，RS 排序沿用旧冻结结果。检索编码仍用旧规范内容，交付时再附加来源字段，以免把检索语义变化混入表示对照。

| 实际容量 | 结果 |
|---|---:|
| train/dev 前缀 | 114 |
| 相同修复库存、旧交付表示的可达终值计划 | 7,170 |
| 新交付表示的可达终值计划 | 6,899 |

## 72条原诊断与16条修复

原诊断固定六个 dev 前缀、三个 owner：base／旧 epoch3 LoRA × 旧／v2表示 × OFF／RS-only／memory-only，共72条。两个表示使用相同修复后条目；“新旧表示”是角色、包装和 RS 动作说明的组合对照，不是单一字段消融，也没有单独识别来源过滤的效果。

本次六个 memory-only 条件按事前相似度规则选出的都是 **MS**。因此，这72条不能证明 MP／ME 修复已改善生成，更不能证明多资源条件已学会。

已知母亲案例的直接证据：

| 同一个开发案例 | 观察 |
|---|---|
| 旧 LoRA＋旧表示，OFF／RS／MS | 三个回复均编造自己的母亲或人生经历 |
| 旧 LoRA＋v2整体 JSON 表示，OFF／RS／MS | 三个回复均出现不必要的拒答；避免编造没有自动带来可用回复 |
| base＋v2 | 部分回复分析 seeker／supporter，而非自然接续当前用户 |
| 最新一句恢复原生 user 的 direct_v3 | 补充16条全部直接回复，无上述拒答；旧 LoRA 的该案例 OFF 仍把历史 supporter 的原话认作自己说过 |

因此增加了**一次明确记账的接口修复**：原六个前缀 OFF，加该身份案例原 RS／MS 条件，两执行器共16条。原72条全部保留。16条属于发现问题后的开发回归，不是独立确认，也不计作技术重试或隐藏在原72条额度里。本轮不继续搜索提示。

16条均逐条做过 AI 辅助开发检查；旧72条中的母亲案例12条也保留了来源和回复证据，其余60条没有生成“全量语义通过率”。旧 LoRA 的 MS 回复还存在把过去家庭／大学情境直接带到现在的谨慎性问题，本报告不将此直接判为事实已被证实为假。

## 接下来怎样推进

P2已固定每前缀六种合法条件：OFF、单条、跨类两条、同类两条、三条、四条，共684个（train576、dev108），没有不可行槽位或重复替换。每种train类别均覆盖96个前缀、12个owner。选择按合法库存与固定 hash，不看回复质量；12个 dev 行为检查输入也已固定，每类别2个、每owner4个，保留已知身份案例。见[P2输入统计](pm_rl1_completion_20260930_v2/p2_input_summary.json)。

之后绑定本地示范作者及逐条来源核验，制作一次弱监督候选与有界修复。**输入清单存在不等于标签已接纳，更不等于新执行器已经训练。** 来源引用、当前性、意向／行动／结果、合理忽略资源与说话者归属，都要进入准入记录；作者只能看到相应条件实际交付的输入。

沿用已定计划：从 base 做一次最多三 epoch 的 LoRA，排除有来源证实的严重回归，再按开发 NLL 选择；没有合格 checkpoint 就继续新版输入下的 base，不无限加训。然后冻结主执行器，构造共同回复池和有限测量校准包。

目前尚需真正解决的是：执行器在 MP／ME、多条资源下能否可靠使用／澄清／忽略；评分边界能否在真实回复上稳定执行；由此是否产生可学习的资源净收益差异。P1提供了更明确的事实边界与可运行输入，但没有替代后续质量和 reward 验证。
