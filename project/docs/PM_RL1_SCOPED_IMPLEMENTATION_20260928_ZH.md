## 2. 取消任务级回复硬截断

新自然支持回复不设置 60、256、512 等任务级输出 token 上限。局部生成接口 `LocalNaturalGenerator` 用模型实际 `generation_config.json` 的 EOS 列表结束；当前 Llama 配置是 `[128001,128008,128009]`。这与旧批处理的 EOT-only 配置身份有差异，不能跨配置直接命中旧回复缓存。

明确传入 `max_new_tokens = native_context_limit - actual_chat_prompt_tokens`，避免删除参数后落回库默认短上限。`forced_eos_token_id=None`，不把达到长度边界时强行补出的 EOS 当作自然结束。`do_sample=False`、seed=0，加载实际 tokenizer/chat template，完整记录模型权重哈希、软件、设备与解码配置。

保留不可回避的模型上下文边界和技术异常保护：300 秒逐解码步检查、连续四次相同 32-token 尾块的循环检查。它们是开发阶段技术配置，正式训练前须统一冻结。超时、循环、上下文耗尽、空输出都进入未完成状态，不打零分。逐步 watchdog 不能保证中断卡死的 CUDA kernel，HTTP 断开/进程监督/队列恢复仍待接线与验证。

旧 `46_serve_local_llama31_reference.py` 继续保留其历史实验接口，PM-RL1 不使用它。这里已实现的是本地进程生成接口；没有把尚未实现的新 HTTP 服务写成已部署。

## 3. 保留资源输入预算

2,048 tokens 是资源信息获取预算，包含资源指导、来源标签、时间、分隔符和正文，与回复长度限制不同。它定义各策略共享的动作域。当前仅为开发候选值，先比较 1,024 / 2,048 / 4,096 的完整渲染容量再冻结。

MS 必须是完整原始过去 session；不能截短 MS 来勉强容纳下一条。GET 只取各类下一条，累计至多四条，已取资源全部交给 G；RS 指导允许合理不采用。规范顺序为 RS / MP / MS / ME，类内按冻结排名。

GET 回报使用真实整块 tokenizer 长度差，不裁掉负差值；STOP 只给实际质量效用差，不再扣一次资源费用。初始 OneShot mask 按逐步可达性计算，避免非单调 token 长度下凭空进入顺序策略不可达的计划。
