# PM-RL1-J：静态收口与动态 Agent 计量交付

起点为 `f2d59f1c42de672c0785e034dbbd76e424f5529e`。本轮新增模型调用、模型加载、GPU、收费 API 和训练均为 **0**。动态执行器已完成真实来源的 CPU 接线、冻结和独立准入检查；真实模型运行仍待研究者新批准。

研究目标按研究者决定明确为：**用户当前目标完成、资源使用可靠性、与用户体验相关的实际端到端延迟**。tokens、访问次数和 GPU 消耗只作辅助机制指标。M0+R0 是合法系统行为；自然支持按用户需要评价，不要求复述全部记忆。

## 2. 动态执行器已完成什么

新增独立运行身份 `pmrl1-j-dynamic88-run-v1`，保留原提案的 **8 题、4 个来源情境、每情境事实与自然支持两个目标、六臂**。来源、任务、评价、初始控制提示和确定策略不变；旧 FiniteHeadEnv、旧生成和负结果不变。没有新来源选择或结果筛题。

实际链路是：可见请求进入本地 Agent → 实际来源与时间身份检查 → 控制器 → SEARCH/EXPAND 的实际返回 → 观察及可执行动作更新 → 后续控制器或 STOP → 原 renderer/native tokenizer → 原 Generator。OneShot 只接初始观察并一次承诺程序；ToolAgent 后续输入只来自实际已读观察。每步保存任务、状态、观察、请求、输入 IDs、工具返回、终局和事件前驱 SHA。未读正文、评价答案和人工必要来源不进入控制器或检索输入。

监督器与 worker 分别执行任务/角色/总 start 预算，失败 start 也占用额度；独立审批不继承旧授权。来源配对有不可覆盖的尝试登记，换执行器或审批文件也不能隐式重试。模型、设备、存储、单作业全局 deadline 和原 worker 守卫保留；只清理本作业进程。

最终冻结执行器实际 CPU 回放：**8 题 × 六臂 = 48 条路径，88 次协议测试替身分发，0 次真实模型调用**。全部运行真实 Ledger/PrefixPort、合法来源检索、展开、renderer 和 native tokenizer；32 个确定臂的 `messages/input_ids/decode` 与旧冻结请求逐字一致。测试替身 JSON 只检验运输和控制协议，没有被写成模型推理或任务成功。最终全 Journal 测试 **429 通过、0 失败、0 跳过**。详见 [最终 CPU 收据](dynamic_v1/FROZEN_EXECUTOR_CPU_CHECK.json)与[交付核验](DYNAMIC88_VALIDATION_PUBLIC.json)。

CPU 准备期间出现过一次原提案字段名称读取错误，失败的 `packages-v1` 保留。修正后建立新的 `packages-v2`；不存在覆盖旧包或模型重试。活动包只冻结一次有效运行身份，运行时不自动改协议。

## 3. 控制器 JSON 的实际可执行性

复用 SC36 的本地 XGrammar 0.1.21 隔离依赖，给两个新控制器冻结共同语法协议。grammar 只限制 JSON 结构，不使用正确动作、gold、候选源位置或任务答案。查询词、已读句柄、动作次数及 STOP 后不得行动，由独立状态检查处理；不修复非法模型动作或将其静默替换成 STOP。

native tokenizer 的 CPU 回放发现：原 `no_repeat_ngram_size=3` 会阻断 18 条指定合法路径中的 15 条预定下一 token。它并不证明所有合法输出死锁，本次没有观察到全有限 logits 为空。新协议将**两个控制器共同设为 `no_repeat_ngram_size=0`**，18/18 指定路径完成；终局 G 仍保留原 decode（包括原值 3）。这是生成前公开的新控制身份，需要本次独立批准，不是遇错后放宽。

合法有限 logits 交集、NaN/正无穷、EOS、重复键、尾随文本、未读词、句柄、截断等均有 CPU 检查；真实模型仍可能产生语法合法但状态非法的动作。此类协议/长度技术失败按冻结规则停整包，0 重试，不能当科学负结果或成功。详见[共同协议及局限](dynamic_v1/CONTROLLER_PROTOCOL_AND_LATENCY_ZH.md)。

## 4. 六臂公平性与不等价之处

|臂|读前/读后信息与动作|控制器模型调用 / 题|终局 G / 题|比较边界|
|---|---|---:|---:|---|
|STOP|只用当前可见请求，立即结束获取|0|1|完整合法基线，不要求调用资源|
|FixedTop4Macro|初始 query 的合法 Top4，读取完整 parent|0|1|1 检索 + 4 读取 = **5 原语**；强实践基线，不是四动作匹配臂|
|LLMOneShot|同一模型仅看初始观察，一次承诺 SEARCH/EXPAND/STOP 程序|1|1|至多四次获取，不能读后改计划；EXPAND 引用先前 SEARCH 及 rank|
|LLMToolAgent|同一模型每次看实际返回，逐步决定 SEARCH/EXPAND/STOP|≤4|1|同一原语动作域；只允许已观察 handle 和合法 query 词|
|SequentialRule|沿用已冻结的透明读后规则|0|1|不是训练 PM；与 LLM 的规划计算量不同|
|SequentialNoText|沿用已有透明规则及非正文线索|0|1|**不是同一 LLM 的正文屏蔽消融**，不用于隔离 LLM 读文本的因果效应|

共同部分：同一来源池及时间边界、同一用户目标、同一终局 G/system/decode、同一终局评价、相同工具规则与上下文限制（资源 4096 native tokens、输入加预留输出的上下文 16384）。两个 LLM 控制器使用同一基础模型、共同新 grammar/decode，OneShot 输出上限 1×768、ToolAgent 上限 4×192；总输出上限相等不代表输入量、调用次数、规划能力或延迟相等，必须报告实际值。Top4 的原语及完整会话粒度差异保留，不能用共同 token cap 消除。

为测量实际运行延迟，**本包关闭端点结果缓存**，即使精确 payload 相等也各自真实执行；仍不超过 48 个终局 + 8 个 OneShot + 32 个 ToolAgent = 88 次。以后若为质量分析复用端点，必须另标 `reused/not_executed`，不能把缓存返回当部署时延优势。

原固定臂序保留，不临时随机化：STOP、Top4、OneShot、ToolAgent、Rule、NoText。每作业第一次 STOP 是加载后的首次推理，其余共享后续运行状态；0 warmup，不因计时结果重跑。**这批适合发现路径和时间组成，不足以给出随机化、稳定尾延迟或部署因果结论。**每臂 n=8 的 nearest-rank P95 仍是最大观察值，事实/支持分层各 n=4。后续若需要生产延迟结论，须新冻结冷热/并发/顺序平衡，而不改本包。

来源均是先前已暴露的开发来源。按四个来源情境和成对目标报告，不把八题或各轮控制器当独立来源样本。ToolAgent 若优于 OneShot，也须分别检查新增证据、证据利用、目标适用性及真实时间；不能只用访问次数或 tokens 解释优劣。

## 5. 实际计时合同与观察面

所有可相减的本机事件使用 `CLOCK_MONOTONIC`、`boot_id`、纳秒值和 PID，保存哈希链。CPU 已验证父子进程同域可比；跨主机、跨 boot 或 UTC 不直接相减。

|观察|新增实际执行钩子|包含关系与限制|
|---|---|---|
|请求进入 Agent|`AGENT_PATH_START`，在每条路径实际建状态前|基准把可见请求交给 Agent 的时刻；不是 HTTP/客户端/用户说完话|
|控制器|request start、worker generate start/end、首 token/首非空文字、严格动作或程序 validated|首可执行控制输出在完整 JSON 严格校验后；首个花括号不算有效动作|
|工具及供应|SEARCH/EXPAND、合法性、原文跨度选择、token 计数、native chat tokenization、renderer spans|工具 wall 包含子检查；renderer 包含相关 tokenization，不重复相加|
|PM 完成|`PM_FINISHED`，终局实际输入绑定后|包括控制调用、工具、打包和相关日志；未发生则保持缺失|
|最终 G|request start、worker generate、首非空解码文字、完整返回及校验结束|首文字只表示可见字符，标点也可满足；不代表语义正确或有效支持|
|完整在线路径|入口至经过验证的完整回复 ready|本地文本 Agent wall，包含控制、工具、IPC、实验守卫和日志；不包含网络、播放、ASR/TTS|
|冷启动|来源 startup、worker spawn、外层 load 与 worker load|独立报告，存在嵌套；不把每题都算一次 load，也不隐去整作业冷启动|
|失败|开始、部分时长、错误、budget refusal、pending、deadline及私有 wire 证据|未测为 null；超时/截断不填零，不丢失失败 start，不自动续跑|

当前 HF stdout 仅在最终回包发送文本，**client TTFT 固定未测**。新增被动 streamer 记录 worker 内首 token 和首非空解码文字，不改变 logits、tokens 或终局语义配置；它会带来逐 token CPU 传输、同步和解码开销。`callback_work_ns` 只含回调内部，可能漏掉进入回调前的传输；完整 generation wall 则包含全部观察开销。各臂使用相同测量身份，但本轮未用 GPU 验证其真实数值，也不把它与历史未加 observer 的计时直接当同条件配对。

日志保存区间及嵌套关系。job wall 包含模型字节检查、来源准备和 load；常驻在线路径不包含这些启动工作。完整路径直接用起止相减，不通过相加组件构造。首文字未出现、技术未完成、模型 load 失败分别报告；有 1–2 个终局 length 的作业即使循环结束，也保留 pending 和 `all_endpoints_technically_complete=false`。第三次终局 length、任何控制协议/长度错误及原守卫失败按冻结规则停机。

Tokkio 未来主值是同客户端“用户最后语音样本结束 → 首段本轮正文语音实际播放”和“→ 最后一段播放结束”，另记 ASR/PM/G/TTS/网络/缓冲及并行关系。当前仅有[协议](dynamic_v1/SMV_LATENCY_TOKKIO_PROTOCOL_ZH.md)，没有接入数字人，也没有音频端到端结果。

## 6. 下一阶段研究决策

**已有证据**：SMV30 支持在这批开发任务中按需要获取 Memory，STOP 能成为成功路径；资源供给与事实使用仍不能互相替代。新 CPU 结果证明能够执行读后改 query/EXPAND 的独立协议、严守身份并记录时间。它没有证明 LLM 能正确规划、序贯优于静态、资源任务收益或延迟优势。

**本轮决定**：关闭同类静态扩样和 C1 调参。保留 RAW/SPAN、MS-SUM 导航、Time-Lexical 基线与 Hybrid 竞争候选；MP/ME pending/mask、同类 RS 扩充停止、五项真人复核仍 pending。旧 220 次未运行额度、PR #28 和全部历史评价保持原身份。不另开 Step-2、BC/PPO 或新 G 训练。

**下一次唯一有限验证**：按原八题六臂运行，先判断当前目标和已读内容是否真的改变合法下一动作及最终目标完成。分别呈现事实目标、支持目标、可靠性错误、完整/未知、读后获取路径和实际时间，不把证据覆盖当成功；不强制多次获取。若没有可确认的任务收益，收窄该数据与预算下的序贯主张，不用不断换案例或卡片寻找正结果；不把有限负结果外推为长期交互 POMDP 普遍无效。

**未来可研究但未实施**：在动作前加入 `elapsed_agent_wall`、`remaining_time`、实际剩余可行动作、已读证据及其充分性/冲突/未知、当前目标和已观察运行状态。尚无同客户端时钟桥时，用户说完话以来耗时置空。未来动作耗时来自独立校准的预测及不确定界，不用本轮未来真实时长、gold 或未读正文。停止机制应约束真实墙钟与任务可靠性，不能退化为 token 惩罚；本包只计时，不把 elapsed-time 接入旧策略。

轻量 PM 未来可能替代重复大型 LLM 规划，但需同时证明读后选择能力和实际在线收益，并计入编码、查询生成、合法性检查及最终 G 成本。现有透明规则不是已训练的轻量 PM，CPU 开销较小也不证明任务收益。当前将其作为待验证工程/研究假设，不宣称 POMDP、动态检索或小模型规划本身构成创新。

RQ1 仍有有限 Memory 任务修复证据，RS 独立专业增量未成立；RQ2 资源组织与检索增量须与供给量和 G 使用分开；RQ3 读后动作/观察执行已实现、效果尚未运行；RQ4 增加了完整文本 Agent 的计量通道，数字人端到端及长期自然支持外部验证仍未完成。

具体批准对象见 [DYNAMIC88_RUN_REQUEST_ZH.md](DYNAMIC88_RUN_REQUEST_ZH.md)，复跑见 [REPRODUCE_DYNAMIC88_ZH.md](REPRODUCE_DYNAMIC88_ZH.md)。CPU 就绪不构成 GPU 授权。
