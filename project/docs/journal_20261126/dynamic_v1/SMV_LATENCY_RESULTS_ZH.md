本轮从 `f2d59f1c` 继续，只复算既有 30 个真实输出、原评价和冻结策略选择。没有新模型调用，没有改 C1、任务或语义标签。**任务成功、可靠性和实际用户体验优先；token 仅作辅助解释。**

## 4. 物理成本与因果限制

30次物理生成合计156.709秒；两个整作业wall合计296.629秒。两次worker load合计54.398秒，其外层supervisor load约84.203秒，存在包含关系，不可相加；加载不按四策略重复计费。30次均EOS；本分析没有删掉失败样本来美化时延，只是该固定批次没有技术失败。

每端点仅一次计时，原请求按冻结顺序串行执行，没有为本问题随机化重复延迟试验。输入长度、输出长短、调用顺序、GPU调度/缓存/加载后的状态均可能影响时间；确定性解码不使运行秒数成为确定常量。原STOP/MS输出tokens分别954/870，C1/简单基线选择后为829/839；这些差异提示不能把总时间差单归因于检索或输入压缩。

本批没有实时PM决策、在线检索/打包、网络、ASR、TTS、播放或客户端时间；不能用未实测的CPU/GPU工程估算填补缺口。C1的5.687秒只是复用生成分量差，可能被实际选择/获取开销抵消或改变。不能把四策略秒数相加称为本轮真实总花费。原语义观察依然是助手开发观察，非独立人评、非正式reward。

未来端到端与elapsed-time状态建议见 [SMV_LATENCY_TOKKIO_PROTOCOL_ZH.md](SMV_LATENCY_TOKKIO_PROTOCOL_ZH.md)。本轮不接系统。
