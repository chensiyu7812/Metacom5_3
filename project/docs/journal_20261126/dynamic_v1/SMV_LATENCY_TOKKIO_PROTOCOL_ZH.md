# Tokkio 端到端计时与 elapsed-time 状态：未来接线协议

本文件仅规划，尚未接入 Tokkio，也没有测得语音端到端收益。有限查看当前研究 checkout 和本机顶层目录后，未确认可检查的 Tokkio ASR/TTS/播放客户端部署源码，因此以下是待映射到实际版本的事件契约，不声称某个现行组件已经暴露这些事件。本轮不连接系统、不启动服务、不调用模型。

复用本仓库的[客户端计时 v3 合同](../../../data/paper1_authority/paper1_client_latency_measurement_contract_v3.json)、[旧文本端到端合同](../../../data/paper1_authority/paper1_end_to_end_latency_policy_contract_v1.json)及[客户端统计实现](../../../src/metacom_pm/paper1/evaluation/client_latency.py)中的同客户端单调钟、原始逐调用分位数、配对时间块、冷/热分层和失败保留原则。旧 Paper-1 的文本专用字段、60 秒阈值及其奖励/资格规则保留原身份，不自动成为新的音频 SLA 或 PM-RL1-J 奖励。

## 1. 研究目标与比较单位

先报告当前任务是否完成、事实/来源/时间可靠性、支持要求和用户边界；不把少读、少生成或快拒答自动当成功。自然支持仍按当前目标评价，不能把可选回忆变成强制任务。语义未知保留，技术失败与语义失败分开。

在满足同一预冻结任务和可靠性要求的候选中，再比较真实用户等待时间及尾部延迟。输入/输出 tokens、检索次数和模型时长是解释变量及资源诊断，不是主要优化目标。策略增加少量获取时间但改善任务完成时，应在任务—时间前沿上呈现，不因 token 增加提前否决；反之，低延迟但未完成任务不能称效率提升。

未来比较必须固定任务、G、输出规则、服务/模型状态、连接复用与并发，按目标相邻执行并预先随机化臂序和目标微块序。按独立来源/用户家族报告相关性；不得把共享端点、共享情境的通道变体当独立样本。重复数、失败期限、实用非劣界及 SLA 在新测量前确定，不能从本次 15 题的耗时或质量结果反推。

## 2. 同客户端的主观察面

同一个会话客户端记录单调时间 `t_user_end`：用户最后一个语音样本结束的捕获时间。应把音频设备采样时间线映射到该客户端单调钟，保存映射误差和端点检测规则。这个起点不是 ASR 最终文本到达时间；用后者会漏掉端点等待和识别尾部开销。实时端点可能稍后才确认，确认延迟另记，不能回写为零。

|事件或指标|固定含义|不得替代为|
|---|---|---|
|`t_user_end`|本轮最后用户语音样本结束；保存修订版本及确认事件|ASR final 时间或 PM 接收时间|
|`t_first_any_audio_played`|本轮首个实际可听非静音音频样本开始播放|首包收到或排入播放队列|
|`t_first_task_audio_played`|本轮回答正文首段实际开始播放；预先排除等待提示、耳标、旧轮残留|“正在处理”等占位语或服务端合成完成|
|`t_playback_complete`|本轮完整回答最后一个有效音频样本播放完毕|最后音频包到达、TTS 结束或文本 EOS|
|首段有效音频等待|`t_first_task_audio_played - t_user_end`|生成 TTFT 或输入 token 估计|
|完整播放等待|`t_playback_complete - t_user_end`|模型耗时、分组件之和|

“有效”在这里表示属于本轮回答正文、实际可听、非占位，**不代表内容已经正确或有用**。必须同时报告任务评价和该指标，不能事后跳过错误开头，只选后面正确的一句重新定义首段时间。正文段与音频 chunk 用 `turn_id / response_id / segment_id` 对齐。客户端回调若只表明已调度而非已播放，应明确标为代理观察面；没有硬件回环时不声称精确声学听到时间。

## 3. 时钟、包含关系与并行

每个事件保存 `trace_id、turn_id、process_id、clock_domain_id、monotonic_ns、event、parent_span_id、attempt_id、measurement_surface、warm_or_cold、concurrency`。跨机器、跨进程或音频设备与浏览器的时间戳，未证明同一时钟域前不得相减。UTC 只用于追踪和粗略排序；NTP 同步不是直接相减的充分证明。浏览器音频时钟、捕获样本钟与 UI 单调钟需要成对校准与漂移/误差记录；跨主机 trace 依赖消息父子关系和各域内部 duration。若必须对齐，报告校准方法和不确定界，不能隐藏为精确端到端值。

端到端主值由客户端起止点直接测量。服务端各阶段记录本地单调跨度，并保留并行依赖图：ASR、PM 控制器、SEARCH/EXPAND、打包、G prefill/decode、TTS、网络、缓冲/播放可能部分重叠。并行耗时既不能逐项相加，也不能简单全部取最大值；实际关键路径须由依赖和时间观察确定。包含关系须明确：请求 wall 已含排队/IPC 时，不再把其子 span 重复加总。

|诊断层|分别记录|
|---|---|
|客户端/传输|端点确认、发送、收包、解码、缓冲、实际播放、网络/连接复用状态|
|Agent|入口→终点 wall、每次控制器动作 wall、排队、重试、各获取动作开始/结束/被取消|
|模型|进程冷启动、tokenizer/权重 load、prefill、decode、首 token、完整输出；不齐的字段保持 missing|
|音频|ASR partial/final、TTS 首 chunk/完成、首正文音频播放、完整播放、打断/音频缺口|
|离线工作|来源构建、评价、Judge、统计：不进入用户等待时间|

SMV 的 `seconds` 只围绕本地 `model.generate` 至随后 GPU synchronize；tokenization/载入在外、文本解码和 IPC 在后，未拆 prefill/decode，更没有客户端和音频事件。两个 worker load 与更外层 supervisor load 相互包含，均包含在各作业 wall 内。不能把它们相加冒充 Agent 总耗时，也不能按策略摊分既有两次 load 制造部署成本。

## 4. 失败、打断、可靠性与分位数

超时、没有正文音频、ASR 无结果、空回答、错误轮音频、截断、TTS/网络失败全部保留；给出完整分母、状态与观察截止时间。未发生终点的样本是未完成或删失，不填零、不只保留成功样本，也不把它当确实在截止时间完成。若未来采用预冻结的超时惩罚指标，单列其人为下限，和真实观察值分开。成功 fallback 的延迟用实际客户端结果，另报触发原因/频率，不能凭 fallback 标签强加超时值。

用户打断、主动取消和系统失败分开。被打断的回答没有“完整播放完成”，报告至打断的时间、已播放长度和交互状态，不能视为完整回答。重试保留全部尝试，主用户等待从原起点持续计时，不从最后成功尝试重置。

每个相同观察面/冷热状态/并发分层，报告原始逐调用 P50/P95、max、n、失败率、打断率；采用 nearest-rank `sorted[ceil(p*n)-1]`，不对状态均值再取分位数。小样本尾分位不是稳定生产 SLA。预先采用相邻配对、多时间块后再讨论时间差；不能靠“输入变少”替代观察。

## 5. PM 的未来 elapsed-time 状态

在控制器每次决策开始时保存可见状态：本进程合法的 `elapsed_agent_wall_ms`、已完成动作/失败/重试、正在运行的工作及其已观察持续时间、已读内容和当前有效资源状态。若已有经过验证的同客户端时间桥，可另给 `elapsed_since_user_end_ms` 及误差；没有则置空，不用两个机器的单调时间直接相减。冷/热、连接、并发和可观察排队状态也应在允许范围内显式记录。

新增获取、继续查询或 STOP 的预期剩余时间只能来自动作前可用的历史训练/校准数据及当前可见状态，预测区间与实测值分开。不得把本轮未来生成秒、最终成功标签、未读来源或未完成动作的未来成本塞入当前状态。并行运行时用已观察 wall 与依赖状态；累计 tokens 不能替代已经过去的时间。

未来可研究“在任务成功和可靠性约束下，按已耗时与预期信息增量决定继续或停止”，但本轮不设置权重、不训练策略、不修改原 C1，也不把这些字段接成正式 reward。需要实际接线和经过授权的 E2E 测量后，才能比较是否改善用户等待体验。
