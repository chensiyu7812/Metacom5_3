# PM-RL1-J：原目标、实际机制与下一阶段研究审查

审查起点：`c40b90c99cb991cf1c2793ffbe9927a0011885ab`。本轮新增模型调用、GPU作业、付费API及训练均为0。旧DR3不修、不重跑；53次实际调用、原始输出、评价和全部负结果保持。本报告及代码诊断是新增旁证，不是对旧结果重新打分。

**结论：现有实现已经完成可追溯、时间合法的小池Memory获取实验，但尚未实现研究目标所要求的完整“用户目标—读后信息—获取/支持行为—真实等待”条件决策。** DR负结果仅约束这套动作、表示、来源与控制协议，不能否定完整POMDP或长期陪伴方向。继续研究有依据；直接进入轻量PM训练尚无充分依据。优先修订的是证据单元和查询/状态合同，并检验具体继续动作的价值，不是再扩大相同静态任务或追求更低token。

## 1. 原研究目标与实际实现的差距

研究面向实时长期陪伴数字人。Generator已有较强基础自然对话能力，M0+R0是合法且有价值的成功路径。PM应根据当前需求、用户可见状态、已获得信息和实际时间代价，决定是否获取、取何种能力、取多少、是否继续，以及如何适当地支持。自然支持不要求机械复述全部个人记忆。

原[9月单轮实施方案](../PM_RL1_ORIGINAL_IMPLEMENTATION_PLAN_20260928_ZH.md)已明确区分自然pre-supporter前缀、受控诊断与长期用户转移；[V3.1 §0/6.9](../PM_RL1_SOLUTION_PLAN_V3_20261116_ZH.md)区分四头有限子集与内容自适应阶段；[Journal主方案](../journal_20261125/MASTER_PLAN_ZH.md)保留RQ1–RQ4与失败收缩分支。它们都是历史方向/边界，当前用户指令控制本轮：不训练、不重开资格、不覆盖冻结实验。

`allowed_tokens`和`status`虽然不直接在旧hash里，目前分别能由初始query+contents、done重建；本轮没有把这些遗漏一概宣布为独立碰撞。已读排除、重复获取收费、handle版本、拒绝后STOP与whole-parent展开是新设计的明确取舍，不能事后改原运行含义。

当前观察里确有用户query、已读内容、handle、last_hits、input/access/token预算和动作类型mask。它没有公开task的timestamp、实际elapsed/remaining-time、按粒度的可达候选或目标缺口；`belief`只有计数。这是可核查的设计限制，而“增加这些字段就会改善任务”仍是假设。新字段不能从人工needs层、gold引用或未读正文生成。

## 4. 数据适用性与真实条件空间

详见[来源用途与逐情境诊断](system_review_v1/DATA_FIT_AND_SOURCE_DIAGNOSTICS_ZH.md)。只读取既有已暴露开发缓存，未打开封存测试正文、未修改旧评价、未根据生成效果重选任务。原DR8题与扩展检查的已有16个CPU任务分母分开；后者是原8个来源情境的事实/支持两目标，不是新采样实验。

本轮实际拆开了两类词面诊断。16条原完整query的Top2中，32个span含9个支持者问句，563个匹配token位有407落入本轮CPU比较前固定的功能词表；移除功能词的CPU敏感性排序改变10/16个Top2。包装独有匹配只有2位，去包装没有改变Top2，因此**不能把包装词写成已证实的主要排序原因**。实际LLM改写只有4次SEARCH、8个span，其中4个为支持者问句，其匹配没有功能词贡献；这种失败不能套用原完整query的停用词解释。该词表在旧结果已暴露之后建立，敏感性条件仅用于诊断，不是旧实验预注册，也没有替换Time-Lexical或旧请求。

原16个构造任务与真实pre-supporter前缀不是同一输入对象；可信Prefix用于来源合法性，不代表G实际看到了完整自然对话。原文中的报告更新、计划/执行边界和未知可用于证据条件研究，但自然支持目标有构造成分，不能当真实需求流行率或人群效果。

八类情况分别记录“存在”“局部/条件成立”“本池未证实”。当前充分和合法信息仍无法确认有实例；多来源历史需求与后续阶段报告也有实例。**本池没有得到历史事实任务第一次SEARCH后全部必要证据齐全的正例**，当前信息已充分的任务不能替它充数。历史阶段改变不自动证明旧报告失实或失效；没有明确撤回/失效证据时保持未知。来源可用、潜在增量、实际供给和最终完成不合并。

EvoEmo/ES-MemEval适合时间合法记忆及受控事实研究，不能直接提供真实长期干预因果数据。ESConv适合支持对话前缀/行为示例，不能伪装成同用户纵向记忆；AnnoMI标签用于行为识别，TIP35方法需保留原领域和适用性边界。数据与标签各有用途，不能将行为识别准确率作为支持质量或RL奖励。

## 5. 原T01、T03中间状态：有限对照的意义

保持原预选两状态。CPU已恢复state、完整observation、handles/last_hits、剩余预算和原G payload；每个状态有2个实际可见EXPAND候选，四个都时间合法且预算可达。候选贡献先按原文区间增量记录，必要原子覆盖仅在评价侧另算，绝不决定rank选择。

预定rank1展开使T01输入355→1034 tokens、T03输入356→1092 tokens；各增加23个原话轮并重复包含先前1个话轮。计数不是任务收益。rank2即使有不同贡献也不替换预选rank1。

选择冻结后的独立供证核对显示：T01选中分支的完整必要原引用群由1/3增至2/3，T03由0/2增至1/2，**两者仍各缺一个群**。T01第二候选不增加完整必要群；T03第二候选补的是另一群。参考群不是全部可能等价证据的穷尽真值，但现有检查不支持“这一步展开就足够回答全题”的预期。申请仍保留原完整任务评价，另报告新增供证的使用、角色/阶段错误是否修复及合理未知，不因结果降格成功标准。

新包只比较每状态STOP与rank1 EXPAND后STOP，共最多4次终局G。两分支都重新实际执行，分支时间从相同恢复完成的决策点起算；状态恢复和冷启动单列。旧STOP只核对质量与payload，不能当新分支延迟。完整CPU诊断和冻结申请见[MIDSTATE_CPU_DIAGNOSTICS_ZH.md](system_review_v1/MIDSTATE_CPU_DIAGNOSTICS_ZH.md)、[MIDSTATE4_RUN_REQUEST_ZH.md](system_review_v1/MIDSTATE4_RUN_REQUEST_ZH.md)。未获独立批准前不运行。

这个实验只能检验一次具体继续动作。即使修复，也不能证明读后语义查询、多能力选择或完整序贯策略有效；若不修复，也不能证明其他合法动作无价值。后续不能据结果改选hit或重复采样寻找正结果。

## 6. 一次有根因的新机制版本

独立提案[GE2](system_review_v1/GOAL_EVIDENCE_V2_DESIGN_ZH.md)只针对本次查明的限制：允许语义改写但保持运行时来源隔离；上下文完整的原文窗口；可变粒度与已读区间记录；充分/不足/不适用/无法确认的证据状态；可见目标和实际时间预算；完整决策状态身份与请求级故障隔离。

新组织方式须由所有新策略共享，不能把新v2对旧v1的总改进都归序贯。Static/OneShot/ToolAgent/Rule使用同索引、同动作、同原文池及预算；Top4五原语差异要在新合同中解决。真正同控制器NoText与旧透明规则分开。所有规划成本进入实际在线时间。

不立即恢复显式Step-2主线。旧SMV30 T15/MS确有必要证据完整供应而漏掉所问行动阶段，本轮只读回这一条核身份，保留旧失败和额外断言unknown。它允许提出一次同资源、同G、同调用/总输出/墙钟预算的短操作计划对照，但不能证明内部理解失败或预期计划一定有效。DR T03缺源部分不能被拿来为Step-2背书。详细条件与停止规则在GE2 §6，未实现、未申请或运行额外模型。
