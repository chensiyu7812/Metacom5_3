# DR1–DR4：真实质量、可靠性、延迟与资源决策

本轮从 `cc900c40e8b3394ee4f74fe11d92e8faf483c8e2` 出发，收到研究者“批准仅上述 DR1–DR4”后，严格执行原 `packages-v2`。实际发生 **53 次模型调用、4 次加载、0 warmup、0 retry**，整作业墙钟合计 **653.895 秒**；没有新增调用补齐缺失。模型、来源、任务、六臂、评价合同和执行器身份均未改变。

主要结论是：**资源在部分历史事实任务上有实质价值，正确不获取也有明确实例；本批没有证明 ToolAgent 优于 OneShot，也尚未确认特权选择相对最强固定策略的优势。**当前不具备据此专门训练轻量 PM 的充分证据。值得保留的是两个真实读后状态的有限分支诊断，而非立即 BC/PPO 或继续扩充同类静态题。

## 1. 本研究的目标与评价口径

本研究服务于实时长期陪伴数字人，主要评价四个方面：用户目标完成与回复质量；资源使用可靠性及安全边界；实际在线 Agent 延迟，未来扩展到 Tokkio 客户端首段有效语音；资源获取与停止决策的适当性。tokens、调用次数和 GPU 消耗是辅助诊断，不替代上述目标。

Generator 本身可以完成许多自然回复。M0+R0 是正常、有价值的成功路径；自然支持不要求复述全部记忆。PM 需要在必要时获取，在不必要时关闭，并在信息充分时停止。是否获取不能由资源需求标签、命中率、引用存在或访问次数直接判为正确。

质量观察严格沿原 EvalSpec，逐条绑定实际输入、来源、完整输出与 SHA。本次是**助手开发审阅，未获得独立真人资格，formal reward 全部为空**。事实、支持操作、范围/时间约束、无依据断言和未知分别记录；五项既有真人复核继续 pending。没有新增万能 Judge 或调整原任务评价规则。

53 次模型调用均返回 EOS，输入/输出与单调时钟校验通过；没有 OOM、超时、terminal length 或重试。15 次控制输出的 JSON 语法完成，14 次通过动作状态协议。模型返回、JSON 合法、动作可执行和任务完成是四层不同结果。

唯一协议失败是 DR3/T05 的 OneShot：JSON 中一条查询用了初始可见 query 没有的词 `status`。原协议只允许来自初始可见 query 的词；原冻结 parser 的一次 CPU 读回复现同样拒绝。它是**词面来源协议不满足**，并无证据证明该词来自未来事实或 gold，也不能把它写成普通任务回答错误。整段程序先验证再执行，所以该路径实际获取为 0。

最终 48 槽分别为 **38 个实际终局、1 条控制器技术未完成路径、9 个未执行端点**。T05 只有 STOP/Top4 两臂终局；T06 六臂均未执行。后续槽缺失源于预冻结整包停止规则，不是这些策略的语义失败。38/48 是此次批处理的终局可得覆盖，不能直接当生产单请求可靠率。未用调用上限不转移，不使用原剩余 220 次额度。

完整匿名逐题表和全部计量见 [TASKWISE_QUALITY_LATENCY_ZH.md](dynamic_results_v1/TASKWISE_QUALITY_LATENCY_ZH.md)。完整问题、原文、回复与评价依据保留在本地私有 `quality/review-v1/READBACK_PRIVATE.md`；公开仓库仅包含匿名评价、计量、SHA 和代码。

## 3. 任务完成与资源价值

**STOP 的成功**是 T04、T07、T08：通用非施压反映、当前信息内的事实回答、按当前短注记作简短回应。没有因此要求记忆复述或将不获取判为失败。T07 六臂回复完全相同；T08 各臂均满足原支持目标。T02 提供了可用草稿，但多数臂给出多个选项，是否完成“一个表述”的完整要求保留范围争议；不另加字数阈值。T04 的 Top4 引入旧压力作为近期现状，其持续性未确定，保留未知而不认定已证实错误。

**实际资源收益**出现在 T01、T05 的 Top4 相对 STOP。T01 三个必要历史事实均得到供应和回答；T05 明确区分已有计划报告与无法确认的实际执行。后者只成立于报告范围内的未知，不能被评价器改写成真实世界“没有发生”。Top4 仍是五原语宏、完整父会话读取，和其他臂至多四次 SEARCH/EXPAND 的操作量、来源覆盖不同；其收益不能归给序贯排序或读后推理。

**T03 的所有实际臂均未完成**。不同条件下分别出现：未供应历史却把当前问题里的阶段词回填成曾经的报告；只读到支持者问句便断言用户已建立日常习惯；供应了尝试融入日常的材料，却遗漏具体练习的小幅受益。可见问题本来含有阶段词，因此部分答案和参考相符也不能证明可靠记忆使用。这里同时存在供应不足、角色/问句理解、行动阶段误判和目标遗漏，不能全部归因于 G，也不能全部归因于检索。

38 个必要事实呈现位中，有 22 个内容与原参考相符，其中 3 个实际未供应对应完整原证据群；这 3 个不升级为可靠回忆。这个 38 是跨条件的必要原子分母，恰好与 38 个实际终局同数，但含义不同。原子内容相符、供证和完整任务成功始终分开。

两条终局出现字面 `thought` 前缀，原文未清洗。它们单列为呈现问题，不自动覆盖事实判定；也说明模型内部“首非空文字”可能不是首段可用正文。

## 4. OneShot、ToolAgent 与固定策略

实际完整六臂集合为 **T01/T02/T03/T04/T07/T08 六题**。以下只比较这个相同集合；T05/T06 的缺失不补零，也不混入不同分母。

六个已完成 OneShot/ToolAgent 配对的**终局 payload、回复文本和 token IDs 逐对完全相同**。两条历史事实路径上，ToolAgent 都只 SEARCH 一次，然后主动 STOP；其终局与 OneShot 单次 SEARCH 后程序结束一致，没有增添证据或修复答案。对应 Agent 时间分别多约 0.759、0.902 秒。其他四条路径两者均初始不获取，控制输出结构与长度不同；总体 ToolAgent 合计略短约 0.727 秒，但没有新增任务效果，也不是稳健的延迟优势证据。

六条 Rule 路径实际进行了包含新观察词的第二次查询，说明透明程序确实使用了读后信息；本批没有据此取得完整任务修复的序贯优势。NoText 是不同的透明规则，不是同一 LLM 的正文屏蔽消融。T02 的输出形式差异也不能自动归为专业记忆知识增量。

同一六题的逐题特权完成包络为 **5/6**；最强固定臂的可确定区间为 **4–5/6**，差距为 **0–1 题**，尚未确认有正的改进空间。该包络是事后开发诊断，非可部署策略、非合格 PM Oracle 或 reward。NoText 的开发确定 4/6 不能消除 Top4 可能达到 5/6 的评价不确定性；不能只挑某一个固定臂宣布 Oracle 已胜出。尤其 T02 单草稿与多个选项的要求边界尚无独立真人裁决，不能把这项开发解释变成训练资格。

## 5. 实际在线时间与控制开销

时间来自同 boot 的单调纳秒事件，不由 tokens 或总生成时间推算。主要观察面是**预建合法来源环境、模型已加载后，可见请求进入本地 Agent 至完整回复经过校验 ready**；它包含 PM、实际工具、打包、IPC、实验守卫和相关日志。它不是 HTTP 客户端、Tokkio 或用户说完话以来的端到端等待。

53 次模型生成合计 322.379 秒，其中终局 G 305.015 秒、OneShot 11.513 秒、ToolAgent 5.851 秒。控制时间包含 DR3 被协议拒绝的真实输出，不删除失败成本。输入 60,048、输出 4,114 tokens 仅作资源记录。

四次外层 supervisor load 合计 171.985 秒，内含 worker load 110.400 秒、后者又含 grammar compile 10.017 秒；不能相加。模型文件身份检查 87.256 秒、来源 startup 25.466 秒分别在常驻路径之前，也都计入实际整作业墙钟。没有给每个终局重复摊一次加载，亦没有把这些冷启动隐去。

实验 guard 的实际跨度合计 **7.007 秒**，保留在原 Agent/调用区间内。**日志没有独立计时跨度，`logging_wall_ns=null`**；余量还混有 Python、验证、文件持久化、IPC 等，不能命名为日志耗时。减去 guard 也不自动得到真实部署时延。工具、合法性、renderer/tokenization 的嵌套跨度见机器记录，不能重复相加。

在两端均确定完成的同题对照中：T04/T07/T08 的 OneShot 相对 STOP 合计多 5.041 秒，ToolAgent 多 3.079 秒；它们均不获取，回复也与 STOP 相同。T07/T08 的 Top4 相对 STOP 合计多 2.294 秒。Rule/NoText 在共同成功三题的配对变化分别约 −0.009、+1.021 秒，方向并不一致，不能把额外获取直接当额外总时延。T01/T05 的 Top4 同时完成了 STOP 未完成的任务，且本次实际总时间更短；输出内容/长度、顺序及运行状态共同变化，不能归为单一 token 或检索因果效应。

每个终局只有一次实际执行，臂序固定、首个 STOP 承受加载后的首次推理；P95 使用 nearest-rank，六题 P95 等于最大值。上述是观察到的质量—时间对照，不是生产尾延迟或随机化因果估计。失败路径保留部分时长；无终局不进入回复完成时间分位数，但同时展示其覆盖分母和状态。

模型内部首 token、首非空文字均有实际记录；语义有效性未自动资格化，客户端首文本仍未测。两个 `thought` 前缀尤其不能当首段有用正文。没有新增 Tokkio/ASR/TTS/客户端计量；未来沿既有同客户端“用户最后语音样本 → 首段正文语音实际播放”协议扩展。

## 6. 获取和停止的适当性

停止原因明确分层：固定 STOP 7、Top4 宏结束 7、ToolAgent 显式 STOP 6、OneShot 承诺 STOP 4、OneShot 计划耗尽 2、透明规则结束 12、控制状态协议失败 1、未执行 9。Rule 六条都触及四次获取上限；NoText 六条各三次获取、未触上限。本批没有实际 token 上限拒绝、资源不可用或缺失计划 hit 停止；不能从未执行反推这些原因。

有限决策诊断中，9 格可称“该任务内合理不获取”，来自 T04/T07/T08 的 STOP/OneShot/ToolAgent；8 格为“可能过度获取”，其任务完成且同题 STOP 也完成。后者并不证明个性化或用户体验没有其他收益，也不代表时间必然更差。其余 31 格保持未决，其中 12 格有“未完成且必要原证据群缺失/不全”的不足获取线索，**与未决重叠，不是新增正确动作标签**。

按结果读取前的固定规则，仅两个实际中间状态合格：DR1/T01、DR2/T03 的第一次 SEARCH 返回之后。CPU 用原 renderer/tokenizer 精确重建 G payload，均匹配已有 OneShot 及 ToolAgent 的 STOP 终局。但**没有同一状态继续获取后的终局**；初始 Top4 不等同从该状态继续。故能确认已读内容和剩余动作可观察，不能确认该时刻 STOP 最优、继续一定有益或某个正确下一动作。

完整停止与状态匹配证据见 [DECISION_IDENTIFIABILITY_AND_STOP_PLAN_ZH.md](dynamic_results_v1/DECISION_IDENTIFIABILITY_AND_STOP_PLAN_ZH.md)。

## 7. 下一阶段建议与明确停止的主张

继续保留选择性资源获取这一研究问题：历史事实和当前充分信息的对照确有不同需求，关闭资源可以是成功行为。但**暂停“现有 ToolAgent 已体现序贯优势”“本批已提供可训练的最优动作标签”“轻量 PM 将改善质量与延迟”的实证主张**。本批既未证明这些主张，也不构成对完整长期交互 POMDP 的否定。

当前首先需要解决的是证据充分性和证据使用：识别支持者问句与用户事实，避免把计划/尝试升级成执行/习惯，区分历史报告和当前状态，并完成用户指定的输出操作。JSON 已可生成，DR3 的瓶颈是更严格的动作词面协议；修订该协议需独立新身份，不能在本批遇错后静默放宽。自然支持质量仍需外部验证，不能靠事实 QA 或格式通过替代。

后续仅提出一项有限设计，**没有新增执行包或授权申请**：使用已经按固定规则得到的两个中间状态，不重抽有利样本。比较各状态的 STOP 与一次预先规定、当前合法的最高排名 hit EXPAND 后 STOP；不输入 gold、不按答案选来源，预算拒绝或无收益照实保留。若需要新的同条件质量及时间配对，上界为两状态 × 两分支 = **4 次终局 G**，其加载、硬限、顺序及新身份仍需另行冻结批准。已有 STOP 可用于质量读回，不能把旧测量或离线复用当新分支的实时延迟。此设计只检验一次展开的价值，不冒充完整自适应策略或生产性能。

若这一有限分支仍不产生完整任务改善，应停止以当前小池作为专门训练 PM 的依据，不继续枚举动作寻找正结果；转而处理证据理解/供应或重新界定独立真实交互任务。即便有改善，两个状态也只提供机制可行性，仍不能直接训练或宣称泛化。轻量 PM 替代重复大型 LLM 规划的假设仍值得保留，但必须有独立、可见状态条件下的任务收益与实际时间证据。

本轮不重开静态实验，不调 C1，不追加 RS 卡片，MP/ME 继续 pending/mask；RAW/SPAN、MS-SUM 导航、Time-Lexical 与 Hybrid 原身份保留。不启动 BC/PPO 或新 Generator 训练。原剩余 220 次与此次未用上限均未使用。
