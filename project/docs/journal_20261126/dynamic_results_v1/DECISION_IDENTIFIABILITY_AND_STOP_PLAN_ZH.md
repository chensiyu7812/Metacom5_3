## 1. 六臂实际能回答什么

| 比较 | 已有信息 | 不能据此识别 |
|---|---|---|
| 初始 STOP 与获取臂 | 同题当前输入下，不读资源和各完整政策包的终局差异 | 任意读后状态的 STOP 价值；单步动作的独立增益 |
| OneShot 与 ToolAgent | 一次承诺计划与逐步控制的实际调用、状态、终局 | 单独的“看到资源正文”的因果效果；控制调用数量与输入也改变 |
| Rule 与 NoText | 两个确定性程序的实际获取路径及结果 | LLM 读正文消融；NoText 的动作程序也不同 |
| Top4 与动态臂 | 固定宏完整政策包的结果 | 四动作匹配比较：Top4 实际为一次检索加四次父资源读取，共五原语；其他臂最多四次 SEARCH/EXPAND |
| 已验证同 payload 的跨臂终局 | 相同任务、来源顺序、可见上下文、G 输入及 decode 下的已有 STOP 端点 | 新独立重复、随机化分支、部署缓存延迟，或自动获得继续分支 |

固定臂顺序、每次加载后的首个推断和真实资源长度都会影响时间。本轮没有用总墙钟减模型时间来命名 PM 或日志成本。冻结执行器没有单独日志跨度，`logging_wall_ns=null`；已有 PM、工具、模型、序列化等计量分别沿原事件边界保留。worker 首 token、首非空解码文本和用户收到有意义文本不同；没有实际 client 首段交付则 client TTFT 仍为空。被动 streamer 的额外处理开销计入实际墙钟，不能声称零扰动。

## 2. 停止原因与协议失败

| 真实停止/路径原因 | 槽数 | 解释 |
|---|---:|---|
| 固定初始 STOP | 7 | 基线行为，不是模型选择 |
| Top4 宏完成 | 7 | 每条均实际五原语，不是主动 STOP |

| 确定性规则程序结束 | 12 | Rule 六条、NoText 六条 |
| 控制状态协议失败 | 1 | 技术未完成，不是任务语义失败 |

本轮没有实际 token 预算拒绝、缺少计划 hit 或资源不可用停止；这些类别在诊断代码中保持分离，不从零调用或缺少终局反推。Rule 六条均获取四次，`binding_limits=[acquisition_cap]` 与 `stop_reason=rule_program_end` 同时保留；NoText 六条均获取三次，未触及四次上限。不能把规则结束描述为模型主动选择或学习得到的最优停止，也不能只报“规则结束”隐去 Rule 的实际预算边界。

唯一失败位于 T05 的 OneShot：控制输出自然 EOS、JSON grammar 完成，但计划中的后续 query 使用了初始未观察词，冻结状态验证拒绝整段计划。整计划验证发生在动作执行前，因此该路径**实际 SEARCH/EXPAND 均为零**，不是工具不可用或检索未找到。T05 后续三臂与 T06 全六臂未执行。其余 38 终局均保留，未重试或用失败路径换题。

## 3. 固定中间状态选择及真实匹配

生成结果读取前的有限设计是：每个原批次按冻结任务顺序、再按事件顺序，取首个 ToolAgent 获取返回后仍有剩余预算且实际 mask 允许 SEARCH 或 EXPAND 的状态，每批最多一个、总计最多四个；不依据回复、质量、覆盖率或之后选中的动作筛选。没有合格状态则保持缺失。未来对照的概念是同一状态 STOP 与合法剩余预算内继续获取；本轮只检查已有端点，不创建新请求或授权包。

实际仅 DR1/T01、DR2/T03 有合格状态，均在第一次 SEARCH 返回后。使用冻结 renderer、原 tokenizer/config 文件、原 baseline 在 CPU 上重建完整 G payload；核对完整规范 JSON 字节、payload SHA、native input token 数及日志 observation SHA。两状态均与同题 OneShot 的真实终局完全相同，也与 ToolAgent 自身终局相同；两臂回复文本及 token IDs 也一致。整个六题已完成 OneShot/ToolAgent 配对中，终局 payload、回复文本和 token IDs 均逐对一致；这些是六个同题政策配对，不是十二个独立状态。

DR3 在 ToolAgent 执行前终止；DR4 两题 ToolAgent 均初始 STOP，因此没有替换挑选其他“更好”的状态。两条可复用端点均为 **STOP 端点**，实际下一步也是 STOP。没有同一中间状态继续获取的终局，故无法判定停止是否最优，不能把初始 Top4 的完整结果冒充该继续分支。原计划最多四状态保持不变。

实际查询轨迹也有限：OneShot 与 ToolAgent 没有执行第二次查询或使用新观察词的查询细化；六条 Rule 路径执行了含新观察词的第二次查询。这证明相应确定性程序实际运行，不证明语言模型读后改写能力或改写的任务价值。NoText 观察刻意不含 `readings` 字段，诊断将其正文变化记为 unknown，未错误计为“内容完全没变”。

- **有限合理不获取**：T04/T07/T08 的 STOP、OneShot、ToolAgent 均不获取且任务开发观察完成，共 9 格，来自 3 题。此标签只表示这些实际任务中不获取也完成，不等于通用正确 STOP。

严格自动分类保留 31 格未决：包括上述未完成、uncertain、技术失败及未执行。单列“未完成且至少一个必要原引用群缺失或部分交付”的描述性线索有 12 格：初始 STOP 三格、Top4 一格、OneShot/ToolAgent 各两格、Rule/NoText 各两格。上述四条 LLM 路径是其中子集。**这些获取不足候选与 31 个未决格重叠**，不是额外排他的决策类别，不把“未供完整参考群”升级为“获取一定能救回”。原引用群覆盖的计数单列，不用它代替任务质量。10 个无 G 端点的供证计数为 null，不能解释成零。公开逐格文件同时保留事实群缺失/部分/完整数、质量区间及相对初始 STOP 的区间；这些并非独立随机试验置信区间。

只在六臂均有实际终局的 T01/T02/T03/T04/T07/T08 上，按这些开发区间计算事后逐题最佳包络为 5/6，最强固定臂的可行范围为 4–5/6，差值仅 0–1 题。因此尚不能确认逐题特权选择相对最强固定臂存在严格正优势；包络也不是可部署策略或已学习 PM 的成绩。T05 只有两臂终局、T06 无终局，不补造它们的 Oracle 标签。

## 5. 对轻量 PM 学习的当前含义

现在已不只是接口和调用次数：有真实完整包收益差异、同题不获取也完成的案例、真实控制协议失效，以及逐步状态和成本日志。它们可以支持有限的初始策略选择开发分析。但当前只有 8 个任务、4 个原来源配对，且一对受到技术中止；大量跨臂 G 输入完全相同，不能把重复端点增加为独立监督量。观测中的 source coverage 或“用了多少次工具”都不是 action value。

本批没有证明 ToolAgent 相对 OneShot 的独立任务增量，也没有给预选中间状态提供 STOP/继续两侧的质量端点。Top4 的两处明确收益仍混有五原语与资源范围差异。因而不能据这批数据声称多步 RL 所需的正确动作监督已建立，或真实读后自适应优于一次承诺；更不能把未知与未执行转成负例开训。本轮没有创建训练包、训练模型、增加运行申请或改变旧规则。

## 6. 可复跑产物与边界

实现为 `journal/pomdp_decision_diagnostics.py`、`journal_diagnose_pomdp_decisions.py` 和 `journal_check_pomdp_midstates.py`。前者只读已核验的 collection，后者只加载冻结 CPU tokenizer，不加载模型权重。26 个专名 CPU 测试通过，覆盖未执行/截断/状态失败区分、未知保留、质量绑定、同 payload 的真实字节比较、固定状态选择和公开字段白名单。

私有 `decisions/observations-quality-v3` 是最终质量联结诊断，`decisions/exact-final-v1` 是最终有限重建回执；早期 snapshot 与中间开发诊断均保留，不能替代最终版本。公开交付仅包括 `DECISION_AGGREGATE_PUBLIC.json`、`DECISION_TASKWISE_PUBLIC.jsonl`、`POLICY_PAIR_REUSE_PUBLIC.json`、`MIDSTATE_EXACT_MATCH_PUBLIC.json` 及对应 manifest。完整 query、源内容、gold、回复、private state 和 reviewer 引用不进入公开仓库。
