# PM-RL1-J：静态选择收口与读后条件决策的独立研究身份

本轮起点为 `0f3d9842d5b1a5e7e211c319beddc7477705ff76`。研究者单独批准的 SMV1/SMV2 已完成 **30 次实际生成、2 次加载、0 warmup、0 retry**。此外完成 80 条 SEARCH/EXPAND/STOP CPU 路径、16 条完整 Top4 压力读回及来源复核；新序贯机制没有调用模型。旧结果与负结果、PR #28、原剩余 220 次未授权请求全部保留。

本轮的研究决定是：**结束围绕同一批静态任务继续扩样，保留选择性 Memory 的有限开发信号；恢复对读后条件决策的独立检验，但不预设它优于强静态检索。** 现有证据既没有证明序贯收益，也不能否定更完整的 POMDP 研究。真正待检验的是已读证据能否改变下一步的有用性，并改善当前用户目标下的最终行为，而不是是否多检索一次或减少了多少输入 tokens。

C1 只在 T02、T11 改用 STOP。两题均是共同确定成功，因此相对 MS 的三个通道完成差都为 `[0,0]`，**7,075 输入 tokens 节省全部来自成功题**。这是一项有限的开发效率信号，不足以宣布 C1 普遍有效。简单基线的总区间虽然相同，逐题配对差为 `[-1,1]`；24,191 tokens 节省中有 5,856 来自未知选择，不能宣布等质量。

MS 在 17 个必要事实槽位上供证 17/17、表达 16/17。T15 已拿到所需早期行动阶段，却转而比较心理负担和缓解，漏掉用户明确要求的行动阶段比较。这个失败不能归咎于未取到来源。T01 的问题则是附加真实历史是否越过用户限定的当前摘句范围；真实性与使用适用性不同，原未知保留。其余确定修复、共同成功、双失败与争议都列在[逐题表](smv30_results_v1/SMV30_TASKWISE_ZH.md)。

语义记录是按冻结合同逐条阅读后的助手开发观察；六处争议有第二次助手阅读，不是独立真人评价或新资格测试。原五项真人复核仍 pending。没有把这些标签接入 reward，也没有修改 C1、旧 J06 或原 SC36 评分。

## 2. 原研究目标与当前实现的差距

原方案具有不同层级，不能把其中一个受限实现当作完整目标。09-28 实施方案允许当前轮最多四次 GET、同头重复，但 query 和检索排序仍固定；11 月实际 FiniteHead 将其收窄为每头一次、固定 query、规范化 subset 终点。V3.1 Phase-2 文档已有 adaptive query、EXPAND 与有序 OneShot 的计划，但文档不等于运行结果。[原方案](../PM_RL1_ORIGINAL_IMPLEMENTATION_PLAN_20260928_ZH.md)、[V3.1](../PM_RL1_SOLUTION_PLAN_V3_20261116_ZH.md)、[实际差异表](pomdp_v1/MECHANISM_AND_CPU_ZH.md)

|研究层级|当前已经具备|尚未验证|
|---|---|---|
|当前目标下是否获取 Memory|真实 STOP/MS 端点、冻结规则与开发结果|来源组外泛化、自然支持独立效益|
|读取后改变下一步|新原型允许已读词进入 query，实际返回的句柄解锁完整父会话；成本和路径随动作更新|相对强 OneShot/普通 Tool Agent 的任务收益|
|跨时间的个人状态变化|原始报告日期、As-of 合法范围、真实计划/体验/更新来源|MP/ME 语义写入、持续更新的资格与性能|
|长期陪伴的交互控制|保留最终研究目标和自然支持评价线|策略动作改变后续用户状态的转移数据、跨轮回报与独立长期评价|

旧域中的 MS 后仍有合法 RS，旧 24 条路径也已实际接通；但这并没有证明必须先读 MS 才能选择 RS。反过来，旧域不能重新查询或改变候选，其结果不能否定新的读后检索域。新原型也只验证信息获取中的部分观测：未读库对策略不可见、读取改变知识；没有宣称已估计用户心理后验。

目前来源是既有 EvoEmo 构造人物对话文件，候选当前目标由研究者侧构建。“真实来源案例”表示实际原文件和报告序列，不是本轮招募的真人长期互动实验。历史重放可以检验来源更新的正确处理，不能单独证明长期陪伴效果或用户状态的因果改善。

## 3. 已实际运行的新机制和真实案例

独立身份为 `pmrl1-j-pomdp-memory-cpu-v1`，旧 FiniteHead、冻结 G/C0、任务和历史结果未改。复用 `As-of Ledger → SnapshotPrefixPort → ReadingView → 原 Generator renderer`；保留 RAW/SPAN，MS-SUM 仍只做导航，Time-Lexical 是本次实际后端，Hybrid 仅接入既有 RRF 接口及 CPU 合同测试，本轮未重新编码或冒称 Hybrid 实测。

- `SEARCH(query)`：在完整合法池排序，交付最多两个完整原始话轮及不透明句柄。首检只用当前可见请求，后续词必须来自当前请求或实际已交付文字。
- `EXPAND(handle)`：只能展开本 episode 已返回的句柄，交付完整父会话；不能使用人工评价 locator 指定下一来源。
- `STOP`：随时可选，最终由冻结 G 回答；当前 CPU 轨迹终值均为 pending，不能把 STOP 或命中当成功。

每题最多四次获取、累计 4,096 个实际交付 tokens；原上下文 16,384，预留输出 320。重复读取重复计费，G 内容只精确去重，轨迹成本与 payload 身份分开。可见状态包含当前目标、已经收到的文字/句柄、预算和历史；私有 owner、gold、参考原子及未读文本不成为策略特征。NoText 不读正文、实体、向量或私有分数。查询词权限是保守的来源约束，不是语义理解或所有动态检索的完整动作域；它也限制了未出现的同义改写。[实现与实际路径](pomdp_v1/MECHANISM_AND_CPU_ZH.md)

8 个情境各有事实与自然支持目标，共 16 题；每题保留 11–26 个合法历史会话，合计涉及 54 个不同会话。包含分散事实、计划与执行未知、事件身份边界、真实报告更新和当前已充分情境。没有删来源、制造矛盾或要求必须多次读取。

|CPU 对照|事实必要来源 / 16|支持可选背景来源 / 16|终局输入 tokens|获取操作总数|
|---|---:|---:|---:|---:|
|STOP|1|1|1,832|0|
|Fixed Top2|12|6|32,388|48|
|透明初态 OneShot 程序|10|6|35,116|64|
|Sequential Rule|11|8|32,168|64|
|Sequential NoText|12|6|32,388|48|
|完整 Top4 压力对照|14|10|55,113|80|

这里的 16 是跨目标复用的来源槽位，不是 16 个独立受试者。支持列全部是可选背景，不是支持成功率。完整 Top4 均可放入同一 token/context 上限，因此原 Top2 不能冒充容量约束下的最强静态方法。Top4 是“一次检索＋四次父读取”，每题五操作，且不交付检索 snippets；它超过原四操作域，只是更强的实践压力参照，不能伪装成同动作预算的政策效应。[原始计数与 Top4 边界](pomdp_v1/SOURCE_TOP4_COMPARISON.json)

具体路径给出的证据比“查询变了”更有限：P02 首次展开确实提供一个新实体词，第二次 query 实际使用，但最终必要覆盖仍只有 2/3；P03 的分散事实通过两个展开取得，却原本就在首次 Top2 中；P05 展开补齐了短答解释语境，当前规则却没有使用另一条已出现线索；P08 当前信息已足够，继续读取没有增加该事实清单。P01 的规则还丢失了静态方案原本覆盖的来源。全部正负例和未知均保留。[匿名逐例说明与私有读回位置](pomdp_v1/SOURCE_CANDIDATES_ZH.md)

80 条路径中的 320 个交付单元及查询来源链均通过原文核查。Seq 第二检索在 6/16 题返回新父会话，但本次第二 SEARCH 本身没有直接补齐新的已知事实组；价值若有，需要通过后续合法展开和最终回答确认。当前大小写词代理既使用正文词，也混入包装词，没有按覆盖结果再调词。

这支持“读后内容能改变合法 query 参数与下一读取候选”的机制可行性，**不支持该透明规则优于宽检索**。当前 NoText 恰好与 Top2 的最终 payload 全相同，也不是同一 LLM 的等调用正文屏蔽消融。该结果不能当作完整序贯方法或读后语义信息无用的结论。

## 4. 创新性审查后的研究定位

本轮实读七项工作、下载八份论文版本，保存 PDF hash 和官方仓库快照；阅读范围与版本差异可复核。[完整审查](pomdp_v1/RELATED_WORK_AND_NOVELTY_ZH.md)

MemRetriever 已有根据已有证据继续查询、反思去噪、充分性停止和学习获取；ENPMR-Bench 已把支持需求用于个人记忆检索；ProgMem 已实现事实/动态/计划状态与来源核验。SEARCH/EXPAND/STOP、目标条件化或结构化状态本身都不能直接作为创新。[MemRetriever](https://arxiv.org/html/2609.11951v1)、[ENPMR-Bench](https://aclanthology.org/2026.findings-acl.2080/)、[ProgMem](https://aclanthology.org/2026.findings-aacl.120/)

Memory-R1 已学习记忆写操作及候选使用，AFA 已系统研究观察后获取/停止及成本，DreamCUB 已把用户状态和支持对话建为 POMDP。因此不主张首次 POMDP、RL、动态检索、结构化记忆或需求感知支持。[Memory-R1](https://aclanthology.org/2026.acl-long.583/)、[AFA](https://papers.nips.cc/paper_files/paper/2018/hash/e5841df2166dd424a57127423d276bbe-Abstract.html)、[Dream to Chat](https://aclanthology.org/2025.findings-emnlp.256/)

唯一优先研究假设是：**在相同合法来源、当前可见目标和成本限制下，目标与实际读后证据的共同作用，是否带来超过初态规划和普通 Tool Agent 的最终任务收益。** 事实回答、支持目标、额外错误和实际成本必须分开；更多记忆复述不等于更好的支持。这个定位仍是待检验的贡献候选，尤其不能忽略与 MemRetriever 的直接重叠。

## 5. 一次有限后续实验的具体提案与未完成项

源分层在 CPU 检索结果前已经冻结：P08 当前充分、P06 执行未知、P05 真实更新，分散事实层按 case ID 的 SHA 规则选 P02。四情境各事实/自然支持两目标，共八题。其余情境及负结果不删除，不能按本次覆盖胜负换题。

|未来条件|决策信息与比较作用|
|---|---|
|STOP|只用当前可见请求；合法的不读取路径|
|Fixed Top4 macro|当前 query 一次排序、四个完整父会话；强实践参照，五操作差异明示|
|LLM OneShot|同模型只看初态，一次预承诺完整程序；不在读后重写 query/计划|
|普通 LLM Tool Agent|同模型看实际 observation，每步选择 SEARCH/EXPAND/STOP；不加入新训练模块|
|Sequential Rule|保留当前透明规则及失败，不按结果追调|
|Sequential NoText|保留无正文的透明程序；用于信息边界诊断，不冒充同 LLM 正文因果消融|

终局 G、decode、来源和任务要求不变。严格读后机制判断优先比较**同动作域、同 LLM 的 OneShot 与 Tool Agent**，而非拿 Top2 弱基线或透明 OneShot 代替强基线。两者每题控制输出上限都是 768 tokens，所有控制输入、输出、工具及加载成本均计。Tool Agent 的多次输入开销不会被输出限额抵消。若要对所有六臂作完全同动作域声明，必须先固定共同 Top4/五操作域；本提案没有静默改旧四操作路径。

最大预算为 **48 次终局 G＋8 次 OneShot 控制＋32 次 Tool Agent 控制＝88 次调用**，精确复用前上限。四个来源情境各作为一个完整配对作业：每包最多 22 次、一次加载、0 warmup、0 retry、1,200 秒，总硬限 4,800 秒，仅原 GPU 与模型。32 个确定臂 payload 已实际构建，其中 30 unique，合计输入 61,626、单条最大 3,906 tokens。动态控制与终局 payload 必须在真实读取后逐步绑定，不能预造静态 hash。

**这是一份有预算和具体任务/初始请求的研究提案，尚不是可执行运行申请。** `authorized=false, execution_ready=false`。缺少的是有调用上限、日志链、超时和设备守卫的动态 controller→tool→G 执行器及其独立 admission；尤其不能套用旧的 20-call checker 启动每包 22 次。现有 CPU parser 和确定臂输入不代替它。本轮不请求批准一个尚未准入的作业；不使用 SMV 授权或剩余额度启动它。[v2 预算与身份](pomdp_v1/BOUNDED_PROPOSAL_V2_PUBLIC.json)、[公平性及预算边界](pomdp_v1/FIXED_TOP4_FAIRNESS_ZH.md)

评价合同沿三层记录：程序验证严格时间/来源/字段/成本；事实参考逐项记正确、遗漏、错误、合理未知；自然支持按目标、约束与新增个人事实断言审阅，允许多种合理回应，不要求回忆全部背景。未校准语义维持 unknown 或显式开发观察，不作为正式 reward。新增命中、格式、工具成功、更多事实复述均不替代最终成功。

预先保留失败分支：若 OneShot 已解释全部改善，则收窄为目标驱动检索；若宽静态检索获得相同任务收益，则不主张序贯必要性；若来源齐备而 G 仍偏离目标，则主要瓶颈在证据使用而非获取；若支持任务的差异无法可靠识别，则只报告事实能力和成本，不写自然支持增益。即使这八题没有增量，也只限制该动作/来源/目标范围，不能形式化否定所有长期 POMDP；但不继续在同批任务上重抽、追调或无限扩大来寻找正结果。

## 6. 下一阶段决定与原 RQ 进度

|研究问题|本轮新增实际证据|仍缺什么、如何收窄|
|---|---|---|
|RQ1：个人/方法知识的条件能力|SMV 事实/联合必要内容由 STOP 4/10 到 MS 9/10，存在明确修复及供后遗漏|仅开发 Memory 能力；RS 独立增量未建立，不扩同类卡；MP/ME pending/mask|
|RQ2：组织、检索和 M×RS|新全合法池、实际展开与强宽检索压力读回；来源与最终行为继续分开|供给数量/动作粒度不同必须保留，未证明协同；RAW/SPAN 保留|
|RQ3：选择、序贯及学习|C1 两次共同成功选择节省 7,075 tokens；新读后参数和句柄转移实际运行|静态线收口；序贯最终任务对照未运行，不能外推旧域；BC/PPO 仍不启动|
|RQ4：自然支持和全成本|SMV 有真实回复、token/加载/生成计量；源/目标边界明示|尚非独立自然支持或长期互动外评，分量时间不等于部署端到端|

当前最值得解决的瓶颈有两个相连但不能混同的部分：**让读取决策识别当前目标还缺什么；让 G 在得到证据后完成该目标而非泛化安慰或无关回忆。** 纯输出格式已在 SC36 范围内改善，但不说明自然支持语义使用已经解决。T15 是后一瓶颈的实际案例；仅凭这一案例不足以直接另起 Step-2 或训练包。

下一步只推进上述一次读后机制对照的必要执行接线和有限生成资格，不再增加新的同类组件研究包。用户交互造成的长期状态转移属于之后单独的研究层；不能用当前只读重放代替，也不能因当前动作域有限就取消该目标。正式学习需要先有可辨别的任务空间和适用评价，目前不开始 BC/PPO 或新 Generator 训练。

本轮代码和公开聚合另行提交，私有源、完整输出、gold 和有限复核材料不上传。状态为新增 [V8](JOURNAL_EXECUTION_STATE_V8.json)，旧版本不覆盖。CPU 回归、冻结输入保护、复跑命令见 [本轮复跑与核验](REPRODUCE_POMDP_RETURN_ZH.md)。
