日期：2026-09-29。本文接续第一批执行器小批量结果，保留其全部数据和结论。**来源门禁已经接入实际生成入口；第二批原合同未通过；另立、明确标记为事后的工程实验，完成真实 LoRA 更新和新进程重载。工程 adapter 不具备正式研究或 RL 资格。**

## 1. 来源层实际修复的范围

对第一批合法过去内的 101 次相同 owner/slot/value 再出现完成逐项 AI 辅助来源审阅：

| 新引文的充分性 | 条数 | 解释 |
|---|---:|---|
| 支持完整表述 | 13 | 仍须另查条目类别、当前时效和使用场景 |
| 只支持一部分 | 60 | 例如只说 thesis，不能重新证明 graduate 身份；代词可能需要上下文 |
| 与表述无关 | 26 | 例如问候不能重新确认睡眠困难 |
| 与旧“当前状态”冲突 | 2 | 新来源已经表示兴趣或关系发生变化 |

这不是 88 条历史事实被证明为假，也不是全语料的错误率。13 条充分引文同样不构成“临床诊断”“永久偏好”或“当前仍然有效”的证明。部分引文本身不充分的条目，可能通过额外上下文得到解释；本版采用保守隔离，没有声称全部不可恢复。

新增的版本化 overlay 在**先按截止点选出最新 MP，再执行隔离**的顺序下工作。因此去掉坏的新记录，不会自动把同一 slot 的旧记录当成当前事实重新放回来。原始记录、原始日期、引文和完整 MS 均保留。决策、证据、代码和新检索身份有哈希绑定。

另外处理三个明确的来源/状态问题：

- p6 的 Lisa 关系：2024-10-05 原文是担心失去友情，不能提前当成已经失去；2024-10-15 明确失联后，隔离当前亲密朋友 slot。后来的变化不影响更早前缀。
- p6 的 current partner：2024-09-15 已说 breakup，但未清楚指认是哪一位伴侣。因此标成当前关系不确定并隔离，不能自行断言某个具体伴侣已分手。
- p8 的 esc995：原始对话后部明确说工作场所饮酒是扮演的场景，并否认自己的酒精滥用。隔离由该 session 编译出的 MP/ME；完整 MS 保留。其他 session 的新自述不自动证明旧场景确实发生过。

对旧批 18 个输入重新投影，隔离 **49 个唯一资源、54 次资源出现**；没有改写旧实验。这个数字不是整个资源池删除条数。修复范围限于已审阅材料，未覆盖的 MP/ME 不自动成为合格资源。

## 2. 门禁已实际接入，第二批也已经生成

第二批保留原来的 train/dev owner 划分：12 个训练 owner 各 1 个输入，3 个开发 owner 各 2 个输入。依据当前诉求和合法过去选样，减少单纯问候/结束语；**这是开发选择，已知上一批结果，不是随机、独立的效果评估。** 新作者输出在选样之后产生，未接触 test 输出。

36 个选中资源条件经过逐项来源、角色、时间和当前诉求核对。OFF 加入后共 54 个条件，`47_author_repaired_pilot.py` 在导入/加载推理模型前验证来源审查、证据、资源和精确渲染消息。缺少审查、不确定、证据变更、输入变更均拒绝生成。审查记录不进入 G/作者输入。

沿用本地 Qwen3.5-9B nonthinking 作者和原解码，每条件 seed17/29，共 **108 条回复，全部自然结束**。没有 60/256 token 上限，没有修复后重抽，没有新增付费 API 或人工答卷。

逐条 AI 辅助弱监督审查结果：90 accept、12 reject、6 uncertain；其中 61 train、29 dev 被接受。明确且被接受的历史引用覆盖 4 个训练 prefix。这里的接受不是独立人工准确率。

**原定“每个 prefix-condition 至少一条接受回复”仍未通过**：4/L、9/L、14/L 三个格子缺失。原始合同、失败状态和所有拒绝/不确定回复保留，不能写成第二批通过了原合同。

新发现已经能区分来源错误与执行错误：

- 作者 12/R/17 再次把“考虑招聘顾问/职业咨询建议”变成“已经求助且有效”。这次提供的 MS 明确说尚未尝试，错误发生在回复生成。
- 作者 14/L 的两条回复，把用户听朋友谈心理困扰改成用户向朋友谈自己的困扰，是人物/事件归属错误。
- 作者 2/L/17 跟随 Self Disclosure 策略编造了自己的父母和求学经历。
- 作者 4/L 的问题是精确可见输入不能支持其狗相关个人历史预设；完整私有过去中确有养狗证据。**“作者输入不支持”不能换算成“全部合法历史证明事实为假”。** 对弱监督准入和事实测量应分别记录这两个维度。

不能要求 R 一定引用历史或胜出，也不能要求 L 一定有害；同样，不能把所有比喻、共情或可选建议都误判成个人事实。

## 3. 为什么另开工程验证，以及它没有证明什么

再次无限补抽作者，直到每个格子都出现一条“好答案”，既不解决覆盖机制，也会引入挑选。另一方面，优化器、掩码和重载是否正常，并不需要一份覆盖所有格子的正式研究训练集。

因此本次**在看到第二批结果之后**另立 `executor_engineering_20260929_v1`：使用全部、且仅使用 90 条已接受的原回复；不重写、不改判、不追加生成。仍要求每个原抽样 owner、每种 OFF/R/L 标签在各 split 出现，并保留 4 个训练历史引用 prefix 的条件。新的用途、事后性质和原缺失格子写入独立合同。

这更新了推进方式，没有把事后实验伪装为事前设计：原研究批次仍失败，工程实验只能回答训练程序是否运转。测试还验证了这 90 条在原准入函数下仍然被拒绝。

| 实测项目 | 结果 |
|---|---|
| 训练/开发弱目标 | 61 / 29，owner 分离 |
| 参数更新 | 3 epochs，12 次 optimizer step |
| 可训练参数 | 3,407,872，全部为 q_proj/v_proj 的 LoRA |
| 基础权重 | 全部冻结参数训练前后哈希完全一致 |
| 开发 response+EOT NLL | 基线 1.853669 → epoch1 1.766077 → epoch2 1.617692 → epoch3 1.560451 |
| checkpoint | 按既定最小开发 NLL 选择 epoch3；基线单独报告 |
| 新进程重载 | 通过；总体和逐样本 NLL 最大绝对差均为 0 |
| GPU 峰值 allocated | 约 17.48 GiB，不是整进程保留显存或租赁费用 |

损失仅计算回复和真实终止符，prompt 被掩码；最后不足 16 条的累计组使用自己的目标 token 分母。模型、模板、实际输入、原回复、审查和 adapter 权重均绑定。

NLL 下降只说明拟合这批被接受的 Qwen 弱目标，**不说明支持质量提升、资源使用更正确或 reward 可用**。开发 NLL 还受到事后筛选及缺失条件的限制。

尤其不能把这个 adapter 称为完成了四类资源学习：61 条训练回复中，OFF 22、MS 18、ME 16、RS 5，**MP 训练例为 0**；开发集有 2 条 MP。没有多头资源组合训练。这些结构性缺口比再追求若干小数位的 NLL 更重要。

## 4. 同输入生成诊断

生成诊断使用 6 个 dev prefix × OFF/R/L × 基础模型/工程 adapter，共 36 次。两个模型得到完全相同的消息和资源；使用冻结基础模型的 greedy 自然结束策略，没有给 adapter 更多证据。包含弱监督没有合格答案的条件，不因老师失败而删掉诊断输入。

36/36 自然结束，18 对输入逐字一致，终止 token 都经过检查。基础模型输出中位数 57 tokens、范围 35–83；工程 adapter 中位数 32.5、范围 14–319。没有把更短自动当成失败，也没有把更长自动当成改善。

实际逐对阅读发现：

- 15/L 的基础模型和 adapter 都编造了“我曾经历相似情况”的个人经历；本次训练未消除该问题。
- 17/OFF、17/R、17/L 的 adapter 都自然停止在一句泛泛的感受回应，缺少对具体照护处境的推进；14、15 的部分输入也出现类似现象。长度本身不是错误，但结合具体诉求，这是正式资格需要检查的行为。
- 18/L 的 adapter 正确提到来源已核实的姐姐 Annie；基础模型没有用到。这证明能够引用这一信息，不能单独证明它更好地解决了职场问题。
- 13/R 的两模型都会根据 MS 问及 therapist；不是训练后新增的能力。14/L 的两模型都未重复作者把朋友与用户经历对调的错误。

因此 **NLL 改善与行为合格必须分开检查**。不能只选开发 NLL 最低 checkpoint，就宣布它是正式 X_l；也不根据这 18 对开发材料报告胜率。逐对依据在 [诊断记录](../outputs/pm_rl1/source_repair_20260929_v2/diagnostic_observations_private.json) 中，完整输入和回复在浏览页。这是参与开发的 AI 定性诊断，不是独立人评，也不产生新 reward。

## 5. 接下来应解决的具体问题

1. **固定这次来源层和工程结果。** 不再用原样的 18×3×2 小批次反复抽到“全格通过”。source gate 与弱监督单条准入继续生效；原合同失败保留。
2. **补齐正式执行器训练集的结构。** 先在不看新生成结果的前提下，列出四头、历史提供实际新信息、历史与当前冲突、合法但应忽略、多资源组合、OFF 六类覆盖；每个训练条件必须有完整可追溯来源。MP 在本次训练中为零，必须正面解决，不能以开发表现代替训练覆盖。
3. **把已核实错误纳入 R04B 的有限开发压力集。** 区分原文不支持记忆、合法历史不支持回复、G 可见输入不支持断言、建议与行动混淆、对象/时态混淆、无事实问题但支持不合适。Prometheus/Skywork 的候选范围和一次集中终评设计仍沿用原约定；本次未下载或运行新裁判，没有宣布其合格。
4. **人评继续留给冻结系统。** 本次不新开人工表。正式 X_l、有效测量范围及可比较策略尚未齐，工程 adapter 不接入自然支持 PPO。不能承诺一次人工审阅永久解决以后所有版本；能保证的是终评材料不因当前工程摸索反复改卷。
