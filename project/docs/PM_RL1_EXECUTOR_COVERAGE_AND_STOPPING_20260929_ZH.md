## 1. 短答问题查到了什么

重新检查上轮实际使用的 90 条训练/开发样本：prompt 全部被 mask，回复正文能逐字回解，每条目标只有一个真实 EOT，正文没有额外控制符；chat template 后缀也已正确排除。没有发现把 prompt、重复终止符或下一轮 header 错算进损失的问题。

对同一批 29 条开发参考回复，分解基础模型与已选 epoch 3 adapter 的损失：

| token 范围 | 基础模型 NLL | 工程 LoRA NLL |
|---|---:|---:|
| 正文＋EOT | 1.853669 | 1.560451 |
| 仅正文 | 1.868740 | 1.572776 |
| 仅参考结尾 EOT | 0.028039 | 0.067441 |

3,542 个目标 token 中只有 29 个 EOT，占 0.819%。NLL 改善来自正文；参考结尾的 EOT 拟合反而略差。因此，“EOT 占比太大导致总体 NLL 看似变好”不符合这批实测。

另对上轮 36 条已生成回复的完整续写上下文，分别用基础模型和 LoRA 计算下一 token 分布；不重新生成回复，不修改 checkpoint。在 LoRA 自己结束的 18 个位置，LoRA 的最大概率 token 全部为 EOT，基础模型只有 6 个位置如此。其余 12 个位置，基础模型倾向继续说。

例如旧开发编号 17 的 OFF/R/L，LoRA 输出分别只有 16/14/16 tokens（含终止符）。在相同结束位置，基础模型总 EOS 概率约为 0.0000095 / 0.0000347 / 0.0000130，LoRA 为 0.1666 / 0.1548 / 0.1492；LoRA 中 EOS 已排第一。这个现象确认了**相同上下文上的停止倾向改变**，但不是对“EOS loss 是唯一原因”的因果证明，也不是独立质量评分。

处理决定：保持原方案的 response＋EOT 损失与自然 EOS/EOT 停止，不添加最低字数，也不移除 EOS loss。下一次固定报告 base 与三个 epoch 的同条件生成诊断，以观察变化；仍按原先的 dev response NLL 选择 checkpoint，不用诊断结果挑更好看的 checkpoint。适当的短回应可以接受；面对具体求助只剩泛泛确认，仍需作为适当性问题单独检查。

## 2. 补充输入已经具有什么覆盖

盘点覆盖全部冻结 train/dev roster；没有抽取 test。盘点是候选与容量检查，**不意味着所有候选都已通过语义审核**。旧修复 overlay 也只覆盖其声明的来源问题，不能给整个记忆库自动背书。

本次从中逐项核对 18 个前缀、48 个前缀内资源实例，组成 OFF/R/L 三条件。每条资源保持原排名，组合里的 MS 仍为完整原始会话，没有跳过不合格的第一名去取后面的条目。

这些 owners 是公开 ES-MemEval 的数据集身份，不是本研究招募的真实参与者。选材时已知旧批次的开发结果；这里是针对既知缺口的开发补充，不是独立确认性抽样。本输入包与旧输入包的前缀并集为 19 train、9 dev，仍在原始 96/18 roster 内。

| 已核对的输入覆盖 | train | dev |
|---|---:|---:|
| 前缀 / owners | 12 / 12 | 6 / 3 |
| 条件数 | 36 | 18 |
| 含 RS 的条件 | 9 | 6 |
| 含 MP 的条件 | 9 | 3 |
| 含 MS 的条件 | 6 | 5 |
| 含 ME 的条件 | 7 | 3 |
| 多资源条件 | 6 | 5 |
| 含 MP 的 owners | 9 | 2 |
| 最大完整资源块 tokens | 826 | 876 |

类型计数允许重叠。上述数字是提供给模型的输入覆盖，尚不是接受回复数、学会使用资源的数量或资源效益。所有 54 个条件均通过实际逐步 GET/STOP 路径核验和 2,048-token 资源预算检查；该预算不限制回复长度。

新增内容着重补上此前训练 MP 为零和单资源为主的缺口，并保留难点：

- **有来源但此时不该强用。** 办公室工作、摄影兴趣、对前任直接沟通的偏好，都有原文；面对一句问候或“能聊聊吗”，不能猜成当前问题。
- **有用的约束仍需限定范围。** 学习困难是用户自述，不升级为临床诊断；治疗费用困难是历史报告，当前经济紧张使其相关，但不自动变成永久事实。
- **当前更新优先。** p6 历史说日记有帮助，当前明确说帮助有限、没有改变工作处境；不能把旧有效体验重复说成解决了现在的问题。
- **组合中允许选择性采用。** p5 同时有费用限制、完整家庭会话和兼职建议，兼职可能增加负担；R 条件不等于其中每条都应采用。
- **对象、时间和说话者不能偷换。** Henry 与前女友、朋友的心理困扰与用户自己的困扰、考虑调解与已完成调解、建议联系招聘顾问与实际获得帮助，均有明确核对说明。
- **助手不能承接虚构自传。** p15 当前对话里已有助手谈自己母亲的说法；下一回复应避免继续编造，不因为它出现在前文就把它当成助手真实经历。

另排除 p15 的“我是父母最喜欢的孩子”MP：完整原文存在讽刺解释，不能仅凭一句可引用的话就认证为稳定家庭身份。部分其他候选仍把短期情绪编成长期健康约束；本次没有靠这些条目补 MP 数量，也未把尚未审核的整个库宣布合格。

## 3. 下一批如何避免重抽与事后改规则

54 条件 × 2 seeds 共 108 个逻辑位置。其中 **26 个可逐 messages、prefix、seed、原始文件 hash 复用旧回复**：原审核为 24 accept、2 reject，全部保留原结果。仅 **82 个新输入/seed 对需要生成（54 train、28 dev）**，不把复用记录叫新增独立样本，也不把旧拒绝项重新抽到通过。

下一批工作合同已经在任何新输出前冻结：

1. 本地原 Qwen author 身份、解码和真实可见输入保持一致；82 个新位置各生成一次，不修复、不因质量不佳重抽。作者只是弱监督示例作者，不是 reward 裁判。
2. 逐回复记录 accept/reject/uncertain/technical_failure；核对来源、时态、对象、助手身份和当前求助适当性。合理不使用资源可以是合格回复，不要求最低字数或必须引用记忆。
3. 训练集由上轮 90 条已接受原回复与新增合格回复合并；相同 prompt/response 去重。所有 owner split 保持不变。复用 dev 明确属于开发数据。
4. 从原冻结 Llama base 重新初始化 LoRA，沿用 r8/alpha16、q/v、lr1e-4、最多 3 epochs、seed17 等参数；不接着工程 adapter 续训。最多新增 82 条候选，即合并前弱监督记录最多 172 条，实际接受数待审。
5. 按原 dev NLL 规则选一次 checkpoint、验证重载；固定对本次六个 dev 前缀的三个条件运行 base＋三个 epoch，共 72 条自然结束诊断，单独报告正文/EOT损失与生成行为。**没有要求 X_l 必须胜过 X_g，也不要求资源 ON 必须胜过 OFF。** 没有正收益是可以报告的研究结果。

旧 pilot 的“每个前缀×条件都至少一条通过、至少四个历史采用前缀”是那个 pilot 自己预先写的门槛，失败记录原样保留。本次新合同不继承这种全格门槛，不事后改称旧实验通过；逐条准入和缺失情况仍完整报告。

四资源执行器的覆盖主张必须有相应接受样本支撑。若实际审核后某头或组合仍为零，收缩该部分主张并注明缺口，不能靠输入计数冒充已训练，也不能自动反复补样直到效果为正。原方案至多扩展 96 个训练前缀的边界保持；任何进一步扩展都必须先说明具体来源/覆盖缺口，不由测试集或收益方向触发。

## 4. 裁判与人评保持什么状态

来源审核、弱监督准入、训练损失、增量质量与 reward 资格是不同证据。本次完成前两者中的输入来源部分和工程诊断；没有解决自然支持 reward 的可靠性，也没有把开发者 AI 审核改称独立人类真值。

R04B 仍按 [有限测量与集中人评方案](PM_RL1_R04B_MEASUREMENT_AND_SINGLE_HUMAN_CAMPAIGN_20260929_ZH.md) 推进：Prometheus/Skywork 候选的有限开发测量、明确可判范围、冻结后集中终评。新补充的来源错配、建议与行动混淆、当前覆盖旧状态、虚构助手经历等，可作为有出处的开发压力案例，不能用模型最喜欢的标签替代证据。

本次没有下载或运行新裁判。工程 adapter 不接入自然支持 PPO。现阶段也没有新人工表要用户填写；最终集中人评应审冻结后的真实系统对照，保留旧 A/B 的实际来源属性，不能把共同审核包装成两份独立标注。一次集中评审能避免开发期反复改卷，但不能保证所有未来版本从此无需核验。
