# PM-RL1：当前轮评价协议与小型考卷草案

状态：**按用户新方案细化的开发草案；未完成实测、未冻结为训练奖励。** 不修改旧考卷、原始人评或官方 scorer。没有新裁判判分或新增人工答卷。

**评价对象。** 给定公开当前对话前缀和该切点前合法历史，评价一条新生成的当前回复。过去对话只提供语境和证据，不计入该回复的质量。没有后续用户反应，不评价其未来情绪变化或实际心理疗效。主研究的 q/m 是声明的代理测量。

**三种权限。** PM 只看白名单 observation；G/示例作者只看当前前缀及实际取得资源；训练裁判和独立评审看同一套完整合法评审证据。合法评审证据为之前完整 sessions＋当前 session 到切点为止的原文，不含当前后续、未来 session、旧 target 的 gold/reference。旧 target 的“完整历史”不一定对新中途切点合法，必须重建。

评审输入附日期、角色和可定位的盲化 span ID。匿名 source ID 不携带 owner/原 session/分组标识。旧 supporter 的猜测、问题、建议不能直接当作用户已确认事实；意向不等于执行、执行不等于有效。当前明确更正优先于过时状态。缺少证据的用户特定断言要与一般性建议、明确假设、问题和不确定表达区分。

**质量 q 的操作锚点。** 沿用新方案 0–4 整体编码，不把七个旧官方维度简单求平均。解释必须指出当前需求/约束、回复中的对应片段、决定该档的重要优点或缺陷。

| q | 锚点 | 与邻档区分时优先检查 |
|---:|---|---|
| 0 | 严重失配或不能使用 | 是否基本未回应当前需要，或有使回复无法使用的严重问题 |
| 1 | 回应有明显问题 | 是否存在主导性的错误、越界或失配，使大部分支持不成立 |
| 2 | 基本回应，但有重要不足 | 是否遗漏当前明确需要/关键约束，或有影响使用的不足 |
| 3 | 贴合、连贯、适当 | 当前需要得到妥当回应，无明显重要缺陷 |
| 4 | 充分回应当前需要并尊重已知约束 | 在当前任务确有要求的方面充分完成；简短回复也能是 4，不要求展示记忆或增加建议 |

这些锚点仍须通过新题检查相邻档是否能被稳定、可解释地使用。不能给每档编一段万能“理想回答”然后让所有情境模仿它。不同支持策略可以同样适当；用户未表达的回复风格偏好不可凭空补出。适度共情和建议要符合当前需求，不能机械要求每题都建议、追问、总结或给出个人化历史。

**误用 m 的操作锚点。** 评价回复中与人物、历史事实、时间、意向/结果和明确边界相关的错误。OFF 同样可能编造记忆，不能预设 m=0。

| m | 含义 | 记录要求 |
|---:|---|---|
| 0 | 在实际检查范围内未发现相应错误 | 列明检查覆盖；若没有可核查的个体事实断言，另记 `claims=0, precision=NA` |
| 0.25 | 局部失准，不改变核心建议/理解 | 指出错误片段、所据原文及为什么只属局部 |
| 1 | 实质性误用 | 如把未执行说成已有效、过时限制当现状、示例人物当用户、违背当前明确边界；指出对本次回复的影响 |

q 中严重事实错误可能已经降低整体质量，m 再惩罚是有意的风险偏好；两者不是互不重叠的独立构念。保留 q 和 m 分项，不能用总 reward 掩盖这个选择。

**证据判定与缺失。** 每项事实/时态问题记录 `response_span`、`source_span(s)`、关系 `supported / contradicted / unsupported / uncertain` 和理由。`unsupported` 不能只靠“没在一小段摘要里找到”：需说明在完整合法材料中未找到支持，相关反证若有则引用。它不等于已经证明世界中该事实为假。`uncertain` 是证据/语义不足；解析失败、上下文超限、超时和空回复属于不同的技术状态。

相互矛盾或尚不能完成的 q/m 不强填 0；保留待处理及各缺失原因。语义不确定若集中在某类回复/策略，不能简单删除后只报告剩余样本的高分；必须按方法报告覆盖与缺失率，避免把选择性测量当完整效果。

**评分记录的最小结构。** 下面是设计示例，不是已经运行的解析器，也不是已返回评分：

```json
{
  "measurement_status": "pending",
  "q": null,
  "m": null,
  "q_rationale": null,
  "claims": [],
  "misuse_findings": [],
  "uncertainty_reasons": [],
  "response_sha256": "由程序绑定",
  "legal_evidence_sha256": "由程序绑定",
  "rubric_identity": "待冻结",
  "judge_runtime_identity": "待冻结",
  "parser_identity": "待实现和冻结",
  "measurement_draw_id": "由程序绑定"
}
```

span 结构至少要包含证据条目 ID、原文摘录和原文位置；程序核验其确实存在。找到对应字符串不能证明蕴含关系成立，后者仍需语义复核。隐藏的 method/k/cost/资源来源映射只在协调端保存，不能填进评审 payload。当前 `rl1.schema.Score` 只有粗粒度字段，不能代替上述绑定和证据校验。

旧 Gemini 有四题因理由超过 600 字符而在冻结 parser 下失败。这次不继承该任意理由长度拒绝条件，也不靠裁掉解释追认成功；自然结束策略同样适用于裁判。解析器仍严格检查必需字段、枚举、重复/冲突结果和可定位证据。任何纯格式规范化须保留 raw 与变换记录，不能替模型选择某个语义结论来提高可用率。

**裁判配置与分工。** 本地 J_train 首先开发已安装的 Qwen3.5-9B 通用推理配置，理由是旧实测的稳定性与证据检查表现，不是宣称它已合格。复用已有独立环境与 serving 经验；固定 revision、原生模板、thinking/解码、seed 规则、natural-end/技术异常处理和 parser。Compass 可对预先指定的少量争议题补充诊断，不默认三模型投票或重启全体候选比赛。

执行器示例作者 T_X 生成 SFT 弱监督文本；核验者 V_X 检查来源和适用性；J_train 生成 PM 训练 reward；J_eval/人工评审提供终局独立证据。这四个角色可复用部分工程，但要分别记录身份。T_X 和 J_train 同家族时披露相关性。V_X 若读完整历史，不能把 G 未取得的正确事实经“修复建议”传给 T_X；修复仍只使用 G 的可见证据。盲评阶段的归因（编译/检索/生成问题）由评完后单独结合私有资源链进行，不让 J 先见方法身份来判断。

**12 前缀测量卷。** 当前离线草拟每个 train owner 一条，共 12 条；按固定 hash 在现有初步 train pool 中选取，已知 p13 的共享 `esc1198` 及后继切点暂不入此小卷。它没有替代全量来源/暴露审计，也未冻结为正式样本。选样不能由新模型输出是否正收益决定。

每个前缀计划四条回复：

1. 真正的 OFF；
2. 同一 X_g、同一切点下，预先固定的合法资源计划生成的 ON；计划在看回复前冻结，不能事后挑最有收益的组合；
3. 从一条实际回复做单点事实/时间/主体/意向结果损伤，保留原始版本与精确修改；
4. 从一条实际回复做尽量保持语义、语气、断言确定性及行动导向的风格改写，核验后才作为风格对照。

自然 ON/OFF 是实际任务样本；人工/程序修改的两条单列为诊断。某个真实回复无可改的断言，或所谓“风格改写”已经改变支持含义时，保留不适用/不合格说明，不伪造一个天然正确控制、不换掉整条自然 prefix 来追求理想判别率。

最多 48 个单回复评分 payload；每个 prefix 预选一条重复一次，四条件各 3 条，共再 12 次评分。重复必须实际执行并保存不同 measurement draw ID，不能读缓存假装稳定性实测。固定同一解码协议，提前声明重复是否改变随机 seed：同 seed 重跑主要测运行重复性，换 seed 测包括采样在内的判分稳定性，不混报。

另有 12 对独立复核，草拟配额为 6 对自然 ON/OFF、3 对原始/损伤、3 对原始/风格，每个 prefix 一对；分配按 hash 预定。这是本次细化的草案，生成前封存，不按裁判分歧或效果挑选这 12 对。出现问题后追加的具体疑难案例作为开发排错单列，不并入预选样本比例。

独立复核允许 `A更好 / B更好 / 无可辨净差异 / 无法判断`；“同样差”可以无净差异，不能据此把两条 q 都设成高分。复核表兼收 q/m、关键依据与总体比较，分别检查分档和差异方向。两名人工都能参与时先各自答完再讨论；只有一名也如实称单人复核。独立模型是模型复核，不能改名人评。没有必要重填旧 96 题。

**分析输出。** 报告自然样本与控制样本分别的 q/m 分布、uncertain/技术失败、损伤识别与证据关系、风格变化分差、重复评分分差、独立复核分歧与决定性事实，列出分母。既看漏报，也看把正确事实误判成错误；只测坏样本识别不足以发现“逢事实就罚”的裁判。零断言数不自动高忠实度；没有正确参照的自然 pair 不计算臆造的准确率。

不预置一个任意的“80% 就合格”门槛。若关键错误能通过单次明确的 train/dev rubric 修订解决，保留前后版本并重评分原回复，不重生成来凑理想数据；该轮仍属于开发证据。若只能稳定识别事实/时态错误，保留执行风险研究，不能把它扩大成已可靠的帮助性优化 reward。若证据更强，只冻结其已支持的有限任务范围，再开展后续训练。

**奖励尺度检查。** 默认 `U=q/4-m`、最大资源惩罚 `0.05*c/2048`。q 的相邻档差 0.25，是用满资源预算时总惩罚 0.05 的五倍；m 的局部档差也为 0.25。因此一档无依据的波动就可能主导资源选择。12 次重复和独立比较必须检查“误差是否足以反转所比较计划的结论”，不能只看 JSON 合法或模型两次方向一致。若 q 分辨率不足，先收缩/修订测量；不直接为追求正 reward 调 λ/α，也不凭空换成更精细小数制造分辨率。

**正式评价。** 冻结后，在新 test replies 上保留两类互补证据：J_train 的 q/m（明确叫训练代理的 held-out 分数）以及独立盲审。正式执行矩阵至多 432 个回复、策略交叉至多 960 个回复；完全相同生成身份才去重，新的重复实验不并掉。

24 对正式独立盲审中，12 对是同 prefix、同资源的 X_g/X_l，另 12 对是同 X_l 的 RL/OneShot；分别覆盖 3 个 test owners，每个比较每 owner 4 对，seed 在结果前轮换。样本与顺序在查看结果前 hash 固定；独立评审不看训练分数、不回流调参。需要反序重复时额外列调用和人力，不能把反序计成新独立样本。

主报告分别给 q 原档分布和配对差、重大误用率、局部错误/不确定、GET/STOP/类型量分布、实际资源输入 tokens、输出 tokens、检索/编码/G/PM 全链时延、失败与训练成本。额外事实指标注明“全部回复 / 含事实回复 / 断言数”分母。按 owner 呈现结果，18 个虚拟用户、3 个 test owners 的结论保持受限，不用千余回复冒充千余独立人。

ESC-RANK 七维可作单轮适配后的补充，但不是原官方多轮协议复现；若执行原官方 benchmark，则独立保留其完整定义与官方名称。可选 48 个 outcome-isolated QA targets × 4 方法 = 192 个答案提供事实检索外部证据，不代替自然支持适当性。修改 J 只重评分旧回复；修改 X/prompt/资源表示才重生成对应请求。

无独立有效评价时，仅可报告优化声明的模型代理。独立模型和小样本人评均不构成真实用户疗效证明。若 RL 只胜 Fixed、不胜同数据/动作域 OneShot，就不主张已证实序贯获取的额外价值；若 X_l 的 OFF 也提高而资源增量不提高，就不主张已学会更好利用资源。
