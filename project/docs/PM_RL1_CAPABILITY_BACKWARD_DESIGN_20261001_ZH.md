## 1 先确定要造出什么

第一版 PM 是一个**在回答之前决定查什么、继续查还是停止的小策略模型**。执行器负责写回复；PM 负责给执行器选择资料。训练 PM 不等于用 RL 改造整个语言模型。

一次工作过程：看到当前对话及候选资料的长度、排序、相似度等元信息；选一类资料并看到正文；据此继续取另一条、换一类或停止；最后把已取资料交给同一个冻结执行器，生成一次回复。

四类资源的现实含义：RS 是候选支持动作；MP 是有出处的个人背景或偏好；MS 是完整过去会话；ME 是过去事件和经历，未必包含已验证的有效行动。它们不是四个必须全用的技能，也不要求每一类都产生正效应。

说明用途的假设例子，非真实实验结果：当前用户提到“又睡不好”。PM 读到一段历史，发现某种办法只是曾被建议，并没有实际尝试记录；它可能需要再查原会话，也可能已有足够信息而停止。执行器应据此谨慎回应，不能说“上次这个方法对你有效”。选择资料和正确理解资料是两个不同环节，必须分别验证。

| 第一版拟实现的能力 | 成功时能观察到什么 | 这不意味着什么 |
|---|---|---|
| 按情境选类型 | 相同预算下，不同对话选择不同的有用资源 | 仅动作分布不同不证明选择正确 |
| 按情境选数量 | 有时不取、有时多取，净效果优于统一取量 | 不是 GET 次数越少越好，也不是多样性越高越好 |
| 读后调整与停止 | 已取正文能帮助后续取舍；与 OneShot、NoText 对照相符 | 多步执行本身不证明顺序观察有价值 |
| 稳健地支持当前回复 | 有助于适切回应、正确使用历史，减少无依据陈述或无用资源 | 不证明长期情绪改善、疗效或真实心理状态估计 |

第一版不更新检索器、不改头内排名、不随意跳取、不写回或删除长期记忆、不向用户发问作为 RL 动作、不模拟未来用户，也不做跨轮关系优化。有效资料不在冻结候选前四条时，PM 无法凭空找到；资料错误时，它最多学会避开部分风险，不能代替来源修复。执行器忽略全部资料时，PM 的可实现收益会很低。

## 2 什么程度才算实现研究目标

必须把工程完成、能力成立和论文主张区分开，但主攻仍是正面的能力证据，不能把“发现失败”预先当作等价替代目标。

1. **工程底座完成**：合法动作、真实生成与评分、参数更新、可恢复且无泄漏。这部分已有大量成果；不是核心科学结论。
2. **情境化 PM 成立**：在冻结评价上，按情境选择比 OFF、强固定计划、匹配随机方案更有价值。价值可以是明确可感知的回复改善，或在有证据支持质量维持时降低资源成本；不能用“不显著”代替质量维持的证据。
3. **RL 更新的贡献成立**：PPO 相对实际 BC 起点有可复现改善，并用 BC-union 检查收益是否只来自更多监督反馈。PPO 与 BC-union 都使用的标签及采样成本必须披露。
4. **顺序信息利用成立**：相同初始信息和终值动作空间下，对照 OneShot；独立训练的 NoText 用于检验已取正文的作用。若只胜固定策略，不能宣称顺序决策优势；若 NoText 不受损，也不能仅因轨迹好看而声称在理解正文。

第一篇最值得主攻的是第2–4项的证据链。第4项若不成立，研究需要明确收缩结论，而不是降低 OneShot、加无用步骤或改变测试题来维持名称。

“有价值的改善”应在开发阶段用实际回复锚定：例如纠正与当前明确说法冲突的历史回顾、避免再次推荐已明确不适用的建议、恰当回应当前需要。只更长、更像标准答案、多提一个历史细节，不自动算改善。人工评价同时允许平局和无法判断。

最终判断结合配对效果、owner/seed分布、错误与成本分项、独立人工证据。当前 test 只有3个构造人物，不足以支撑广泛人群推断；已有32/48当前会话历史暴露必须披露。预先冻结最小有意义差异及其量表锚点，但本轮不凭空设一个百分比，假称现有样本一定能证明它。小样本不确定时，报告证据范围，不把更多同人物回复算作更多独立人。

## 3 反推所需的环境

| 必要条件 | 为什么需要 | 目前情况与够用标准 |
|---|---|---|
| 真实可执行的 GET/STOP | PM 的决定必须改变可见信息与最终输入 | 已实现；新表示后回归动作、预算、自然结束与缓存 |
| 有些资源提供当前对话之外的信息 | 否则查询没有收益空间 | 来源存在，但“相关且新增”比例未知；只分析严格过去、实际可取资源 |
| 不同场景的最佳取舍有差异 | 否则一个固定方案足够 | 尚无可靠自然效用表；需在共同回复池检查，不能用库存差异替代 |
| 已取正文会影响后续取舍 | 否则一次规划可解决主要问题 | 结构允许，实际价值未证明；需读后分支诊断及 OneShot/NoText 对照 |
| 固定执行器能响应正确证据 | 否则 PM 的好选择无法转成好回复 | 旧 LoRA NLL 降低但语义失败仍存在；先修表示，再做一次有界适配 |
| 反馈能分清要优化的改善和风险 | 否则策略学到的是评分偏差 | 现有具体裁判均未获自然任务奖励资格；新校准仍待做 |
| 训练与评价按人物、来源隔离 | 否则记住材料可能伪装成选择能力 | 已有切分与隔离；维持身份并披露暴露，不能靠重划 test 重置历史 |

不需要为了让它叫 RL 而添加未来用户模拟。这里的后果是“新信息被揭示，后续动作发生变化，最终回复及成本改变”。已有主动特征获取研究就使用类似的取信息／停止框架；我们的新意必须落在支持任务、多类来源、执行与测量的具体证据上，不能说 GET/STOP 形式本身首次提出。[相关原始论文](https://papers.nips.cc/paper_files/paper/2018/hash/e5841df2166dd424a57127423d276bbe-Abstract.html)。

反过来，顺序动作不自动带来额外信息价值。在这套冻结检索系统里，资料对每个前缀是固定的；如果初始输入已足以预测全部有用资料，或资源只是重复它，一次性策略也可能达到相同结果。顺序方案的价值需要在有限训练和计算条件下实证检验，而不是由“部分可观察”四个字保证。

## 4 现有数据实际能支持到哪一步

本节使用2026-09-30旧 renderer 的 train/dev 导出重新计算。主键是前缀；计划主键是前缀与四类数量向量。未读 test 答案；旧词法标记不当人工语义标签。

| 特征 | 实际证据 | 对研究的含义 |
|---|---|---|
| 主任务规模 | train 96前缀/12 owners；dev 18/3，每前缀来自不同当前 session | 可做有限方法研究；重复 rollout 增加优化步数，不增加独立人物 |
| 动作空间 | 理论114×70=7,980；库存允许7,477；实际可达7,240 | 库存排除503；再受渲染预算、上下文或路径规则排除237，占库存允许计划3.17%；不能据此认定预算普遍紧张 |
| 四头各取一条 | 105/114前缀可达，约92.1% | “每头各一条”的固定混合计划必须认真比较；不能只设弱单头基线 |
| 高剂量动作 | 可达计划中3/4条占77.1%；所有114前缀均有某种4条可行计划 | 真实动作域远大于旧训练覆盖；比例不是自然策略访问频率 |
| 单条成本 | 整块资源中位数：RS129、MP139、MS702、ME147 tokens | MS明显更昂贵；不同类型数量不能直接等同信息量。数字包含公共包装，不是纯正文或边际成本 |
| 跨头来源重叠 | 两头都有候选时，top4共享至少一个历史session：MP/MS为87/106，MP/ME为77/105，MS/ME为99/113 | 多类资源经常是同一历史的不同视图；可能重复，也可能互补。共享来源不等于语义重复，需进一步看具体新增信息 |
| 四条成本 | train中位724、dev796.5 tokens，预算2,048 | 很多组合并不贴近token上限；不能预先把任务解释成紧预算分配 |
| 执行器覆盖 | train 103弱示范、19前缀，0/1/2条为34/59/10；3/4条和同类多取为0 | 旧训练只覆盖96个train前缀的19.8%；覆盖缺口可修，但增样不自动证明正确使用 |
| MP时效 | train/dev重复更新173条；已审101，待审72 | 来源字符串可解析不等于支持该次更新；有限修复队列明确 |
| ME结果 | 历史报告记录1,523条ME，4条action_observed_outcome，7条非空结果文本 | 支持事件回顾、意向与尝试区分；不支持学习个体行动疗效。低抽取量不等于原文没有结果 |
| QA可用性 | train/dev 1,261题，224无证据、20仅私有事件引用、219跨多个可见session | 是事实核查与时间诊断的来源，不能直接作为单轮支持真值；各计数可能重叠，不相加成错误率 |

现有输入还有问候、感谢、历史更新等词法标记。这些只用于事先分层，不能自动把问候标成“不需要记忆”、把出现历史词标成“需要记忆”，更不能据它们给奖励。

本轮没有测得以下关键比例：资源真正新增信息的比例、四头语义重复与互补的比例、正确资料被执行器有效采用的比例、不同计划产生实际有意义差异的比例、读后应改变后续选择的比例。旧结构统计不能代填这些数值。

## 5 把缺口缩成三个可回答的问题

后续在v2已有的共同回复池和40对校准中加入以下字段和比较，先复用，不另开无限评测。已知旧失败仅为开发案例。评价前缀和来源家族分组沿用原计划。

**A. 资源收益空间：这批可取资料能帮助冻结执行器吗？**

对同前缀比较OFF与固定不同计划，先核对新增依据，再看回复如何改变，最后看人和裁判是否识别。记录“信息未新增／信息新增但本轮无关／相关但执行器未用好／执行正确但评分漏掉／观察到改善”。一条回复可能包含多种问题，不用一个互斥标签掩盖它们。不能仅靠关键词判因。

**B. 情境化空间：是否存在一个对所有情况都足够好的固定计划？**

比较同一全局固定计划与不同前缀中已测计划的表现；按owner和需求层报告，不只挑最有利例子。若各场景都偏同一计划，先检查动作资源是否重复、需求是否单一、评分是否塌缩；没有证据时，不扩大PPO期待解决任务本身没有差异的问题。

**C. 顺序观察空间：看到某条正文后，下一步选择会变吗？**

在共同池已有终点上分析包含关系：取到某类第1条后，STOP、同头再取、换头续取的已测终值有何差异；记录哪段已取内容说明继续或停止可能值得，以及该依据是否早已存在于初始前缀/metadata。它是机制诊断，不是单凭人工故事证明最优动作。未测终点保持未知；跨前缀比较存在混杂，最后仍由冻结的OneShot/NoText对照判断泛化价值。

可计算的开发统计包括：已测最优净效用与OFF差、已测按前缀选优与全局固定差、自然明确偏好/平局/无法判断比例、严重风险比例、正文新增/重复/不确定比例。最大值会受到评分噪声和挑选偏差放大；只叫已测支持集差距，不叫全空间oracle，也不当最终效果。

对“根因已经解决”的证据要求是：修改作用到预定类别、来源可核对、在非同一已知案例上检查，并明确还不能覆盖的情况。单个母亲案例修好，不能宣称角色问题彻底解决。

## 6 奖励应当奖励什么

目标是“本轮适切支持＋正确处理历史与边界＋合理资源开销”。不能奖励固定多取、提及记忆、长回答、复述参考答案、表面积极，或没有真实观测的未来情绪变化。

保留v2形式作为待校准候选：

```text
U = q/4 - m
终值净回报 = U(有资源回复) - U(同前缀无资源回复)
             - 0.05 × 最终完整资源tokens / 2048
```

它有四个需要明确的性质：

1. 同前缀同执行器的OFF值是常数。相减提供相对解释，不改变该前缀不同计划的排序，也不会自动创造因果标签或保证降低方差。
2. GET只扣真实新增资源成本，STOP给质量差；gamma=1时步成本相加等于最终成本。最多四步的短任务不必每个GET再调用裁判造“即时帮助度”，也不能把便宜的GET误读为有帮助。
3. q/m组合使U最小非零档差为0.25，成本最多0.05。于是单前缀层面是效用档位优先，同档偏向便宜；单条RS/MP/ME成本约0.003，MS约0.017。它不是连续精细的质量成本交换。如果人能区分而q/m大量同分，先修测量分辨率或明确更粗的主张，不给每次GET发正奖励。
4. m是测量到的风险惩罚，不是安全保证。高q仍可能伴随严重错误；OFF本身差时，相对收益为正也不代表回复可接受。必须报告绝对q、严重风险和可检查事实，不能只报ΔU。当前alpha=1并非数学上的严格风险优先排序，本轮不悄悄改系数。

q需要以真实对话需求锚定：尊重当前明确纠正、避免不适用建议、需要时澄清、不强行解决或长篇说教。m需要区分：被来源否定、无充分依据、主体错配、时态错误、建议/意向冒充实际行动与结果；一般性共情和试探性提问不能机械罚成事实错误。无法判断必须保留，不填零。

测量“够用”包括四件事：严重错误可识别；一般支持不被乱罚；对同一内容相对稳定；对真实资源/策略产生的有意义差异有分辨力。人和裁判都认为相当时允许平局；只有人发现差异而评分遗漏时，才是分辨率问题。旧v2中的75%、重复11/12等是有限运行边界，不能替代上述任务有效性，更不保证泛化可靠。

## 7 evaluator与外部资源分别能补什么

| 组成 | 正确职责 | 当前能用到什么程度 |
|---|---|---|
| 程序检查与来源账本 | 检查主体、严格过去、原文位置、完整交付、缺测与身份 | 可大量自动化，但字符串匹配不等于语义支持 |
| 来源约束事实核查 | 判断具体断言是否被当前可用材料支持或反驳 | 既有机制可复用；MiniCheck最多作为一个有界候选验证，不能默认接入奖励 |
| 支持适当性评分 | 判断是否回应本轮需要、是否尊重边界、是否合理使用信息 | 现有Qwen checkpoint可做新版候选；旧错误不会因换协议名消失 |
| 人类校准 | 建立量表含义，检验错误控制和自然差异 | 使用v2的40对开发/封存设计，兼记上述三类任务诊断；不重做旧96题 |
| 最终盲评 | 判断真实冻结策略的改善是否超出自动奖励偏好 | v2的48对；不能用前期开发材料代替，也不能提前评价尚不存在的PPO回复 |
| 官方QA/ESC能力评测 | 补充事实、时间、一般支持能力信息 | 保持原协议；不能替代本轮资源决策收益评价 |

MiniCheck的官方接口是文档与单句主张的支持判断，不是情绪支持质量评分器；“不支持”也不自动等于“被证伪”。[官方实现](https://github.com/Liyan06/MiniCheck)。奖励模型过度优化研究则支持把训练评分与独立效果检查分开，但不证明本项目某个候选一定会失败。[原始研究](https://arxiv.org/abs/2210.10760)。

需要补充的第一优先级是**本任务的证据和标签**，不是更大模型名单：实际可用的相关历史、来源正确的不同计划回复、人类对其差异的有限判断。若需要跨真人长期效果，才需要新人物、真实纵向反馈与另一个研究设计；当前模型升级不能替代这些数据。

## 8 针对性补缺，而不是把所有缺口一起修完

| 实际发现 | 先做什么 | 解决到什么程度足够 | 仍解决不了时 |
|---|---|---|---|
| 主体/时间/行动状态误导 | 修renderer及有限MP/ME来源审查 | 每个保留字段有依据或unknown；共同规则适用于各方法 | 删去无依据断言/保留不确定，不能要求补出不存在的真相 |
| 有用信息没进入候选 | 区分上游来源缺失、抽取遗漏和冻结排名问题 | 明确候选覆盖上限；修实现遗漏须新身份 | 检索器研究另立范围，不能宣称PM能选不存在的条目 |
| 资料正确但执行器不用或误用 | 覆盖取量、组合、谨慎澄清和合理忽略的一次SFT | 固定回归不再出现已证实严重缺陷，并保留真实资源效果证据 | base可用则继续base；两者都不能利用资源，则先处理执行瓶颈 |
| 人能分辨而裁判不能 | 修来源协议与量表锚点，最多一次修订 | 封存中控制与自然差异均满足对应有限用途 | 自动B0准备；人工终值表B1需实际人力及明确缩小范围 |
| 人和裁判都看不出计划差异 | 检查相关信息、执行响应、任务分布与成本 | 区分真实等效和证据不足 | 不为制造差异删掉简单场景；必要时独立定义有来源依据的开发诊断任务，不能替代自然主评测 |
| 情境化有用、顺序正文没帮助 | 强化并公平比较OneShot，检查NoText | 保留情境化结论，解释顺序边界 | 不人为隐藏本来应给基线的信息；顺序优势未成立就不宣称 |
| 信号清楚、策略仍学不到 | 查编码、mask、BC拟合、价值初始化、更新与探索覆盖 | 已测小支持集可拟合、优化正确，再判断样本与表示限制 | 有证据后针对性调整并新登记；不把任意追加episode当根治 |

时间状态采用可核查字段，不以新时序网络替代来源；ME不要求每条都有结果；裁判不要求通用完美，但必须能处理拟优化的具体差异；资源不要求全有用，但必须允许观察哪些情况值得取以及何时不值得取。这些是本轮的“解决到什么程度”。

## 9 对v2执行顺序的具体补充

1. **当前已做**：能力边界、成功证据分层、旧数据任务适配性复算。本文件与notebook为产物。
2. **下一步仍是P1**：修角色与时间；同时为既定诊断材料建立“需求、资料新增信息、资料依据、执行响应、评价分辨力”记录。词法规则只能分层，不能代替人工/来源核查。
3. **先用P1既定生成做执行诊断**：充分利用原定72条old/new renderer与base/旧LoRA对照，查看好资料是否能改变回复；不为新增审计自动扩大生成量。
4. **P2/P3增加任务适配性读数**：在既定共同池和40对人评中回答A/B/C，既有一次SFT上限不变。新执行器冻结后，旧执行器的分数不混入正式奖励。任何需要新增终点的分支诊断先列缺失，不擅自扩池。
5. **P4前写一页实际结论**：哪些来源可产生何种收益、情境化与顺序信息有哪些证据、哪些自然差异能可靠测量、目前最大瓶颈在哪里。不能只写parser通过率，也不把未证明收益直接当不许做小型RL的理由。
6. **按证据分配正式训练**：信号与资格充分，沿用384/128吞吐选择；低对比但测量稳定，按v2做128有限研究；反馈失败则B0。低对比有界实验不等价于已证明PM能力。
7. **冻结评价与论文**：保留强固定混合计划、OneShot、BC及NoText。结论按第2节对照逐条填写，不能从“PPO跑完”直接跳到“RL-PM有效”。

本补充不增加一轮通用人评，不新增模型训练网格，也不自动缩小test或改奖励。新增的是使每项既定工作都能回答“它解决了哪一个必要条件”，并及时把有限工作量投向真正限制效果的环节。
