# PM-RL1：R04B 测量约定与一次集中人评的用途

2026-09-29。这是本次推进后的测量约定与实施设计；没有新增人工答卷，没有宣布新裁判合格，也没有启动自然支持 PPO。它补充原方案，不覆盖旧 A/B、原方案、旧模型和结果身份。

## 1. 先明确每份证据回答什么

研究主问题仍是：在同一执行器、合法过去信息、相同资源/计算约束下，PM 能否选择合适的 RS/MP/MS/ME 并决定何时 STOP；执行器训练能否改善资源利用，同时保持 OFF 能力。逐步策略的额外价值必须与共享训练反馈及动作域的 OneShot 比较。

| 环节 | 当前能够支持的结论 | 不能由它推出的结论 |
|---|---|---|
| owner/cutoff/排序/预算/原文哈希 | 信息和执行机械合法 | 引文支持抽取结论、旧事实仍有效 |
| 源记忆语义核查 | 某条记忆的来源、人物、时间是否成立 | 给 G 看它必定改善回复 |
| 作者及准入审查 | 有可追溯的开发弱监督候选 | 独立人类金标准、已合格 reward |
| dev response NLL | 对固定弱监督目标的拟合程度 | 情感支持效果或资源增量改善 |
| 冻结自动评审 | 在实际核查范围内的自动代理结果 | 人类认可或心理疗效 |
| 最终独立盲审 | 对被冻结系统和特定测试样本的外部判断 | 全人群长期有效，或追溯性证明训练 reward 正确 |

本批发现，MP 可以把早期睡眠问题重新绑定到后期的“你在吗”；另一个 MP 把已经结束的友情继续表示成当前亲密关系。因此测量链必须增加**源记忆真实性/时效性**记录。不能把源错误、G 误用、J 误判混成一个错误率。

## 2. R04B 先记录分项，暂不确定新 scalar reward

每条测量绑定 prefix、回复、共同合法证据、模型、权重、提示、解析器、解码、draw 和完整性哈希。方法名、资源成本、旧评分、训练阶段不得进入质量盲评提示。

1. **机械有效性**：owner、截止点、GET rank、资源预算、完整上下文、正常结束。技术失败独立记录；不等同于零分、平局或语义 uncertain。
2. **源数据状态**：抽取条目及其引文、原始角色、原始日期、是否是复制的旧 profile、是否有后续更新或相反证据。沿用 profile 不得伪装为新一次确认。未核查不等于通过。
3. **回复事实核查**：逐项记录 response span、显式事实/内嵌预设、证据 ID、supported/contradicted/unsupported/uncertain、人物/时态/意图与行动混淆等可并存标签、对当前回复的影响。建议可以含事实预设；正常共情、比喻、可选建议也不能一概误罚为事实编造。
4. **支持质量比较**：在当前诉求和合法已知约束下，A/B 哪个存在实质优势，或 equivalent/uncertain；记录具体原因。字数、建议数量、个性化、引用记忆均不天然加分。相同差的两条回复可以 equivalent。
5. **稳定性与适用范围**：适用接口下的反序、重复、理由结论一致性；完整证据覆盖、条件性失败率和成本。反序与重复不是新独立样本。

`equivalent` 是有足够依据认为没有实质差别；`uncertain` 是无法可靠判定。若某模型没有这两个原生类别，必须明确适配和验证，不能把反序冲突一律转换成平局。

源条目引文错，不代表使用它的每条回复都必定错。例如旧历史确有睡眠问题，一条准确说“你以前提到过睡眠困难”的回复，不能仅因 MP 后来引用了错误的问候句就自动罚错；但“你最近仍每天失眠”需要额外时效依据。源错误与回复错误须分别检查。

质量偏好若已计入事实错误，另加误用惩罚是显式风险加权。旧 α=1、λ=.05 不自动继承到新偏好尺度。先保留 raw 分项，再在训练前独立冻结映射、权重、严重度和 OFF 参照。缺失不得填零或无限重生成到过关；有效的坏回答应保留为负结果，不能当技术失败删除。

## 3. 有限候选实验的边界

保持最多 Prometheus-2 7B 与 Skywork Reward V2 Llama-3.1-8B 两个候选，先做接口适配可行性，尚未下载或运行。Prometheus 的原生配对接口是 A/B；Skywork 是标量模型，反序和理由审查不适用，不能把“不适用”计为通过。具体版本、官方输入要求及上下文限制仍须在执行时绑定。

同一开发压力集覆盖自然差异、已核实损伤、语义保持的风格变化、旧事实更新、建议中的预设、正常共情误报、源引文存在但不支持结论。已损伤语法的旧风格题不能用于纯风格不变性结论。旧卷只能作开发材料，不能改名成为未见确认卷。

先冻结题目和控制答案的证据，再运行。技术完成率、各错误类型、重复/反序一致性、uncertain 与长历史覆盖都按真实分母报告。不能以 ON 胜率选择裁判，也不能只看总一致率掩盖大量平局。控制题过关与重复稳定只支持开发资格，不单独证明自然支持 reward 有效；正式 natural-support PPO 还需限定其有效测量范围。

若只能测误用而测不了支持收益，不能自动退成纯风险 RL：当 OFF 已无误用且成本最低时，始终 STOP 可能就是最优。QA 分支先做题型、gold、别名、时态和合法证据 census；它不是未经核查就“客观”，也不替代自然支持结论。

## 4. 推荐的人评安排：一次冻结后的集中活动，两个明确用途

用户并不排斥人评；应避免评审机制、数据源和系统仍在变时，反复让人校对整张考卷。推荐保留现有最多 **24 对最终独立盲审**框架，不另开一张训练前校准卷。

同一批独立判断可以支持两个分析：

- 评估冻结系统在指定比较中的表现。
- 将**事前冻结且不再调整**的自动裁判与这些人工判断比较，报告它在哪些案例一致、误判或无法判断。

第二项是终评审计，不是用这批答案调好裁判后再报告它的“独立验证”。如果要用人工意见修 reward 并重训，就必须保留另一份独立终评证据；这与“所有系统只评一次”在时间顺序上不能同时保证。应在开展人评前选定用途，而不是事后改名。

**旧资产继续有效。** 旧 ESC 有 24 题、两份独立人工七维评分；后一期是 80 个 base pair 和 16 个反序呈现，其中 A 是联合人工答卷，B 是探索性 AI 答卷。后者不能当成第二名独立人类。可复用说明、界面和失败案例，不能把旧胜平负换算成新 q/m。

## 5. 考卷与评卷老师的具体设计

沿用原定 12 对执行器比较＋12 对策略比较。以下是实施草案，最终题目 ID 和系统身份必须在看 test 输出和人工意见之前绑定：

| 题组 | 设计 | 要回答的问题 |
|---|---|---|
| 执行器 12 对 | 6 个预选 test prefix，每个 OFF 和一个合法 ON 条件；每条件比较 X_g/X_l，同输入同资源；3 个 test owner 各 2 个 prefix | 训练后 OFF 是否退化，同资源执行是否改变；不能只看 ON |
| 策略 12 对 | 3 个 test owner 各 4 个预选 prefix；同执行器下 RL/OneShot，共享训练反馈与动作域；两执行器各 6 对 | 逐步选择是否胜过一次性选择 |

ON 条件在开发阶段规定选择规则和资源类型覆盖，不能根据谁生成得好来挑。方法未运行或回复技术失败时保留缺失，不临时换成胜率更高的比较。当前没有正式 X_l 或自然支持 RL，因此现在只能冻结评审设计，不能发一张假装已有最终系统的考卷。

每对由 **2 名独立人类**先单独提交；研究者可参与但须披露开发参与，独立外部证据优先来自未参与系统调优的评审。若有人接受集中安排，可预先约定第 3 人只处理实质分歧；原始两份判断仍保留，仲裁不是抹除分歧。人员尚未招募，不能写成已具备。

同一次活动内先用少量**旧开发案例**统一说明，再完成正式卷；说明阶段不得展示正式题的标准答案。评审者先看当前 prefix 与随机 A/B 回复，记录贴合性、是否有实质优势和原因；然后查阅双方完全相同的合法过去证据，检查具体事实与时间问题，再提交最终判断。界面可检索/展开完整历史，不能只给助手挑好的引文。方法、模型名、GET 数、费用、自动分数和另一个人的意见都隐藏，身份 key 单独保存。评审者先录入个人判断再讨论，不能把讨论后的一份联合答卷算两人。

简化的正式字段：`A_better / B_better / equivalent / uncertain`；关键回复片段；对应原文证据/当前诉求；误用类型及影响；判断不足的原因。无需把一次人评扩展成大量没有明确用途的维度。

## 6. 如何尽量一次收口

开展前一次性检查：源数据修复版本、系统/生成/裁判哈希、试卷选择规则、盲化 key、评审说明、界面导出和统计代码都已固定。技术演练复用旧题，不消耗正式题；正式答案只采集一次，缺项可按预先规则补齐字段，不诱导改成共识。

完成后固定输出：两人原始答卷、分歧与可选仲裁、各比较胜/平/负/不确定和技术缺失、逐 owner/逐 prefix 结果、错误类型、冻结自动裁判的逐题混淆情况。题目顺序随机化和评审者重复不能增加独立样本数。只有 3 个 test owner、24 个 pair，不能据此夸大人群泛化或心理疗效；统计分析保留 owner/prefix 相关性，不把所有票当独立 Bernoulli 样本。

已有 test 暴露事实继续披露：这是新参数拟合留出，不是整个研究过程完全未见的材料。独立的是此次评审身份和用途，不是追溯性擦除历史暴露。

若结果不支持优势，就以负结果或有限证据收口，不再换裁判/挑题重评。若确实要开展下一版研究，另设版本和新确认材料；不能承诺一批人评永久覆盖所有未来变化。

## 7. 现在的执行顺序

先收口本批失败来源与准入结果，隔离已确认的 MP 来源刷新错误；完成有边界的 train/dev 来源与状态更新修复后，再冻结下一版 R05 数据合同。不能把本批没有足够历史利用示例，归因成 PPO 不会学习。训练 runner 已准备，但真实更新、重载和行为诊断必须等输入与准入通过，未完成的项目明确保留。

R04B 候选实验以这份测量约定为起点，不能替源记忆核验。人评暂不开展，保留给真正冻结且可比较的系统。这样把需要人的工作集中到有明确结论用途的终评，而不是让人反复处理工程与数据准备缺陷。
