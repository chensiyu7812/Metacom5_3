# PM-RL1：既有 A/B 审核、裁判与评测就绪情况及推进顺序

**结论：我们已有两套已执行的考卷/审核、一个在旧官方协议下已冻结的 ESC-RANK、几种实际运行过的本地裁判、自然轮次适当性规范和新方案 q/m 草案。缺的是将这些资产适配并验证为新的“当前轮、合法过去、q/m”测量闭环。** 上一轮只说“J 尚未验证”过于概括；它应解释为新用途缺验证，不是以前没有做过裁判校对。

本次只做来源核验、方案分析与离线材料准备，没有模型判分、付费请求、原始答卷改写或训练。十个旧原始提交/模板/聚合文件通过对应 hash 核验。可复算脚本为 `scripts/rl1/04_audit_evaluation_assets.py`，产物为 `outputs/pm_rl1/evaluation_preparation_20260928_v1/`。

**先分清两套 A/B。**

| 材料 | 实际完成情况 | 当时检查什么 | 新方案可以继承什么 |
|---|---|---|---|
| 2026-08 的 ESC evaluator 考卷 | 24 题、A/B 两份独立人评、七维；336 个原始人工维度评分；后续一项 Overall 定向仲裁 | 官方 ESC-RANK 与人工七维评分的关系、输出格式和一些偏差 | 旧官方 rubric、模型与 parser、两份人评、偏差诊断、复现入口 |
| 2026-09 的 pairwise teacher 考卷 | 80 个基础 pair＋16 个反序呈现；联合人工 A、探索性 AI B、六题人工复核与助手事实敏感性分析 | ESC/QA/Summary/DG 中 ON/OFF 的任务实质收益，及裁判的 equivalent/uncertain 边界 | 原文、事实审查案例、反序检查、盲评表单和来源校验、失败模式 |

这两套的“A/B”不是同一种评审身份。第一套确实记录为两份独立人评。第二套的 A 是两名评审共同审阅形成的一份联合答卷；B 按研究者记录为 GPT-6 Astra（极高）的独立作答，其精确 API snapshot/采样参数未提供。后者不是第二份人评，也不是已冻结的生产裁判。原始答卷、后续复核、助手事实分析不能合并成事前独立人工金标准。

第二套的 16 道反序不增加语义样本数。原始 A 的 80 个 base 是 56 equivalent、12 uncertain、12 明确胜负；始终判 equivalent 即有 70% 同判，所以总 agreement 本身不能决定谁适合当裁判。A 对 AI B 的 base 同判为 27/80，也不能把 AI B 当成用来覆盖 A 的正确答案。

证据：[ESC 双人记录](../data/paper1_authority/paper1_esc_evaluator_dual_human_reference_20260823_v1.json)、[ESC 最终收口](../data/paper1_authority/paper1_official_esc_rank_qualification_closeout_20260902_v1.json)、[后一期实际人评来源](../data/paper1_authority/paper1_human_review_closeout_20260917_v1.json)。早期 manifest 的“192 个独立评分待收集”等状态要结合后来的实际收口理解，不能把原计划当作已经发生。

**已有裁判的结论，也各有范围。**

ESC-RANK 已完成 24 题 × 七维 = 168 次正式解析，并在旧 ESC-Eval 协议下完成资格收口。Overall 对人评 A/B 的二次加权 kappa 约 0.373 / 0.508，相关系数约 0.766 / 0.819；部分维度有分数压缩、弱或负的一致性。这表示有可复现的官方评分器和已知局限，不表示七维都与人类等价。旧卷 Skillful/Humanoid 曾有位置映射错误，已经按实际 rubric 作可追踪归一化；以后不能复制未修正旧模板。

Gemini 96 个呈现全部尝试、92 个有效解析，77 个有效 base 对联合 A 同判 7 个；54 个 A-equivalent 中只复现 4 个，13 个可比反序中一致 8 个。该特定冻结配置未获 material-effect teacher 提升。这不是 Gemini 家族的总能力结论，也不等于把所有人模分歧算模型错误。[结果及具体案例](PM_PAPER1_GEMINI_QUALIFICATION_RESULTS_20260917_ZH.md)

后来本地已完成 796 次裁判呈现，包含三模型同题、Selene 输出布局、Summary 完整历史与自然结束对照。Qwen3.5-9B 初始比较换序一致 70/80，Compass 55/80，Selene JSON 11/80；Selene 更改输出布局后为 48/77，另 3 对缺失。Qwen 更稳定，但仍经常把轻微表达优势判成明确胜负；现有用途结论是“Qwen 优先本地开发、Compass 补充”，没有把任何一款升级为自动全任务真值标注器。[本地实测收口](PM_PAPER1_LOCAL_TEACHER_DEVELOPMENT_RESULTS_20260917_ZH.md)

因此，新 J 首先沿用已有 Qwen 的软件/权重/运行经验，重新绑定新任务输入与判分。没有必要重新下载一批候选，或再跑旧 96 题来追求更好看的数字。旧卷适合作为已见的回归与错误案例库；若因新 rubric 重评分，须明说是开发复测。

**现在到底哪些东西已经有了？**

| 组成 | 当前状态 | PM-RL1 还需要做什么 |
|---|---|---|
| 评测目的 | 新方案已定义为当前回复质量、误用和资源成本的取舍 | 把目标写进同一份执行协议，避免又变成“多用记忆/多建议就更好” |
| 内容标准 | 旧自然轮次适当性 rubric 已有；新 q=0…4、m=0/.25/1 已有锚点 | 明确邻档、证据、时态、无断言、不确定与技术失败的处理 |
| 本地评卷模型 | 权重、独立环境和旧运行记录已有 | 冻结新的完整 J 请求、runtime、parser；进行有限实测 |
| 旧校准卷与答案 | 两套均有，来源和限制已明确 | 复用规范与失败案例；不把旧标签直接转换为新 reward |
| 新校准卷 | 有真实 prefix 数据和六条开发回复；本次增加 12 prefix 草拟名册与三对未评分样例 | 冻结合法 ON 条件、生成其余自然回复、构造并核验控制题，形成完整卷 |
| 最终考试数据 | 暂定 96/24/48 分区，有严格过去候选构造能力 | 完成共享来源/事实家族与历史暴露、统一容量及正式抽样冻结 |
| 最终独立评卷老师 | 有旧人工流程和可选外部模型路线 | 新任务的人员/模型、独立输入、盲化和判分协议尚未实际落实/完成 |
| 新评测结果 | 六条 G 已自然结束；J=0、reward=0 条、训练=0 次 | 不把 env 测试的模拟 Score 当成真实测量 |

自然轮次规范已明确“更多共情、记忆、个性化、建议、细节不天然更好”，可以直接作为语义基础：[既有 rubric](../data/paper1_authority/paper1_natural_turn_appropriateness_rubric_v1.json)。旧官方七维主要评价其原协议中的对话，直接把整段原历史一起打分可能让前面的好回答掩盖新末句的问题。新评分要明确只评新回复，历史仅作语境；旧 official Overall 不能无解释地当新 q。

**旧考卷不能直接变成新训练标签的原因。** 旧任务问“两个回答有没有实质差异”，新训练需要“每条当前回复的 q 和 m”。同为 equivalent 的两条，可以都很好，也可以都拒答；一个 B_better 标签也无法推出 A=2、B=3。旧尺度到新尺度没有这样的映射。

其次，旧 QA/Summary/DG 目标的历史截止点常在整个历史末尾；新 prefix 在其中一段对话的中途。直接复用旧卷完整历史，可能把当前切点之后才发生的事件交给新裁判。来源能复用，评审证据必须按新 cutoff 重建。旧问题的官方答案与后续回复也不能当作新题的标准答案。

开放式支持回复通常没有唯一标准文本。新“答案依据”应记录当前明确需求、合法已知事实、未知/歧义、当前约束及可核查错误，而不是让另一个模型写一段理想回答后按相似度给分。原始 supporter 的后续回复不能拿来要求新回复模仿，也不是当前决策时可见证据。

**用“学生、出题、评卷”来分工。**

| 角色 | 具体职责 | 不能混用的地方 |
|---|---|---|
| 被训练的系统 | PM 选资源，X 生成当前回复 | 不能读取后续、gold、完整未取得库存或 J 的分数特征 |
| 数据构造/程序核查 | 固定 prefix、as-of、分组、合法资源与 evidence spans | 只能证明机械合法与摘录存在，不能证明语义好坏 |
| 执行示例作者 T_X / 核验者 V_X | 产生和筛选 Step-2 的弱监督样本 | 作者只看 G 可见输入；核验者不能经修复提示传递隐藏的正确事实 |
| 训练评卷 J_train | 固定尺度给 q/m，为 PM 提供反馈 | 分数上涨只说明此代理上涨，不能自己证明真实支持收益 |
| 独立评卷 J_eval / 人工 | 在新结果上盲评适当性和来源错误 | 不看训练分数/策略名，不据 test 结果再调整模型或 rubric |

“独立”包含评审来源、输入盲化、参数选择与结果用途，不能只靠换模型名字。T_X/J_train 同家族要披露；当前参与题目和规则开发的助手，其后续分析可作辅助，但不能追溯性称作未见材料的独立人评。方法身份能从文本中被猜测的可能性也不能靠隐藏字段完全消除。

**建议下一份具体交付，是小型新任务测量包。** 从 train/dev 的合法前缀取 12 条，每条实际 OFF、实际合法 ON、单点损伤、内容保持风格改写各一，共最多 48 条；再预选 12 条实际重复评分，共 60 次本地 J。另做 12 对独立复核。详细锚点、输入/输出结构、控制题适用性、重复 seed 与分析要求已写成[可执行协议草案](PM_RL1_EVALUATION_DESIGN_DRAFT_20260928_ZH.md)。

此卷专门检查：事实是否判断对、引用是否找对；把意向写成已有效是否能识别；正确个体事实是否被误罚；风格/篇幅是否无依据主导分数；普通 ON/OFF 是否有可解释的差异或合理平局；重复判分是否会反转决策。它不是重做旧全卷，也不是新的任意准确率资格门。

没有依据的分歧保留 uncertain，解析/超时另列。只允许一次针对明确 train/dev 问题的 rubric 修订，旧新版本分别保存。若裁判只能可靠处理事实/时态，就先形成执行风险结果，不大量训练含糊的“帮助性”奖励。若可以支持更广范围，冻结其范围再继续。不能因为需要 PPO 输入，就在 uncertain 处填零。

**奖励尺度使这一步尤其值得先做。** 现定 q 每跳一档，`q/4` 就变化 0.25；全部资源预算花满，成本项最多 0.05。一档质量误差是最大资源成本差的五倍，局部 m 档差也是 0.25。因此句式偏好或一档不稳定足以主导学到的取用策略。q 是序数，其均匀数值化是研究偏好，不是天然等距的心理量。先检查证据与可分辨性，再做小范围 dev 权重检查，不能用调 λ/α 或加小数位把不可靠测量装成精确 reward。

**最终 evaluation 要回答三个不同问题。** 执行器：同 prefix、同资源下 X_l 是否比 X_g 更合适、更少误用；还要比较其 OFF 的变化，区分一般回复能力提升与资源利用增量。策略：同 X 下 RL 是否胜过 Fixed/Random，尤其是否胜过共享训练反馈和动作域的 OneShot；否则不能主张逐步信息获取的额外价值。系统效率：分别报告资源输入、输出 tokens、检索/编码/生成/PM 时延、技术失败与训练成本，不把省输入 tokens 自动称为全链提速。

正式起始上限仍是 432 个执行实验回复、960 个策略交叉回复，以及预先固定的 24 对独立盲审（12 对 X_g/X_l、12 对 RL/OneShot）。J_train 分数单列为 held-out 代理分数，独立证据另列。小型官方 QA 可补充事实性外部测量；它不能替代自然支持评价。七维 ESC-RANK 若按新的单轮输入适配，必须注明是适配后的补充，不冒称原官方 ESC-Eval 复现。

24 对由 3 个 test owners 平衡选取，在看结果前固定条件/seed/顺序。它是有界的独立证据，不保证统计功效，也不支持广泛人群/心理疗效主张。这里只有公开来源的 18 个虚拟用户；成百上千条回复、重复 seed 和反序题都不是新独立人。

**数据考卷还存在一项已核实的历史暴露问题。** 暂定 test owners 为 p14、p4、p7；旧 80-base 考卷中相关 memory pairs 分别为 5、1、4 个，p14/p7 的完整历史还出现在旧 DG 评审材料中。因此，“对新 PM/LoRA 参数训练留出”和“所有研究过程从未看过”必须分开记录。上述 owner 交集不是自动判定全部测试污染的证明，也不允许继续声称完全未见。

下一步建立逐 prefix 的来源/事实/旧题/旧模型评分/人工阅读/实际用于规则修改的 exposure 映射。精确落在训练/开发同事实家族的改写按新方案隔离，不能换名字算 test；只有候选加载或构造域统计的记录，与实际训练或基于结果调参区分。不能为了得到有利结果重新 hash split，也不先粗暴删掉三个 owner。若确实无法留下严格的新确认集，明确下调规模或把现有结果限定为受限 held-out 验证；要声称全新独立确认则需另有合法独立材料与明示设计，不能假装现有池满足。

还有一条已知跨 split 源冲突：`esc1198` 在 p13/train rank14 与 p18/dev rank7 重复。需要把其后继可见历史和派生记忆一并处理，不能只去掉同名当次样本。若采用两边相关后继均隔离的保守规则，p18 仅余 ranks1–6 六个合法 memory sessions，dev 的每 owner 8 条上限就不能全取；可按方案下调共同数量。当前仍未据此冻结新的总样本数或悄悄修改方案表中费用分母。

**可实际执行的先后顺序。**

| 次序 | 具体工作 | 交付物/结束条件 | 可以同时做的工作 |
|---|---|---|---|
| 1 | 整理旧 exposure、共享来源和全部候选容量；定稿新证据结构与 q/m 草案 | 每个前缀有边界/分组/暴露状态；J 输入无未来/身份泄漏；不强凑 48 test | 在确定合法的 train 子集开发 J 和 parser |
| 2 | 固定 12 prefix 的 ON 条件，形成真实回复与受控修改，接入本地 J | 具体可阅读的考卷、答案依据、原始判分、完整性/误差报告；12 对独立复核材料 | 全量无 outcome 容量、缓存/预算工程 |
| 3 | 一次有依据的 rubric 修订或限定可用范围，冻结测量 | J 模型/提示/解析/证据/重复规则及范围均有版本；缺失不填零 | 准备 SFT 作者与核验流程 |
| 4 | 构造弱监督数据，训练并冻结 X_l | X_g/X_l 同推理提示，LoRA checkpoint 由 dev NLL 选；资源利用另测 | 固定/随机/OneShot 基线的工程 |
| 5 | 共同计划监督、E0 学习测试、受限 PPO | 同反馈/动作域对照；技术恢复可靠；只在已有测量范围内训练 | 不依赖 PPO 的执行矩阵准备 |
| 6 | 冻结 test 清单后执行正式矩阵和独立盲审 | q/m、独立判决、成本、逐 owner 与失败分别报告；未支持的主张不写入结论 | 原官方 QA 的可选补充，费用单列 |

这次已具体准备：12 个 train owner 各一条的**未冻结名册**、三对现成自然回复的**无评分评审样例**（同一合法历史、隐藏 arm/资源身份、协调端另存 key），以及本文件和 rubric 草案。三对示例不是 12 前缀考卷，也不是新的人工结果；它们让“要给评卷老师看什么”能够被直接检查。

**费用和人力。** 本地 60 次 J 诊断、24 次自然 OFF/ON 生成上限以及控制题改写/核验要单列，控制题不是免费真值。旧六条仅在选样、资源、X、完整 prompt/runtime 身份吻合时复用，不能为了省调用事后改变抽样。若 12 对开发复核＋24 对最终复核用外部模型，就是 36 个单次呈现；换序复核另计。若使用人工，API 费用可为零，但审阅完整历史的时间不能记为零。人员尚未实际安排，不把计划人评写成已完成。

沿[上一轮费用情景](PM_RL1_COST_REASSESSMENT_20260928_ZH.md)，36 次外部复核 Batch 约 $0.48–1.13，可选 192 次 QA 约 $0.10–0.15；这只支持“少量外部核验、本地规模化评分”的预算安排。若把 3,168 次常规 J 都换成 API，借用每次 8,719 输入＋512 输出的情景作量级计算，GPT-4o 约 $85 同步/$43 Batch，尚未计 SFT 核验、OFF、重试，超出原 $20。该数字只是同一报价情景，不是新 J payload 的实际 token 测量。模型质量和实际吞吐仍须在新卷上核验，不能因本地便宜就宣布可靠，也不能把少量外部复核当全套训练评分报价。
