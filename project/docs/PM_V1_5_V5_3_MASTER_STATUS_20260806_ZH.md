# V5.3全组件状态总报告：V5.2到现在，修了什么、提升了多少、还剩什么（2026-08-06）

本报告回答一个问题："5.3能不能确保没问题，学出来的PM能用，和baseline可比，结果有意义？"
覆盖MP/ME/MS/RS四个组件 + Step1（训练管线）+ Step2（真实生成兼容门），按"V5.2是什么状态→
V5.3现在验证到什么程度→还剩什么没修"的顺序整理。取代之前的`PM_V1_5_V5_3_CONSOLIDATED_
FINDINGS_20260806_ZH.md`（那份文档写于ME/MP/MS真实效果测试和Step1试点之前，现在信息已经
过时，具体分项证据仍保留在各自的分项文档里，这里只做最新的汇总判断）。

## V5.2的根本问题：不是某个组件的bug，是生成器根本看不到证据原文

`compose_locked_response()`是确定性字符串拼接——LLM从来没有真正看到MS/ME的证据文本，只是
把模板片段拼在一起。这意味着V5.2时代做的任何"MP/MS/ME候选质量"评估，都测不出"生成器会不会
正确使用这个证据"这个问题，因为生成器根本不参与证据使用这一步。V5.3的typed response program
（生成器看到完整typed证据，产出一次整合过的回复，配一层guard+rewrite+兜底的安全网）是专门
针对这个根本问题设计的，本报告里几乎所有"V5.3新发现的bug"，都是这个新架构第一次让"生成器
怎么用证据"这件事变得可测试、可观察之后才发现的——V5.2不是没有这些问题，是V5.2的架构让这些
问题不可见。

## 五、Step1（训练管线）

- 此前判断：全量训练成本高（每组件几十到几百次真实调用），未经管线验证前不该直接投入，
  提议先做"最小试点"（单组件、10-20个真实state、带/不带对照、真实judge打分）验证管线本身
  能不能跑通。用户批准后先做了MP，这次扩展到MS/RS（ME因0命中无法测）。
- **管线本身：验证通过**——四个组件里三个（MP/MS/RS）都真实跑通了"生成→真实judge打分
  （复用已有的正式judge instrument，正反序配对+4项风险判定）→提取信号"全链路，累计上百次
  真实API调用（生成器+judge两侧）。过程中发现并修复2个试点脚本本身的bug（judge遇到瞬时
  provider错误会崩掉整批；格式修复重试没有真正生效），随后在MS/RS试点复用时未再复发。
- **管线之外，发现了2个真实的核心代码bug**（不是试点脚本的bug，是`v1_5_v5_3_typed_
  response_program.py`本身的bug）：M0+R0证据幻觉（见MS一节）、RS guard契约不适配（见RS
  一节）——这两个修复的价值已经超出Step1试点本身，直接影响V5.3生产路径的正确性。
- **仍未做的**：正式的、使用"已认证裁决模型"（需要预先跑qualification report）的全量Step1
  训练。这次做的是"最小试点"这一档，不是完整训练——这是此前明确商定的范围，不是遗漏。

## 六、Step2（真实生成兼容门）

此前（本次扩展之前）已经做过约58+次真实调用，修复验证了说话人归属、记号回显、化名指代三个
bug，判断"基本solid"。这次扩展通过Step1试点，**真实触碰到了此前Step2测试从未覆盖过的两条
路径**（真正的M0+R0、真正的RS）——覆盖面变宽后，又发现了2个新的真实bug（M0+R0证据幻觉、
RS guard不适配）。这说明"基本solid"这个判断本身是对的，但覆盖面此前不够全，现在更全了，
也确实多找出了问题——这是覆盖面扩大的正常结果，不代表之前的验证是错的。

## 七、所有组件共同的一个已知缺口：judge没有别名映射

Step1的MS试点里发现：EvoEmo的证据文本习惯用第三人称叙事（比如把用户叫"Anna"），生成器
拿到了`current_user_known_aliases`能正确把"Anna"解析回"you"，但risk judge没有拿到同样的
映射，会把这种**正确的**指代解析误判成`unsupported_personal_claim`违规。这个问题在MP/MS
试点里都出现过，**目前未修**——不影响生成质量本身，但会让任何在EvoEmo数据上做的真实judge
打分（这次的所有pilot，以及未来真正的Step1训练）的风险违规率虚高。

## 八、总体判断

按用户设定的门槛（"能用、和baseline可比、结果有意义"，不是"发表级完美"）：

- **MP、MS、RS：可以进入V5.3。** 已知的correctness bug都已修复并用真实数据重新验证过，
  质量效果MP中性、MS明确正面、RS方向正面（样本较小）。
- **ME：安全但无效。** 在当前"保守用严格编译器"的决定下，这批真实数据完全打不出候选——
  不会让PM变差，但学不到任何ME信号。不阻塞上线，是明确记录的已知状态,不是"未完成的bug"。
- **Step1：管线验证通过，全量训练未开始。** 三个组件的真实generate→judge→信号链路都跑通了，
  但"用已认证裁决模型做的正式训练"这一档还没开始——这是此前商定的范围边界，不是遗漏。
- **Step2：更全面地验证过，新发现的问题已修复。**
- **仍未修的已知项**：judge别名映射缺失（影响未来judge打分的准确度，不影响生成本身）；
  ME检索/编译层未连接（技术债，目前无害）；M0+R0证据幻觉修复后仍有约33%残留（明显改善，
  未完全消除）。

**结论：V5.3在MP/MS/RS三个组件上已经达到"能用、和baseline可比"的门槛，有真实数据支持；
ME保守地保持无效但安全；Step1管线机制已验证，全量训练待启动；已知缺口都有清楚记录，没有
被隐藏或忽略。**
