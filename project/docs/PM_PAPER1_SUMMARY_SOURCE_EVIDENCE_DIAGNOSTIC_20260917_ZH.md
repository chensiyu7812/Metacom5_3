# Summary 裁判证据缺口及对照（2026-09-17）

本轮发现，旧 Summary 裁判请求只有 390–590 字符的官方参考摘要，没有完整原始历史；DG 则已有完整历史。由此不能把“官方短摘要未提到”直接当作“该事实不存在”。

## 已核实的例子

`p5::summary::1` / `teacher_base_9820ce4a3b73f46a1aaf1c98`：ON 的 MS 资源包含完整原始对话，用户明确提到治疗帮助自己面对父亲去世，伴侣刚获得全职工作，自己也已进入压力更小的新岗位。自然结束的 ON 回复据此作答。

旧裁判所见官方参考摘要没有治疗和父亲的信息，只提到伴侣在较早阶段找到兼职。Qwen 在旧、纠正采样配置的两个版本中，均把 ON 的治疗／父亲信息称为幻觉，或将全职与参考中的兼职视为事实冲突。这些理由与实际源对话不符。它说明输入证据不足也会造成误判，不能把全部问题归结为模型大小或“是否专门做裁判”。

该发现不代表 ON 已是完整优质摘要：它仍可能遗漏失业等早期事件；事实有出处、覆盖充分和有实质优势是三个需要分别判断的问题。原始人评也不因这一个例子被整体替换。

## 已完成的有限对照

沿用同一 13 对 Summary，不补人评。每对保留两个顺序，使用同一个任务之前的完整源历史，分两版：

1. **原回答＋完整历史**：固定原回答，检验补足裁判证据后的判断与理由。
2. **自然结束回答＋完整历史**：固定完整历史，再观察消除输出截断后的判断。

Compass 和 Qwen 各 52 个请求，共 104 个额外开发判定，使用同一 4 小时 GPU 生成墙钟范围，无新增 API 费用。各版本同一顺序的 Qwen seed 绑定原 presentation ID，减少无关随机差异。所有额外消耗与 480 条初始比较分开记录。

历史由当前 sanitized runtime source 和既定 target cutoff 构造，按原始 session 排序并保留角色。两回答看到同一完整历史，输入不暴露 ON/OFF、head 或注入资源身份。完整参考最多 91,210 字符；Compass 实际完整输入为 9,452–21,498 tokens，适配其 32,768 上下文，无需删减历史。Qwen 当前服务上下文为 131,072。

准备脚本：`scripts/paper1/71_prepare_summary_source_evidence_diagnostic.py`。请求及 source lineage：`outputs/paper1_pairwise_teacher/local_comparison_20260917_v2/summary_evidence_diagnostic/`。旧人评反映旧证据／旧回答，不把新版本与旧人评的一致率称为新的独立准确率。官方 benchmark 指标及参考答案不改写；这里修的是内部 material-effect 裁判的证据输入。

Selene 在 JSON 中出现理由与标签矛盾后，另做一次先理由后结论格式适配；也对该格式运行同样 52 条 Summary 请求。完整证据诊断因此为三种配置各 52 条、共 156 条，均在原共享 4 小时 GPU 生成预算内。这样三款模型都能在相同完整历史下比较，随后收口，不继续扩展候选名单。

## 实测结果

156/156 全部自然结束；Qwen、Compass、Selene 严格解析成功分别为 43/52、51/52、43/52，明确格式修复后各 52/52。原始输出与原始解析状态均保留。

| 配置 | 旧回复＋完整历史换序一致 | 自然结束回复＋完整历史换序一致 | 补齐证据改变基础判决 | 自然补全改变基础判决 |
|---|---:|---:|---:|---:|
| Qwen 通用推理 | 13/13 | 11/13 | 3/13 | 0/13 |
| Compass | 12/13 | 11/13 | 6/13 | 1/13 |
| Selene 先理由后结论 | 8/13 | 9/13 | 4/12 | 3/13 |

两对新旧回复逐字相同的基础题在三个配置中均未改变基础判决。Qwen 的基础判决虽未因自然补全改变，两个反序呈现仍有变化。增加完整历史同时增加了明确的证据使用说明，且 Qwen 采用采样推理，故这些是开发条件对照，不是只改变输入长度的无噪声因果实验。判决改变不自动算纠错；`p5` 的理由改善已人工核对原始历史，不能据此推及所有题。
