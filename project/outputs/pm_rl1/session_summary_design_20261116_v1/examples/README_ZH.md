# 会话结束摘要：三个来源完整的设计样例

2026-11-16。已逐段阅读 M04、M17、M24 的完整过去会话，为每段制作一个自然英文摘要及命题—原话映射。这是用户新提出的 MS-summary 尝试的 **助手撰写 schema 原型**，不是部署摘要模型的运行结果、独立语义金标或已证实收益。

来源仅为 `research_preparation_20261115_v1/memory/SELECTED_COMPLETE_SESSIONS_PRIVATE.json` 中固定的三段 train/dev 导出。未读取其他后续会话、目标回复、gold、test 或废弃来源。每段原文保留在对应 `Mxx_source.json`；不替换历史 MS。

## 实际样例

| 样例 | 原文英文空白词数 | 摘要英文空白词数 | 保留的关键内容 |
|---|---:|---:|---|
| M04 / p2_conv_10 | 327 | 112 | 治疗谈话的混合反应、学业压力、写作工作坊主观帮助与残留困难、社群支持、结束时的意向 |
| M17 / esc242 | 788 | 174 | 长电话冲突、已经尝试沟通与挂断、朋友反应、希望维持友谊、明确想要实际方法、不喜欢画画、电话问题仍未解决 |
| M24 / p1_conv_11 | 313 | 166 | 工作评语与自我怀疑、旧上司事件细节未知、朋友与Jack的担忧、今晚沟通是计划、绘画帮助的指代、结束时仍无后续结果 |

这里比较的是 `summary_text` 正文和源 turns 的空白分词数，**不是 tokenizer token 数，也不是实际 G 输入总量或延迟**。完整 JSON 的审计引文较长，不应把它全部自动注入 G 后仍宣称使用了短摘要。运行时需明确 reader payload 与私有审计 ledger 的边界。

每份 `Mxx_summary_candidate.json` 中：

- `summary_text`：可审阅的自然英文会话摘要。
- `summary_sentences`：每句对应 claim ID。
- `structured_claim_index`：主题进展、行动/反应、建议/下一步、偏好约束及未解决事项的分类索引；不为凑满字段编造内容。
- `claim_source_ledger`：每个重要命题的源 hash、原 turn ordinal、角色与完整引文；原始 turn ID 与导出 ordinal 不混用。
- `not_established`：不能从这次会话推出的事项。
- `quality_self_review`：本次人工式助手首审保留的易丢信息点，独立复核仍未完成。

## 时间与使用方式

这些样例实际写于 2026-11-16，属于回溯设计样例，**不是历史时点确已存在的摘要文件**。实验可模拟“仅根据已完成的第 t 次会话生成摘要，在第 t+1 次及以后读取”。不能将一整段会话的结束摘要用于该段会话中途的 pre-supporter 目标，即使数据库把它们记在同一天。

未来实现应记录会话完成事件、摘要实际完成时间、来源 hash 和摘要器身份。若新会话开始时摘要仍在生成，只能按预先定义的策略使用当时已可用的原文/旧记忆或等待并计时，不能回填摘要假装当时可见。

本例摘要生成不读取当前检索问题，不针对某一道待答题择取信息。所有样例只根据本会话原文重建，不递归改写旧摘要。摘要不自动晋升 MP 稳定事实，行动与主观反应也不自动形成因果疗效记录。

## 校验与下一步

`python build_examples.py` 可复算 JSON 和 `VALIDATION.json`。已验证 3 个完整源 hash 及 59 个准确原文跨度；共17句有来源绑定。校验不等于证明摘要没有遗漏或所有概括均最优。

下一步应先固定相同已选会话，比较完整原文与结束摘要的保真、G采用和支持质量，再比较摘要索引与原文索引的实际召回。按需原文回查属于后续单独的获取机制，其动作、可见地址、计时和成本必须对 PM 与基线一致。不能用上述3个手写样例宣称自动摘要器已有效，或以词数减少宣称部署更快。
