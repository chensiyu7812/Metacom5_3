# 四个缺项与108 token的真实影响

复用原环境的顺序可达性算法、原本地tokenizer及冻结资源库存，在CPU上核查既定9个开发前缀×70计划。只解码这9份开发输入；没有模型/GPU调用，没有读取PM测试正文、封存标签或旧生成回复。

四个缺项来自两项原库存不足：

| 前缀 | 原RS/MP/MS/ME条数 | 四类各一条的缺失原因 | 旧/新是否可达 |
|---|---|---|---|
| 108 | 4 / 1 / 1 / 0 | ME无条目，要求1而现有0 | 均不可达，各一槽，共2槽 |
| 110 | 4 / 0 / 3 / 4 | MP无条目，要求1而现有0 | 均不可达，各一槽，共2槽 |

它们不是因为预算太小，更不是新增108 token造成的。没有完整四类组合可供渲染，因此token成本和预算是否通过记null/不适用，不能渲染缺项后把残缺组合叫完整四类。原共同池已有`not_reachable`记录。本次只是把原因追到原库存，未重建或替换清单。

新增指导确实影响了另外5个计划，但它们不在准备的41个请求中：

| 前缀 | RS/MP/MS/ME计划 | 旧资源token | 新资源token | 结果 |
|---|---|---:|---:|---|
| 98 | 1 / 1 / 2 / 0 | 1946 | 2054 | 新版超过2048 |
| 99 | 1 / 0 / 2 / 1 | 2004 | 2112 | 新版超过2048 |
| 99 | 1 / 1 / 2 / 0 | 2006 | 2114 | 新版超过2048 |
| 110 | 1 / 0 / 3 / 0 | 1996 | 2104 | 新版超过2048 |
| 112 | 1 / 0 / 3 / 0 | 2021 | 2129 | 新版超过2048 |

9个前缀共502个旧可达前缀×计划，新为497，新增可达0。41份准备请求全部仍合法；最大资源1482，未截断或改输入。结果与原25份不同条件请求的资源计数一致。108-token指导在含RS的完整块中出现一次，其成本按原渲染差额收费，不按RS条数重复乘。

这不是“全库存预算已通过”。正式采用该执行器前，程序仍需核对全部允许的train/dev库存，及获准机械检查的test投影；重新绑定初始终值mask、顺序动作mask、预算、Fixed/Random回退和缓存身份。各方法在同一新执行器下必须共用同一可达域。新旧执行器若比较完整策略系统，应披露它们可达域不同，不能把影响全部归为纯语义改善。

机器回执`reachability_receipt.json`包含630行及代码/输入哈希；原41次包及其协议身份保持未变。
