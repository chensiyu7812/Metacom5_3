# 八条开发参照：可以开始填写的离线包

日期：2026-10-16。当前评分仍120次；所有STOP保留。本包没有模型调用、自动评分、预填答案或新的人评结论。

**本次核查排除了一个重要猜测：这五条实际生成回复使用的原始请求，与裁判和原人评卷的NEW AI身份前提在文字上相符。** 另三条为人工构造的开发控制，没有生成请求，不能假装核验过其生成器行为。原人评说明是否被当时评审者充分理解，仍无法由文件证明。07A的上下文绑定正确，但旧阅读材料没有在该项重复展示来源入口；已在新卷P05单独展示全部当前对话与完整历史。

## 直接使用

1. 研究者打开 [researcher.html](researcher.html)，另一位评审使用 [reviewer_2.html](reviewer_2.html)。两份卷是同一批八条、相同顺序和来源，答案分别保存；给另一位评审只需该HTML和`materials/`目录。HTML也内置完整来源，无外部依赖。不要把`coordinator/`材料当成盲评材料。
2. 先各自填写，再讨论。研究者已看过模型结果，应在“是否看过相关结果”如实选择；第二位评审也自行记录暴露情况。八条属于开发校准，不能作为独立准确率测试。若第二人只复核争议题，不能据此报告整批人际一致性。
3. 每条记录主张、主体/时间/行动、证据关系、具体后果、当前需要、q单档/范围/未知及理由。q和严重度可分别未知；留空不会变成0。页面不会计算U、替换旧标签或授予资格。
4. 可分次填写，浏览器保存草稿；每次导出带独立时间与ID的JSON。请保留首次独立答案及之后每次导出，放入本地`answers/originals/`；后续讨论单独记录在 [讨论模板](answers/discussion/DISCUSSION_TEMPLATE_ZH.md)。目前这两个目录没有任何真实答案。没有向任何人发送材料。

原英文回复保持不变。页面含中文填写说明、英文原规则、每题完整当前对话、展开式完整历史及文本入口。没有候选名称、模型分数、旧人评答案或预期结论。新增字段只是收集分项参照，不是暗改原q/m量表；若讨论形成实质新边界，须另记未来版本，不能回写旧成绩。
