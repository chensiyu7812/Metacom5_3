# PM-RL1：有限用途反馈机制原型与离线回放

更新：2026-10-22T01:19:27.738939+09:00。本轮实际新增调用、费用、生成、人工作答、训练更新均为0；累计评分仍285，容量349，API保守账$1.602273，未结0。本文件是主方案的实验附件，不另立总体研究方案。

## 这次做成了什么

实现了首选候选流程的离线接口、严格校验、不可覆盖的补核记录和整批反馈状态机：**原联合评分 → 自动证据/后果审查 → 必要时一次有界补核 → 有依据的候选标量或明确未决**。原q/m/U、成本、生成器、PPO及训练缓存不改。既有旧两步提取字段、来源检查、完整final外层适配器继续复用。不是声称多问一次就能变准。

新增干预在于审查评分之后的依据，分别记录读法、人物/行动/阶段、来源关系和对核心理解/建议的后果；不再只把自动提取的关系表交给第二次打分。新审查不产生q/m，补核才使用原尺度；所有原始分数保留。审查模型仍可能同错或误指控，这正是下一次开发验证要测的缺口。

离线准备入口：`117_prepare_feedback_prototype.py`；复核现有包用`--verify`。本模块没有API或优化器入口，付费调度仍需给既有runner增加audit/条件性补核适配并完成mock回归后才能启用；没有写一个平行的网络调用框架，也没有把此缺口标成已完成。

全部14个已计划配对读数组合保留：8个候选、6个未决。按配对类型是2/4候选，而且这2类同属母亲情境，不能算2个独立来源的成功。所有原数值都在表中，未决不填0、不当平局、不静默排除；候选也不直接发给训练。

35B的两个数值相差0.75。在当前γ=1实现中，这会使同轨迹此前决策的return与未归一化advantage各变化0.75。以**假设旧价值预测为0**演算，value平方误差从约0.570变为2.264；这不是实际网络误差。PPO还会按整个batch的非强制动作归一化优势、clip ratio并拟合value，所以不能据此宣称梯度恰好翻倍或策略已经变化。

观察到的极值只用于这些敏感性场景，不是正确奖励区间、置信区间或已知正确方向。不同arm的35B不是同配置随机重复。代码没有取均值、最坏值、裁剪奖励或更改风险权重。

## 有限补核与批次如何结束

1. 初评分和自动审查都绑定完整回复/来源、运行身份与独立请求身份；schema和原文引用机械有效，不等于语义正确。
2. 发现会影响数值依据的明确问题/未决，允许每终点最多1次补核；全批最多4次，先按固定槽位顺序选择。不中途挑较有利的分数。技术失败或请求状态未知不走语义补核通道。
3. 补核可以说明保留、在原尺度下形成新的派生评分、或仍未决。原分、原unknown、原错误和STOP不覆盖。机器建议仍需该测量用途的证据核验；不得自封人类金标。
4. 16条真实轨迹一旦采样，就保留全部轨迹和行为策略；共享OFF未决传播到依赖它的终点。补齐前不更新、不采新批顶替难例。4次补核/120分钟用完或结束窗口仍未齐，记录整批未完成、0更新，转向该类测量问题的研究决定；不以丢弃难例后的“高覆盖”继续训练。

这条整批政策仍是未启用候选；本轮只用状态夹具验证。旧32次评分槽不是16条真实轨迹，不能拿回放批次当自然学习成功。若单轨迹有效率95%且**假设相互独立**，16条全齐率约44%；实际共享OFF不独立。这说明后续要测完整反馈批次的可完成性，而不是只报单条交付率。

## 自动化还缺什么

- 自动审查是否能发现没有在原分中承认的双读、错误来源关系和无后果依据的严重度，以及是否会误罚正常邀请，尚无本原型实测结果。
- 程序能检查ID/引文/字段/计数，不能证明所有重要主张都找到了，更不能仅从“理由非空”判定理由正确。
- 真正合理且会影响等级的双读，若原尺度不能决定，补核仍可能无解。此时才提出具体的测量目标/不确定性规则修订；不能先把最坏值或平均值塞进训练。
- BC-init的合格目标与真实检查点仍未完成；自动反馈开发检查、真实接线、BC、正式比较、独立评价各有作用，不能互相替代。
