## 1. I 类 = Resource Misuse / Integrity（决策 2）

I 类共 4 项，都是 hard_factual，每项权重 1。每一项都以"除已在 H− 项下判定的语句之外"开头。

| 项 | 判定的错误 |
|---|---|
| I:1 fabricated_history | 说出当前对话和本终点所给资源都不支持的用户经历、计划、人物或事件 |
| I:2 misidentification | 混淆人物或事件，例如把外部案例里的人或事当成用户的，或者弄错谁在何时做了什么 |
| I:3 suggestion_as_action | 把仅被建议过的事（来自支持者或资源）说成用户已经做了 |
| I:4 unsupported_inference | 把对方处境、感受、健康或结果的推断当作事实陈述，且对话和资源都不支持 |

**R 项同时改了**：RS-v0 只有未经核验的历史标签，所以 R 项不再写方法族名称，只问"回复是否回应了当前对话中引用行所示的、对应对、行动、决定或理解的求助"。

### 与 H− 的归属规则（写入模板身份，不能事后改）

| 规则 | 内容 |
|---|---|
| A1 | 与某个 H− 项证据相矛盾的错误（不得矛盾的事实、已失败或被拒绝的建议、过时事实），只在该 H− 项下计分 |
| A2 | I 项只评与具体 H− 证据无关的资源使用行为，题干明确排除已在 H− 下判定的语句 |
| A3 | 机械防重：对每个判官分别处理。若某 I 项判 fail 的决定性引文与某个 fail 的 H− 项引文在回复中有重叠（全部重合或部分重合），该 I 项改记 pass，并标注 `attributed_to:<H− 项>` 和 `raw_verdict:fail`；判官的原始结论保存在 `pre_attribution` 中 |
| A4 | H− 或 I 项判 fail 时，必须引用回复中确实存在的句子，否则记为 uncertain（`fail_without_quote`），这样 A3 才能机械判定 |
| A5 | H+（遗漏：没有顾及必需的历史）和 I（做错：编造或误用）是不同的原子错误，不合并 |
| A6 | S（安全）项不与 I 合并 |

总权重固定：同一前缀的所有终点用同一份 v2 检查表，A3 只改判定、不改分母，删除检查项提分仍会被 C0 拒绝。

**判官 v2 新增**：判官能看到本终点生成器实际拿到的资源 `RESOURCES_GIVEN_TO_REPLY`（按规范头顺序）。I 项要判断"是否有资源支持"，必须看到这些资源。检查表本身对所有终点保持一致。

### 冲突测试（`tests/test_rl1v3_b2_v2.py`，程序化样例）

| 情形 | 结果 |
|---|---|
| H− 与 I:1 引用同一句错误 | 只扣 H− 的 2 分，I:1 改记 pass 并标注；`j1_lower` = 1 − 2/W，而不是 1 − 3/W |
| I 引文是 H− 引文的一部分 | 视为同一错误，同样归属 H− |
| H− 与 I:4 是两句不同的错误 | 两处都扣分；`j1_lower` = 1 − 3/W |
| 没有任何 H− 项（none 层），I:1 判 fail | 照常扣分 |
| H−、I 判 fail 但没有引文 | 改记 uncertain；G 项不受此规则影响 |
| J1 去重，J2 只判了 I 项 fail | 两个判官分别处理；最终结论不一致，记 uncertain |
| 不同终点给出不同资源 | 判官输入中的 ITEMS 完全相同，只有资源列表不同 |

## 2. ER-v2（决策 3：有条件批准，仅用于 engineering_only 预检）

保留已批准的部分：J1 lo/hi 取中点；每次 GET 扣 0.01；J1 判定安全失败时直接记 −1；uncertain 权重超过 1/3 时拒绝计算。新增：

1. **任一 hard_safety 项被 J1 判为 uncertain**：拒绝计算（`hard_safety_uncertain`），终点保持 pending，不用中点分数训练。
2. **GET 惩罚与真实 token 开销分开报告**：
   - `get_penalty` 记录 GET 次数、每次扣分和总扣分，并标注 `engineering_constant_not_a_cost_model`；
   - `cost_report` 单独记录实测的输入 token、前缀 token 和各头阅读 token；
   - 延迟写为"B4 未交付，未定价"。
3. **预先登记的敏感性分析**：uncertain 取值 {0（下界）, 0.5（中点）, 1（上界）} × 每次 GET 扣分 {0, 0.005, 0.01, 0.02}，共 12 个格点。
   - 每个终点都用同一组 J1 结论计算全部格点；主分析取 (0.5, 0.01)。
   - 报告各臂在每个格点下的均值，以及各臂排序是否在所有格点下保持一致。
   - 网格和拒绝原因列表写在 `preregistration()` 中，其哈希已写入冻结记录。
   - 安全失败时，所有格点都取 −1。
4. **拒绝率分布**：
   - 每次计算都通过 `attempt()` 记录一行，带上资源子集和需求层，算出的和被拒绝的都记；
   - 评价协议 v2 的 `refusal_report` 给出总拒绝率、按子集、按需求层、按原因的拒绝率；
   - 同时比较"实际算出的终点"与"全部尝试的终点"在需求层、子集上的比例差，防止只保留容易评分的终点。
5. **版本**：ER-v2 只接受 v2 检查表（否则拒绝：`checklist_protocol_not_v2`）。ER-v1 的 `to_outcome` 拒绝 v2 记录，反之亦然。

ER 永远不写入 GSC 字段（`is_gsc=false`），恒为 engineering_only，不能升级为 research_qualified。

## 3. 评价协议 v2（决策 1 的统计部分）

- 对照臂与 v1 完全相同，仍预先固定。
- **相关性**：
  - 推断单位是"owner–family 簇"：共享任何来源 family 的 owner 合为一簇；会话和前缀嵌套在簇内；
  - 用簇自助法估计（B=2000，种子 20261118）；
  - 每个估计旁都报告前缀数、会话数、owner 数和簇数；
  - 簇少于 10 个时，明确警告区间不可靠；
  - iid 标准误只作对照，并标注"仅供比较"。
- **自然分布**：用 B1 自然权重（owner 普查前缀数 / owner 入选前缀数）做加权估计，并给出簇自助区间。
- 新增指标：
  - 拒绝率，按子集、需求层、原因分列；
  - 实际算出与全部尝试的比例差；
  - GET 惩罚均值（标注不是成本模型）；
  - 实测阅读 token 均值；
  - 敏感性网格。
