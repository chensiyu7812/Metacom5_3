## 1. 结论：v2 确实存在误判

v2 判断"是不是同一个原子错误"只有两个依据，而且都是整句粒度，不是原子错误粒度：

- **A3**：一个 I 失败和一个 H− 失败的决定性引文，只要字符区间有重叠，就把 I 失败归给 H−；
- **I 类题干**：直接要求判官"除已在 H− 下判过的语句外"再判 I 类。

用同一张 fixture 检查表（总权重 18；H− 每项 2，I 每项 1）跑冻结的 v2 代码，结果如下：

| 反例 | 真实情况 | v2 结果 | v3 结果 |
|---|---|---|---|
| 1. 同一句含两个不同事实错误：Anna 仍在柏林（过时）+ 编造的失眠诊断 | H−:3 与 I:1 各错一次，0.833 | 只算 H−:3，0.889，**漏掉一个错误** | 0.833，正确 |
| 2. 同一句含历史矛盾 + 把资源里的建议当成已执行 | H−:1 与 I:3，0.833 | 0.889，**漏掉** | 正确 |
| 3a. 判官引整句，但只有一个子命题错（同一错误又报在 I:1 下） | 只算 H−:3，0.889 | 0.889，正确 | 正确（同一错误 id） |
| 3c. 同样引整句，但两个子命题各是一个不同错误 | H−:3 + I:1，0.833 | 0.889，**漏掉** | 正确 |
| 4. 不同引文表达同一个原子错误（两处都说 Anna 在柏林） | 只算 H−:3，0.889 | H−:3 和 I:2 都扣，0.833，**重复扣分** | 正确 |
| 5. 两名判官对同一错误的归属不同（J1 归 H−:3，J2 归 I:2） | 一个错误，0.889 | C0 下两项都是 uncertain，GSC 区间 [0.833, 1.0]：下界把错误算两次，上界一次也不算 | 进入人工裁决前保持 pending；裁决后为 0.889 |

关于 3a 和 3c：两者给 v2 的输入完全相同（两条引文都是整句），正确答案却不同。所以任何只看字符区间的规则，最多只能在其中一个上正确。

## 2. v3 规则（按原子错误判，不按引文重叠判）

v3 包含三个部分：
- 检查表模板 `pmrl1v3-checklist-template-v3`；
- 判官协议 `pmrl1v3-itemjudge-v3`；
- 双判官聚合 `pmrl1v3-judge-aggregation-v3`。

判官先列出**原子错误账本**（ERRORS），每个原子错误一条，包含：
- `id`；
- `kind`：history_conflict，或 I 类四种之一；
- `quotes`：回复里表达该错误的**每一处最短原文**；
- `evidence`：被违反的证据编号。

然后逐项作答。H− 或 I 判 fail 时，必须引用账本里的错误 id。

| 规则 | 内容 |
|---|---|
| L1 | 一个原子错误只占账本一条。同一错误说了两次：一条，两处引文。同一句里有两个错误：两条，各自给最短原文 |
| L2 | **归属只看错误类型和证据，不看文本**：history_conflict 归持有该证据的 H− 项；I 类错误如果引用了某个 H− 项的证据，也归该 H− 项（研究者规则：与具体历史证据矛盾的归 H−）；其余 I 类错误归对应的 I 项 |
| L3 | 一个错误只在它的归属项下扣一次；其他项引用同一个错误时，改记为 pass，并保留 `attributed_to` 和原判 |
| L4 | 不同条目、引文不重叠，就是不同错误，全部计入，同一句里也一样 |
| L5 | 不同条目归属不同、但引文重叠（相同、包含或部分重叠）时，**既不合并，也不确定地重复扣分**：优先级高的一项判 fail（H− 按检查表顺序，然后 I:1 到 I:4），优先级低的一项判 uncertain。J1 区间因此是"两个错误"到"一个错误"，真实情况一定在区间内 |
| L6 | 判 fail 必须有有效的错误 id，否则记 uncertain；某项在账本里有归属于它的错误，却答了 pass 或 uncertain，也记 uncertain |
| L7 | 双判官时，如果 H−/I 内出现"J1 判 X 失败、J2 判 Y 失败"这样的交叉，该终点在人工裁决这些项之前**不进入 GSC 表**（C0 合同要求此时 final = uncertain；如果不拦，下界会扣两次，上界一次也不扣） |
| L8 | H+（遗漏）和 S（安全）不与 I 合并（沿用 v2 的 A5/A6） |

v3 的固定结构与 v2 相同：
- 检查表项目、类别 H+/H−/R/G/I/S、约束类型、权重、总权重和证据都不变；
- 唯一的文字改动：I 类四个问题去掉了"除已在 H− 下判过的语句外"这一整句粒度的限定。

**已知限度（如实记录，没有隐藏）**：同一个错误出现在两处，而判官既没有合并成一条、又没有引用证据，且两处引文不重叠时，没有任何机械规则能判断它们是同一错误，这时会计入两次（见 `test_case4_residual_...`）。账本保留了两条记录，供 B2 开发核查和 J2 对照时发现。

## 3. ER 版本随之升级

ER-v2 按设计会拒绝所有不是模板 v2 的检查表，所以新增 ER-v3（`pmrl1v3-engineering-reward-v3`）：

- **计算与研究者条件完全沿用 ER-v2**：
  - J1 上下界取中点；
  - 每次 GET 扣 0.01，并与实测 token 开销分开报告；
  - J1 安全项失败记 −1；
  - 任何 hard_safety 项为 uncertain 时拒绝计算；
  - 不确定权重超过 1/3 时拒绝计算；
  - 同一个 12 格敏感性网格；
  - 拒绝情况按子集和需求层统计。
- **只改输入绑定**：检查表必须是 v3，J1 必须是判官 v3。记录中附带 J1 账本摘要：归属、改归、重叠歧义、无效条目。
- ER-v3 有新的预登记哈希；ER-v2 原样保留。ER 永远不写入 GSC，也不标 research_qualified。
