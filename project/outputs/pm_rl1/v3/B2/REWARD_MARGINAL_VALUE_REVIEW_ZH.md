## 0. 核心问题的回答

**ER-v3 只能辨认一种增量**：读了资源后，回复满足了 NeedCard 预先写明的 `required` 历史（H+），或者避开了 NeedCard 记下的已失败建议、过时事实、冲突（H−），同时没有新增 I/S 错误。除此之外它看不到：

| ER-v3 看不到的 | 反例 | 后果 |
|---|---|---|
| 支持质量是否因资源变好：只有 3 个对所有前缀都相同的通用是非题（G） | C2a、C8b | 读资源后"更贴切、更温暖、更有用"无法得分 |
| 不必要提及、无关但真实的引用：没有对应条目 | C2a、C4 | 只付出 0.01（一次 GET 的工程常数） |
| 资源本身已过时：I:1 明文接受"资源里有"的陈述 | C9b | 只有写卡时记下了更正，H− 才能抓到 |
| G 没用上读到的资源，还是资源本身没价值 | C3 | 研究上会被写成"资源无价值" |
| 区间未定的两个终点：主值 u=0.5 仍给出排序 | C10a | DP、BC、PPO 用的正是这个主值 |

此外，权重让"引用 required 历史"压过支持质量：H+ 权重 2，等于两个 G 项。一条引用历史但说教的回复，得分高于一条温暖但不知道历史的回复（C8b，+0.046）。

**结论**：ER-v3 主要奖励"覆盖写卡者认定的必要历史，加上避免表面事实错误"，不是资源带来的支持质量增量。
- PM 只选子集，G 冻结，所以 PM 不能直接迎合判官。但它会学到"打开能让 G 引用 required 历史的资源"。
- 只要 `required` 标多了，就会变成奖励引用历史（C2b，+0.101）。
- ER-v3 可以继续作为 engineering_only 的训练信号，**不能**作为资源边际价值或自然支持收益的证据。

ER-v3 做对的部分：
- 不奖励 GET 本身，也不奖励 RS 被读到（C5）；
- `relevant_optional` 不生成条目，不提不扣分（C1、C2a）；
- 能抓住案例引起的错认和已失败建议的重复推荐（C6），以及组合时的冲突（C7）；
- uncertain 不填 0，安全项不确定就 pending（C10b）；
- 同一前缀的分母固定。

## 2. 十类反例的预期评价结果

- 同一个 fixture 前缀。当前对话：工作压得喘不过气、睡不着、"要不要再试呼吸练习？今晚需要个计划"。严格过去：呼吸练习没用；Anna 搬去柏林，后来又搬回来；老板拒绝减少加班。

从这十类反例得出三条结构性结论：
1. **ER-v3 能看到的增量，全部来自 NeedCard**：H+ 条目，或 OFF 违反的 H− 条目。NeedCard 没写的价值（例如更贴切的安慰）和 NeedCard 没写的风险（例如无关暴露、漏记的更正），ER 都看不到。
2. **ER-v3 做对的部分，全部依赖 NeedCard 角色和更正标注的准确性**。目前写卡 0 次、核查 0 次。核查要单列两项：`required` 的精确率，以及更正和失败建议的召回率。
3. **主值 u=0.5 会给未定的终点对排序**。DP 教师、BC 标签和 PPO 回报都继承这个排序。网格能事后暴露，但训练时不会自动避开。

## 3. ER-v3 的能力边界

| 维度 | ER-v3 的做法 | 能说明什么 | 不能说明什么 |
|---|---|---|---|
| 单位 | 单个终点的绝对分：检查表通过的权重比例，减 0.01×GET；安全失败直接记 −1 | 这个终点满足了多少预先写好的检查项 | 相对 OFF、相对已读集合的边际价值（要靠同一前缀的终点差，见第 5 节） |
| 支持质量 | 3 个通用 G 项，对所有前缀相同 | 有没有回应最近一句、有没有回应情绪、有没有说教 | 资源带来的贴切度、具体性、时机 |
| 事实 | H−（写卡者记下的冲突、失败、过时）和 I:1–4（编造、错认、把建议当作行动、无据推断） | 回复违反了已知证据，或编造了用户历史 | 资源支持但已过时的陈述（C9b）、无关但真实的暴露（C4） |
| 历史需要 | H+，权重 2，问句是"take into account" | 写卡者认为必需的历史有没有被顾及 | 这个"必需"是否属实（未核查）；顾及 ≠ 必须明说（判官解读待测） |
| 方法 | R 只问是否回应了求助请求 | 不会因为读了 RS 就加分 | 方法是否适用、案例是否合适 |
| 判官 | 只有 J1；J2 未运行；不是 GSC | 工程上可复现的逐项信号 | 研究资格（B3 未做）、跨家族一致性 |
| 不确定 | 取区间中点；不确定权重超过 1/3 或安全项不确定时拒绝，终点 pending | 不填 0，也不为缺失项编造结论 | 中点排序可能把未定说成更好（C10a） |
| 成本 | 0.01/GET，标明是工程常数；token 单独报告 | 读取次数 | 真实在线等待（B4 未交付） |
| 归因 | 无 | — | 区分检索漏召回、G 没用上、资源无价值 |

**用途边界**：ER-v3 可以继续支撑 B6e/B8e 的工程训练和代码自检。它的数值不能写成"资源有效""PM 学会了何时开"或"自然支持改善"。B6e 报告中的 ER 均值不能与人评或正式奖励混在一张表里比较。

## 4. 可信奖励所需的人评与判官资格

**4.1 必须先有的人评（研究者完成；Codex 的文本检查不算人评）**

| 人评对象 | 为什么不能省 | 最低要求 |
|---|---|---|
| NeedCard 核查（20 卡试点 → 正式 B1 40 卡） | ER 和检查表的全部增量都来自 NeedCard（第 2 节结论 1） | 证据错误 ≤10%（已预注册）；另外单独报告 `required` 精确率（C2b）、更正和失败建议的召回率（C9b）。这两项不达标时，H+/H− 不能进入研究级奖励 |
| 成对支持质量 Q(S, 基线) | ER 没有支持质量通道 | 同一前缀，OFF 对 S、B 对 B+h，随机左右；"明显好 / 略好 / 相当 / 略差 / 明显差 / 无法判断"；必须允许"相当" |
| 吸收（uptake）抽样 | 区分 G 没用和资源无价值 | 先用机械方法（回复中的陈述能否在读到的文本中找到依据）给出初判，再人工抽样核对精确率 |
| H3 最终盲评 | 自然支持收益只能由它确认 | 冻结后进行，使用未参与调参的 owner，按 V3.1 的 120 对设计 |

**4.2 判官资格（B3）的补充要求**

V3.1 已有的候选最低验收：逐项准确率 ≥ .85、κ ≥ .6、偏好一致 ≥ .75、uncertain ≤ 20%，按类别分别计算。按本审查需要增加：
- **把十类反例作为分层类别写进校准集**，至少包括：OFF 已足够、可选历史不提、无关引用、G 忽略资源、过时事实、真正相当、案例误用。
- **"相当"识别率**：人评判为相当时，判官也判相当或不确定的比例。历史上的 Qwen 在 80 题里 0 次不确定，这一项必须单独过门。
- **换序一致率 ≥ .80**（成对通道）：历史上的成对比较全部低于 .80。
- **H+ 的解读**："take into account"是否被判官当成"必须明说"。用"隐含顾及但没有明说"的样本单独测。
- **写卡与判官同源偏差**：J1 与 writer 都是 Qwen3.5-9B。至少要有不同家族的 J2，或者人工抽样，来估计两者共同的漏判。
- **样本量**：p≈.85 时，Wilson 95% 区间的半宽，30 例约 ±.13，60 例约 ±.09。V3.1 初批的约 60 个终点加 40 对，不足以给 10 个类别分别定资格。应优先保证：H+ 必要性与解读、H− 过时或失败、Q 的相当识别、无关引用、安全。数据不足的类别标为"未定资格"，不得用总体高分代替，也不得悄悄把权重设成 0。

## 5. 资源价值、Generator 能力、检索质量的错误归因分离方案

**5.1 比较条件**：同一合法前缀，同一 G，同一解码身份，同一检查项全集和分母。

| 条件 | 用途 | 是否可部署 |
|---|---|---|
| OFF | 共同参照 | 是 |
| 各单资源 RS / MP / ME / MS | 对 OFF 的单头边际 | 是 |
| 实际可达的组合（≤16 个子集，以 B5/G0e 的可达表为准） | 相对已读集合的边际 Δ(h｜B) 与交互项 | 是 |
| 固定强基线：ALL、Fixed-best（只在训练折上选） | 学到的选择是否胜过固定选择 | 是 |
| F-resident（方法指导常驻提示词，不读取资源） | RS 的价值来自"读取"还是来自"提示" | 是 |
| RS 只给方法卡 / 只给案例 / 两者都给 | 案例是否引起误用（C6） | 是 |
| oracle 证据（直接注入 NeedCard 证据原文） | 诊断检索与 G 的上限 | 否，只作诊断 |

**5.2 每个条件分别报告**（不拼成一个分数）：
- 有证据的事实正确性 F：H−/I 的通过、失败、不确定，以及保留区间的 required 遗漏；
- 支持质量 Q：相对 OFF 和相对 B 的成对结果，标明人评或已获资格的判官；
- 不必要提及率、误用率：I 类失败，加上无关引用（需要新增检查项或人评字段，见第 8 节）；
- 安全：失败、不确定、通过；
- 真实端到端在线等待：首段可见与完成的 p50/p95，口径按 B4；离线 NeedCard 与判官耗时不计入；
- 判官 uncertain 比例、ER 拒绝原因、pending 终点数。

**5.3 边际的定义**（`evaluate/marginal_value.py`，提案；单元测试 4 项，另有 20 项反例测试用它计算边际）：
- 对 OFF：Δ(S｜OFF) = [L(S) − U(OFF), U(S) − L(OFF)]；
- 对已读集合：Δ(h｜B) = Δ(B∪{h}, B)，只对可达的 B∪{h} 计算。不可达的不出现，pending 的记为 pending，**都不记 0**；
- 交互项：I(h1,h2｜B) = V(B+h1+h2) − V(B+h1) − V(B+h2) + V(B)，用区间运算；
- 判定：整个区间高于 +δ 才是 benefit，整个区间低于 −δ 才是 harm，落在 [−δ, δ] 内是 equivalent，其余是 undetermined。δ 在 train/dev 上预登记；**中点差不能单独作为改善的证据**（C10a）；
- 部署标签沿用 Paper-1 的决策正确性规则：beneficial = 质量有益，且没有实质危害，且满足等待约束。等待未实测时只能标 undetermined。
- **不得**把 GET 成功率、检索相关率、方法调用率转成奖励；它们只出现在下面的归因链里。

**5.4 归因链**（每个边际 Δ(h｜B) 一条）

```
need（经核查的 NeedCard）→ retrieval_hit（读到的文本是否含 NeedCard 证据，机械检查）
  → uptake（回复是否陈述了读到文本中的内容）→ effect（区间边际）→ 归因类别
```

| 归因类别 | 条件 | 归到谁 |
|---|---|---|
| retrieval_miss | 有需要，但读到的文本里没有 NeedCard 证据 | 检索、资源库 |
| generator_not_used | 有需要、检索命中，但回复没有用上 | G（G1 训练的对象） |
| used_no_gain | 用上了，但相当 | 资源对这个 G 冗余（例如通用 RS，C5） |
| realized_value | 用上了，而且整个区间有益 | 资源价值兑现 |
| misuse_or_harmful_use | 用上了，而且有害 | 资源内容或 G 的使用方式 |
| unneeded_read / unneeded_read_harm | 卡片说不需要 | PM 的开销或误开 |
| unanticipated_value | 卡片说不需要，但有益而且用上了 | NeedCard 的召回缺口（反过来核查写卡） |
| undetermined / need_unverified / pending | 区间未定、卡片未核查、终点缺失 | 不下结论 |

再用三组对照区分"资源本身"和"这个 G 的能力"：
1. oracle 证据对检索证据：oracle 有益而检索无益，归检索；两者都无益而需要属实，归 G 吸收或需要本身不成立；
2. 同一资源换较小的 G：资源对 12B 的 G0e 冗余，不等于资源无价值（11-13 的建议之一）；
3. F-resident 对 GET_RS：两者相当，说明 RS 的价值来自提示词，不来自检索，也就不需要 PM 来开。

PM 的决策正确性（ON-benefit recall、OFF specificity、unnecessary-open、missed-benefit、balanced accuracy）用上面的**收益标签**计算，不用 NeedCard 的需要标签。NeedCard 需要覆盖率只作描述性指标单独报告。

## 6. latency-aware 正式奖励候选（`pmrl1v3-research-reward-candidate-v0`，提案，未采用）

**6.1 定义**（每个前缀 x、每个终点 S；同一 G，同一解码）

```
可行性（硬约束，不与等待交换）：
  Safety(S) = fail → 不可行；uncertain → pending；只有 pass 进入效用
  F(S)：H−/I 和来源、时间、角色约束中，确定的违例数；不确定的保留区间
效用（只在可行终点上）：
  R(S) = Q(S ‖ OFF) − κ · F_viol(S) − λ · ΔT(S)
  Q：经人评校准的成对支持质量。五级映射到预登记的 {−1, −.5, 0, .5, 1}；"无法判断"保留为区间，不记 0
  ΔT：B4 验证过的在线附加等待（秒），相对 OFF
  required 遗漏：只在写卡核查合格后，作为 F 中的一类违例
```

**6.2 原则如何落实**

| 原则 | 落实方式 |
|---|---|
| 可验证的事实与来源约束 | F 优先程序化（证据跨度、时间版本、说话人）；语义判断只用通过困难反例校准的判官 |
| 经人评校准的支持质量 | Q 是成对比较，校准见第 4 节；不用 3 个通用是非题代替 |
| 硬安全约束 | 安全失败的终点不可行，不能用低等待抵消 |
| 经 B4 实测验证的在线延迟 | ΔT 来自 80 组真实请求的成本模型，并在独立请求上测误差；0.01/GET 不再出现 |
| uncertain 不填 0 | 全部用区间；可能颠倒训练折最优动作的未定，主动补标或标为"区间最优" |
| 相同前缀固定分母 | 检查项全集和 OFF 参照都在候选回复之前冻结 |
| 不强制提及 relevant_optional | 没有任何条目奖励提及可选内容；Q 只问支持质量 |
| 离线判官和 NeedCard 耗时不计入在线等待 | ΔT 只计 PM、检索、读取、渲染和 G 的在线环节 |

**6.3 预登记**：κ、λ、δ、Q 的映射，以及质量非劣界，都只在 train/dev 上确定。
- λ 沿用 V3.1 的网格 {0, .02, .05, .1, .2, .4}。
- 工作点选法：dev 上质量相对 Fixed-best 非劣（界 δ），且平均附加等待 ≤1.5 秒、p95 ≤3 秒。做不到就报告完整的质量—等待前沿，不改测试。
- 测试折和 H3 封存；结果出来以后不改任何参数。
- 始终同时报告原始的 Q、F、Safety、ΔT、GET 次数，不只报一个拼装分数。

**6.4 ER-v3 与正式奖励的区别**

| 项 | ER-v3（冻结，工程级） | 研究级候选（提案） |
|---|---|---|
| 用途 | B6e/B8e 工程训练、代码自检 | B6/B8 正式主比较 |
| 支持质量 | 3 个通用 G 项 | 经人评校准的成对 Q |
| 历史需要 | 写卡者的 required，未核查，权重 2 | 只用核查合格的 required，作为 F 中的遗漏违例 |
| 不必要或无关提及 | 不计 | 进入 Q 和误用率 |
| 判官 | 只有 J1 | 过了资格的判官（分类别）+ 人工校准；J2 不同家族 |
| 不确定 | 中点 0.5 作主值 | 区间；未定不排序 |
| 成本 | 0.01/GET 工程常数 | B4 实测的 ΔT，λ 在 dev 上选 |
| 安全 | 失败记 −1，不确定拒绝 | 失败不可行，不确定 pending |
| 能支持的主张 | 只有工程运行和学习机制 | 在资格范围内的资源价值和 PM 决策；自然支持收益仍需 H3 |

## 7. BC / OneShot / PPO 的必要消融（学习问题是否真的存在）

**7.1 Phase-1 固定 16 个终点能证明什么**
- 终点只取决于子集；全表打分后，DP 能精确给出每个前缀的最优子集。学习问题因此只剩一个：**从可见观察泛化到留出 owner 的最优子集**。
- 能回答：
  - 读前可见信息能否预测最优子集（OneShot）；
  - 读后正文是否带来额外的预测信息（Seq-BC 对 OneShot，对 NoText）；
  - 相对 Oracle 的遗憾。
  这些都**在所用奖励之下**成立。
- 不能回答：
  - 奖励是否反映支持质量（第 3 节）；
  - 长期收益；
  - 自适应查询的价值（Phase-2）；
  - 自然分布下的效果。
- 在完整的确定性表上，BC 模仿的就是最优标签。PPO 在训练集上找不到更好的标签；它的优势只可能来自泛化方式（正则、用期望回报而不是噪声 argmax）。**预期差异很小。**

**7.2 何时 OneShot 或 BC 已经足够**
- 最优子集由读前观察决定，或者读后正文不改变下一步决策 → OneShot 足够。
- 大部分前缀的最优是 OFF，少数在明确回指时需要记忆 → 透明规则（Rule）可能与学到的策略相当。
- 在训练折上先算一个上界：用全表比较"看到正文后才决定的最优"与"一次性最优子集"的差，作为读后信息价值。这个上界很小时，不必期待 Seq 或 PPO 胜出。

**7.3 读后观察提供什么新的决策信息**
- Phase-1 是静态查询。读头 h 揭示 h 的 top 记录正文，只有当它预示**其他头**的价值时，才对下一步有用。例如：
  - ME 正文指向某次会话 → 需要 MS；
  - MP 已经完整覆盖了需要的事实 → 不必读 MS；
  - 读到的记录无关 → 检索在这个前缀上不可靠。
- B8e 合成预检（engineering_only）中，任务按构造让正文指向 MS：Seq-BC .628、OneShot .617、Seq-BC-NoText .616、Bayes .643。这只说明代码**能**利用存在的信息，不说明真实前缀里有这种信息。
- 同一预检中 PPO 为 .638，高于 Seq-BC，但 PPO 用了约 41 万环境步，Seq-BC 只用了 760 个实例的 DP 标签，不是同反馈对照。这正是 BC-union 必须存在的原因。

**7.4 PPO 可能有额外收益的条件**
1. Phase-2 自适应域：终点无法枚举，BC 没有完整的 DP 教师，PPO 按需探索。代价是在线生成，pending 不能当 0。
2. 平局多、标签噪声大：PPO 优化期望回报，可能避开 argmax 的赢家诅咒。但 OneShot 的软目标和 Seq-BC 的多标签平局已经针对这一点，必须用同样多反馈的 **BC-union** 作对照。
3. 序贯 BC 的误差累积：最多 4 步，影响有限。

**7.5 PPO 不优于 BC 时的解释**
- 这是 Phase-1 的**预期结果之一**：这个有限决策问题能由 DP 标签的监督学习解决，RL 在这里没有额外收益。这不是 PM 失败。
- 主张要分开写：Seq 对 OneShot 回答"读后信息是否有用"；PPO 对 BC 回答"优化方式是否有用"。
- **禁止**：
  - 看到结果后改奖励（加塑形项，改 GET 惩罚、u 值或 δ），让 PPO 胜出；
  - 只报告 PPO 胜出的网格点；
  - 让 PPO 比 BC 用更多反馈而不加 BC-union。
- 所有臂都在同一个冻结奖励和完整网格上评价，报告排序在网格上是否稳定。

**7.6 必要消融**

| 臂或对照 | 回答的问题 | 公平条件 |
|---|---|---|
| OFF / ALL / Fixed-best / Rule / Random-matched | 需不需要按前缀选择 | 同 G、同可见信息；Random 与 PM 的平均 GET 数相同 |
| F-resident；RS 方法卡与案例分开 | RS 价值来自读取，还是来自提示 | 同等提示长度报告 |
| OneShot 对 Seq-BC | 读后信息的价值 | 同一读前观察 |
| Seq-BC 对 Seq-BC-NoText，以及**打乱正文对照**（换成其他前缀同一头的正文） | 有用的是正文内容，还是"读过"这个标志 | 同一表 |
| BC-union 对 PPO-BC-init；PPO-scratch | 优化方式本身，以及 BC 初始化的作用 | 同样多的终点反馈 |
| LLM-gate | 零样本门控是否已够 | 门控耗时计入在线等待 |
| DP-Oracle | 上界 | 只作特权诊断 |
| **奖励交换**：用 ER-v3 训练，再用研究级奖励或人评评价 | 有没有对工程奖励过拟合（Goodhart） | 评价奖励不参与任何选择 |
| **需要标签对收益标签**：决策正确性分别按 NeedCard 需要和第 5 节的收益标签计算 | 学到的是"需要"还是"收益" | 两者都报告，不互相替代 |
| 按需求层（none / method / history / both）和自然权重 | 结果是否只来自过采样层 | owner 聚类 |

## 8. 尚不能成立的研究主张，以及下一步最低验证条件

| 主张 | 现状 | 最低验证条件 |
|---|---|---|
| 某类资源在 G0e 下有边际支持收益 | 真实终点 0 个；历史上 RS 约等于占位，记忆只在需要回忆的轮次有大反差 | B6 完整子集表；Q 通道过 B3 资格；有 uptake 记录；按 owner 的区间 Δ 下界高于预登记的 δ |
| ER-v3 反映支持质量或资源价值 | 否（本审查） | 不成立。只作工程信号 |
| NeedCard 的 required 是可靠的需要标签 | 0 张卡；写卡者与 J1 同为 Qwen3.5-9B | 20 卡试点和 40 卡正式 B1 核查通过；另报 required 精确率、更正召回率 |
| GET_RS 有必要 | RS-v0 标签未验证；历史 RS 设计阶梯约等于占位 | 只能由 RS 单读、F-resident、方法与案例分开的边际 Δ 证明；RS 内容是否改为 G 缺少的外部情景知识，由研究者决定 |
| PM 学会了何时开、何时关 | 没有合格奖励 | 留出 owner 上，按收益标签计算的决策正确性优于 Rule 和 Fixed-best，且附加等待不更高 |
| 读后信息有价值（序贯优于一次性） | 只有合成预检 | 真实表上 Seq-BC 同时优于 OneShot 和打乱正文对照，owner 级区间不含 0 |
| PPO 优于 BC | 未测；Phase-1 预期差异小 | 同反馈 BC-union 对照、冻结奖励、全网格稳定；否则如实写"BC 已足够" |
| 延迟—质量权衡是最优的 | B4 未交付；0.01/GET 是工程常数 | 80 组真实请求建立成本模型并测独立误差；λ 在 dev 上选定 |
| 自然支持收益、用户获益 | 无 | H3：冻结后的独立盲评，与 F、ΔT 一起报告 |

**下一步的最低顺序**（GPU、模型调用、付费调用都要研究者单独授权）：
1. **研究者决定（CPU，不改冻结版本，只能另立新版本）**：
   - 评价协议 v3 提案：`omission_rate`、`unneeded_read_rate` 改名为"NeedCard 需要覆盖（描述性）"；RS 在核查前不进入 required_heads；新增基于收益标签的决策正确性。
   - 是否在检查表 v4 中加入"无关或不必要的个人细节"条目，以及"资源支持但已被后文更正"的规则。也可以不加，改由 Q 的人评通道覆盖。
   - 两者都必须在任何候选回复出现之前冻结。
