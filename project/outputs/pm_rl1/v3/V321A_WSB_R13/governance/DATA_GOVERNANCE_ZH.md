## 1. 清单（独立整理）

**方法**：

- 从 sanitized artifact 和 ESConv.json 中，按 sha 排序确定性抽取 850 个 ≥50 字符的句子作为指纹：
  - EvoEmo 生成会话 400 个；
  - EvoEmo 中来自 ESConv 的会话 150 个；
  - 只在 ESConv 中出现的 300 个。
- 对所有远端分支的全部 blob 去重后逐一读取，按 8 词片段匹配（已把 `&#x27;` 还原成撇号）。某文件命中 ≥3 个不同指纹，即记为“含 RAW”。
- 指纹只是抽样，所以清单是**下界**：只含少量原文的文件可能没被检出。

## 2. 三个使用范围

| 范围 | ESConv（含 EvoEmo 中来自 ESConv 的会话） | EvoEmo 生成会话 | 当前做法 |
|---|---|---|---|
| 内部研究 | 允许非商业学术研究，须署名 | Zenodo 记录为 CC BY 4.0（是否覆盖数据未写明），可能另受生成模型条款约束 | 研究者确认“非商业学术”后即有依据 |
| 人工评审共享 | BY-NC 允许以非商业目的分享，须附署名与许可链接；README 要求仅限学术研究 | 同上；最好得到作者确认 | 只在研究者确认受限共享条件之后，以仓库外的任务包、受限人员、承诺书的方式进行 |
| 公开再分发 | BY-NC 原则上允许非商业再分发，但 README 写有“All rights reserved … academic research use only”，有歧义 | **未确立** | **暂停新增**；现有文件的处理见 §3 |

## 3. 治理决策表

| 方案 | 做法 | 对 CI | 对协作者 | 对复现 | 对已存在的 Git 历史 |
|---|---|---|---|---|---|
| **A. 临时转私有** | 仓库设为 private | 继续可用：私有仓库的 Actions 消耗账户的分钟额度 | 只有被邀请的人能访问；外部审稿或协作需要逐个邀请 | 对外不可复现，直到重新公开 | 转私有之后，外人无法再访问分支、PR、提交和源码压缩包。但已有的克隆、fork（公开仓库转私有时，GitHub 会把公开 fork 分离成独立仓库）和任何缓存都无法收回 |
| **B. 保留公开代码，停止分发数据** | 把原始数据与 RAW 派生文件移出当前树，改为受控获取：只保留哈希、清单和获取脚本；测试使用合成夹具，或在数据存在时才运行 | 依赖真实数据的测试必须改成用合成夹具，或在 CI 中跳过（注意 V3 门禁拒绝 skip，需要相应调整） | 协作者需要单独获取数据（例如从作者处或受控存储） | 代码和流程可以公开复现，数据需要申请 | **只从当前树中移除不够**：历史提交、全部分支、PR 引用（refs/pull/N/head）中仍然存在。彻底移除需要改写历史（filter-repo）、强推所有分支，并请 GitHub 清除缓存的 PR 引用；这会使所有现有克隆与 PR 失效 |
| **C. 获得明确许可后维持现状** | 向作者确认许可（见邮件草稿）；补上署名、许可说明和 NOTICE | 不变 | 不变 | 最好 | 不变；前提是许可明确允许公开再分发 |

**建议的顺序**（供研究者决定）：

1. 立即做到（已做）：停止新增公开的 RAW 派生内容；分发包放在仓库外。
2. 尽快决定 A 还是 C：等待作者回复期间，**A 是最可逆的保护措施**，之后可以再转回公开；B 的历史清理成本高且不可逆，建议只在许可明确不允许、而又必须保持公开时采用。
3. 发出许可确认邮件（草稿见 [EMAIL_DRAFT_ES_MEMEVAL_LICENSE.md](EMAIL_DRAFT_ES_MEMEVAL_LICENSE.md)，研究者审核后自行发送）。
4. 收到回复后，再决定是否回到公开（C），或转为 B。
