## 1. 模拟的完整流程

1. **整理者**（9 个前缀，其中 1 个没有历史，用表单 S7）：
   - 先填 4 项并提交，第 5 项只存草稿，然后关闭页面；
   - 重新打开后进度恢复，草稿也恢复；
   - 导出进度，换一台“新电脑”（全新的浏览器配置）导入；
   - 完成全部、锁定阶段、导出阶段文件。
   - 另外验证：不内置任务包的通用工具可以通过“打开任务包文件”使用。
2. **审阅者 R1、R2：第一部分（Q0）**：8 对全部提交，锁定后导出阶段文件。
3. **协调人**：
   - 用 Python 复核阶段文件；
   - 登记锚点（Q0 锁定事件的哈希）；
   - 生成第二部分，同时生成一个锚点错误的“坏”第二部分用于测试。
4. **审阅者：第二部分**：
   - 载入坏的第二部分，被拒绝；载入正确的第二部分；
   - 完成 QH 8 对、探针 8 对、F 16 份；
   - R1 在 F 中途关闭页面后重开；R2 在 F 中途导出进度，换电脑导入；
   - 最后锁定并导出最终文件。
5. **协调人**：从两份已全部锁定的最终文件构建裁决包和 F-A 包。
6. **裁决者与 F-A 审计**：完成后导出。
7. **Python 收尾**：复核所有文件，运行篡改测试，扫描所有盲页面的可见文字，计算程序指标。

## 3. 盲态

- **任务包**：所有盲包（整理者、R1/R2 的第一和第二部分、裁决包）都通过泄露扫描：
  - 键名和非正文字段中，没有条件、资源、标签、分数、请求、会话或层名称的词汇；
  - 正文中没有任何真实标识（回复键、案例键、owner 键）。
- **第一部分**：不含任何历史。
- **页面可见文字**：Q0、QH、F、探针和裁决页面的文字中，0 处条件、标签或分数词汇，0 处标识。F-A 页面按设计显示条件，不计入扫描。
- **位置**：每个通道恰好 4/8 的对照出现在“回复甲”；R2 与 R1 位置镜像，所以每一对在两名审阅者之间以两种顺序出现。
- **QH 页面**：每一对打开时都没有任何预选，也就是不显示 Q0 的选择。
- **限制**：盲态检查管的是“表单和页面不泄露”。回复自身如果提到过去，那是正文内容，照常显示，由审计侧标记。PP1 中的探针猜中率只作描述。

## 4. 失败与篡改测试

| 篡改方式 | 被谁发现 |
|---|---|
| 改动一个已锁定的答案 | 哈希不符 |
| 删除一个事件 | 序号断开 |
| 交换两个事件的顺序 | 序号断开 |
| 改动 Q0 答案后把整条链重新哈希 | 第二部分的锚点对不上，重放失败；即使不载入第二部分，也会因为不再扩展已登记的锚点而被发现 |
| 对已锁定的项目追加一个格式正确的草稿 | 重放规则拒绝 |
| 改动任务包内容 | 包哈希不符 |
| 去掉 Q0 锁定事件后整链重新哈希 | 后续步骤全部非法（阶段顺序或锚点） |
| 自行重新封装一个协调人没有发放过的任务包 | 收件核验拒绝 |
| 向审阅者包注入条件字段 | 泄露扫描发现 |

浏览器中另外验证的拒绝情况：

- 表单 S 选 S1 却没有理由和“必要”片段，不能提交；
- F 中引用的不是回复原句，不能提交；
- 锚点不符的第二部分，不能载入；
- 锁定后修改、查看已锁定阶段，都被拒绝。

## 5. 已知限制

- **防篡改的边界**：没有密钥签名，日志是“可发现篡改”，不是“不可篡改”。整条链被重写，要靠协调人在收件时登记的锚点来发现。所以协调人必须在收到 Q0 阶段文件时立即登记锚点。
- **本地存储**：进度存在浏览器的本地存储里。清除浏览器数据就会丢失，所以要求定期导出进度。
- **时钟**：计时依赖本机时钟；时钟回拨会被记为警告，不会被修正。
- **浏览器覆盖**：只在 Chrome 中做了自动验收。Edge 用同一内核；Firefox 未做自动验收，建议 PP1 统一使用 Chrome 或 Edge。
- **数据**：真实的 PP1 任务包需要真实回复，要在生成之后才能构建。整理者包已经可以用真实数据构建，见 [PP1_CURATOR_PACKAGE_REGISTRY.json](../pp1_tool/PP1_CURATOR_PACKAGE_REGISTRY.json)；包放在仓库外，只登记哈希。
