# PP1 人工评审：角色职责模板与操作说明

- **工具**：[PP1_REVIEW_TOOL.html](PP1_REVIEW_TOOL.html)。单个离线 HTML 文件，不联网、不依赖外部资源，用 Chrome、Edge 或 Firefox 直接打开即可。
- **实际使用方式**：协调人为每个人生成一个内置了任务包的 HTML（例如 `PP1_REVIEWER_R1.html`），本人直接打开，不需要再选文件。
- **验收**：工具已通过模拟数据的端到端验收，见 [E2E 报告](../pp1_e2e/E2E_REPORT_ZH.md)。

## 1. 角色与可见范围

| 角色 | 人数 | 能看到 | 看不到 | 做什么 | 交付 |
|---|---|---|---|---|---|
| 研究者 | 1 | 全部 | — | 批准协议；授权 16 次调用；指派人员；保管真实姓名与代码的对照 | 批准与授权记录 |
| 协调人（审计侧） | 1（可由研究者兼任；WS-B 提供脚本） | 条件映射、salt、全部文件 | — | 生成并分发任务包；收件核验；登记锚点；锁定后构建裁决包与 F-A 包；揭盲与统计 | 收件登记表、锚点、程序指标报告 |
| 筛查整理者 | 1 | 当前会话；此刻之前的全部过往对话 | 任何回复、检索排名、样本层、DP 材料 | 表单 S：需要标签、风险、历史片段标注；兼任 DP 选材（规则见协议 A4） | S 阶段文件 |
| 审阅者 R1、R2 | 2 | Q0：当前会话 + 两份回复；QH/F：再加过往对话 | 条件、资源、读取内容、需要标签、任何旧分数或模型评判、对方的答案 | Q0 → QH → 盲态探针 → F | Q0 阶段文件；最终文件 |
| 裁决者 | 1（不是这些前缀的审阅者；人手不足时可由整理者担任，并登记） | 回复、历史、两名审阅者的匿名标签 | 条件 | 只处理 F 严重项的分歧 | 裁决文件 |
| F-A 审计 | 1（不是审阅者；可由协调人担任） | 条件，以及回复实际收到的材料 | — | 对每个“有”的错误做归因；不改变任何评审标签 | F-A 文件 |
| 生成执行（WS-A） | — | 请求与输出 | — | 按获批规程生成；输出交协调人封存，**不推送到公开仓库** | 输出文件与哈希 |
| 译者（如采用） | 1（不兼任审阅者） | 原文；回复（不知道条件） | 条件 | 逐句翻译，不润色、不删减 | 译文与映射 |

**利益冲突规则**：

- 整理者不担任同一前缀的审阅者；
- 审阅者不参与生成，也不访问仓库中的生成输出；
- F-A 审计和协调人不做盲评。

## 2. 流程与交接

```
协调人：salt 只登记 sha256 ── 生成整理者包 ── 整理者完成 S 并锁定 ──▶ 协调人收件核验（标签封存）
                                                    │
WS-A：研究者授权后生成 16 次 ── 输出交协调人封存（只登记哈希）
                                                    │
协调人：生成审阅者第一部分（Q0，无历史）──▶ R1、R2 完成 Q0 并锁定 ──▶ 交 Q0 阶段文件
协调人：核验，登记锚点（Q0 锁定事件哈希）──▶ 生成第二部分（QH、探针、F）
R1、R2：载入第二部分 ── QH 锁定 ── 探针锁定 ── F 锁定 ──▶ 交最终文件
协调人：核验（扩展了已登记的锚点；所有阶段都已锁定）──▶ 裁决包 ──▶ 裁决者 ──▶ 交裁决文件
协调人：F-A 包 ──▶ F-A 审计 ──▶ 揭盲（公开 salt）── 程序指标报告
```

协调人使用的命令（WS-B 脚本）都在 [V321A_wsb.py](../../../../../scripts/rl1v3/V321A_wsb.py) 和 [pp1_tool.py](../../../../../src/metacom_pm/rl1v3/review/pp1_tool.py) 中：

- `curator_package` / `reviewer_packages` / `adjudication_package` / `auditor_package`：生成各角色的任务包；
- `verify_export`：核验收到的文件；
- `extends`：核对最终文件是否扩展了已登记的锚点；
- `procedure_metrics`：计算程序指标。

## 3. 操作说明（发给整理者、审阅者、裁决者）

### 3.1 开始前

1. 用电脑上的 Chrome、Edge 或 Firefox 打开协调人发给你的 HTML 文件，不要用手机。
2. 页面顶部会显示角色、你的代码和“任务包”的前 8 位校验码。请与协调人告诉你的校验码核对。
3. 如果页面顶部是红色的“模拟数据”横幅，说明那是练习文件，不是正式任务。

### 3.2 作答

- 左侧列表是本阶段的全部项目。点击项目打开，按页面上的题目作答。
- 每次选择都会自动保存为草稿，文字在离开输入框时保存。也可以随时点“保存草稿”。
- 点“提交并锁定”并确认后，这一项就不能再改。
- 本阶段全部提交后，左侧出现“锁定本阶段”。锁定后本阶段的项目不能再查看，然后按提示**立即导出阶段文件**交给协调人。
- 页面里的回复按生成原文显示，不做任何修改。

### 3.3 各角色的特别说明

- **审阅者**：
  - **Q0**：只看当前会话和两份回复，判断即时支持质量。回复提到你看不到的过去信息时，只判断提法是否自然得体。
  - **QH**：Q0 锁定、并载入协调人发来的第二部分后才开放。你会看到对方完整的过往对话，按时间排列，可以搜索。是否提到过去本身不是评判标准。QH 页面不显示你在 Q0 的选择。
  - **盲态探针**：只回答“你认为哪份回复参考了过去的对话”，不影响任何评分。
  - **F**：逐份检查回复。选“有”时必须：
    - 选严重程度；
    - **逐字复制**回复中的原句；
    - 点“设为当前引用项”，再在历史中点“引用为依据”。
  - F5（虚构历史）可以勾选“查无来源”。没有提及可选的历史不是错误。
- **筛查整理者**：
  - 判断要给出合适的回复，是否需要知道这些历史。S1 必须写出理由，并在历史中至少标注一条“必要”片段。
  - 同一人物的前缀按时间先后排列，请按顺序做。
  - 你看不到任何回复，你的标签只有审计侧能看到。
- **裁决者**：两名评审者的原始标签保留不变。请独立查看后给出裁决和理由。

### 3.4 中断、换电脑和出错

- **中途关闭**：直接关闭浏览器即可。进度保存在本机浏览器里，再次打开同一个 HTML 就会恢复。
- **备份或换电脑**：点“导出进度”保存文件。在另一台电脑打开同一个 HTML，点“导入进度”选择这个文件。工具会先校验，然后接着做。
- **工具拒绝导入**：例如提示“分叉”或“校验失败”时，不要自己修改文件，把文件和截图交给协调人。
- **请勿**：
  - 清除浏览器数据；
  - 编辑导出的文件；
  - 把文件转发给协调人以外的人。

### 3.5 计时

工具记录每一项的打开、离开和提交时间，只用于估计评审耗时，不用于评价个人。中途休息时请离开项目页面或关闭浏览器。

## 4. 协调人收件核验清单

- [ ] 文件的 `base_package_sha256` 是本人的任务包。
- [ ] `verify_export` 通过：哈希链、阶段顺序、锁定后未改动、答案合规。
- [ ] Q0 阶段文件：登记 `stages.Q0.lock_event_h` 作为锚点，再用它生成第二部分。
- [ ] 最终文件：所有阶段都已锁定，并且 `extends(Q0 阶段文件, 最终文件)` 为真。
- [ ] 登记文件哈希、收件时间和 head 校验码，并在回执中告知本人。
- [ ] 生成输出和审计映射不进入公开仓库；全部锁定后再公开 salt 和映射。
