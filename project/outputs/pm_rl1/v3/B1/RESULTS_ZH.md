- 证据等级：engineering_only；只用 CPU，模型调用 0 次，没有 GPU 或付费调用
- 代码提交：`768084c8`；manifest：`manifest.json`（输入、输出、代码的 SHA256 都在其中）
- **没有生成任何真实 NeedCard**。生成器（本地 Qwen3.5-9B）需要两样东西：WS-A 的 RS 方法目录，以及研究者的 GPU 授权。本目录里没有需求标签，也没有正则得出的"需求"

## 1. 已实现（`src/metacom_pm/rl1v3/needs/`）

| 模块 | 内容 |
|---|---|
| `sources.py` | 把 B0 普查的输入转成 C0 的 `SourceSession`/`PrefixSpec`，并调用 `verify_source_context` 检查。**它不是 A1 的 source_registry**：<br>• 来源标记写为 `wsb-b0-census-source-adapter-v1`；<br>• A1 交付后，`cross_check` 要先确认轮次文本、角色、rank、日期、family、transcript 哈希零差异，B1 才改用 A1 的来源 |
| `spans.py` | 引文定位，只接受与原文逐字符完全相同的引文：<br>• 当前会话只搜索到 cut_turn（含）为止；<br>• 严格过去会话必须属于同一 owner 且完整；<br>• 同一引文出现多于一次时判为歧义并拒绝，除非指定了轮次（对应 T13）；<br>• 定位后再用 C0 的 `verify_legal_span` 复核 |
| `protocol.py` | NeedCard 生成器协议 `pmrl1v3-needcard-writer-v1`（英文提示，按附录 A）：<br>• 输入：当前对话最后 8 轮 + 所有严格过去会话的**完整**原文 + RS 方法目录；<br>• 不做截断：超出预算就判为 `over_budget`，不运行；<br>• 没有方法目录就判为 `blocked_method_catalog`，不运行；<br>• 原文作为带引号的 JSON 数据传入（防注入，对应 T23）；<br>• 输出按严格 schema 校验，解析失败报错，不会产生空卡 |
| `cards.py` | 组装 C0 NeedCard 和 B 侧外包记录（envelope）：<br>• 引文定位失败的条目删除，并记录原因；<br>• **需求层级根据保留下来的证据推出，生成器自报的层级只留作审计**，两者不一致时标记 `stratum_conflict`；<br>• 方法需求必须有当前对话中经核验的证据，否则删除；<br>• 生成失败记为 `writer_failed`，**不会记为 none** |
| `sampling.py` | 四种抽样框架：<br>• 自然评价池（不依赖标签）；<br>• 覆盖样本（不依赖标签）；<br>• 训练分层抽样（需要 NeedCard）；<br>• 审计抽样（40 张） |

**需求层级如何推出**：

- history：至少满足一项——有 `required` 或 `must_not_contradict` 条目，或有已失败/被拒绝的建议，或有被后来更正的旧事实；
- method：有方法族，并且当前对话中有经核验的证据；
- both：两者都满足；
- none：都不满足。只有 `relevant_optional` 条目时也是 none（不提这类内容不扣分）。

**细粒度头需求**（只记在评价侧的 envelope 中，不进入任何观察）：

| 证据 | 对应的头 |
|---|---|
| 方法需求 | RS |
| 个人稳定事实 | MP |
| 事件、尝试过的建议及其结果 | ME |
| 某次会话的具体细节 | MS |
| 已失败或被拒绝的建议 | ME |
| 被更正的旧事实 | MP |

## 2. 真实文本上的合法跨度验证（`span_validation.json`）

- 全部 4,119 个 B0 前缀都能重建为 C0 前缀，且通过 `verify_source_context`，失败 0 个；`prefix_id` 与 B0 一致。
- 每个前缀都做了机械探针。这些探针只检查定位规则是否正确，**不代表任何需求判断**：

| 探针 | 预期 | 实际结果 | 前缀数 |
|---|---|---|---:|
| 严格过去会话中最长一轮的前 60 个字符 | 能定位且合法 | 全部符合 | 4,119 |
| 同一引文多加一个空格 | not_found | 全部符合 | 4,119 |
| 另一个 owner 的原文，指定到本 owner 的会话 | not_found | 全部符合 | 4,119 |
| 切点后紧接的 supporter 回复 | future_turn | 全部符合 | 4,108 |
| 同一 owner 的未来会话 | unknown_session | 全部符合 | 3,926 |

- 预期与实际不一致：0 个。
- 切点后探针少 11 个：这 11 个前缀切点后的回复过短，或同一句话已在可见部分出现过，无法构造探针。
- 未来会话探针少 193 个：这些前缀所在会话已是该 owner 的最后一次会话，没有未来会话可测。

## 3. 抽样框架（只按哈希和折分选择，不使用任何标签）

### 3.1 覆盖样本 `coverage_sample_v1.jsonl`（24 个前缀）

- 每折 4 个：严格过去会话数分为 early（1–3）、mid（4–9）、late（≥10）三段，每段各取 1 个，再加 1 个任意段；每个会话最多取 1 个。
- 用途：
  - 全部 24 个用于 B5 真实回放；
  - 第 1–5 折的 20 个同时作为 NeedCard 试点样本和 B6e 候选；
  - 第 6 折（历史 test owner p4/p7/p14）只用于回放，不用于调试生成器或 B6e。
- 唯一带旧曝光的前缀是 p4_conv_4（`judge_or_feedback`），它在第 6 折。
- 20 个试点前缀的输入包状态都是 `blocked_method_catalog`。严格过去原文长度为 4,422–46,530 字符，都在 120,000 字符预算以内（全部普查最大为 78,940），所以将来可以**放入完整原文、不做截断**。

### 3.2 自然评价池 `natural_eval_pool_v1.jsonl`

- 选法：每个 owner 内按 B0 的 `sample_key` 排序依次取；同一 owner 的同一会话最多 2 个前缀；S ⊂ M ⊂ L 嵌套。
- 自然权重：`owner_census_n / owner_selected_n`，用来恢复按切点计的自然分布。
- 每行都继承 B0 的 fold 和曝光记录，`independent_unexposed_test` 一律为 false。B0 普查文件没有改动。

### 3.3 档位实际可达数（新发现，需要研究者决定）

| 档位 | 每 owner 目标 | 名义总数 | 实际可取 | 不足的 owner |
|---|---:|---:|---:|---|
| S | 16 | 288 | **288** | 无 |
| M | 27 | 486（方案写约 480） | **482** | p17 只有 24，p18 只有 26 |
| L | 54 | 972（方案写 960） | **748** | 15 个 owner 不足 |

- 原因：rank≥1 的会话一共只有 383 个，"每会话最多 2 个前缀"意味着总数上限是 766。所以**按现行规则，L 档 960 不可达**。
- 可选做法：放宽为每会话 3 个、取消 L 档，或接受 748。这需要研究者决定，B1 不会自行改动规则。
- M 档 482 已满足方案"约 480"的要求。

### 3.4 训练分层抽样（代码已完成，尚未运行）

- 需要先有经核验的 NeedCard。
- 每个 owner 的目标比例：history/both 50%、method 20%、none 30%。
- 某一层数量不够时用相邻层补足，补足原因逐行记录。
