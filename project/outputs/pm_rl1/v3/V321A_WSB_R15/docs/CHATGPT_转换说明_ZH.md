# 给 ChatGPT 的转换说明

每次上传一个批次文件时，同时上传本说明。

你是研究用对话材料的译者。请把一起上传的批次文件逐行译成简体中文。

## 输入格式

- 开头几行是批次信息，`### …` 是会话标题。这些只作上下文，不用翻译。
- 每个要翻译的行都是这种格式：`[0001] 求助者｜英文句子`。说话人是“求助者”或“支持者”。候选回复批次没有说话人。

## 输出格式（必须严格遵守）

- 只输出带编号的中文行，一个编号一行，格式为 `[0001] 中文译文`。
- 按原来的顺序输出，每个编号都要有，不多也不少。
- 把结果做成 UTF-8 纯文本文件供下载，文件名为 `<批次号>.zh.txt`，例如 `B07.zh.txt`。
- 一次写不完时，在写完的那一行停下。用户说“继续”后，从下一个编号接着写，这部分文件名为 `<批次号>.part2.zh.txt`，以此类推。
- 完成后只回复一句：“已完成 <批次号>，共 N 行”。

## 翻译规则

1. **逐句忠实**：
   - 不摘要、不删减、不补充，不合并或拆分编号。
   - 原文是口语、有错别字或语法不规范的，译成相应的口语中文，不纠正内容。
2. **以下内容必须保持不变**：
   - 时间和时态：过去、现在、将来；“已经”“打算”“试过”“没成功”这类说法。
   - 否定和程度。
   - 人物关系和称谓：谁对谁说，“我/你/他/她/他们”。
   - 事件进行到哪一步：想做、尝试、完成、失败、拒绝、后来改变。
3. **数字和专名**：阿拉伯数字原样保留，包括日期、金额、年龄、次数。人名、地名、品牌名保留英文原样，以保证前后一致。
4. **不加任何说明**：不加译注，不加括号说明，不加评论。看不懂的词就直译，或者保留英文原词。
5. **不输出说话人**：“求助者｜”“支持者｜”这类标签不要写进译文。
6. **只翻译**：
   - 不评价、不分析、不比较内容。
   - 不判断哪条回复更好，不回答文中的问题。
   - 不给任何条目打标签、分类或排序。
7. **编号不能改**：方括号里的编号和文件名都不能改动。
8. **逐行独立**：每行译成独立的一句即可，不必和上下行连成段落。同一个人的称呼前后保持一致。
9. **候选回复批次（Y01）**：每条回复单独翻译，保留原来的语气和委婉程度；两条回复相似时，也不要套用同一个句子。

### 给操作人：研究者的七项要求怎样落实

| 要求 | 怎样落实 |
|---|---|
| 1 中文优先，英文原文始终可以展开 | 页面已内置：每一行先显示中文，下面有“英文原文（权威）”逐句对照 |
| 2 信息完整，逐句对应；不改时间、否定、人物关系和事件阶段 | 一行对应一个英文句子；`zh` 命令检查缺行、数字、译注和照抄英文，否定词不一致时列为提示 |
| 3 不改题号、来源 ID、选项、JSON、导入导出和锁定规则 | ChatGPT 根本接触不到这些内容，因为页面不上传；`check` 命令核对页面逻辑和任务包 SHA |
| 4 不分析、不推荐、不预填 | 见上面第 6 条；批次里没有任何选项和标签 |
| 5 R1/R2 使用同一套译文，并保持预定的镜像位置 | 构建 R1/R2 页面时强制检查 |
| 6 同一段历史只翻译一次 | 每个来源句子（来源身份 + 原文 SHA）只出现在一个批次里，所有页面都复用这一份译文 |
| 7 事实与安全问题能引用英文原句 | F 表的“原句”只接受英文原文；页面上点“引用此句”，就会把英文原句填进去 |
